## 3. A. 路线收藏完整规格

### 3.1 数据模型演进（组合 / 组合下方案）

**融合后的层级**（D2）：

```
收藏（本机）
 └─ 组合 Combo（出发地 → 目的地）        ← 由 v2.2.0「地点对」升级而来
      ├─ 自定义站链 chain?（可选）
      ├─ 步行/五档参数 walk? tiers?（可选）
      └─ 已保存方案 ComboPlan[]（0..N）    ← 由 v2.2.0「路线方案快照」迁入
```

| 概念 | 语义 | 由 v2.2.0 何者升级 | 关键点 |
|---|---|---|---|
| **组合 Combo** | 一对「出发地 → 目的地」+ 可选自定义站链/参数 | `PlaceFavorite` | 顶层收藏单元；代表"去哪" |
| **组合下方案 ComboPlan** | 该组合下**用户显式保存**的一条具体方案（指纹 + 快照） | `PlanFavorite` | 代表"怎么走"；一条组合可含多条 |

**「多方案」的语义（D4，关键）**：
- 「多方案」= **点组合卡时现场实时算出的候选方案列表**（可能 0~N 条），**不是**静态存储；
- `ComboPlan`（已保存方案）只是其中**被用户显式存下**的子集；
- 结果列表中，与某个 `ComboPlan.fingerprint` 命中的卡 → 打「已保存」角标；未命中的 → 仍展示（实时结果）。

### 3.2 命名规则

| 项 | 规则 |
|---|---|
| 组合默认名 | `「出发地 label」 → 「目的地 label」`（如「擎天匯 → 澳科大」）；端点 label 用官方繁体原名 |
| 可改名 | 用户可将组合名改为别名（≤ 24 字）；改后默认名不再覆盖 |
| 组合下方案默认名 | 取 `summary` 或 `「首段线路 · 出发地 → 目的地」`（沿用 v2.2.0 `planTitle` 口径） |
| 方案可改名 | 同 v2.2.0（备注 `note` ≤ 40 字） |
| 迁移命名 | v2.2.0 `note`（用户备注）**优先作为新名称**；无 note 则用默认名（无损用户既有命名） |

### 3.3 自定义编辑器

**入口**：组合卡片「更多 → 编辑」；新建组合时进入；结果页「以此方案新建组合」（可选）。

**形态**：**纵向流程图**（自上而下），节点可点开编辑、可增删：

```
出发地
  │ 步行①
上车站
  │ 乘车段①（可多线并行，斜杠 A/B）
换乘站（可插入 / 可删除；最多 3 个换乘 → 最多 4 段）
  │ 乘车段②
下车站
  │ 步行②
目的地
```

**每节点可编辑项与默认值 / 范围**：

| 区块 | 字段 | 默认值 | 可编辑范围 | 说明 |
|---|---|---|---|---|
| 站链 | 出发地 / 目的地 | 必填（端点） | —— | 复用 `FavoriteEndpoint` |
| 站链 | 上车站 / 下车站 | 系统按实时算（chain 空 = 自动） | 可指定站点（搜索/地图选） | 指定后 chain 非空 |
| 站链 | 换乘站 | 无（直达） | 可插 0~3 个 | 插入后段数 = 换乘数 + 1 |
| **步行①（出发地→上车站）** | 距离 | 系统算（如 擎天汇(T8)→石排灣 = **450m**，D6） | `0–2000 m` | 单位 m |
| | 时长 | `距离 ÷ 84 m/min`（`WALK_BASE_M_PER_MIN`，架构师查订） | `0–30 min` | 改距离可不自动改时长（**待决**，见 §7） |
| **步行②（下车站→目的地）** | 距离 / 时长 | 同上 | 同上 | |
| **五档 · 速度** | 档1~5 速度 (m/s) | **`3.6 / 2.0 / 1.4 / 1.0 / 0.7`**（档3 = 基准，对应 `SPEED_RATIO[3]=1.0`） | `0.5–6.0 m/s` | 参考 `recommend/types.ts` 既有定义 |
| **五档 · 用时** | 档1~5 用时 (min) | 由该段距离 × 各档速度派生（档1 用随距离衰减 `TIER1_SEGMENTS`） | `0–120 min` | 用户可覆盖 |

**五档语义（沿用既有，架构师查订后回填精确值）**：
- 档位文案：`全力冲刺有机会赶上 / 小跑能赶上 / 正常走能赶上 / 慢慢走能赶上 / 爬过去都能赶上`；
- 档3（正常 1.4 m/s = 84 m/min）为**基准档**；改动档3会影响全局步行基线 → 编辑时**明确提示**（可能影响其他行程的步行估算）；
- 档1 具随距离衰减（`TIER1_SEGMENTS`：8s→3.8、22s→3.58、90s→2.68、>120s→2.24 m/s）。

**编辑器交互要求**：
- 图表节点可点选、可在任意两站之间**插入换乘**、可删除；
- 每个编辑项有默认值与范围校验（越界即回退并提示）；
- 提供「恢复系统默认」按钮（一键清空该组合的 chain/walk/tiers 覆盖）；
- 实时反馈：编辑参数后**即时预览**该组合的步行/五档用时（不请求）。

### 3.4 实时计算多方案（点组合卡）

**主流程**：
```
点组合卡
  → 取 combo：from/to + query + chain? + walk? + tiers?
  → 现场计算：
       · chain 为空  → 等价 /api/nav?${query}（现有契约，取 5 条）
       · chain 非空  → 按「自定义站链 + 步行参数 + 实时班次」现场算多方案
  → 结果：卡片列表（复用 RecommendCard / RecommendCards）
  → 已保存方案命中 → 打「已保存」角标
```

**口径**：
- 结果卡**复用现有卡片组件**（含 D1 斜杠渲染、赶车分档、`altBuses` 后续班车）；
- 组合卡上**不预显示具体时长**（避免误导）；点击后才出现时长（实时）；
- **已保存方案快照仅用于离线/降级展示**，不作真值（延续 02 §2.5）。

**无实时数据的降级表现**：

| 场景 | 表现 |
|---|---|
| 某段无实时班次（收班/无在途车） | 该段标注「暂无实时班次」；整链可算则仍出卡并说明 |
| 整链算不出（无任何候选） | 展示**已保存方案快照**（标「历史记录，可能已变化」）+「重新规划」按钮；无快照则空态 |
| 网络/接口失败 | 行内错误提示 + 「重试」；不崩、不清空 |

### 3.5 融合迁移（v2.2.0 → 新 schema）

**迁移锚点与新键**：读优先 **`must.favorites.v2`**；缺失时从 `must.favorites.v1` **迁移**（v1 键**不删**，留作回滚/审计）。

| v2.2.0 源 | 迁移目标 | 映射规则 |
|---|---|---|
| `PlaceFavorite` | `Combo`（`plans: []`） | `from/to/query` 直传；`name` = `note` ?? `「from → to」`；`createdAt/updatedAt/pinned/lastUsedAt` 保留 |
| `PlanFavorite` | `Combo` + 一条 `ComboPlan` | 先按 `query` **分组**：同 `query` 的多条 `PlanFavorite` → **合并进同一 `Combo`**；每条成为其下一个 `ComboPlan{fingerprint, snapshot, note}` |
| `PlanFavorite` 的 `from/to` | 提供 `Combo` 端点 | 若同 `query` 已由某 `PlaceFavorite` 建过 `Combo`，则**复用该 Combo**（不再重复建） |

**旧计时 4 预设内置为默认组合（D2/D3，可删）**：
- 预设来源：旧首页 `PLACE_SHORT` = `擎天匯(home)` / `澳科大(school)` / `橫琴口岸(hengqin)` / `關閘（拱北口岸）(gate)`；`PAIR_ORDER = [school, hengqin, gate]`；
- 内置为默认组合：`擎天匯 ⇄ 澳科大` · `擎天匯 ⇄ 橫琴口岸` · `擎天匯 ⇄ 關閘（拱北口岸）`（3 对，含去回两向），标记 `isDefault: true`；
- 仅当**不存在同名组合**时注入（不覆盖用户数据）；可被用户删除；
- ⚠️ 预设的端点**坐标**须由既有地点定义提供（旧链路用 slug，新链路需 GCJ-02 坐标）——**来源待架构师确认**（§7）。

**无损要求**：迁移后**条目数不减少**（`PlaceFavorite + PlanFavorite` 总数 → `Combo + ComboPlan` 总数不丢）；`id` 尽量复用；`pinned` 保留。

### 3.6 删除（真实有效确认）

| 入口 | 删除对象 | 行为 |
|---|---|---|
| 组合卡「更多 → 删除组合」 | 整个 `Combo`（含其下所有 `ComboPlan`） | 弹确认 |
| 组合下方案卡「更多 → 删除方案」 | 单条 `ComboPlan` | 弹确认（组合保留） |

**确认弹窗（"真实有效"要求）**：必须显示
1. **对象名**（组合名 / 方案名）；
2. **影响范围**：删除组合 → 「将删除组合『擎天匯 → 澳科大』**及其 2 条已保存方案**，此操作不可恢复」；删除方案 → 「将从组合『…』中移除该方案，组合本身保留」；
3. 按钮：**主色=删除** / 次按钮=取消（文案用「取消」或「再想想」，禁用空泛词）；
4. 删除后：行内反馈「已删除」；组合下无方案时组合仍保留（不级联误删）。

### 3.7 新 Schema（字段级草案，供架构师落定）

```ts
// 键：localStorage["must.favorites.v2"]
interface FavoritesFileV2 {
  schemaVersion: 2;
  updatedAt: number;
  combos: Combo[];
}

interface Combo {
  id: string;                     // 复用 v1 id（可）
  type: "combo";
  name: string;                   // ≤24 字
  from: FavoriteEndpoint;         // 复用 v1 类型（GCJ-02）
  to: FavoriteEndpoint;
  query: string;                  // = parseNavParams().query（不含 plan）—— 重算锚点
  chain?: ChainStep[];            // 空 = 自动选线
  walk?: WalkOverride;            // 两段步行覆盖
  tiers?: TierOverride;           // 五档覆盖
  plans: ComboPlan[];             // 组合下已保存方案
  isDefault?: boolean;            // 旧计时预设内置
  createdAt: number; updatedAt: number; pinned?: boolean; lastUsedAt?: number;
}

interface ComboPlan {             // ≈ v1 PlanFavorite 去 OD 化
  id: string;
  fingerprint: string;            // 复用 planFingerprint（同一真源）
  snapshot: PlanSnapshot;         // 复用 v1 类型（含 capturedAt → 「保存于 MM-DD」）
  note?: string;
  createdAt: number; updatedAt: number; pinned?: boolean;
}

type ChainStepKind = "board" | "transfer" | "alight";
interface ChainStep {
  kind: ChainStepKind;
  code?: string; label: string; lng?: number; lat?: number;   // 站点（station）
}

interface WalkOverride {
  seg1?: { distanceM?: number; minutes?: number };   // 出发地→上车站
  seg2?: { distanceM?: number; minutes?: number };   // 下车站→目的地
}

interface TierOverride {
  speedMps?: Partial<Record<1|2|3|4|5, number>>;
  minutes?:  Partial<Record<1|2|3|4|5, number>>;
}
```

**兼容原则（沿用 02 §2.6）**：顶层 `schemaVersion`；未知更高版本**只读不写**；坏条逐条剔除；`localStorage` 不可用→只读降级。

### 3.8 A 验收标准（EARS）

- **FA-A.1（Ubiquitous）**：系统必须支持「组合（出发地→目的地）」与「组合下方案（0..N 条）」两级收藏结构。
- **FA-A.2（When）**：当用户首次在装有 v2.2.0 数据的浏览器打开应用，系统必须将 `must.favorites.v1` 无损迁移到 `must.favorites.v2`（条目总数不减、命名保留）。
- **FA-A.3（When）**：当同一 `query` 下存在多条 v2.2.0 方案收藏，系统必须将其**合并进同一组合**、各自成为一个组合下方案。
- **FA-A.4（While）**：在组合卡片显示期间，系统**不得**预展示易失的实时时长；时长只在点击计算后出现。
- **FA-A.5（When）**：当用户点组合卡片，系统必须按该组合的 `query` 与可选 `chain/walk/tiers` **现场计算多方案**并展示卡片列表。
- **FA-A.6（When）**：当计算结果中存在与某个 `ComboPlan.fingerprint` 命中的方案，系统必须为该卡标注「已保存」。
- **FA-A.7（Unwanted）**：若某段无实时班次，系统必须标注「暂无实时班次」且**不阻塞**其余内容展示。
- **FA-A.8（Unwanted）**：若整链无任何候选，系统必须展示该组合的已保存方案快照并标「历史记录，可能已变化」，并提供「重新规划」。
- **FA-A.9（When）**：当用户打开自定义编辑器，系统必须展示纵向流程图（出发地/上车站/换乘站/下车站/目的地）与两段步行、五档参数，且各字段带默认值与范围校验。
- **FA-A.10（When）**：当用户在两站之间插入/删除换乘，系统必须相应更新段数（段数 = 换乘数 + 1）并即时预览。
- **FA-A.11（Ubiquitous）**：五档速度默认值必须为 `3.6/2.0/1.4/1.0/0.7 m/s`，档3 为基准；档3 被修改时系统必须提示其全局影响。
- **FA-A.12（Ubiquitous）**：步行时长默认必须按 `距离 ÷ 84 m/min` 派生；`擎天汇(T8)→石排灣` 的步行距离必须为 `450 m`（D6，全库统一）。
- **FA-A.13（When）**：当用户确认删除组合，系统必须在确认弹窗中显示**组合名与实际影响**（含将被删除的方案条数），删除不可恢复。
- **FA-A.14（When）**：当用户删除组合下某方案，系统必须仅移除该方案、**保留组合本身**。
- **FA-A.15（Unwanted）**：若 `localStorage` 不可用或顶层 `schemaVersion` 高于当前，系统必须降级为**只读**且不崩 UI。

**FIX-07 斜杠渲染**（锚点 `RecommendCard.tsx:124`，D1）
- **FIX-07.1（While）**：方案卡渲染线路标签时，系统必须**按段分组**：段内并行线用斜杠 `/`、段间换乘用箭头 `→`（含复合 `A/B→C/D`）（当前 `RouteStack codes={rides.map(...)}` 拍平 → 不符）。
- **FIX-07.2（When）**：当并行线路 A、B 均有可乘后续班车，系统必须在卡片下方**分别列出** A、B 的后续班车。

- **FIX-08.1（Ubiquitous）**：本地补漏方案徽章**不得**使用「其他組合」（与新增「组合」概念冲突），必须改用 **「备选路线」**（候选见 §4.3）。
- **FIX-08.2（Unwanted）**：该徽章文案**不得**暴露实现（本地 / 自算 / 高德）。

**FIX-09 多台站分组**（锚点 `StationCard.tsx`，D7）
- **FIX-09.1（When）**：站点信息卡展示多站台站（如 `T373`）时，必须**以主编号为标题**、各站台（`T373/1`、`T373/2`…）为**子分组**、线路**归组到对应站台**（当前按 `route-dir` 平铺 → 不符）。
- **FIX-09.2（When）**：搜索结果命中同一主编号的多站台，必须**合并为一行**（主编号）展示。
- **FIX-09.3（When）**：收藏站点端点必须保存**主编号**（`code`），展示/回放统一用主编号。

**FIX-10 轻轨校正**（锚点 `LrtEta.tsx`，D5）
- **FIX-10.1（When）**：当显示「现正到达」窗口，系统必须按线路应用偏移：**石排湾 `-5s`**、**横琴 `+40s` 关门偏移**、**氹仔 `±30s`**。
- **FIX-10.2（State）**：石排湾线 / 横琴线的**固定乘车时长**（`1 分 40 秒` / `2 分 15 秒`）必须**秒级**显示。
- **FIX-10.3（Unwanted）**：偏移/窗口只作用于到站判定，**不得**改变时刻表本身的绝对发车时刻。

## 5. C. 边界

### 5.1 移动 + 桌面双适配
- **视口**：移动 `430×932` 为主第一现场；桌面 `1440` 为辅（沿用 05-Spec §8）。
- 编辑器（纵向流程图 + 参数面板）、收藏页、结果卡列表、站点分组卡须在两端**无横向滚动、无溢出**；触达目标 ≥ 44px；底部安全区 `env(safe-area-inset-bottom)`。

### 5.2 旧数据无损
- 迁移**不丢条目**、不覆盖用户命名（`note` 优先为新名称）；`pinned` 保留；
- v1 键**保留不删**（回滚/审计）；仅在 v2 缺失时读取 v1；
- 需**构造 v1 fixture** 做迁移回归（含：纯地点对、纯方案、同 OD 多方案、含坏条、超上限）。

### 5.3 PWA 缓存场景
- 本仓库**无自建 Service Worker**（仅 `manifest.webmanifest`，见 `layout.tsx`）；收藏迁移在**客户端读取时**执行，与 HTTP/壳缓存无关；
- **部署新版本后**：旧数据（v1）在客户端首次读取时迁移；**不得**因壳缓存导致「读不到旧收藏」或「重复注入默认组合」；
- 默认组合注入须**幂等**（重复打开不重复添加）。
