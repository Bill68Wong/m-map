## A. 「其他组合」徽章：文案候选与推荐

### A.1 事实与现状问题

| 项 | 内容 |
|---|---|
| 语义 | 该方案**来自自建模型的补漏**（高德未返回该组合，由我们本地规划补上） |
| 现状 | `RecommendCard.tsx:123` → `<span className="rc-badge-local">其他組合</span>`（`origin === "local"` 时显示） |
| 问题 1 | **用字违规**：`組合` 是**繁体**，违反项目铁律「**界面文案一律简体**」（站名/线路名才用繁体）→ 应为「组合」 |
| 问题 2 | **语义虚**：「其他」是**相对谁**？用户不知道"其他"的参照系（高德？其它线路？） |
| 问题 3 | 样式越界：`.rc-badge-local` 用了 `border-radius: var(--r-pill)`（`globals.css:2297`）——**pill 在新体系里只留给圆点/头像**，应改 `--radius-chip` |

### A.2 三个候选

| # | 文案 | 气质 | 优点 | 风险 |
|---|---|---|---|---|
| **1（推荐）** | **本地补充** | 克制 · 可信 · 说明性 | ① 事实准确、**不夸大**；② 与 POI 结果里已有的**「来自高德」**徽章**成对**（两个都是"来源标注"）；③ 用词与项目既有合规口径一致（架构方案内部即称 `local = 本地补漏`）；④ 4 字，标牌式 | 「本地」对极少数用户可能读成"本机设备" |
| 2 | **自算备选** | 标牌式 · 短促 · 技术 | 更短（4 字），强调"**备选**"→ **主动降预期** | 「自算」偏技术；"备选"略削弱该方案的正面感 |
| 3 | **另有走法** | 人的口吻 · 轻 | 有性格（§B5 原则）、不技术、不夸大 | 口语化，与其它徽章的"说明性"语域不一致；信息量低 |

**定稿：「本地补充」**（team-lead 2026-09-20 拍板采纳）。理由：本案是**来源标注**（provenance），不是营销标签——「本地补充」与「来自高德」在语义、字形长度、视觉层级上天然配成一对；且它**只陈述事实、不做承诺**，符合"不夸大"的要求。

> 候选 2「自算备选」留作**更短版备用**（若窄容器放不下 4 字）；候选 3「另有走法」更适合用在**空状态文案**，不用于徽章。

### A.2b 实现要点（三处必改 —— 前端照做）

| # | 改什么 | 从 | 到 |
|---|---|---|---|
| 1 | **用字** `RecommendCard.tsx:123` | `其他組合`（含繁体「組」，违反简体铁律） | **`本地补充`** |
| 2 | **圆角** `globals.css:2297` | `border-radius: var(--r-pill)`（pill 越界） | `border-radius: var(--radius-chip)`（6px） |
| 3 | **配色** 同一处 | `background: var(--surface-dim); color: var(--on-surface-var)`（灰底灰字，与「来自高德」同款 → 分不出来源） | `background: var(--accent-soft); color: var(--accent)`（青花蓝底字 → 与「来自高德」的灰底形成"我们的 / 别家的"对照） |

> 保留类名 `.rc-badge-local`（不动 JSX 结构）；`origin === "local"` 的判定逻辑不变。

### A.3 样式建议（徽章）

```
.rc-badge-local {
  font-size: var(--text-xs);           /* 12px */
  font-weight: var(--fw-emphasize);    /* 600 */
  padding: 2px 8px;
  border-radius: var(--radius-chip);   /* 6px，替代 pill */
  background: var(--accent-soft);      /* 青花蓝 10% 底 */
  color: var(--accent);                /* 青花蓝字 */
  letter-spacing: var(--tracking-mono);
}
```
> 用**蓝**（= 我们的规划来源）而非灰底，让它与「来自高德」的**灰底**形成"我们的/别家的"对照。**每屏 ≤1 处**（一张卡最多一个徽章）。

## B. 目的地弹窗（`StepSheet`）改进

### B.1 现状与三个反馈的定位

现状实现（`globals.css:2558`）：
```
.step-sheet { position: fixed; left:0; right:0;
              bottom: calc(var(--tabbar-h) + var(--safe-bottom));
              max-height: 62dvh; border-top-*-radius: 14px; }
```

| 用户反馈 | 现状根因 | 判定 |
|---|---|---|
| **位置偏下** | `max-height` 而非固定高 → 内容短时弹层**收缩到很小**并贴在底部；第 1 步只有"1 个输入框 + 常用"，弹层只有 ~260px 高 ⇒ **输入框落在屏幕 ~58% 处**，拇指够着累 | 成立，需**固定顶部锚点** |
| **宽度过窄** | 移动端 `left:0/right:0` 本已满宽；**但桌面端同样满宽 → 内容被拉成超宽一条**，而应用主体是 480px 列，视觉上"内容窄、边框远" | 注意：**移动端不成立、桌面端成立**（见 B.4）。若用户实测在手机上仍觉窄，则是**内层 padding 过大**，按 B.3 一并收 | 
| **推荐框难以下拖** | ① 弹层**不可拖拽**（只有一根装饰 grip，无手势）；② 下拉结果区在弹层内**嵌套滚动**，与地图/弹层争手势（架构方案 §3.4-1 已预警） | 成立，需**整层可拖 + 列表滚动隔离** |

### B.2 移动端规格（[重点] 主战场）

```
┌─────────────────────────────────────────────┐ ← 0%
│  ▒▒▒▒▒ 地图（被 scrim 压暗 30%，可见） ▒▒▒▒▒ │
│                                             │
├─────────────────────────────────────────────┤ ← [重点] 顶部锚点 top: 14vh（可拖到 6vh）
│           ━━━━   ← grip 44×6 命中区（真正可拖）│
│  ←     选目的地              ● ● ○ ○        │ ← 步进轨（现有，保留）
│ ─────────────────────────────────────────── │
│  ⌕   去哪儿？                      [ 搜索 ] │ ← 输入框（继承 .nav-sbox）
│ ─────────────────────────────────────────── │
│  常用                                        │
│  ○ 家 → ◉ 澳科大                        ›   │ ← 快捷地点对
│  ○ 澳科大 → ◉ 关闸                      ›   │
│ ─────────────────────────────────────────── │ ← 列表独立滚动区（pan-y）
│  [ 公交站 ]  T373 偉龍／科技大學        320m │
│  [ 轻轨站 ]  科大                        410m │
│  [ 地点 ]    澳门科技大学               —    │
│              ⌄ 继续往下滑，还有 6 条          │
└─────────────────────────────────────────────┘ ← 100%（让出底导 64 + 安全区）
```

**关键尺寸（移动端）**

| 项 | 现状 | 改为 | 理由 |
|---|---|---|---|
| 顶部锚点 | 由内容决定（浮动） | **固定 `top: 14vh`**（≈118px @844） | 输入框稳定落在**拇指自然区**（屏幕 14%–45%），不再"忽高忽低" |
| 高度 | `max-height: 62dvh` | **`height: 74dvh`**（下拉展开时；收起态 `height: auto`） | 固定高 → 列表有稳定可视区 |
| 水平 | `left:0; right:0`（满宽） | **`left: 12px; right: 12px`**（圆角 14px **四角**） | 近全宽（内容宽 = 视口 − 24px，**比现状可用宽度更大**：现状内层 padding 16×2 + 无外边距）；12px 留缝让弹层像一块"实体纸"浮在地图上（站牌语言），而非贴边 |
| 内层 padding | 16px | **16px**（保持） | 与 tokens 一致 |
| 圆角 | 只上两角 14px | **四角 14px**（`--radius-sheet`） | 留缝后必须四角圆，否则像"半张纸" |
| grip | 装饰 | **44×24 命中区** + 6×4 视觉条 | 可点/可拖（WCAG 命中区） |
| 底部 | 让出底导 | 保持（勿遮高德 Logo） | 合规 |

**桌面端（≥1024px）**

| 项 | 值 |
|---|---|
| 形态 | **居中面板**（不是底部弹层）：`left: 50%; translateX(-50%)`；`width: 440px`；`top: 96px`；`border-radius: 14px`（四角）；`box-shadow: --shadow-sheet` |
| 高度 | `height: auto; max-height: calc(100dvh - 200px)` |
| scrim | 保留（点击关闭），但**不做全屏压暗**（桌面地图常驻可交互）；改为 `background: rgba(15,23,32,.18)` |
| 输入框 | 常驻可聚焦（`autoFocus`） |
| 拖拽 | **不需要**（桌面用 scrim 点击 / Esc / 关闭键） |
| 地图 | 让出右侧：地图 `right: 460px` 避免被面板长期压住（首屏地图仍可看可点） |

### B.3 整层可拖拽（手势设计）

| 项 | 规格 |
|---|---|
| 拖拽把手 | **整层可拖**，但只从 **grip 区 + 头部区**（y < 56px）**起拖**——避免与列表滚动、输入框选择冲突 |
| 跟手 | `transform: translateY(0 → +Δ)`，`transition: none`（拖动中）；松手后 `transition: transform 200ms var(--ease-standard)` |
| **吸附点（snap）** | `top: 6vh`（展开，列表可视更高）· `top: 14vh`（**默认**）· `top: 62vh`（收起，只剩搜索条一行） |
| 关闭 | 从 **收起态**继续下拖 > 100px 或速度 > 0.5px/ms → `setSheetOpen(false)` |
| 阻尼 | 超出 `top: 6vh` 上界时 `translateY` 乘 `0.35`（橡皮筋） |
| 触觉 | 吸附到 snap 点时 `navigator.vibrate(8)`（可选，安卓） |
| 键盘 | Esc = 关闭；↑/↓ 在 snapt 点间切换（桌面/外接键盘） |
| `prefers-reduced-motion` | 禁用橡皮筋与吸附动画，改为瞬时落位 |

**手势隔离（防"难以下拖"重演）**
```
.step-sheet        { touch-action: none; }        /* 弹层本身不做原生的滚动 */
.step-sheet__body  { touch-action: pan-y; overscroll-behavior: contain;
                     -webkit-overflow-scrolling: touch; }   /* 只有内容区滚 */
.nav-sbox__drop    { touch-action: pan-y; overscroll-behavior: contain; }
```
> 拖动判定：`pointerdown` 记录起点；`pointermove` 若 |Δx| > |Δy| 或起点**不在**把手区 → **放弃接管**（把事件留给列表/输入框）。**只有在把手区且 |Δy| > 6px 时**才进入拖拽模式。

### B.4 下拉结果的滚动与惯性

| 项 | 规格 |
|---|---|
| 容器 | `.step-sheet__body` 内独立滚动区；`max-height` 自适应剩余空间 |
| 惯性 | `-webkit-overflow-scrolling: touch`（iOS 惯性） |
| 滚动链 | `overscroll-behavior: contain`（滚到底**不把滚动传给地图/页面**） |
| 行高 | 每行 **≥52px**（≥44 命中）；类型徽章 + 名称 + 距离三栏 |
| 键盘态 | 输入框聚焦、软键盘弹起 → 监听 `visualViewport`，弹层 `top` 改为 `min(14vh, viewportHeight - 键盘高 - 内容高)`；**列表自动滚到可见**（不遮当前高亮行） |
| 加载 | 行内 loading（现有 `.nav-sbox__spin`），**不动弹层高度**（防跳） |
| 滚动提示 | 列表底部渐隐遮罩 + 「继续往下滑，还有 N 条」（可选） |

### B.5 线框（含第 2/3/4 步的弹层高度差异）

| 步 | 弹层 `top` | 内容高 | 说明 |
|---|---|---|---|
| 1 选目的地 | 14vh | 74dvh | 最需要列表空间 |
| 2 确认位置 | **62vh（收起态）** | auto | 此步主角是地图，弹层**故意收小**，只留"用这个点 / 换目的地" |
| 3 选出发地 | 14vh | 74dvh | 同 1 |
| 4 出发 | **46vh** | auto | 只留 OD + 出发按钮 + 收藏 |

> [重点] **每步弹层高度不同**——这正是"没有大标题也成立"的同一条逻辑：**版面节奏跟着内容走**，而不是一个固定盒子。

## C. 路线收藏「自定义编辑器」（本次最大设计）

### C.1 信息架构（与 v2.2.0 融合）

| | v2.2.0 现状 | 增量（本次） |
|---|---|---|
| 模型 | 两组：`路线方案` / `地点对` | **一组主体：组合**（`组合 = 出发地 → 目的地 + 可选的行程编排`） |
| 卡 | `FavoriteCard`（`fav-row` / `fav-plan`） | **组合卡**（`fav-combo`）：命名 + OD + 摘要 + 菜单 |
| 点击行为 | 地点对 → 回首页预填；方案 → 重算+指纹比对 | **一律实时计算多方案** → 跳 `/nav`（PRD 决策） |
| 编辑 | 无 | **自定义编辑器**（本次新增） |

**融合原则**：**沿用** v2.2.0 的 `localStorage` 存储（`must.favorites.v1`）、`schemaVersion`、SSR `mounted` 守卫、`readOnly` 降级、`.fav-page/.fav-group` 骨架；**新增** `combo` 类型与编辑器（`schemaVersion: 2`，V1→V2 迁移：`place` → `combo`（无编排）、`plan` → `combo`（带 `rides` 快照））。

> 注意：存储字段细节以 **PM 增量规格（#19）** 为准；本文只定**视觉与交互结构**。

### C.2 组合列表页

**组合卡规格**

| 元素 | 规格 |
|---|---|
| 卡 | `--radius-card 10px` + `1.5px var(--border-strong)` 框 + `--shadow-hard-sm`；命中区整卡可点 |
| 命名 | `--text-lg 17px / 600 / -0.005em`；默认「出发地→目的地」；过长 → 单行省略（`text-overflow: ellipsis`） |
| 摘要行 | `--text-sm 13px / var(--muted)`：`{编排条数}·{最近用时}·{线路标签}` |
| 左侧图标对 | `Icon name="origin" 16` + `Icon name="arrowRight" 16` + `Icon name="destination" 16`（**已注册**） |
| 拖动把手 | `⠿` → **需新增图标 `dragHandle`**（§F）；仅桌面（或长按）可拖；移动端用长按进入排序 |
| 菜单 | `⋯` → **需新增图标 `more`**；菜单项：`重命名 / 编辑编排 / 置顶 / 停用 / 删除`（现有 `.fav-menu` 复用） |
| 停用态 | 整体 `--meta` 色 + 摘要行显示「已停用」；**排序沉底**；点击提示"已停用，可在 ⋯ 里启用" |

**[重点] 删除入口 + 确认弹窗（真实有效：显示组合名 + 影响）**

```

│  删除组合？                            │ ← 标题 20px/600
│                                       │

│                                       │
```

- 复用现有 `.dialog-backdrop / .dialog-card`（`globals.css:886`），**但需**：危险按钮用 `--danger`、**主按钮在右且默认 focus 在"取消"**（防误删）、`Esc` = 取消、焦点陷阱。
- **文案原则**：列出**具体影响**（几条编排、是否含记录），禁止「确定要删除吗？」这类空话。
- 桌面：居中 Modal；移动：**底部 ActionSheet** 承载（更易点，符合 HIG）。

**(a) 可编辑项与控件选型**

| 可编辑项 | 控件 | 为什么 |
|---|---|---|
| **步行路程**（距离） | **不做自由输入**；只允许"在手选的两站之间取自动距离"或"点选邻近站点改写端点" | 距离不是用户的心智单位（架构方案已定：**距离由端点决定**）；让用户改距离 = 伪精度 |
| **五档速度区间** | **分段选择（segmented）**：`慢 / 稍慢 / 正常 / 快 / 飞快`（等宽 5 格，选中格 = 青花蓝底白字） | ① 5 个离散档 < 工作记忆上限（≤4 的边界，配"正常"默认即可扫）；② **不用滑杆**——滑杆在手机上拖不准、且暗示"连续可调"（不存在）；③ 与项目既有 **`步行速度五档-文献依据`** 文档一一对应 |
| **五档用时区间** | **同上分段选择**，但**档位是"分钟区间"**（如 `5 / 4 / 3 / 3 / 2`），随距离实时算 | 用时是用户真正在意的量（分钟），给离散区间而非连续值 |
| **换乘站** | 流程线上的 **`＋ 插入换乘`** 插入点 → 打开站点选择弹层（复用 `PoiSearchBox`） | 插入点是**空间化的**（在哪两段之间插），比下拉列表直观 |
| **车站（上下车）** | 点站点行 → 站点选择弹层；**同一站台多分组时**按 §D 展开子分组 | —— |
| **起点/终点** | 点端点行 → 回 `StepSheet` 第 1/3 步 | 复用现有流程 |

**(b) 「系统自动算 vs 用户手改」的状态表达** [重点]

| 状态 | 视觉 | 文案 |
|---|---|---|
| **自动** | 值用 `--muted` 灰字；行右侧一枚 **`自动`** 小标记（`--radius-chip`，`--border` 发丝底、`--meta` 字） | `自动 4 分 · 320 m` |
| **手改** | 值用 `--fg` **实色 + 加粗**；行右侧 **`手改`** 标记（`--accent-soft` 底、`--accent` 字） + **`↺` 还原为自动** 文字按钮 | `6 分 · 480 m` |
| **变更来源** | hover/长按 `手改` 标记 → 气泡：「你改过这段：正常 → 快（省 1 分）」 | 让人**知道改了什么、值不值** |
| 未编排 | 整个复合段用虚线边框（`.combo-seg--auto`） | 「未编排 · 用系统推荐」 |

> [重点] 关键：**"哪些是估算、哪些被改过"必须一眼可辨**（这是编辑器的信任基础）。规则：**灰度 = 系统给的，实色 = 你定的**。这套"灰/实"二分与全站"估算是灰、确知是黑"的既有口径一致（如 `RecommendCard` 的 `.rc-est`「估算」）。

**(c) 编辑器的提交语义**

| 动作 | 行为 |

| 保存后 | 回组合列表；该卡摘要行更新为「N 条编排 · 最近 X 分」 |

### D.2 排布规则

| 项 | 规格 |
|---|---|
| **主编号行** | `T373` 用 `--font-mono` 12px/700（站牌编号感）；中文站名 `--text-lg`；**主行不做分组**（避免用户以为有 2 个站） |
| **副行** | `2 个站台分组 · 5 条线路`——**先告诉用户"为什么下面分了两块"**，消除困惑 |
| **分组容器** | **发丝线框 + `--radius-card` 但无阴影**（`border: 1px var(--border)`）→ 与卡片区分，不做"卡中卡"的投影堆叠 |
| **子码行** | `T373/1` 等宽 12px + `--meta` 色；方向说明 `巴士 > 氹仔方向` 用 `--muted` 13px |
| **子码斜杠** | 注意：**此处 `/` 是站码的组成部分（分组号），不是"线路并列"** → **必须与 §G 线路标签的"白色斜杠"区分**：站码用**同色同字**（`T373/1` 连写、`--meta` 色），**绝不套线路标签的墨色组胶囊**（否则会被读成"T373 或 1 两条线"） |
| **报站行** | **完全沿用现有 `.nav-station-card__row`**（`RouteStack` + 方向 + 报站），只是**被归到对应分组下** |
| **排序** | 分组按**子码升序**（`/1` 前 `/2` 后）；组内按**报站升序**（约 5 分 → 8 分）；跨组不混排 |
| **单分组时** | **不显示分组容器**（无分组就没有框、也不显示子码行）——只有多分组才展开；副行仍显示分区等 |
| **折叠** | 分组数 > 3 时，第 3 组起折叠（`展开其余 N 个分组`，复用 `caretDown`） |
| 空报站 | 单个分组内无报站 → 组内行内灰字「这组暂时没有报站」 |

### D.3 与现有实现的关系

- 现有 `StationCard.tsx` 的 `items` 是**扁平**的（`route` + `dir` + `etaMin`）。
- 增量：数据结构补 `berth`（子码，如 `T373/1`）与 `berthLabel`（站台说明）；**无 `berth` 时退化为现状**（单分组，不加框、不加子码行）——**向后兼容，旧数据零改动**。
- **全统一（用户决策）**：多台站标注在**首页站点卡**与 **`/nav/detail` 站点折叠栏**里**同一套排布**（同一组件复用），不出现两套样式。

### F4 说明（重要澄清 —— 已并入 `03-设计方向.md` §G.4）

「复合 `A/B→C/D`」**不是编辑器的事**，而是**卡片上线路标签的显示规则**：

| 形态 | 含义 |
|---|---|
| `A / B` | **同一段的两条并行可选线**（同站上、同站下） |
| `A → B` | **一段换乘** |
| **`A/B → C/D`** | **复合**：A、B 共享**上车站与换乘站**；C、D 共享**下车站** —— 即"第一段可 A 或 B、第二段可 C 或 D" |

> 编辑器里的「复合段（步行 + 等待）默认系统值、用户可改」**保持原样**（那正是需求本体）——两者是**不同层面**的事，只是名字撞车。
