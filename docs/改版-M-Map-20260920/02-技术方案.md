## 0. 结论摘要

### 0.1 两个硬技术问题的直接答案

**★1 地图"只显示澳门"**：可行，且**成本很低**。做法是"**限制 + 收敛 + 强调**"三层组合，按必要性排序：

1. **`map.setLimitBounds(bounds)`** —— 限制拖动范围（官方 API，2.0 存在，签名见 §1.3.a）。这是**必做项**，一行代码把"能拖到珠海/香港"的问题解决掉。
2. **`map.setZooms([minZoom, maxZoom])` + 初始 `map.setBounds()`** —— 防止用户拉远到看到整片珠三角，并让首屏视野正好覆盖澳门。**必做项**。
3. **域外遮罩（带洞多边形）** —— 用一个大矩形**镂空澳门**后半透明压暗，把"一眼突出澳门主体"做到位。**增强项**，官方 demo 明确支持"带孔多边形"，但**多洞/绕向行为必须先用探针验证**（见 §1.5 验证清单）。

**瓦片级裁剪不可行**（底图整块预渲染，前提正确），**自绘澳门边界被合规否决**（见 §1.2）；边界轮廓**只能取自高德自身 `AMap.DistrictSearch`**。

> **范围口径（裁定）**：地图范围 = **澳门行政区范围（含横琴口岸澳方管辖区）**；用户定位在境外时地图**不自动移出**，定位蓝点按真实坐标**如实显示**。

**★2 收藏功能**：无账号体系下，**推荐 `localStorage`**（设备本地、不落库、不涉账号，天然满足"个人位置数据仅本地私有存储"的合规要求）。存储两类实体：**地点对**（起终点）与**路线方案**（地点对 + 一条方案快照）。字段与 `/nav` URL 参数体系**完全对齐**（起终点复用 `fromLng/fromLat/.../toCode`；方案以**稳定指纹 `fingerprint`** 标识，回放时重算后按指纹命中当前卡再取 planId）。容量压力可忽略（≤200 条 ≈ 100 KB，远低于 5 MB 上限）。收藏入口共 **4 处**：方案收藏 `/nav` 每张卡 + `/nav/detail`；地点对收藏 首页选定目的地后 + `/nav` 顶部 OD 栏。

### 0.2 一句话风险提示

本次改造的三处**真正会翻车的地方**不是地图 API，而是：**全屏地图与移动端滚动手势的冲突**、**iOS 安全区与高德版权标识（审图号/Logo）不可被遮挡**、**localStorage 在 Safari 隐私模式下可能被清理**。三处均已在 §3.4 给出对策。

## 1. ★1 地图范围方案（只显示澳门）

### 1.1 目标与约束

- **目标**：进入首页地图，一眼看到澳门全境并突出主体；不显示或大幅弱化珠海/香港/中山等周边。
- **既有前提**（已核实）：高德底图为**整块预渲染瓦片**，**瓦片级裁剪不可行**——不能只请求澳门那几块瓦片。
- **现状**（`src/components/nav/NavMap.tsx`）：地图以 `INIT_ZOOM = 13.5`、中心 `{lng:113.558, lat:22.155}` 建图，随后按"横向 5 km"重算 zoom（`zoomForAcross`）。**当前没有任何范围限制**：用户可任意拖动、可拉到 z=3 看整个中国。

### 1.2 合规前置结论（先读后做）

依据团队地图合规技能（`geo-map-compliance-guard`）与项目既有合规记录（`docs/合规-高德API使用-20260917.md`、`docs/调研-全澳导航-高德API能力-20260918.md` §A5.3），本方案遵守以下**红线**：

| 红线 | 本方案的遵守方式 |
|---|---|
| 地图源白名单 | 继续用**高德（AMap）**——在白名单内（腾讯/高德/百度/天地图）。**不引入** Google/Apple/Bing 海外版/OSM/Mapbox 等 |
| **不得引入境外数据源、不得自绘边界** | 澳门轮廓**只取自高德 `AMap.DistrictSearch` 官方行政区边界**；**明确否决**"用我们 610 个站点拟合边界"这一做法（会构成"自绘边界"，触碰"国界/领土要素须符合国家标准"红线） |
| **不得遮挡版权/审图号/Logo** | 遮罩用**地图覆盖物（Polygon）**实现，仅作用于画布；高德 Logo、审图号、比例尺是**独立 DOM 层**，**不会被 Polygon 覆盖**。底部导航栏**必须留出地图版权区高度**，不得压住 |
| 必须展示来源 | 首页/结果页保留"本服务来源于高德地图"（现有 `ComplianceBar`） |
| 前端不下发明文安全密钥 | 维持现状：`window._AMapSecurityConfig = { serviceHost: '<origin>/_AMapService' }`，密钥只在代理 `src/app/api/amap-service/[...path]/route.ts` |
| 不缓存瓦片/不截图/不抓取服务数据 | §1.5 的边界缓存**仅在内存/sessionStorage**，**不落库、不持久化**；标注为**需合规复核项** |

> 结论：**"限制范围"与"遮罩强调"本身合规**；**唯一有合规争议的是"澳门边界坐标能否被缓存"**，已在 §1.5、§3.6、附录列为待复核项。

### 1.3 候选能力清单（对应任务 a–d）

#### a. `map.setLimitBounds()` —— 限制视野/拖动范围

**2.0 的正确 API 名已核实为 `setLimitBounds`**（三种官方/权威来源一致）：

| 方法 | 签名 | 说明 |
|---|---|---|
| `map.setLimitBounds(bounds)` | `bounds: AMap.Bounds` | 设定限制区域；**设定后地图仅在区域内可拖拽** |
| `map.getLimitBounds()` | `→ AMap.Bounds \| null` | 获取当前限制区域 |
| `map.clearLimitBounds()` | `→ void` | 清除限制 |
| `map.setBounds(bounds)` | `bounds: AMap.Bounds` | 指定**当前显示范围**（用于初始视野） |
| `map.setZooms([min, max])` | `[number, number]` | 设置缩放等级范围 |
| `map.getZooms()` | `→ [number, number]` | 读取缩放范围 |

`AMap.Bounds` 构造：`new AMap.Bounds(southWest: LngLat, northEast: LngLat)`，或用数组 `new AMap.Bounds([lng,lat], [lng,lat])`（**经度在前**）。

**与 `setZoomAndCenter` 的配合**：两者**不冲突**——`setLimitBounds` 约束的是**可拖动范围**，`setZoomAndCenter` 约束的是**当前视角**。唯一需注意的是：**若当前 zoom 使可视范围大于 limitBounds，则限制不生效（画面仍会显示区域外）**。因此 `setLimitBounds` **必须**与"最小 zoom 限制"配套使用。

**已知边界情况**：`setLimitBounds` 只约束"拖拽"；用户仍可**缩放**。若不做 `setZooms` 最小级别限制，拉远后依然能看到区域外 → 必须组合（这是本方案推荐组合拳的根因）。

#### b. 域外遮罩（带洞多边形）

**高德官方 demo 明确支持"带孔多边形/多个带孔多边形"**，且这正是社区 2D 区域遮掩的标准解法：

- `AMap.Polygon` 的 `path` 支持**嵌套数组**：`path = [外圈环, 内圈环, ...]`，**后续所有环被镂空**；
- **遮罩做法**：外圈 = 一个**远大于澳门**的大矩形，内圈 = 澳门边界环，`fillColor` 用深色 + `fillOpacity ≈ 0.35~0.55` → 只压暗澳门以外；
- 镂空部分**不触发 Polygon 事件**（不会挡住澳门内的站点点击）。

```ts
// 形态（示意，非最终代码）
const maskOuter = [[112.0, 20.6], [115.1, 20.6], [115.1, 23.7], [112.0, 23.7]]; // 澳门外扩约 1.5°
const mask = new AMap.Polygon({
  path: [maskOuter, ...macauRings], // ★ 内圈（澳门）为洞
  fillColor: "#0b1220",
  fillOpacity: 0.45,
  strokeOpacity: 0,
  zIndex: 99,
  bubble: false,     // 不参与事件冒泡（避免影响地图交互）
});
map.add(mask);
```

**必须验证的两点**（社区资料不足以直接采信，见 §1.5）：
1. **多环（澳门可能有多个子多边形，如半岛 + 路氹）作为多个洞**的行为是否如预期；
2. **环的绕向（顺/逆时针）**：嵌套 `path` 的"洞"判定依赖绕向，需实测确认，否则可能画成"实心"。

**大外圈的性能/投影风险**：Web Mercator 下超大矩形（跨半球）会畸变且拖慢渲染，故**外圈只外扩约 1.5°**（约 150 km），配合 `minZoom` 保证可视范围永远落在这一圈内（验算见 §1.4）。

#### c. 澳门边界轮廓数据来源

| 方案 | 可行性 | 合规 | 结论 |
|---|---|---|---|
| **高德 `AMap.DistrictSearch`（推荐）** | 高。插件 `AMap.DistrictSearch`，`extensions:'all'` 返回 `districtList[0].boundaries`（环数组，GCJ-02） | **合规**（用高德官方行政区数据，非自绘） | **采用**。澳门 adcode `820000`（省级），见下 |
| 高德 Web 服务 `config/district?keywords=澳门&extensions=all` | 高（已有实测，返回 `polyline`） | 合规 | 备选（免走 JS 插件、可服务端取），但会多一次网络往返 |
| **用我们 stations 拟合近似轮廓** | —— | **不合规**（自绘边界） | **否决**（红线） |
| 第三方/境外边界 GeoJSON | —— | **不合规** | **否决**（红线） |

**`AMap.DistrictSearch` 用法**（官方文档口径）：

```ts
AMap.plugin("AMap.DistrictSearch", () => {
  const ds = new AMap.DistrictSearch({
    level: "province",   // 澳门特别行政区为省级；亦可用 'city' 兜底（需探针确认命中）
    subdistrict: 0,      // 只要边界，不返回下级
    extensions: "all",   // ★ 必须 all，否则不返回 boundaries
  });
  ds.search("820000", (status, result) => {
    if (status !== "complete") return;
    const rings: number[][][] = result.districtList[0].boundaries; // 环 → 点 → [lng,lat]
    // 用于：① 计算 bbox 喂给 setLimitBounds/setBounds；② 作为遮罩的洞
  });
});
```

**坐标基准**：`DistrictSearch` 返回坐标**已是 GCJ-02**，与地图、`NavPoint` 口径一致，**不再转换**（遵守项目坐标三铁律）。

#### d. 缩放策略建议

| 参数 | 建议值 | 依据 |
|---|---|---|
| 初始视野 | 由 `map.setBounds(macauBoundsExpanded)` 决定（或 `map.setFitView(边界面)`），使澳门自适应铺满 | 与现有 `zoomForAcross` 思路一致（横向约 5–10 km） |
| `minZoom` | **11**（约横向 27 km），配合大外圈遮罩不漏；可按容器实测微调 | z=11 时米/像素≈70.8（澳门纬度 cos≈0.926），390 px 宽≈27.6 km，远小于遮罩外圈 150 km |
| `maxZoom` | **18**（默认上限）；如需更近可用 `expandZoomRange:true` + `zooms:[3,20]` 放开到 19 | 2.0 的 2D 支持小数与扩展级别 |
| 站点图层阈值 | **保持 `STATION_MIN_ZOOM = 16` 不变** | 现网已验证，避免本次改版引入回归 |
| 定位成功后 | 仍按"横向 5 km"`setZoomAndCenter`（现状），但**中心必须是澳门境内点**；若定位点在澳门之外（如珠海），改为停在澳门中心并提示 | 与 `setLimitBounds` 相容 |

### 1.4 推荐组合方案

**推荐 = A（必做） + B（推荐）**，即：

```
建图
  └─ new AMap.Map(container, { zoom: INIT_ZOOM, center: MACAU_CENTER, viewMode: "2D", resizeEnable: true })

① 取澳门边界（异步，不阻塞建图）
  └─ AMap.DistrictSearch({ level:"province", subdistrict:0, extensions:"all" }).search("820000")
        → macauRings（GCJ-02 环数组）
        → 由环算 bbox：macauBounds = new AMap.Bounds([minLng,minLat],[maxLng,maxLat])

② 限制与收敛（边界就绪后立即执行，失败则跳过——不影响底图）
  ├─ map.setLimitBounds(macauBounds)           // 拖不出澳门
  ├─ map.setZooms([11, 18])                     // 拉不远（防看到周边）
  └─ map.setBounds(macauBounds)                 // 首屏 = 澳门全境

③ 域外遮罩（增强；边界就绪后）
  └─ new AMap.Polygon({ path:[bigOuter, ...macauRings], fillColor:"#0b1220", fillOpacity:0.45, strokeOpacity:0 })

④ 定位成功：地图**始终以澳门行政区范围（含横琴口岸澳方管辖区）为准**（裁定：境外定位不自动移出）
   ├─ 定位点在澳门范围内 → setZoomAndCenter(zoomForAcross(lat,w), [lng,lat])
   └─ 定位点在澳门范围外 → **保持 ② 的澳门视野、不移动地图**；定位蓝点按真实 GCJ-02 坐标落位（如实显示，可能落在视野之外）
   定位失败 → 停在 ② 的澳门视野 + 现有提示

⑤ 站点图层（STATION_MIN_ZOOM=16）逻辑保持不变
```

**降级原则**：边界/遮罩任一环节失败（DistrictSearch 无数据、插件加载失败），**必须回落到"仅 `setLimitBounds`（可用一个写死的澳门矩形兜底）"**，**绝不阻塞底图、定位、搜索、出发点**（延续现状 `§Q7` 不阻塞设计）。

**「澳门范围」的定义（裁定 2026-09-20）**：地图范围以**澳门行政区范围（含横琴口岸澳方管辖区）**为准。一处必须注意的数据细节：横琴口岸澳方管辖区（如澳门大学横琴校区一带）在高德行政区划里归属**广东（adcode `440499`）**，**不落在 `DistrictSearch(820000)` 的环内** ⇒ ① `limitBounds` / `setBounds` 用的 **bbox 必须外扩到覆盖该区域**（bbox 是"可视/可拖范围"的矩形约束，**不涉及在地图上画边界线，合规**）；② 遮罩的"洞"若要**一并镂空**横琴口岸澳方管辖区，需其**官方环**（同样取自高德，不得自绘）；取不到官方环时，遮罩洞**仅用澳门官方环**，该区域会被压暗——列为验证项 V6，并按结果告知产品。

**验算（遮罩是否漏边）**：
- `minZoom=11` 时米/像素 ≈ 156543.03392 × cos(22.15°) / 2¹¹ ≈ **70.8 m/px**；
- 手机宽 390 px ⇒ 横向 ≈ **27.6 km**；竖屏高 844 px ⇒ 纵向 ≈ **59.8 km**；
- 遮罩外圈外扩 1.5°（≈ 154 km × 166 km）**远大于**可视范围 ⇒ **任何合法缩放/拖动下都不会露出未遮罩区域**。

### 1.5 开发前置验证清单（落地前置，按优先级排序）

> **首位 V3 是开发首日的门禁**：先在最小 demo 上把遮罩画法探明白；**若不通过，即按 §1.4 降级路径（仅范围限制 A）交付第一版**，遮罩作为后续增量，不阻塞上线。

| 优先级 | # | 验证项 | 方法 | 不通过的后果 |
|---|---|---|---|---|
| **P0** | **V3** | **带洞多边形**的"洞"判定（多洞 + 环的绕向）是否如预期 | 最小 demo 试画（大矩形 + 澳门洞） | 遮罩可能变"实心"→ 需反转绕向，或拆成多个 Polygon（或降级为"仅范围限制"交付首版） |
| P1 | V1 | `DistrictSearch` 对 `"820000"` 在 `level:"province"` 下能否返回 `boundaries` | 一次性探针脚本 / 控制台 | 换 `level:"city"` 或改用 Web 服务 `config/district` |
| P1 | V2 | `boundaries` 是**单环还是多环**（半岛/路氹是否分离） | 打印 `rings.length` | 决定遮罩用"1 洞"还是"N 洞" |
| P1 | V6 | **横琴口岸澳方管辖区**是否有高德**官方环**可并入遮罩洞；bbox 外扩是否已覆盖该区域 | 探针查询 + 目测 | 取不到则遮罩洞仅澳门，该区域被压暗 → 告知产品 |
| P2 | V4 | `setLimitBounds` + `setZooms` 后，`setZoomAndCenter` 到定位点**不被限制反弹** | 真机 | 需把定位 zoom 夹到可视 ⊆ bounds |
| P2 | V5 | **合规复核**：边界坐标缓存是否触碰高德协议 3.5 | 与合规口径核对 | 若存疑 → 只走**内存**不落任何持久层 |

## 2. ★2 收藏功能数据方案（无账号体系）

### 2.1 约束

- **无用户账号**（当前仅口令门 `ACCESS_PASSWORD`，且是**全站级**，不能作为用户身份）。
- 收藏是**个人数据**，含**位置坐标**（起终点）。合规要求：**个人位置数据仅本地私有存储**（合规技能明列）。
- 收藏页是**新增公开页**，需在 `src/middleware.ts` 白名单显式加入（fail-closed，不加则路人打不开）。

> **R5 一致性确认（PM 规格点名 §7.9）**：收藏端点写入 `localStorage` **不违反**产品 R5「起点不记忆」。R5 约束的是"**自动记忆上次起点**"（隐式、非用户意图）；本方案只有在**用户显式点击"收藏"**时才写入，属于用户显式意图保存，二者不冲突。

### 2.2 存储选型对比

| 方案 | 持久性 | 容量 | 合规 | SSR/水合 | 结论 |
|---|---|---|---|---|---|
| **`localStorage`（推荐）** | 设备本地、长期 | ~5 MB/源 | **最简**：不出设备、不落库、无账号 | 客户端组件 + `mounted` 守卫 | **采用** |
| `IndexedDB` | 本地、长期 | 很大 | 同 localStorage | 异步 API，复杂度高 | 过度设计（本场景不需要） |
| `sessionStorage` | **关标签即清** | 5 MB | 同 | 同 | 不满足"长期收藏" |
| Cookie | 随请求上送 | 4 KB | **会随请求发出**，位置数据外泄风险 | —— | **否决** |
| 服务端库 + 匿名设备 ID | 跨设备 | 无限 | 需隐私政策/同意流 | —— | **本期不做**（无账号，收益不足） |
| URL 分享 | 无持久 | —— | 合规 | —— | 作为"分享"补充，**不作收藏存储** |

**结论：`localStorage`，单一 key，带 `schemaVersion`。** 同时约定：**收藏是"设备资产"**，换设备/清缓存即丢失——这一点必须在收藏页显式告知用户（见 §2.7 风险）。

### 2.3 JSON Schema（字段级）

存储结构：`localStorage["must.favorites.v1"] = JSON.stringify(FavoritesFile)`

```ts
/** 顶层文件（一个 key 装全部收藏） */
interface FavoritesFile {
  schemaVersion: 1;          // 迁移锚点；未来加字段时自增
  updatedAt: number;         // 最后写入时间（ms）
  items: FavoriteItem[];     // 全部收藏（见下）
}

type FavoriteItem = PlaceFavorite | PlanFavorite;

/** 公共字段 */
interface FavoriteBase {
  id: string;                // uuid v4（crypto.randomUUID()）
  createdAt: number;         // 首次收藏时刻（ms）
  updatedAt: number;         // 最近修改时刻（ms）
  pinned?: boolean;          // 置顶（可选，默认 false）
}

/** 端点（与 NavPoint 同构；坐标一律 GCJ-02，与现网铁律一致） */
interface FavoriteEndpoint {
  kind: "gps" | "poi" | "station" | "place"; // 与 NavPointKind 一致
  label: string;             // 展示名（站名用繁体官方原文）
  lng: number;               // 经度 GCJ-02
  lat: number;               // 纬度 GCJ-02
  code?: string;             // 我们库站码（kind="station" 时）
  poiId?: string;            // 高德 POI id（kind="poi" 时，可选）
  adcode?: string;           // 行政区划码（澳门=820000，可选）
}

/** ①「地点对」收藏：只存起终点，规划结果每次实时算 */
interface PlaceFavorite extends FavoriteBase {
  type: "place";
  from: FavoriteEndpoint;
  to: FavoriteEndpoint;
  /** 规范化查询串（= parseNavParams().query，**不含 plan**）——回放/重算的唯一依据 */
  query: string;
  note?: string;             // 用户备注（可选，≤40 字）
  lastUsedAt?: number;       // 最近一次使用时刻（排序/清理用）
}

/** ②「路线方案」收藏：地点对 + 一条具体方案的快照 */
interface PlanFavorite extends FavoriteBase {
  type: "plan";
  from: FavoriteEndpoint;
  to: FavoriteEndpoint;
  /** 同 PlaceFavorite.query（不含 plan），用于重算时命中同一 OD 与参数 */
  query: string;
  /**
   * ★ 方案指纹（**不再存 planId**）：由方案的载具段算出的稳定键，与本地枚举的 `OptionSeed.key` 同构。
   *   算法：`rides.map(r => `${r.route}@${r.board}->${r.alight}`).join("|")`
   *   （`RideLegView` 实测字段为 `route` / `board` / `alight`，见 `src/lib/recommend/types.ts`）
   *   为什么不存 planId：planId 是**每次请求临时生成**的（高德方案序号 / ≥900000 的本地号），
   *   跨请求不稳定 ⇒ 存它必然"回放即失效"。指纹只依赖"坐哪条线、哪站上、哪站下"，稳定可复算。
   */
  fingerprint: string;
  /** 采集时的方案摘要快照（用于离线展示"上次是这样走的"；**不作真值**） */
  snapshot: PlanSnapshot;
  note?: string;
  lastUsedAt?: number;
}

interface PlanSnapshot {
  capturedAt: number;        // 采集时刻（ms）
  fingerprint: string;       // 同 PlanFavorite.fingerprint（快照自洽，便于校验/迁移）
  totalMin: number;          // 门到门总时长（分钟，我们的口径）
  walkMin?: number;          // 步行合计（分钟）
  transfers: number;         // 换乘次数
  legs: string[];            // 载具摘要，如 ["51A 關閘→科大", "輕軌 科大→媽閣"]
  origin: "amap" | "local";  // 方案来源（与 NavPlan.origin 一致）
}
```

**字段取舍说明**：
- **绝不高德原始 polyline / 地图几何**——只存**我们算出的派生数值**（时长/换乘/载具文字），延续项目"只存派生数值、不存服务内部数据"的合规做法。
- `query` 直接复用 `nav-params.ts` 产出的**规范化查询串**，保证与 `/nav`、`/nav/detail`、`/api/nav` 的口径**逐字节一致**。
- **`gps` 端点可收藏，但 label 固定为"我的位置"**，且**回放时不锁定当时坐标**（每次重新定位）——避免收藏一个"过期的我"。

**与 `/nav` URL 参数的衔接（关键）**：

| 收藏字段 | `/nav` URL 参数 | 衔接方式 |
|---|---|---|
| `from.{lng,lat,label,kind,code}` | `fromLng/fromLat/fromLabel/fromKind/fromCode` | 直接复用；回放 = `navUrl(from,to)`（现有函数） |
| `to.{lng,lat,label,kind,code}` | `toLng/toLat/toLabel/toKind/toCode` | 同上 |
| `PlanFavorite.fingerprint` | （无对应参数） | 回放时**先重算 → 用指纹匹配到的「当前卡」的 planId** → `/nav/detail?${query}&plan=<当前planId>`（planId 只作**运行时**跳转参数，**不落库**） |
| `PlaceFavorite.query` | （整串） | 回放 = `/nav?${query}`（重新规划取最新 5 条） |

> 即：**"收藏一条路线"在实现上就是"存下一条可回放的具体 URL（query + 指纹）"**——回放时先重算，用指纹定位到当前那一张卡，再由其 planId 生成 `/nav/detail` 跳转。不新增任何 URL 参数体系，前端零协议变更。

### 2.4 容量评估与清理策略

| 项 | 估算 | 结论 |
|---|---|---|
| 单条 `PlaceFavorite` | ≈ 250–350 B（含 query/label） | —— |
| 单条 `PlanFavorite` | ≈ 450–700 B（含 snapshot.legs） | —— |
| **上限 200 条**（混合） | ≈ **60–140 KB** | **远低于 5 MB**，无压力 |
| `localStorage` 上限 | 通常 5 MB/源（部分浏览器按源合计） | 200 条仅占 ~3% |

**清理策略**：
1. **上限护栏**：`items.length > 200` 时，按 `pinned`（置顶保留）→ `lastUsedAt`/`updatedAt` **最旧优先剔除**；
2. **重复判定**：`PlaceFavorite` 以 `query` 去重；`PlanFavorite` 以 `query + '#' + fingerprint` 去重（同一 OD 可收藏多个不同方案）；
3. **写入容错**：`try/catch` 包住 `setItem`（隐私模式/配额满会抛 `QuotaExceededError`）→ 失败给**行内提示**，不崩 UI；
4. **校验丢弃**：读取时对每条做**结构校验**（见 §2.6），坏数据静默剔除并回写，避免脏数据阻塞整份文件。

### 2.5 「路线方案」数据过期（线路变更）时的校验/重算路径

**核心原则：快照（snapshot）是"展示用的记忆"，不是"可执行的真值"。** 线路/班次会变，收藏**永远以重算为准**。

```
用户点开某条「路线方案」收藏
   │
   ├─ 若为「路线方案」（存 fingerprint）：
   │    1. 请求 /api/nav?${query}（实时重算，拿到最新 5 条）
   │    2. 对返回的**每张卡计算指纹**（与收藏同一算法）：
   │         fp(card) = card.rides.map(r => `${r.route}@${r.board}->${r.alight}`).join("|")
   │    3. 在 cards 中按 fingerprint 比对：
   │         ├─ 命中某卡 → 用**该卡的当前 planId** 跳 /nav/detail?${query}&plan=<当前planId>（方案未变）
   │         └─ 未命中 → 该方案已变化/消失
   │              → 跳 /nav?${query}（列出最新方案）
   │              → 顶部提示：「该方案已调整，已为你重新规划」
   │              → **不自动更新快照**；如用户希望"更新为最新"，需**显式操作**（不静默）
   │
   ├─ 若为「地点对」：直接 /nav?${query} 重算
   │
   └─ 若 /api/nav 失败/降级：展示 snapshot（标「历史记录，可能已变化，点此重新规划」）
```

**快照时效标注（裁定 2026-09-20）**：卡片**永远显示「保存于 MM-DD」**；**不做静默重算、不自动更新快照**。点击收藏时**一律按当次重算**（与 PM 规格 §7.6.4 一致）——按**指纹**命中某卡则用其**当前 planId** 进详情，未命中落 `/nav` 并提示"已重新规划"。`capturedAt` 仅用于展示「保存于 MM-DD」与排序/清理，**不触发任何自动行为**。

### 2.6 关键坑（生成式实现最易翻车处）

| # | 坑 | 后果 | 对策 |
|---|---|---|---|
| F1 | **SSR 水合不一致** | 收藏页在服务端渲染时读不到 `localStorage` → `Hydration failed` | 收藏页整体 `"use client"`；首帧渲染"加载中"骨架，`useEffect(() => setMounted(true))` 后再读 storage；**服务端与首帧输出必须一致** |
| F2 | **Safari 隐私模式/ITP 清 storage** | 用户收藏"莫名消失" | `setItem` 失败捕获；收藏页显式说明"收藏保存在本机浏览器，清除浏览器数据会丢失"；**不宣称跨设备** |
| F3 | **脏数据阻塞** | 一份含一条坏记录 → 整页解析失败 | 读取时**逐条校验**（type/id/坐标数值范围），坏条剔除不改动其余 |
| F4 | **schema 演进** | 未来加字段导致老数据不识别 | 顶层 `schemaVersion`；读取时按版本迁移（V1→V2），未知更高版本**只读不写**（防降级覆盖） |
| F5 | **`gps` 端点回放定位** | 收藏的"我的位置"坐标过期 | 回放时 `kind==="gps"` → 触发实时定位；失败则回落收藏坐标并提示 |
| F6 | **写放大** | 每次交互全量 `JSON.stringify` 写回 | 数量 ≤200，写放大可接受；如需优化可做 300 ms 防抖合并写 |

### 2.7 存放位置与模块边界

- 纯工具/类型：`src/lib/favorites/types.ts`（**纯类型，禁 import pg**，与 `nav/types.ts` 同规）、`src/lib/favorites/storage.ts`（读写/校验/迁移/清理）。

- **不新增 API 路由**（纯本地存储）→ `openapi.yaml` 无需变更（本期无新接口）。

| # | 风险 | 触发场景 | 影响 | 对策 |
|---|---|---|---|---|
| **1** | **全屏地图吞掉移动端滚动手势** | 面板/抽屉需滚动，手势被地图接管 | 用户无法滚动列表 | 地图容器 `touchAction: none` 只作用于画布；**抽屉/列表面板** 单独 `overflow-y:auto` 且 `touchAction: pan-y`；抽屉展开时可用 `map.setStatus({ dragEnable:false })` 临时禁用地图拖动 |
| **2** | **容器从占位改全屏 → 地图尺寸失效** | `aspect-ratio` 占位被替换，建图时/横竖屏切换后尺寸变化 | 地图白屏/错位 | 全屏容器用 `height:100dvh` + `position:fixed`；地图 `resizeEnable:true`；布局稳定后调 `map.resize()`；监听 `orientationchange` |
| **3** | **iOS 安全区** | 刘海/底部 Home 条 | 内容被遮挡、按钮不可点 | 底部导航与抽屉 `padding-bottom: calc(12px + env(safe-area-inset-bottom))`（**沿用** `.page` 既有做法） |
| **4** | **遮挡高德版权/审图号（合规）** | 底部导航/抽屉压住地图右下 Logo | **违规** | 地图版权区上方预留 ≥ 底部导航高度；导航栏**半透明但可让出地图右下角**；上线前人工核对 Logo 可见 |
| **5** | **`setLimitBounds` 与初始 `setBounds` 冲突** | 边界比可视范围小 | 拖拽受限但画面仍显示外部 | 先 `setZooms` 收敛，再 `setBounds`；保证可视 ⊆ bounds（探针 V4） |
| **6** | **遮罩画成实心（绕向）** | 多洞/绕向未验证 | 澳门被压暗，反效果 | 探针 V3；提供"拆成多个 Polygon"兜底 |
| **7** | **边界数据缓存触合规 3.5** | 落库/持久化边界坐标 | 合规风险 | **仅内存/sessionStorage**、不落库（探针 V5 复核） |
| **8** | **收藏页 SSR 水合不一致** | 服务端读不到 localStorage | 页面报错 | §2.6-F1 |
| **9** | **Safari ITP 清 storage** | 隐私模式/长期未访问 | 收藏丢失 | §2.6-F2；文案告知；不宣称跨设备 |
| **10** | **中间件白名单漏加** | 新增 `/favorites` 未进 `PUBLIC_PAGES` | 路人 401/跳登录 | S4 验收项：**未登录访问 `/favorites` 直达页面** |
| **11** | **共享 CSS 类改动回归** | 改 `.nav-map` 影响 `/nav` | 旧页样式回归 | S6 回归 `/nav`、`/nav/detail` |
| **12** | **定位点在澳门境外** | 珠海/跨境用户定位 | 视角被 `setBounds` 拉回澳门，与"我的位置"矛盾 | **已裁定**：地图始终以**澳门行政区范围（含横琴口岸澳方管辖区）**为准；定位在境外**不自动移出**，蓝点按真实坐标**如实落位**（可能落在视野外）（§1.4 ④） |

### 3.5 端到端验证步骤（收尾即验收）

**地图范围（核心成功流 + 边界流）**
1. `npm run build && npm run lint` —— 零类型/构建错误；
2. 打开首页，等待地图就绪：
   - 断言 `canvas[data-limit-bounds="on"]`（新增钩子）；
   - **拖动**地图至珠海方向 → 松手后自动回弹至澳门境内（拖动被限制）；
   - **缩小**（双指/滚轮）到最小级 → 仍看不到澳门以外（`data-nav-z` 不再低于 minZoom）；
   - **遮罩**：澳门以外区域呈半透明压暗，澳门内可正常点击站点（点站点弹信息卡）；
   - **版权核对**：高德 Logo/审图号**可见且未被遮挡**；
3. **边界流**：模拟 `DistrictSearch` 失败 → 地图仍可用（仅范围限制，无遮罩），搜索/出发/定位**不受影响**。

**收藏（核心成功流 + 边界流）**
4. **4 处入口逐一验证**：`/nav` 每张卡收藏方案、`/nav/detail` 收藏方案、首页选定目的地后收藏地点对、`/nav` 顶部 OD 栏收藏地点对 → 打开 `/favorites` → 两类卡片均展示摘要（方案卡显示「保存于 MM-DD」）；
5. 点该收藏 → 若重算后**指纹命中**某卡，用其当前 planId 进详情页；**构造方案失效**（改线路/站序使指纹不匹配）→ 提示"已重新规划"并落 `/nav`；
6. **边界流**：清空 localStorage 后访问 `/favorites` → 空状态（不报错）；写入一条**坏 JSON** → 其余收藏仍正常展示（脏数据剔除）；
7. **未登录访问 `/favorites`** → 直接可达（白名单生效）。

### 3.6 明确不做（out-of-scope）

- 不做**账号体系**、不做收藏**云端同步/跨设备**；
- 不做**瓦片级裁剪**（前提已否决）；
- 不**自绘澳门边界**、不引入**境外边界数据源**；
- 不新增收藏相关**后端接口**（本期纯本地）；
- 不改动**站点图层阈值**、不动**/api/nav 契约**、不动**坐标转换口径**；
- 不做地图**自定义样式**（`amap://styles`）与**地名注记全局隐藏**（收益低/风险高）。

## 4. 关键选型 ADR（MADR）

### ADR-001：地图"只显示澳门"采用"限制 + 收敛 + 遮罩"组合，边界取自高德 DistrictSearch

**Status**: Accepted (2026-09-20)

**Context**: 高德底图为整块预渲染瓦片，无法按区域裁剪瓦片；用户可任意拖动/缩放看到珠海、香港。需让首页地图"一眼是澳门"，同时**必须遵守中国地图合规**——不得引入境外数据源、不得自绘边界。

**Decision**:
1. **必做**：`map.setLimitBounds(bounds)` 限制拖动 + `map.setZooms([11,18])` 收敛缩放 + `map.setBounds(bounds)` 定初始视野；其中 `bounds` = **澳门行政区范围（含横琴口岸澳方管辖区）** 的外扩 bbox（bbox 为矩形约束、非在地图上画边界线，合规）；
2. **推荐**：`AMap.Polygon` 大矩形**镂空澳门**做域外遮罩（半透明压暗）；
3. **边界数据**：**只用高德 `AMap.DistrictSearch`**（`extensions:'all'`，adcode `820000`）返回的官方边界（GCJ-02）；**否决**站点拟合与第三方/境外数据；
4. **境外定位（裁定）**：地图**始终以澳门范围为准、不自动移出**；定位蓝点按真实坐标如实落位；
5. 边界取用失败时**降级**为"仅范围限制 + 兜底矩形"，**不阻塞**底图与全部导航功能。

**Consequences**:
- 正面：满足"突出澳门"的产品目标；全部使用白名单内官方能力，合规；成本低（≈1.5 人日含探针）；降级路径清晰。
- 负面：遮罩"多洞/绕向"需探针验证（**V3 为开发首日门禁** / V2）；**横琴口岸澳方管辖区（adcode `440499`）不在 `820000` 环内**，需 bbox 外扩、遮罩洞可选并入（V6）；边界缓存是否触碰协议 3.5 需合规复核（V5）。

**Related ADRs**: ADR-003

### ADR-002：收藏采用 localStorage（设备本地），字段与 `/nav` URL 参数对齐

**Status**: Accepted (2026-09-20)

**Context**: 项目无用户账号，收藏是含位置坐标的个人数据，且需满足"个人位置数据仅本地私有存储"的合规要求。

**Decision**:
1. 存储介质：**`localStorage`**，单 key `must.favorites.v1`，带 `schemaVersion`；否决 Cookie（位置数据会随请求外泄）、sessionStorage（不持久）、IndexedDB（过度设计）；
2. 数据模型：两类实体 **`PlaceFavorite`（地点对）** 与 **`PlanFavorite`（地点对 + 方案快照）**；端点与 `NavPoint` 同构，坐标 **GCJ-02**；
3. **与 `/nav` 衔接**：直接复用现有 URL 参数体系——`query` 用 `parseNavParams()` 的规范化串，方案以 **`fingerprint`** 标识（**不落 `planId`**）；**"收藏一条路线" = "存 `query` + 方案指纹"**，不新增协议；
4. 过期处理：**快照只作展示，回放一律重算**（重算后**按指纹比对**命中某卡，再用其当前 `planId` 取详情；未命中提示"已重新规划"）；
5. 容量：上限 **200 条**、LRU（置顶保留）清理；单条 ≤ 700 B，全量 ≤ ~140 KB。

**Consequences**:
- 正面：零后端改动、天然合规（数据不出设备）、实现简单、与现有路由零协议变更。
- 负面：**不跨设备**、清缓存即失（须显式告知用户）；Safari 隐私模式可能被清（需容错）。

**Related ADRs**: —

### ADR-003：底部导航与全屏地图按"页级"组织，不挂全局布局

**Status**: Accepted (2026-09-20)

**Context**: 需要底部导航栏；若挂到 `src/app/layout.tsx` 会波及所有既有页面（`/commute`、`/nav`、旧版通勤页等），引入大面积回归。

**Decision**: `BottomNav` 作为**页级组件**，只在需要的页面（首页、收藏页等）挂载；不由根布局统一注入。全屏地图容器同样按页组织，通过 CSS 作用域隔离，避免影响 `/nav` 等页。

**Consequences**:
- 正面：改动面收敛，旧页零回归风险；各页可差异化底部导航。
- 负面：新增页面需手动挂 `BottomNav`（用列表对齐即可，成本低）。

**Related ADRs**: ADR-001

## 附录：裁定结论、剩余确认与待验证清单

**已裁定（team-lead 2026-09-20）**
1. 境外定位：地图**始终以澳门行政区范围（含横琴口岸澳方管辖区）为准**；定位在境外时**不自动移出**，蓝点如实显示。（§1.4 ④ / §3.4-12）
2. 快照 >7 天：**不静默重算、不自动更新**；卡片永远显示「保存于 MM-DD」，点击**一律按当次重算**（PM 规格 §7.6.4）。（§2.5）
3. 收藏入口：**4 处**——方案收藏 `/nav` 每张卡 + `/nav/detail`；地点对收藏 首页选定目的地后 + `/nav` 顶部 OD 栏。（§3.1）
4. R5 一致性：收藏写入 localStorage **不违反** R5「起点不记忆」（R5 管"自动记忆"，收藏是用户显式意图）。（§2.1）
5. 方案收藏键：**弃用 planId，改存 `fingerprint`**（= `rides.map(r => `${r.route}@${r.board}->${r.alight}`).join("|")`，与 `OptionSeed.key` 同构）——planId 每次请求临时生成、跨请求不稳定；回放时**重算后按指纹比对**，命中则用**当前卡的 planId** 跳详情。（§2.3 / §2.4 / §2.5）

**待产品/合规确认（剩余）**
1. **横琴口岸澳方管辖区**在遮罩中的呈现：若能取到高德官方环则一并镂空，否则该区域被压暗（V6 结果决定）。

**待探针验证（开发前置，§1.5）**：**V3（多洞/绕向）为开发首日门禁**；V1/V2/V6 次之；V4/V5 再次。V3 不通过即按降级路径（仅范围限制）交付第一版。
