| 候选 | 值 | 饱和 S | 评估 |
|---|---|---|---|
| ★ **采用** | `#0B6E4F` | ≈0.82 | **作为"辅"色必须比主色更安静**。它比官方值低 18% 饱和 → 会**退后**，不与青花蓝抢戏；且已在全部预览验证，零返工 |

## 2. 每屏强调色用量（纪律）

- **主强调（青花蓝）**：每屏可见使用 **≤ 3 处**（本方案因承担"描边"角色，比一般系统的 ≤2 略放宽——描边是结构性而非装饰性）。三处典型 = 搜索条框 + 主 CTA + 当前选中态。
- **辅主题绿**：**每屏 ≤ 1 处**，且面积必须**远小于**蓝。
- **线路色**：不限（数据色，见 §9）。

---

## 3. ★ 辅主题色（澳门绿）使用边界 —— 硬规则

用户给了绿正式的**辅主题色**身份（不是仅状态色），因此必须有明确边界，否则两色会互抢。

### ✅ 允许（就这两个岗位）

1. **正向状态语义**：成功提示、在途/进行中、赶得上（`--success` 同源）。
2. **品牌辅助点缀**：字标细节（如 M Map 字标的一笔/一点）、favicon、启动页一角、极少量标识元素。

### ❌ 禁止

- ❌ 作 **CTA 底色**（那是蓝的岗位）
- ❌ 作 **选中态**（底导/列表选中 = 蓝）
- ❌ 作 **主描边 / 主框**（路牌蓝框 = 蓝）
- ❌ 作 **大面积填充**（卡片底、区块底）

### ★ 硬规则：**同一焦点只有一个主角**

> **同一屏、同一视觉焦点内，只允许出现一个品牌色。** 蓝与绿**不得并置于同一焦点**。

**判据（呼应 §H.3"冲突不在色相、在'两个主角'"）**：

| 场景 | 判定 |
|---|---|
| 一个按钮"蓝底 + 绿框" | ❌ 违规——同一元素两个主角 |
| 一行标签里同时有蓝色强调字 + 绿色强调字 | ❌ 违规——同一焦点两色 |
| 「在途」绿胶囊 + 右上角蓝色定位按钮 | ✅ 合规——不同元素、不同区域、不共焦点 |
| 字标上一点点绿 + 主 CTA 是蓝 | ✅ 合规——绿是点缀、面积悬殊 |

**配比纪律**：`面积(蓝) ≥ 面积(绿)` 恒成立；绿永远更小、层级更低。

## 4. 字体 Typography

### 4.1 字体栈

| Token | 值 | 说明 |
|---|---|---|
| `--font-display` | `"Barlow", "Noto Sans SC", -apple-system, "PingFang SC", sans-serif` | 标题/展示。**Barlow** 血统即标牌字体，含 tabular 数字 |
| `--font-body` | `"Barlow", "Noto Sans SC", -apple-system, "PingFang SC", sans-serif` | 正文（与 display 同族，靠字重/字号分层） |
| `--font-mono` | `"JetBrains Mono", "Barlow", monospace` | 线路码、站码、坐标、时刻 |

> **为什么选 Barlow**：它是**加州交通标牌**直接衍生的字形——"标牌"方向需要的就是这种被物理约束逼出来的字。中文回落 `Noto Sans SC`（保证跨端一致，不再像现状那样落到系统默认字体）。
> 数字**一律** `font-variant-numeric: tabular-nums` —— 站牌的时间与编号必须竖直对齐。

## 6. 圆角 / 边框 / 层级 Radius & Elevation

### 6.1 圆角（**上限 10px；按钮不用 pill**）

| Token | 值 | 用途 |
|---|---|---|
| `--radius-chip` | 6px | 线路码标签 |
| `--radius-group` | 7px | 多码组胶囊（§G.2 解法 A） |
| `--radius-btn` | 8px | **按钮（★ 非 pill）** |
| `--radius-card` | 10px | 卡片 / 搜索条 / 浮层 |
| `--radius-sheet` | 14px | 底部弹层（Bottom Sheet 顶角） |
| `--radius-full` | 999px | **仅**圆点/头像/定位按钮 |

### 6.2 层级（Elevation）—— **无模糊阴影，用硬投影**

本方案**不用 `box-shadow: … blur`**（模糊阴影是"AI 卡片"的指纹），改用**硬投影（零模糊）**造"实体/贴纸"感：

| Token | 值 | 用途 |
|---|---|---|
| `--shadow-none` | `none` | 列表行 / 内嵌块 |
| `--hairline` | `0 0 0 1px var(--border)` | 发丝线（比 border 更干净） |
| `--shadow-hard-sm` | `2px 2px 0 0 var(--border-strong)` | 小实体（字标、小胶囊） |
| `--shadow-hard` | `3px 3px 0 0 var(--border-strong)` | 主实体（搜索条、主按钮、卡片） |
| `--shadow-sheet` | `0 -6px 24px rgba(15,23,32,.12)` | 仅底部弹层允许一层柔和抬升（**唯一例外**，因其必须"浮"在地图上） |

> **禁止**：`1px 边框 + ≥16px blur 阴影` 同时出现在同一元素（幽灵卡片）。

## 9. ★ 线路标签色（**不纳入 Token 体系**）

**用户特别澄清，务必遵守**：

> 巴士 / 轻轨**线路码的颜色 = 既有线路主题色数据**（`RouteStack` 的 `colorOf` 从线路数据取），**与项目主题色（青花蓝 / 澳门绿）无关，不随主题色变化。**

| 规则 | 说明 |
|---|---|
| 颜色来源 | 线路数据（DSAT 线路色），运行时取，**硬编码在组件里 ❌** |
| 是否 Token | **否**。本 Token 体系**不含**任何线路色 |
| 是否随主题 | **否**。改主题色不影响线路码颜色 |
| 形态（见 §G） | 单码 = 圆角矩形；多码 = 墨色组胶囊 + **白色斜杠**分隔；换乘 = **箭头「→」** |
| 与品牌绿撞色？ | 可能出现"线路数据绿"与"品牌绿"同色。**不冲突**——线路绿只在标签内（有色底 + 白字，形态明确），品牌绿承担状态/点缀语义；两者不会出现在同一焦点 |

> **预览修订记录**：V2/V3 变体预览早期把线路示意色**误染成了青花蓝系**，易被误读为"线路色随主题色变"。**已修订**为与 V1 相同的独立示意色（`25 #C2410C` / `MT4 #0F766E` / `AP1 #B91C1C`，仅示意，实际取线路数据），三变体并列对比时可见"主题色变、线路色不变"。
