# Spec —— 实时巴士位置 + 6 项体验优化

> 生成：2026-09-23 · 版本 **v2.10.0**（目标）· 状态：**已锁定**
> 依据：Phase 0 澄清（17 项决策）+ Phase 1 三文档 + 架构师二次调研
> ⚠️ 本 Spec 是**团队内部契约**，后续开发以它为准；用户已在 Phase 1 确认过关键取舍

## 1. 产品定义

- **一句话**：在 M Map 的路线查看模式里，把该线路的**在途巴士**实时画在地图上（含手动刷新、车辆信息弹窗），并顺带完成 6 项体验优化。
- **目标用户**：澳门通勤者（主要是在澳科大上学、住擎天汇的作者本人及同学）。
- **核心问题**：现有「路线查看模式」只画线路走向，用户看不到**车现在在哪**，无法判断能不能赶上。DSAT 官网 App 同样看不到（实测其点车辆只显示车牌）。

## 3. 明确不做（Out of Scope）

| 不做 | 原因 | 何时考虑 |
|---|---|---|
| **轻轨车辆实时位置** | DSAT 是巴士系统，**无轻轨车辆数据**（已实测穷尽） | 永不（数据源限制） |
| **轻轨车辆图标**（氹仔线/横琴线/石排湾线三套） | 同上——没有车可画，图标无落点 | 若将来有轻轨实时数据 |
| **车辆图标按行驶方向旋转** | 位置接口**无航向角**（实测 busInfoList 仅 5 字段）；手动刷新间隔不固定，位移推算不可靠。用户已拍板「固定朝上」 | 若 DSAT 未来增加航向字段 |
| **拥挤度展示** | 报站接口有 `passengerFlow` 但官方覆盖率仅 34.5%，展示会误导 | 覆盖率提升后 |
| **自动轮询（非手动刷新）** | 用户明确要求手动 + 冷却；且持续轮询会显著增加 DSAT 压力 | 用户反馈需要时 |

## 5. API 端点清单（锁定）

### 5.1 `GET /api/route-vehicles`（新增）

**查询参数**
| 参数 | 必填 | 值 |
|---|---|---|
| `code` | ✅ | 线路码（`26` / `51A` / `N6`） |
| `dir` | ✅ | 方向（`0` \| `1`，即 `dsat_dir`） |
| `kind` | — | 固定 `bus`（轻轨直接返回空数组 + `note: "lrt_no_vehicle"`） |

**服务端逻辑**
1. 本地推导 `routeCode`：**线路号右对齐补零到 5 位**（`26→00026`、`51A→0051A`、`MT1→00MT1`、`N6→000N6`）
   ⚠️ **实为 5 位**（需求文档原写 6 位有误），依据 `scripts/track-collect.mjs:146-153`（10/10 实测）
2. **并行**发两个 DSAT 请求（`Promise.all`，各自独立超时）：
   - `getBusLocations(routeName, dir)` → `/routestation/location`（坐标）
   - `getBusPositions(routeName, dir)` → `/routestation/bus`（挂载站 + status）
   - 实测并行墙钟 **68ms**，串行 451ms
3. 按 `busPlate` 合并两份数据；坐标经 `wgs84ToGcj02` 转 GCJ-02
4. **报站失败降级**：仍返回车辆（有坐标 + 车牌），`interval: null`、`status: "unknown"`

**响应**
```jsonc
{
  "code": "26", "dir": "0", "kind": "bus",
  "fetchedAt": "2026-09-23T00:52:00.000Z",
  "color": "#276299",          // routes.color（画线/图标描边用）
  "company": "新福利",          // routes.company（决定图标配色）
  "lastBusPlate": "MY9362",    // 末班车牌（状态判定）
  "badCar": [...],             // 异常车标记（信号丢失）
  "vehicles": [{
    "plate": "MY9282",
    "busType": "1",
    "lat": 22.1567, "lng": 113.5521,   // GCJ-02
    "speed": 37,
    "status": "moving",                 // moving | stopping | terminal | unknown
    "isLast": false,
    "interval": {                       // 精确区间（报站接口给）；失败时为 null
      "from": { "code": "T373", "name": "偉龍／科技大學" },
      "to":   { "code": "T374", "name": "..." }
    },
    "atStation": null                   // 若停靠中：{ code, name }
  }]
}
```

### 5.2 `/api/route-shapes`（修改）
- 现有实现**返回全部方向的 shapes**，前端 `for` 循环**全画**（`NavMap.tsx:819-837`）⇒ **这是「双向都画」的根因**
- 改为：前端 `pickedLine` 增 `dir` 字段，**只画 `shapes.filter(s => s.dir === dir)`**
- **单向线路判据** = `shapes.length > 1`（76 条单向线路自然无换向按钮）

## 6. 数据库表清单（锁定）

### 6.1 `lrt_route_params`（新增）

> 存轻轨线路级的实测参数。**用户已拍板用表而非常量配置**。

| 字段 | 类型 | 说明 |
|---|---|---|
| `route_code` | TEXT PK | `LRT-石排湾线` / `LRT-横琴线` |
| `dep_bias_sec` | INTEGER | **发车偏差（秒）**：石排湾线 `-5`、横琴线 `+40` |
| `ride_sec` | INTEGER | **单区间乘车用时（秒）**：石排湾线 `100`(1'40")、横琴线 `135`(2'15") |
| `stops` | INTEGER | 区间数（两条线均为 **1**，都只行驶一站） |
| `measured_on` | DATE | 实测日期（合规要求：派生值须说明取得时间） |
| `note` | TEXT | 备注（如「协和医院→石排湾」） |
| `updated_at` | TIMESTAMPTZ | 默认 `now()` |

⚠️ **不采纳**「加到 `lrt_timetables`」——该表粒度是 站×线×方向×班别，而偏差是**线路级**，粒度错配。

## 9. 验收标准（EARS 格式）

| 编号 | 功能 | 验收标准 | 优先级 |
|---|---|---|---|
| AC-01 | 显示车辆 | **When** 用户在路线查看模式选中一条**巴士**线路，系统**必须**在 3 秒内于地图上显示该方向全部在途车辆 | P0 |
| AC-02 | 轻轨无车 | **When** 用户选中的是**轻轨**线路，系统**必须**只画线路走向、不显示车辆，且**不得**报错或空白 | P0 |
| AC-03 | 冷却 | **While** 距上次刷新不足 10 秒，系统**必须**禁用刷新按钮并显示剩余秒数 | P0 |
| AC-04 | 自动刷新 | **When** 用户进入线路或点击换向，系统**必须**自动刷新且**共用**同一冷却计时 | P0 |
| AC-05 | 状态区分 | **When** 车辆处于行驶/停靠/总站待发/末班/信号丢失，图标**必须**有可区分的外观 | P0 |
| AC-06 | 信息弹窗 | **When** 用户点击车辆图标，系统**必须**弹出含状态/车速/区间或进站/车牌的卡片 | P0 |
| AC-07 | 重叠合并 | **If** 多车屏距 ≤28px，系统**必须**合并为一枚图标并显示数量角标（>9 显 `9+`） | P0 |
| AC-08 | 报站降级 | **If** 报站接口失败，系统**必须**仍显示车辆位置与车牌（区间留空，不整块空白） | P0 |
| AC-09 | 偏差值生效 | **When** 轻轨报站显示下一班时刻，系统**必须**已计入该线的实测偏差（石排湾 -5s / 横琴 +40s） | P1 |
| AC-10 | 换乘站切色 | **While** 地图显示站点，蓮花站与協和醫院站**必须**呈现双色切分（方向符合规格） | P1 |
| AC-11 | 换向 | **When** 用户点击换向，系统**必须**切换到另一方向并重算视野；单向线路**不得**显示该按钮 | P1 |
| AC-12 | 帮助页可达 | **When** 用户在底部导航点「帮助」，系统**必须**进入 `/help`；访问 `/about` **必须**重定向到 `/help` | P1 |
| AC-13 | 弹窗不被遮挡 | **While** 选线路弹窗打开，底部**不得**有任何元素遮挡其内容 | P1 |

## 10. 边界与约束

- 只支持**巴士**线路的车辆显示（轻轨无数据）
- 刷新频率上限：**10 秒/次**（前端 disabled + 服务端时间戳兜底）
- 车辆坐标为 **WGS84 → GCJ-02**，服务端转换
- **响应式**：按 390×844 标定（标准手机）
- **P0 规则**：禁 emoji 图标（用 Tabler Icons）· 禁紫粉渐变 · 禁硬编码颜色（线路色是**数据**、例外）

## 11. 内嵌已知坑（必须规避）

| 坑 | 根因 | 规避 |
|---|---|---|
| **新 API 会 401** | `middleware.ts` 是 **fail-closed**（默认拒绝） | **`/api/route-vehicles` 必须加入 `PUBLIC_PREFIXES`**（本项目已踩**两次**） |
| **刷新会把计时器弄哑** | 熔断是全局的（连续失败 3 次静默 30 分钟） | **`live_pos` purpose 必须排除在熔断判定之外**（像 `recommend` 一样） |
| **`routeCode` 传错静默返空** | DSAT 不报错、只回空 | 本地补零**5 位**，并加断言 |
| **marker 泄漏** | 换向/刷新时旧图标未移除 | 先 `remove` 再 `add`（参考 `NavMap.tsx:638-647` 已有模式） |
| **多实例冷却失效** | Vercel 多实例、内存不共享 | 冷却**以前端为主**，服务端只做时间戳兜底 |
| **车辆 GPS 漂移** | 传感器本身误差 | 若用几何匹配须设 **≤120m 阈值**并以「进站/车牌」兜底 |
