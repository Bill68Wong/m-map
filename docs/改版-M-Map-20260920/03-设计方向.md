### 0.3 联网调研：3 个"好品味"真实产品，提炼到「手法」而非「抄外观」

| 产品 | 它好在哪 | 可借鉴的**手法**（不抄皮肤） |
|---|---|---|
| **Citymapper**（transit） | 信息密度极高却不乱；换乘/出口/车厢这种"最后一公里"细节是它的灵魂 | ① 密度靠**分组 + 层级**扛住，不是靠留白；② 文化符号化图标（巴士/轻轨/步行一眼可辨）；③ 主行动（"Get Me Somewhere"）永远在第一屏最显眼处 |
| **Linear**（工具） | 发丝线、单一强调色、"高光笔只用一次"的纪律；4px 数列；**明令禁止**：渐变底、圆角 >8px、卡片投影、<14px 正文 | ① 把强调色当高光笔——一屏至多一次；② 用 **box-shadow 0 0 0 1px** 当边框（比 border 更干净）；③ 用小字号大写 + 正字距做标签 |
| **Apple HIG · Maps 指引** | 地图交互的硬规矩：柔和（去饱和）底图让内容浮出；控件与底图必须有**明确对比**；选中元素要描边；浮层要落在**拇指区**、且"最低静止位置上方 10pt"放归属信息 | ① 地图是主角 → chrome 必须让路；② 底图去饱和，让路线/站点成为唯一彩色；③ 浮层 = 底部卡（Bottom Sheet），不是小气泡（手指会挡住小气泡） |

**综合出的一条主线**：*真实产品的"高级感"来自「纪律」和「主角意识」——彩色克制、线条精确、地图让路、信息真实。AI 模板的"廉价感"来自「平均」和「堆砌」——什么都来一点、每块都套卡片、处处一样密。*

## A. 「AI 味」诊断 —— 现状最像 AI 模板的 6 处

> 逐条给出**代码证据** + **为什么"假"**。（不写"哪里丑"，只写"哪里露了 AI 的怯"。）

### A1. 纯系统字体直出，没有品牌字体、没有字距/字重体系

**证据**：`globals.css:148-151`
```
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
             "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "MiSans", ...;
```
**为什么假**：这是"我不想选字体，交给操作系统吧"的默认值。结果：同一份界面在 iOS 落到 PingFang、在 Android 落到 Roboto+Noto、在 Windows 落到雅黑——**同一款产品，三台手机三种长相**。更关键的是没有字距规则（`--fs-*` 只有字号没有 tracking）、没有字重分层（全靠 600/700 硬撑）。"没有设计师拍过板"的第一特征，就是没有字体主张。

### A2. Google Material You 的"文档默认色"

**证据**：`globals.css:11-15` `--primary: #0b57d0` / `--primary-container: #d3e3fd` / `--on-primary-container: #041e49`；整套 `--surface-dim` / `--on-*-container` 命名。
**为什么假**：`#0b57d0` 是 Material 3 默认蓝的直系，`#d3e3fd` 是 Google 官方 tonal palette 第 90 阶。命名体系（`on-primary-container`）说明它是**照着 M3 文档抄的**，不是为"澳门通勤"设计的。M3 是一套很好但**使用极广**的系统——用户已经在 Gmail、日历、系统设置里见过它一百遍，所以它天然读起来"像某个通用 App 而不是这个 App"。

### A3. 卡片三位一体，全站铺满，无处不"套盒"

**证据**：`.card`（`globals.css:403-409`）= `surface + 1px stroke + 16px 圆角 + var(--shadow-1)`；`.press-card`（427-443）几乎是它的复制；`.rc`（1014）也是。`--r-card: 16px` 贯穿全站。
**为什么假**：**"1px 描边 + 16px 圆角 + 极浅投影"三件套同时出现在每一个容器上**——这是 AI 生成卡片的指纹。真实设计师会问"这块**需要**是个盒子吗？"，而模板从不问，只会把一切装进同一种盒子。加上"同尺寸卡片 + 图标 + 标题 + 正文"无限重复（现状的 5 张路线大卡、记录列表），命中 AI 模板特征「相同卡片网格」。

### A4. 大数字 + 小灰标签的"指标卡"结构

**证据**：`.rc-total` 30px/700 + `.rc-total__unit` 14px（`globals.css:1080-1093`）；`.eta-big` 34px/800（793）。
**为什么假**：孤立的巨大数字配一行小灰标签，源自 SaaS 落地页的"Trust metrics"套路（`10,000+ 用户`）。搬到通勤卡上，数字脱离了它的**语境**——"12 分钟"对通勤者真正有意义的是"哪一班、还剩几站、赶不赶得上"，而版面把"12"放得最大，等于把最廉价的视觉权重给了最不需要强调的东西。

### A5. emoji 与 Unicode 字符冒充图标（★ P0 违规）

**证据**（本次全量正则扫描结果）：
| 文件:行 | 内容 | 判定 |
|---|---|---|
| `src/components/FinishForm.tsx:51` | **`🎉 到达了`** | ★ **P0 违规**：真 emoji 当功能/状态图标 |
| `src/components/FinishForm.tsx:105` | `✓ 行程已完结` | Unicode 字符当图标 |
| `src/components/nav/StationCard.tsx:97` | `✕`（关闭按钮） | Unicode 字符当图标 |
| `src/app/nav/page.tsx:37` | `← 返回` | Unicode 字符当图标 |
| `src/app/page.tsx:44` | `通勤计时（旧版）›` | Unicode 字符当图标 |

**为什么假**：Unicode 字符不是图标——它的**字号跟着字体走**、**粗细不可控**、**跨端字形不同**（`✕` 在三星和 iPhone 上是两个东西）。而 `🎉` 更直接：emoji 是"聊天软件的表情"，出现在一个严肃的通勤工具里，就像把帖纸贴在了仪表盘上。**P0 规则：emoji 只能出现在用户生成内容里，绝不作为 UI 功能图标。**

### A6. 渐变的唯一用途是"装饰"，且间距"均匀到没有节奏"

**证据**：`.rc-sk` 骨架用 `linear-gradient(90deg, …)` 做 shimmer（1372-1378）；`.jp-fill` 载具主题色渐变进度条（528-536）。间距侧：`--gap-card: 12px` / `--gap-row: 10px` / `--pad-card: 14px 16px` / 到处 `padding: 12px 14px`。
**为什么假**：① 渐变在现状里**不承载信息**，只用来"看起来高级"——真正的高级是渐变**表达方向/进度/层级**（时间轴、里程），而不是给一个占位框加流光。② 间距是均匀的 8/10/12/14 混合，**每处一样密 = 没有呼吸 = 没有版面设计**。真实版面是"疏可走马、密不透风"——关键处敢留大白，次要处敢挤紧。

## B. 「真人感」设计原则清单（8 条，可执行）

> 每条都配一句"怎么落地"，给前端可直接照做的判断标准。

| # | 原则 | 落地标准 |
|---|---|---|
| **B1** | **一个强调色，当高光笔用** | 每屏彩色 = 线路色 + 1 个功能强调色；功能强调色每屏 **≤2 处可见使用**（主 CTA、或当前选中态，二选一，不可都出现）。其余全部交给灰阶。 |
| **B2** | **用发丝线 + 亮度层级分层，而不是给每块套盒子** | 分组优先用 `border-top` / `divide-y` / 共享背景；只有"浮在地图之上的浮层"才允许是带描边的实体块。禁止 `1px 边框 + ≥16px blur 阴影` 同时出现在同一元素（幽灵卡片）。 |
| **B3** | **字重倒置 + 尺寸跳跃 + 字距纪律** | 层级靠 **字重与字距**，不靠一味放大字号。大字（≥28px）用**负字距**（-0.02em），小标签用**正字距**（大写 +0.08em）、小字 0.01em、正文 0；数字一律 `font-variant-numeric: tabular-nums`。 |
| **B4** | **非常规留白节奏** | 不追求处处等距。每个版面至少有一处"刻意的极紧"（如站码贴在色块边）与一处"刻意的极松"（如目的地名称周围 24px 空）。4px 网格内**允许**出现 6px 这类"非标但有意"的偏移（见 B8）。 |
| **B5** | **有性格的微文案** | 空状态、失败态、按钮一律用"人话"，具体、克制、带一点在地感。**禁止**"Welcome to / Lorem ipsum / 暂无数据 / Get started"。示例见下方文案对照表。 |
| **B6** | **地图是主角，chrome 必须让路** | 底图去饱和（让路线/站点是唯一彩色）；浮层统一落在**屏幕下 1/3（拇指区）**；浮层与底图保持明确对比 + 内边距；归属/合规信息固定在界面最低静止位置之上，不被浮层长期遮挡。 |
| **B7** | **真实信息的界面密度** | 用真实的澳门地名/线路码/时刻填满界面（氹仔、关闸、横琴、筷子基、25、MT4、AP1…），密度本身就是"真"的证据。禁止"示例地点 A""地点 1"这类占位。 |
| **B8** | **允许手工感的不完美对齐** | 版面不要 100% 机器网格化——允许标签轻微出格（站码像贴纸压在色块边缘）、允许 2px 的微错位作为"手感"。**完全对齐 = 像打印机；5% 的不齐 = 像人手摆过。** |

**文案风格对照（B5 示例）：**

| 场景 | ❌ 模板味 | ✅ 人的口吻（建议） |
|---|---|---|
| 首页搜索占位 | "输入目的地" | "要去边度？" → **改用简体：「去哪儿？」**（在地感，短） |
| 空收藏 | "暂无数据" | "还没存过路线。看到好走的，右下角收着。" |
| 定位失败 | "无法定位 · 请手动选择出发点" | "定位没成功，手动挑个出发点吧" |
| 到达 | `🎉 到达了`（emoji） | 「到了。全程 32 分钟。」（去掉 emoji，用 SVG 图标 + 一句话） |
| 赶不上车 | "赶不上" | "这班赶不上，下一班 6 分钟后" |

## C. 三个风格方向（供对比挑选）

> 三方向在**底色策略 / 强调色 / 描边语言 / 澳门边界处理**上做出了真实分歧，不是同一套皮肤的三种配色。
> 每个方向都有一个可点开的静态预览：`style-previews/*.html`（内联样式、单文件、直接双击打开）。

### 方向 A ——「站牌」SIGNBOARD
**一句话气质**：像澳门街头的巴士站牌——白底黑字、粗描边、线路色是唯一的花，站在太阳底下也一眼看清。

| 项 | 规格 |
|---|---|
| **配色** | `--bg #F1F3EF`（冷调雾白，**刻意避开米黄/奶油**）· `--surface #FFFFFF` · `--fg #12161A`（墨黑）· `--muted #5D646C` · `--border #D9DDD6` · **`--accent #0B6E4F`（澳门绿）** · `--accent-on #FFFFFF` · `--danger #C0392B` · `--warn #B26A00` · `--success #0B6E4F` |
| **字体** | 拉丁/数字 **Barlow**（血统即标牌字体，tabular numerals，400/600/700）· 中文 **Noto Sans SC / MiSans** · 等宽 **JetBrains Mono**（站码、线路码） |
| **圆角与阴影** | 圆角克制：卡片 **10px**、按钮 **8px**（**不用 pill**）、chip 6px。阴影几乎不用——改用 **1.5px 实描边 + 3px 硬投影（offset，零 blur）**，营造"贴纸/标牌"的物理感（这是最不像 AI 的一招）。 |
| **图标风格** | 线性，**2px 描边，方头方角**（butt/miter），几何硬朗。尺寸 16/20/24。 |
| **澳门边界处理** | 域外 → **冷雾白 78% 遮罩**（域外变"纸"）；边界 → **2px 澳门绿实线 + 内侧 1px 白描边**（像个站牌边框）。 |
| **首页无大标题如何成立** | 靠"标牌式搜索条"当视觉锚点：白底、粗描边、硬投影，像一块实体站牌浮在灰阶地图上。 |
| **预览** | `style-previews/A-站牌.html` |

### 方向 B ——「夜班」NIGHTLINE
**一句话气质**：深夜从关闸等尾班车回家的那半小时——暖光、低照度、不刺眼、专注。

| 项 | 规格 |
|---|---|
| **配色（深色优先）** | `--bg #0F1013` · `--surface #17191E` · `--surface-2 #1F222A` · `--fg #ECEDF0` · `--muted #9BA1AC` · `--border rgba(255,255,255,.08)` · **`--accent #E8A33D`（尾班车琥珀 / 路灯暖光）** · `--accent-on #171003` · `--danger #FF7A6B` · `--success #6FD08C`；浅色模式 `--bg #F4F4F6`（中性冷白，非奶油） |
| **字体** | 拉丁 **Hanken Grotesk**（圆润人文无衬线，暖）· 中文 **Noto Sans SC** · 等宽 **JetBrains Mono** |
| **圆角与阴影** | 卡片 14px、按钮 12px（非 pill）。**深色下完全不用阴影**——靠亮度递进（#0F1013 → #17191E → #1F222A）分层；浮层顶边加 1px 极弱内发光（`rgba(255,255,255,.06)`）模拟物理边缘。 |
| **图标风格** | 线性，**1.75px 描边，圆头圆角**（round cap/join），暖色描边。 |
| **澳门边界处理** | 域外 → 向 `#05060A` **渐隐晕影**（像夜航地图的"城外黑"）；边界 → **1px 琥珀发光线**（外发光 6px）+ 交点小圆点。 |
| **首页无大标题如何成立** | 靠"琥珀色光"当焦点：深夜界面里，一点点暖光是天然的视觉中心，搜索条只需一枚琥珀发光小徽记 + 短提示。 |
| **预览** | `style-previews/B-夜班.html` |

### 方向 C ——「坐标」COORDINATE
**一句话气质**：一张被认真标注过的地图——白纸、发丝线、等宽编号，所有装饰都删掉，只剩坐标与时间。

| 项 | 规格 |
|---|---|
| **配色** | `--bg #FBFBFC` · `--surface #FFFFFF` · `--fg #0A0B0D` · `--muted #6A6F78` · `--meta #9AA0A8` · `--border #E6E8EB`（发丝线） · **`--accent #1E4FE0`（信号钴蓝）** · `--accent-on #FFFFFF` · `--danger #D92D20` · `--warn #B54708` · `--success #067647` |
| **字体** | 拉丁 **Public Sans**（或 Archivo，中立系统感）· 中文 **Noto Sans SC** · 等宽 **Geist Mono**（编号/坐标/时间） |
| **圆角与阴影** | 圆角**小**：卡片 **8px 上限**、按钮 8px、chip 6px。**默认零阴影**——仅用 `box-shadow: 0 0 0 1px` 发丝线分层（Linear 做法）；只有浮层允许一层极轻抬升。字距严格成阶：大字 -0.02em / 小标签大写 +0.08em。 |
| **图标风格** | 线性，**1.5px 描边，锐角**（butt/miter），偏几何。 |
| **澳门边界处理** | 域外 → **白色 60% 去饱和遮罩**（地图变灰、而非变纸）；边界 → **1px 虚线 + 四角刻度**（蓝图感），选中区域加 1px 钴蓝描边。 |
| **首页无大标题如何成立** | 靠"地图本身即内容"：白底发丝线 UI 几乎隐形，视觉重量全交给地图，搜索条只做一枚冷淡的描边胶囊。 |
| **预览** | `style-previews/C-坐标.html` |

| 澳门边界 | 纸化遮罩 + 绿描边 | 渐隐晕影 + 琥珀发光线 | 灰化遮罩 + 虚线 + 角刻度 |
| 性格 | 硬朗、可信、在地 | 温暖、专注、夜间 | 精确、安静、技术 |
| 风险 | 绿描边在底图上需验证对比 | 白天户外可能偏暗 | 容易读成"又一个 devtool" |

### 推荐：**方向 A「站牌」**（理由）

1. **最"产品真"**：真实世界的**交通标牌**是最不可能像 AI 的参照系——AI 造不出"站牌"这种被物理约束逼出来的设计语言（室外可读、粗描边、色彩节制）。
2. **最解决"无大标题"命题**：一块粗描边、硬投影的搜索条本身就是实体，不需要标题撑场——这恰恰是"站牌逻辑"。
3. **在地性**：澳门绿 `#0B6E4F` 是本地色（澳门旗帜绿系），比 Material 蓝 / Tailwind 靛蓝更"是这个城市的产品"。
4. **可用性**：澳门通勤大量发生在白天户外、巴士车窗强光下——**浅底高对比 + 去饱和底图**在这里是真实的可读性优势。
5. **可合成**：方向 B 可直接作为 A 的**深色模式**（同一套 Barlow/Noto + 同一套圆角，只换底色与强调色）。

> **✅ 已拍板（2026-09-20）**：用户选定 **方向 A「站牌」**（**浅色单套**）。深色模式**本次不做**——既有 `prefers-color-scheme` 双主题保持现状；**B 夜班留档为后续深色版素材**。
> 主题色在「澳门绿 vs 路牌蓝」之间的取舍，见 **§H**（附三变体预览与专业结论）。

> 待用户拍板后再进入 DESIGN.md 与 Token 落地。

## F. 图标方案建议（不用 emoji）

### F.1 风格主张（按方向）

| 方向 | 描边 | 端头/转角 | 气质 |
|---|---|---|---|
| A 站牌 | **2px** | 方头方角（butt / miter） | 硬朗、标牌、几何 |

### F.2 尺寸与网格规范（★ 全站范围）

- **画布**：24×24 viewBox，`stroke-width` 按上表；`fill="none"`；`currentColor` 描边（随文字色）。
- **三档尺寸**：**16px**（行内 / 行内元数据）· **20px**（按钮内 / 列表前导）· **24px**（底部导航 / 独立图标）。**只此三档，不得混用**。
- **对齐**：图标视觉重心落在 24 网格的**光学中心**（不一定是几何中心），与文字混排时用 `vertical-align: -0.125em` 做光学对齐。
- **禁止**：混用线性 + 面性；混用不同描边粗细；用 emoji 或 Unicode 字符（`✕ ✓ ← ›`）当图标。
- **必需图标清单（首页 + 收藏页）**：搜索（magnifier）· 定位（crosshair / locate）· 房屋（home tab）· 书签（favorites tab）· 起点（circle-outline）· 终点（pin）· 交换（swap）· 步行 · 巴士 · 轻轨 · 关闭（close）· 返回（chevron-left）· 列表箭头（chevron-right）。
- **具体图标库**：由**架构师在 Spec 锁定一套**（建议：与所选方向的描边/端头风格匹配的线性库，例如 Lucide / Phosphor / Tabler 中选其一，全项目不混用）。本文只给**风格主张与尺寸规范**，不指定具体库名——锁定权在架构师。

> **★ 适用范围 = 全站（用户已拍板 2026-09-20）**：本轮「emoji / Unicode 字符当图标」的清理**覆盖全站**，不只首页与收藏页——含旧版功能页共 **30+ 处**（如 `FinishForm.tsx:51` 的 `🎉`、`FinishForm.tsx:105` 的 `✓`、`StationCard.tsx:97` 的 `✕`、`nav/page.tsx:37` 的 `←`、`page.tsx:44` 的 `›`）。
> 因此 §F.1 / §F.2 是**全站统一标准**：一套线性库 + 仅 16/20/24 三档 + 描边风格按最终选定方向（**A 站牌 → 2px 方头方角**），全站不得混用其它图标或字符图标。

## G. 线路标签规范（★ 用户 2026-09-20 直接定义）

> 用户直接定义的 UI 规则，**优先于现存 `.route-stack` 斜切形态**。

### G.1 三种形态与语义

| 场景 | 形态 | 语义 | 示例 |
|---|---|---|---|
| **单个线路码** | 主题色实心**圆角矩形**标签（radius 5–6px；白字；等宽字体 12px/700；水平 padding 9px；高约 22px） | "坐这条线" | `[25]` |
| **多个线路码同时出现** | 各码仍是各自主题色的圆角矩形，**中间用白色斜杠「/」分隔**；**整体套一个墨色组胶囊承底**（见 G.2，已裁定为默认形态） | **并列可选**（同一段有 N 条线，任选其一） | `[25] / [MT4]` |
| **换乘** | **箭头「→」**（保持现状） | **先后推进**（上一程 → 下一程） | `[25] → 步行 4 分 → [MT4]` |

### G.2 白斜杠的承载方式（✅ 已裁定：解法 A 为「多码并列默认形态」）

「白色斜杠」落在**白色卡片**上会**不可见**。团队已核实：现有 23 处 `<RouteStack>` **全部是单码**；「多码并列」是本次**新引入**形态，实际出现位置 = **白 / 浅底卡片上**（收藏卡「常用线路」组、站点信息卡经过线路等）。**故承载方式必须自带对比保障** —— 裁定采用 **解法 A**：

| 解法 | 做法 | 裁定 |
|---|---|---|
| **★ A（默认形态）** | 多码共用一个**墨色组胶囊**承底（`--fg` 底、radius 7px、内 padding 3px），码为各自主题色圆角矩形，白斜杠落在墨色底上 → **在任意背景上都清晰可见** | **✅ 采用**。观感即"线路组徽章"，与站牌/贴纸语言一致；代价是多一层底 |
| B | 码直接排在白卡上，斜杠改用**墨色**（不是白） | ❌ 弃用：斜杠在**彩色码之间**对比不稳定（浅色线路码旁几乎读不出） |
| C | 码紧邻无缝，用 clip-path 从色块间"切"出一道白缝当斜杠 | ❌ 弃用：接近已被否掉的旧 `route-stack` 思路 |

> **✅ 已裁定（团队 2026-09-20）**：多码并列**一律**用解法 A（墨色组胶囊 + 白斜杠）。B / C 弃用。
> **实现要点**：组胶囊内序 = 码 · 斜杠 · 码…；斜杠 `color:#fff`、`opacity ≈0.92`，左右各留 1–3px 空隙避免与色块糊连；胶囊整体作为一个不可拆分的单元参与排版（换行时整体下移，不拆散）。

### G.3 反例（禁止）
- ❌ 斜切梯形（旧 `.route-stack` 的 `clip-path: polygon(...)`）
- ❌ 多码写成 `25/MT4`（无间距）——白斜杠会与色块糊在一起，斜杠左右须各留 2–3px
- ❌ 用斜杠表达"换乘"——换乘是**先后**关系，斜杠是**并列**关系，语义不同

## H. 澳门「道路牌」蓝：考据、三变体与结论

### H.1 考据（对用户提问的正式回应）

**用户原描述「白底 + 蓝框 + 黑字」→ 不完全准确。** 据《澳門記憶》「街牌的百年演變」与中新社《澳门街道名拾趣》等资料：

- 澳门街牌（葡式 toponímia）是**白底 + 蓝框 + 蓝字**（**不是黑字**）：
  - 「白底蓝字，路牌边缘及中、葡文地名之间亦有蓝色花纹」（中新社）
  - 「白色底、蓝色文字和边框的瓷砖街牌」（《澳門記憶·街牌的百年演變》）
- 工艺：中国传统**青花瓷**釉面瓷砖拼成，这一蓝被称为 **「青花蓝」/「墙上青花」**；与葡萄牙 **azulejo**（瓷砖画）同源——**2020 年「葡萄牙瓷砖画制作技艺」列入澳门非遗清单**。
- 规格（2002 年统一后）：整块由 **8 块约 15cm 见方瓷片**拼成（上下两列各四块）；**中文在上（"全真楷书"）、葡文在下（Arial Narrow）**，中葡文之间一条蓝线分隔。
- **官方未发布数字色值**：它是**烧制釉色**而非印刷色，公开资料均无 hex（这与「澳门绿」有官方 CMYK/RGB 参数形成对比）。

**本方案给出的「青花蓝」数字近似（非官方值）：**

| Token | 值 | 说明 |
|---|---|---|
| `--sign-blue`（青花蓝·主） | **#1B4D8F** | 深钴蓝偏靛；对白底对比度 **≈8.4:1**（正文 AAA 级），光下沉稳似釉 |
| `--sign-blue-deep` | **#16406F** | 深一档：按下态 / 深底 |
| `--sign-blue-soft` | **#E6ECF6** | 浅底：选中背景 |

> ⚠️ 数字近似，非官方。若求精确，建议对**实拍街牌取色** / 比对 Pantone（青花蓝通行对标钴蓝系，约 Pantone 288C 一带）后由架构师定稿。

### H.2 三变体（同一组元素对比）

每个变体展示**同一组 5 个元素**：搜索条 / 底导选中态 / 线路标签 / 主按钮 / 地图边界线。

| 变体 | accent | 边框语言 | 文件 |
|---|---|---|---|
| **V1 · 绿主（对照）** | 澳门绿 `#0B6E4F` | 墨黑 | `style-previews/variants/V1-绿主.html` |
| **V2 · 蓝主（路牌语言）** | 青花蓝 `#1B4D8F` | **青花蓝**（白底 + 蓝框，整体变「街牌」） | `style-previews/variants/V2-蓝主.html` |
| **V3 · 分工** | 绿 = 交互 / 蓝 = 地理 | 墨黑 | `style-previews/variants/V3-分工.html` |

### H.3 专业结论：绿与蓝会不会冲突？

**1) 色相上不"打架"，语义上会"抢戏"。**
- 澳门绿 `#0B6E4F`（H≈161°）与青花蓝 `#1B4D8F`（H≈215°）相距约 **54°**，属**冷色区的邻近—分裂搭配**，不像"红配绿"那样产生**视觉振动**——两色并置**本身不刺眼**。
- **冲突发生在"角色"上**：当绿与蓝**都被当作同级品牌强调色**同屏出现（V3 的风险），界面会读成 **"两个品牌"**，用户不知该看哪个——**真正的冲突不是色相，而是"两个主角"。**
- **不冲突的用法**：让两色**分属不同语义层**——蓝只出现在**地图画布内**（边界线 / 路线 / 道路名，等于"地图自己的墨色"），绿只出现在**界面 chrome**（CTA / 选中态）。此时蓝与绿**从不共处同一视觉焦点**。
- 另一隐患：两色都是**中深 + 中饱和**，大面积相邻会显"发闷"。**若并用，面积必须一大一小**（如蓝只在细线、绿在按钮）。

**2) 整体性排序：V2 ＞ V1 ＞ V3。**
- **V2 整体性最好**：**一个隐喻贯彻到底**——白底 + 蓝框 + 蓝强调，正是澳门街牌本身；还把已选的 A 从"巴士站牌"**升级为"澳门街牌"**，语言更完整、更在地。
- V1 次之：单一强调色最省心，但"旗绿"与"牌蓝"是**两个不同的澳门符号**，选绿即放弃街牌这条"全城可见"的线索。
- **V3 最弱**：语义最清晰，但**两个品牌色**使整体性最差——恰恰就是用户担心的那种冲突。

**3) 我的推荐：V2 蓝主。** 理由：
1. 一个隐喻贯彻（街牌语言），**整体性最高**；
2. 青花蓝比区旗绿**更日常可见**（街牌在每个路口，区旗平时少见）；
3. 白底蓝框是**400 年中西合璧的手艺**（青花瓷 → azulejo → 街牌，非遗），比取色于旗帜更有故事；
4. 我们的底图**是灰阶的**，深钴蓝强调色**不会与地图自身的蓝打架**；
5. `#1B4D8F` 与 Material 默认蓝 `#0b57d0` 明显不同（更深、偏靛、降饱和），不会重蹈"通用 App 蓝"的观感。

**如实告知的代价**：换蓝即**失去"澳门绿"的暖意与旗帜象征**。故 **绿降级为语义色**（仅 `--success` / 在途状态），不再作品牌强调色。
若更看重"暖调与延续性"，退回 **V1 绿主**即可——但**请勿采用 V3**。

### H.4 顺带核实：`#0B6E4F` 是不是澳门区旗绿？

**不是精确值，但同族。** 「澳门绿」有**官方参数**：CMYK (86, 43, 73, 3) / RGB (0, 121, 94) → 网页色 **`#00795E`**（百度百科、搜狗百科一致；另有以 Pantone 3295C 对应的 `#077662` 一说）。

| | 我方 A 方案绿 | 官方「澳门绿」 |
|---|---|---|
| hex | `#0B6E4F` | **`#00795E`** |
| RGB | (11, 110, 79) | (0, 121, 94) |
| 色相 H | ≈161° | ≈167° |
| 饱和 S | ≈0.82 | **1.00** |

结论：`#0B6E4F` 是"澳门绿的**降饱和、略偏黄**近亲"，**不是官方色**。若要正式宣称"澳门绿"，请改用 **`#00795E`**（或 Pantone 3295C 的 `#077662`）。
