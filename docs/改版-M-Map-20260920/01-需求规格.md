| 搜索框 | 两段式（打字纯本地 / 点搜索或回车走高德兜底）；结果带类型徽章（公交站／轻轨站／地点） | `PoiSearchBox.tsx` |

| 方案卡 | `RecommendCard { planId; summary; totalMin; walks; rides[]; transfers[]; crossBorder }`；`planId` 仅**同一次规划会话内**有效 | `src/lib/recommend/types.ts` |

| 导航端点「起点不记忆」铁律 | 产品 R5：**起点不用 localStorage 记忆**（`PoiSearchBox` 明确） | 代码注释 |
| 无实际底部导航组件 | 全站无 bottom tab；仅有页内文字入口 | 代码检索 |

⚠️ 两条**必须继承的既有约束**：
- **R5「起点不记忆」**：首页起点默认「我的位置」，不落 localStorage。**例外**：用户**显式收藏**的地点对／方案，其端点应保存（这是"收藏"语义，与"自动记忆上次起点"不同）。← 本条为设计前提，见 §7.9。
- **`planId` 不跨会话**：收藏"具体路线方案"时**不可依赖 `planId`** 复现，必须用**方案指纹**（见 §7.6）。

## 3. 用户故事（As a / I want / so that）

**R1 全屏地图**
- US-1.1：作为澳门科大学生（住擎天汇），我希望**打开 App 就能看到铺满整屏的地图**，这样一进来就能直观判断方位、点选站点，而不是先看半屏空白再滚。
- US-1.2：作为桌面端用户，我希望**地图同样铺满可用区域**，这样在大屏上也能获得与手机一致的"以地图为中心"的体验。

**R2 目的地优先 + 置顶搜索**
- US-2.1：作为赶时间的学生，我希望**首页只需要先想清楚"去哪"**（只填目的地），出发地默认用我的定位，这样少一步操作、更快出发。
- US-2.2：作为要反复核对路线的用户，我希望**选定目的地后地图能标定它的位置**，再让我确认出发地，这样我能确认"目的地确实是我要去的那个地方"。
- US-2.3：作为用户，我希望**能随时改选起终点、回退到上一步**，这样输错的时候不用重开。

**R3 底部导航 + 路线收藏**
- US-3.1：作为每天走同一条路的学生，我希望**一进 App 就能从底部切到"路线收藏"**，这样不必每次重新搜。
- US-3.2：作为用户，我希望**既能收藏"家→澳科大"这种地点对，也能收藏"51 路这条具体方案"**，这样既能存"去哪"，也能存"怎么走"。
- US-3.3：作为偶尔用旧计时功能的用户，我希望**旧版计时还能用**（只是入口挪走），这样我的历史用法不被破坏。

**R4 品牌更名**
- US-4.1：作为用户，我希望 App 叫**「M Map」**，这样名称更简短、更像一个地图工具。（用户已确认，无争议）

**R5 澳门范围**
- US-5.1：作为用户，我希望**地图不会把视角滑到无意义的外地**，这样我始终在看澳门本地路网。

**R6 去 AI 化**
- US-6.1：作为用户，我希望界面**看起来像一个真实、克制的地图/工具产品**，而不是"AI 模板生成"的敷衍感，这样我愿意长期用。

## 4. 功能主流程（一句话）

```
打开 → 全屏地图 + 顶部目的地框
  → 选目的地（搜索命中 或 地图点选）
  → 地图标定目的地（居中 + 落点）
  → 选出发地（默认"我的位置"，可改）
  → 点「出发」→ 跳 /nav（结果列表）→ 点卡 → /nav/detail
底部导航：首页 / 路线收藏
```

## 5. 竞品调研（支撑 §7 路线收藏规格）

**调研方式**：联网检索 4 个直接/间接竞品 + 2 个"过期与变更处理"参考；重点看官方帮助文档与用法说明，提炼**共性字段与交互**。

### 5.1 竞品矩阵

| 产品 | "收藏地点" | "收藏路线/行程" | 入口 | 云同步 | 对"方案过期"的处理 |
|---|---|---|---|---|---|
| **高德地图**（Amap） | 地点详情页点"收藏"（星形图标）；可加自定义标签/备注；有"家/公司"预设 | 路线规划结果页点"收藏"，保存**起终点 + 出行方式 + 偏好** | 地点详情页 / 路线结果页 / "我的收藏" | 有（登录后多端同步） | 收藏路线"可重新查看方案"；不承诺冻结绝对时刻 |
| **百度地图** | 地点详情页收藏，可命名 + 分组（收藏夹） | 路线详情页"…→收藏 / 保存为常走路线"，保存完整路径（起终点+途经点+方式） | 路线页 / 个人中心收藏夹 | 有（账号同步） | 常走路线一键"启动导航"时按**当次**重新规划 |

| **Moovit** | Favorites 页预设 Home/Work + 自定义地点，一键"从当前位置到收藏地" | 收藏**线路（line）**：需三要素=线路名 + 方向 + 上车站；并提供实时到站 | Stations 页线路三点菜单 / Favorites 页 | 有 | 收藏线路**主动推送到站 / 延误 / 中断**通知 |

| **Transit / AT Mobile / Auckland（间接，做"变更提示"参考）** | 可"Save stop" | 行程规划器遇改道/停运时，结果里出现**警示标 + 说明框**，并给**替代站点** | 规划器 / 站点页 | 有 | 规划器**自动计入**改道；停运路线做公告（如迪拜 E102 案例明确"**不要依赖旧截图，出行当天重新规划**"） |

### 5.2 提炼的共性（直接写进 §7 规格）

1. **两类收藏分开**：几乎所有产品都区分"收藏地点/地点对"与"收藏路线/行程"——与用户「两种都要」的判断一致。
2. **地点收藏的字段共性**：名称（可自定义/别名）+ 坐标 + 可选标签/分组。预设"家/公司" = 一个"地点对"的固定语义。
3. **路线收藏的字段共性**：**起终点（OD）+ 出行方式 + 路线方案要点**；百度额外含途经点。**关键：它们保存的是"OD + 方式/偏好"这类稳定信息，而不是"冻结的到达时刻"。**
4. **入口共性**：① 路线结果页（收藏方案）② 地点/结果详情（收藏地点/地点对）③ 独立的"收藏"tab/收藏夹（管理）。→ 与本项目 `/nav` 结果页 + 首页选定后 + 底部收藏 tab 完全对应。
5. **过期处理共性**：**主流做法是"点击时按当前时刻重新规划"，而不是展示冻结的旧结果**。遇到线路调整/改道：给**警示 + 说明 + 替代**，并建议用户重新规划（AT Mobile 的"粉色警示框"、迪拜 E102 的"重新规划"口径）。
6. **收藏线路的价值点**（Moovit）：收藏的不只是"路"，还有**实时到站/延误提醒**——但**推送/通知**依赖账号与后台，本 MVP 明确不做（见 §12）。

> 结论：本项目「地点对 + 方案快照」两类收藏的设计与主流一致；**唯一必须本土化处理的是"方案快照会过期"**——采用"**快照只存静态信息（线路/上下车站名），点击即按当次重新规划**"的策略（§7.6）。

## 6. 术语

| 术语 | 含义 |
|---|---|
| 地点对（Pair） | 一对起终点（如「家 → 澳科大」），不含具体走法 |
| 路线方案（Plan） | 一条**具体走法快照**（如「51 路 · 擎天匯 → 澳科大」，含上/下车站、换乘） |
| OD | Origin-Destination（起点-终点） |
| 方案指纹（fingerprint） | 用于判断"还是不是原来那条方案"的稳定字符串，见 §7.6.2 |
| 标定 | 用户选定目的地后，地图**居中并落一个目的地标记**的动作 |

## 7. 「路线收藏」功能规格（**重点**）

### 7.1 两类收藏定义

| 类型 | 语义 | 典型例子 | 点击后的默认行为 |
|---|---|---|---|
| **A. 地点对收藏**（pair） | 记住"从哪到哪" | 「擎天匯 → 澳科大」 | **带入搜索**：回到首页并预填起点/目的地，进入"可出发"态 |
| **B. 路线方案收藏**（plan） | 记住"具体怎么走" | 「51 路 · 擎天匯 → 澳科大」 | **重新校验并直达**：按当次重算该 OD，命中则直达详情，变化则提示并给最新结果 |

### 7.2 字段定义

#### 7.2.1 通用端点端点（复用 `NavPoint`）

| 字段 | 类型 | 说明 | 本地存储截断 |
|---|---|---|---|
| `label` | string | 展示名（站名保留繁体原文；巴士站带站号，如 `M1 關閘總站`） | ≤ 60 字符 |
| `lng` / `lat` | number | 坐标（**GCJ-02**） | 保留 6 位小数 |
| `kind` | `gps`\|`poi`\|`station`\|`place` | 端点类型 | 原样 |
| `code` | string? | 站码（巴士主码 / 轻轨 `LRT-*`） | ≤ 16 |

> 收藏里的 `gps` 端点：存的是**当次定位坐标快照**（如"家"附近），不随后续定位漂移而变——避免"收藏的家"每次指向不同坐标。文案上若来自定位，标注为「我的位置（保存于 X）」。

#### 7.2.2 A. 地点对收藏（`PairFavorite`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✓ | 本机唯一（`f_` + 随机） |
| `type` | `"pair"` | ✓ | 判别式 |
| `from` | NavPoint | ✓ | 起点端点 |
| `to` | NavPoint | ✓ | 目的地端点 |
| `name` | string? | — | 用户别名（默认自动生成 `起点label → 目的地label`），≤ 20 字符 |
| `createdAt` | number | ✓ | 创建时间（ms） |
| `lastUsedAt` | number? | — | 最近一次点击使用时间（排序用） |
| `useCount` | number | ✓ | 使用次数（可选展示） |
| `schemaVersion` | number | ✓ | =1（迁移用） |

#### 7.2.3 B. 路线方案收藏（`PlanFavorite`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✓ | `fp_` + 随机 |
| `type` | `"plan"` | ✓ | 判别式 |
| `from` / `to` | NavPoint | ✓ | 同 7.2.2 |
| `name` | string? | — | 用户别名（默认取 `summary` 或 `线路 · from → to`） |
| `summary` | string | ✓ | 快照摘要（如「51 路 · 擎天匯 → 澳科大」） |
| `fingerprint` | string | ✓ | 方案指纹（§7.6.2），校验用 |
| `rides` | PlanRideSnap[] | ✓ | 载具段快照：`{ route, kind: "bus"\|"lrt", board, alight, boardLabel, alightLabel }` |
| `transfers` | PlanTransferSnap[] | ✓ | 换乘快照：`{ atLabel, sameField }` |
| `walkOutMin` / `walkInMin` | number | ✓ | 首末段步行分钟（**快照值，展示时标注时间**） |
| `totalMinAtSave` | number | ✓ | 保存时的门到门分钟（**仅作参考，非权威**） |
| `crossBorder` | boolean | ✓ | 是否跨境（UI 标「不含通关」） |
| `origin` | `"amap"`\|`"local"` | ✓ | 来源（**UI 不暴露实现**，仅内部） |
| `savedAt` | number | ✓ | 保存时间（ms） |
| `lastValidatedAt` | number? | — | 最近一次校验时间 |
| `validity` | `"unverified"`\|`"valid"`\|`"changed"`\|`"unavailable"` | ✓ | 校验态（§7.6） |
| `schemaVersion` | number | ✓ | =1 |

> ❌ **不存**：实时到站文案、绝对到达时刻、`planId`。理由：这些是**易失值**，跨会话必然过期或失效（见 §5.2-3、§7.6）。

### 7.3 收藏卡片展示信息

**分组**：收藏页分两组，**"路线方案"在前、"地点对"在后**（方案信息量更大、更常点）。每组有组标题 + 计数。

| 卡片类型 | 主行 | 次行 | 辅助/角标 | 过期态 |
|---|---|---|---|---|
| **地点对** | `起点 → 目的地`（箭头分隔） | 端点类型徽章（公交站/轻轨站/地点/我的位置） | 「最近使用 X」「用 N 次」（可选） | — |
| **路线方案** | `name/summary` | **线路标签**（主题色，`.route-stack` 复用）+「约 X 分」（见下） | 「保存于 MM-DD」 | `changed`/`unavailable` → 卡片顶部细提示条 |

- 时长显示口径（**关键**）：方案卡上显示 **`约 totalMinAtSave 分`** 且必须**标注快照时间**（如「约 30 分 · 保存于 09-20」），**不得**显示为当前实时时长——避免误导。
- 过期提示条文案（简体）：
  - `changed`：「线路或时间可能有变化，点击将按最新情况重新规划」
  - `unavailable`：「该方案当前时段暂无可乘班次，点击查看最新路线」
- **交互元素**：卡片右侧「更多」按钮（竖直三点图标）→ 菜单：**重命名 / 取消收藏**。

### 7.4 收藏 / 取消收藏入口与交互

| # | 界面 | 收藏对象 | 操作元素 | 交互 |
|---|---|---|---|---|
| E1 | `/nav` 结果页 **每张方案卡** | 路线方案 | 卡片上的**书签形状线性图标**按钮 | 点击收藏；已收藏 → 图标变**实心书签**（选中态），再点取消 |
| E2 | `/nav/detail` 详情页顶部 | 路线方案 | 顶部「书签形状线性图标」 | 同上 |
| E3 | `/` 首页 · **选定目的地后**（已选目的地、尚未出发） | 地点对 | 目的地确认条上「收藏」按钮 | 点击保存「出发地(默认我的位置) → 目的地」为地点对；已存在则提示「已收藏」 |
| E4 | `/nav` 结果页**顶部 OD 栏** | 地点对 | OD 文本右侧「书签图标」 | 收藏当前 OD 为地点对 |
| E5 | 收藏页卡片 | 对应类型 | 「更多」菜单 → 取消收藏 | 二次确认（移动端可左滑删除，MVP 以菜单为准） |

**通用反馈**：
- 收藏成功 → 轻量提示（Toast/行内）「已收藏」；图标切选中态。**不弹模态**。
- 取消收藏 → 「已取消收藏」（可撤销，Undo 保留 3 秒；无 Undo 则二次确认）。
- 重复收藏同一对象 → 去重（按 §7.6.2 指纹 / 端点 + 类型）；提示「已在收藏中」。
- **不做** emoji、**不做**紫色→粉色渐变按钮；图标统一为**线性 SVG 图标**（选中态实心），具体图标库由架构师按项目选型锁定。

### 7.5 点击收藏项的行为

| 类型 | 行为 |
|---|---|
| **地点对** | 跳回首页并**预填起点/目的地**，进入"**可出发**"态（不自动跳结果页，让用户确认后点「出发」）。可选：首页顶部出现半透明「已带入收藏：家 → 澳科大」提示条。 |
| **路线方案** | ① 以该 `from/to` **按当前时刻重新调用 `/api/nav`**（重算）；② 在返回卡中按 `fingerprint` 匹配：命中 → 直接跳 `/nav/detail`（并高亮/定位原方案）；未命中 → 跳 `/nav` 并顶部提示「原方案已变化，已为你重新规划」；③ 重算失败/无网络 → 提示「暂时无法校验，可先查看收藏快照」并提供「查看快照」入口（只读展示 7.2.3 静态字段）。 |

### 7.6 "路线方案可能过期"处理策略（**核心**）

**7.6.1 触发时机（不后台轮询，省 DSAT 配额）**
- 进入收藏页时：**不**批量重算；仅对**可见的**方案卡按需校验（懒校验），或以「上次校验时间 > 阈值（建议 12 小时）」才触发。
- 点击方案收藏时：**总是**按当前时刻重算（§7.5）。
- 不做 Service Worker 后台轮询、不做推送（§12）。

**7.6.2 方案指纹（fingerprint）**

```
fingerprint = rides.map(r => `${r.route}@${r.board}->${r.alight}`).join("|")
```

- 与既有 `OptionSeed.key`（`route@board→alight` 链）**同构**，天然稳定。
- 校验 = 用该 OD 重新 `/api/nav`，若返回卡中存在**指纹相等或前缀包含**的卡 → `valid`；否则 `changed`。
- 校验失败（超时/无网/该 OD 无任何路线）→ `unavailable`。

**7.6.3 状态与文案**

| validity | 含义 | 卡片表现 | 点击后 |
|---|---|---|---|
| `unverified` | 从未校验 / 超过阈值未校验 | 正常展示 + 「点击校验」 | 按 §7.5 重算 |
| `valid` | 指纹命中 | 正常展示 | 直达详情 |
| `changed` | 线路/时刻变化，指纹未命中 | 顶部细提示条 | 重算 → 提示已重新规划 |
| `unavailable` | 当前时段无可乘班次 / 重算失败 | 灰化 + 提示条 | 重算，或查看只读快照 |

**7.6.4 明确决策**
- ✅ **重算**：方案收藏点击一律按**当次**重算，快照**不作为时长权威**。
- ✅ **快照只存静态信息**（线路、上/下车站名、换乘站），**不存**绝对时刻与实时文案。
- ❌ **不做**"方案冻结/固定到某班次"（与产品既有「不显示带估算等车时间的替代结果」口径冲突）。
- 卡片上任何时长**必须**带「保存于」时间戳，避免用户误读为实时。

### 7.7 空状态设计

| 场景 | 展示 |
|---|---|
| 收藏页**完全为空**（首次进入） | 居中：**书签形状线性图标**（大号、低饱和）+ 主文案「还没有收藏路线」+ 说明「在路线结果页点书签图标收藏方案；或在首页选定目的地后保存常用路线」+ 主按钮「去规划路线」→ `/` |
| 仅某一组为空 | 该组内行内空态：「暂无收藏的路线方案 / 暂无收藏的地点对」 |
| localStorage 不可用（隐私模式） | 收藏功能**降级为只读禁用**：收藏按钮置灰 + 行内提示「当前浏览器不支持本地收藏」；**不阻塞**导航主流程 |

> 文案要求：具体、可操作，**禁止**「Welcome to」「暂无数据」这类空洞占位。

### 7.8 存储与数据迁移

- **存储位置**：`localStorage`，键 **`must.favorites`**，值为 `{ schemaVersion: 1, pairs: PairFavorite[], plans: PlanFavorite[] }` 的 JSON。
- **沿用既有范式**（`must.zone` / `must.consent`）；**读改共用** `useFavorites()` 封装 + 自定义事件订阅（与 `dev-mode.ts` 同一套模式）。
- **隐私模式容错**：`localStorage` 抛错 → 返回空集合、只读，不崩溃。
- **迁移**：`schemaVersion` 不匹配 → 尝试向下兼容读取；无法兼容则忽略旧数据（不删），并在控制台留痕。
- **体量上限**：方案收藏建议上限 **50 条**、地点对 **50 条**；超出时提示「收藏已达上限，请先清理」。

### 7.9 与既有约束的关系（回传给架构/前端的前置结论）

- 收藏的端点**允许**写入 localStorage（收藏 = 用户显式意图），**不违反** R5「起点不记忆」——R5 针对的是"自动记住上次起点"，二者语义不同。**建议架构师在技术方案中显式确认该边界。**
- `planId` 不参与持久化（见 §1 警告）。

## 8. 首页新交互流程状态机（c）

### 8.1 状态定义

```
S0 目的地未选
  │  选目的地（搜索命中 / 地图点选）
  ▼
S1 已选目的地（地图标定）
  │  选择出发地（默认「我的位置」，可改）
  ▼
S2 已选出发地（= 可出发）
  │  点「出发」
  ▼
S3 跳转 /nav
```

### 8.2 逐步规格

| 状态 | 界面元素 | 可操作性 | 回退路径 | 下一状态 |
|---|---|---|---|---|
| **S0 目的地未选** | 全屏地图；**顶部**固定「目的地」搜索框（**仅此一个输入框**）；底部导航 | 输入/搜索目的地；点地图 POI；拖动地图 | — | → S1 |
| **S1 已选目的地（标定）** | 地图**居中到目的地并落目的地标记**（红色水滴标记，沿用 `.nav-map__destpin` 语义）；目的地确认条（站名/类型徽章 + 「换目的地」+ 「收藏」）；**此时出现"出发地"选择行**（默认「我的位置」） | 换目的地；清空；选择/修改出发地；收藏地点对（E3） | 「换目的地」→ 回 S0；「清空」→ S0 | → S2 |
| **S2 已选出发地（可出发）** | 「出发」主按钮**启用**；出发地行显示已选值 | 修改出发地；修改目的地；**出发** | 修改目的地 → S1；修改出发地 → 仍在 S2 | → S3（点击出发） |
| **S3 跳转** | 短暂「正在规划…」态（沿用 `picking` 文案） | —（防连点） | 浏览器返回 → 回 S2（保留选择） | — |

### 8.3 关键规则
- **"地图标定"是 S1 的进入标志**：选完目的地必须**居中 + 落点**，给用户"我已确认目的地位置"的反馈（R2 的核心体验点）。
- **目的地可来自地图点选**：点地图上的站点/POI 直接进入 S1（复用 `StationCard` 的「设为目的地」）。
- **出发地默认「我的位置」**：定位失败 → 提示「无法定位 · 请手动选择出发点」（沿用现有文案），此时 S2 的「出发」保持禁用直到选定出发地。
- **回退不丢数据**：S2 返回时保留已选内容（仅当次会话内，不落 localStorage —— 与 R5 一致）。
- **单输入框**：S0 首页**只有目的地框**；起点框在 S1 之后才出现（"弹出起终点选择"即此展开）。

## 9. 底部导航规格（d）

### 9.1 结构

- **位置**：屏幕底部，安全区（`env(safe-area-inset-bottom)`）自适应，常驻于**主页面**。
- **两个 Tab**：

| Tab | 文案 | 图标（**文字描述，禁用 emoji**） | 跳转 | 选中态 |
|---|---|---|---|---|
| 1 | **首页** | **房子形状的线性图标** | `/` | **实心房子图标** + 主色 + 文字加粗 |
| 2 | **路线收藏** | **书签形状的线性图标** | `/favorites`（新建页） | **实心书签图标** + 主色 + 文字加粗 |

- **图标语义说明**：收藏统一用「**书签**」隐喻（与卡片内收藏按钮同源，保持一致），**不使用星形**（避免与"评分/点赞"混淆）。
- **选中态判定**：按当前路由；`/` → 首页高亮；`/favorites` → 收藏高亮；其余页面按"归属"（如 `/nav` 归属首页）高亮。
- **未选中态**：线性图标 + `on-surface-var` 色。

### 9.2 覆盖页面（全站）

| 页面 | 底部导航 | 理由 |
|---|---|---|
| `/` 首页 | ✅ 显示 | 主 tab |
| `/favorites` 收藏 | ✅ 显示 | 主 tab |
| `/about` 关于 | ✅ 显示 | 二级信息页，保留全局导航 |
| `/nav` 结果页 | ⚠️ **不显示**（待决，§13） | 沉浸式结果，顶部已有「← 返回」；避免返回与切 tab 冲突 |
| `/nav/detail` 详情 | ⚠️ 不显示 | 同上 |
| `/commute`、`/timer`、`/records`、`/free` 等 | ❌ 不显示 | 旧版/工具页，非本次主流程 |

### 9.3 旧版计时入口移位（R3）
- 首页顶部「通勤计时（旧版）›」入口**移除**，该位置由底部导航取代。
- 旧版计时（`/commute`）**保留不改**；新入口置于 **`/about`** 页新增「旧版功能」区块 → 链接 `/commute`。
- （可选）开发者模式下，首页开发者入口区保留 `/commute` 直达（待决，§13）。

## 10. 验收标准（EARS 格式 · 每条可测试）

> EARS 句式：Ubiquitous「系统必须…」；Event「当…，系统必须…」；State「在…期间，系统必须…」；Unwanted「若…，系统必须…」。

### 10.1 R1 全屏地图
- AC-1.1（State）：**在首页加载完成期间**，系统必须让地图铺满可视区域（移动端：宽度=视口宽、内容随安全区布局；桌面端：地图占据主内容区，无两侧留白柱）。
- AC-1.2（Event）：**当**地图脚本懒加载或加载失败时，系统必须展示占位并在**不阻塞**搜索与「出发」的前提下提供重试（继承现有 §Q7 行为）。

### 10.2 R2 目的地优先 + 置顶
- AC-2.1（State）：**在首页初始状态（S0）期间**，系统必须**只**展示一个目的地输入框，并固定于**顶部安全区**；不得展示起点框。
- AC-2.2（Event）：**当**用户选定目的地，系统必须将地图**居中到该目的地并落下目的地标记**，随后展示出发地选择（S1）。
- AC-2.3（Event）：**当**用户选定出发地后，系统必须启用「出发」按钮（S2）；点击后跳转 `/nav`。
- AC-2.4（Event）：**当**用户在 S1/S2 点「换目的地」，系统必须回到可选择目的地的状态且不丢失已选出发地以外的数据。

### 10.3 R3 底部导航 + 收藏
- AC-3.1（Ubiquitous）：系统必须提供含「首页」「路线收藏」两个 Tab 的底部导航。
- AC-3.2（Event）：**当**用户点击「路线收藏」，系统必须跳转 `/favorites` 并高亮该 Tab。
- AC-3.3（Event）：**当**用户在 `/nav` 结果页点某方案卡的书签图标，系统必须将该方案（含指纹）写入本机收藏，并使图标切换为选中态。
- AC-3.4（Event）：**当**用户点击「地点对」收藏，系统必须回到首页并预填起终点、进入可出发态。
- AC-3.5（Event）：**当**用户点击「方案」收藏，系统必须按当前时刻重算该 OD；命中则直达 `/nav/detail`，未命中则提示「已重新规划」并展示最新列表。
- AC-3.6（Unwanted）：**若**收藏的方案在当前时刻无法复现（`changed`/`unavailable`），系统必须给出**明确提示**且**不得**把快照时长当作实时时长展示。
- AC-3.7（Unwanted）：**若** `localStorage` 不可用，系统必须将收藏降级为只读且**不阻塞**导航主流程。
- AC-3.8（Event）：**当**用户进入收藏页而本机无任何收藏，系统必须展示空状态与「去规划路线」引导。
- AC-3.9（Ubiquitous）：旧版计时功能必须仍可通过 `/about` 的入口访问（`/commute` 返回 200）。

### 10.4 R4 品牌更名
- AC-4.1（Ubiquitous）：系统界面品牌名必须为「M Map」；首页**不得**再出现旧大标题「澳门出行」。
- AC-4.2（Event）：**当**页面 `<title>` / PWA 清单渲染，系统必须使用「M Map」（含 `manifest` 与 metadata）。

### 10.5 R5 澳门范围
- AC-5.1（State）：**在地图加载完成期间**，系统必须将可视范围限制在澳门特别行政区范围内（实现方式由架构师定；PM 验收"用户无法把视角滑出到无意义外地"）。
- AC-5.2（Unwanted）：**若**用户尝试缩放到超出澳门范围，系统必须限制/回弹视角。

### 10.6 R6 去 AI 化（可测试的约束项）
- AC-6.1（Ubiquitous）：界面**不得**使用 emoji 作为功能图标；功能图标统一为线性 SVG 图标（选中态实心）。
- AC-6.2（Ubiquitous）：界面**不得**出现紫色→粉色渐变方案。
- AC-6.3（Ubiquitous）：界面**不得**出现「Welcome to」「Lorem ipsum」「暂无数据」等空洞占位文案；空态文案须具体、可操作。
- AC-6.4（State）：**在浅色主题下**，正文对比度必须 ≥ 4.5:1（沿用既有验收口径）。

## 12. 明确不做（Out-of-Scope）

| 不做项 | 原因 | 何时再考虑 |
|---|---|---|
| **收藏云同步 / 多设备** | 当前**无账号体系**，收藏存本机（localStorage） | 引入账号体系后作为首批功能；届时见 §7.8 迁移 |
| **深色模式（精修/重排）** | 本次聚焦浅色下的**结构 + 交互 + 视觉方向**改造；深色整体重排会显著扩大范围 | 视觉体系（去 AI 化）定稿后统一适配；当前保留既有 `prefers-color-scheme` 双主题**不改** |
| 收藏**分组/文件夹/标签** | 竞品有（百度分组、Google lists），但本 MVP 收藏量级小（≤ 50 条/类） | 收藏量上升或用户明确要求后 |
| 收藏**导出/分享** | 无账号、无分享目标场景 | 与账号/分享能力一起做 |
| 到站/延误**推送提醒** | 需账号 + 后台 + 通知权限，且 DSAT 配额受限 | 有账号与配额评估后（Moovit 类能力） |
| **方案冻结到指定班次** | 与既有「不显示带估算等车时间的替代结果」口径冲突 | 不计划 |
| 多语言 i18n | 当前仅中文用户 | 若有非中文用户 |
| 桌面端**专用布局** | 本次仅要求"可用且地图铺满"，不专门优化 | 桌面使用占比上升后 |

## 13. 待决点（需 team-lead / 架构师 / 设计师确认）

1. **底部导航在 `/nav`、`/nav/detail` 是否显示**（§9.2）——与"沉浸式结果 + 顶部返回"可能冲突，建议**不显示**，请架构师确认。
2. **地点对是否记录座区（zone）**——澳科大方向受座区影响。建议**不存**（座区走全局 `must.zone`），避免同一地点对出现两套步行口径。
3. **`gps` 端点收藏的坐标语义**——建议存当次坐标快照（§7.2.1），请产品确认文案「我的位置（保存于 X）」。
4. **收藏上限**（建议 50/类，§7.8）与**懒校验阈值**（建议 12 小时，§7.6.1）——请架构师按 DSAT 配额给最终值。
5. **`/favorites` 路由命名**——与既有 `/routes`（旧功能）区分，建议 `/favorites`。
