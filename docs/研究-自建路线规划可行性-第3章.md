## 3.2 ★ 覆盖口径之争：3.8% 与 89.0% 各自是什么

这是本章最容易被误读的一节，必须把两个口径写在同一次陈述里，否则全篇可信度会被连带质疑。

| 项 | 旧口径（每线 × 邻接对） | QA 复核口径（物理有向邻接对） |
|---|---|---|
| 分子 | 105 个站对（重算前线上 `segment_stats`） | **886 个物理有向邻接对** |
| 分母 | **~2,750**（`route_stations` 展成「线路×邻接」的行，同一物理段被多条线重复计数） | **996**（主码归一后去重的物理有向邻接对） |
| 结果 | **105 / 2,750 = 3.8%**（`数据盘点-有什么缺什么-20260918.md:59` 记 3.9%，分母取 ~2,660） | **886 / 996 = 89.0%**（`审查-全澳导航方案-批判性-20260918.md:29`） |
| 本章复核 | —— | **88.96%**，与 89.0% 一致【实测】探针 §3 |

**差异来源**：不是谁算错，而是**分子分母两处口径都不同**。① 分母：旧口径把「A 段被 25、25AX、26 三条线共用」记 3 次，新口径只记 1 次；② 分子：旧口径逐条清点，新口径按物理段归并。

**各自适用范围**：旧口径回答「**每条线自身样本够不够**」——运维采集进度视角；新口径回答「**该物理段有没有可复用实测样本**」——取数视角。

**本报告采用新口径（89.0%）**，理由有二：① 线上取数函数本身要求按「邻接站对」评估并**跨线共享**（`审查-全澳导航方案-批判性-20260918.md:29` 引 `segment-lookup.ts:8-14` 明文要求）；② 若沿用旧口径，会得出「全澳大部分车程必须估算」的错误前提，从而在「DSAT 实测」与「站均估算」之外再插入第三个「高德路网时长」口径，破坏单一口径不变量。

**★ 第二处同类陷阱**：`station_amap_map` 的 93.2% 同样**口径依赖**——主码归一后按行算 93.3%、按站点行 93.6%；**不归一则仅 360/610 = 59.0%**【实测】。⇒ 本章所有覆盖率数字**必须带口径**。

**★ 第三处口径差（行级 vs 物理段级）**：`segment_stats` **行级** `samples ≥ 30` 的仅 **1,590 / 24,161 = 6.6%**（中位 `samples = 3`）；**物理段级**聚合后才是 **819 / 886 = 92.4%**。⇒「92% n≥30」说的是后者，**不能拿它去说行级**：车程数据「够用」靠**跨行聚合**，不是单行厚实。

## 3.6 结论性判断：差异化在数据层，不在算法层

**图（996 段）与车程（886 段有实测）是齐的，算法层的「换乘≤2 有界 BFS」只是 RAPTOR 的退化雏形、可升级；真正稀缺的是数据层三样**——

- **`T_ours` 可解释性**：每一跳能追到 `segment_stats` 的具体行（线路 × 周几 × 时段桶 × `arrive_kind`），外部引擎给不出；
- **逐跳实测来源**：181,713 段样本 + 60,544 行原始样本，两条采集链**无系统性偏差**（比值中位 0.989）；
- **澳门本地细节**：穿梭巴士过滤、轻轨在建站桥接、`lrt_timetables` 时刻表——高德/谷歌都不会替我们做的脏活。

反过来：**算法替换（BFS → RAPTOR）不解决任何数据缺口；几何层缺口靠换算法也补不上。**

## 本章结论

1. **资产是「结构齐、车程密、几何空」的三段式**：图 2,870 行 / 95 线 / 119 方向 / 610 站**无缺口**（seq 零断裂），`segment_stats` 181,713 样本覆盖 996 个物理有向邻接对中的 886 个；而**步行几何、票价、无障碍三项结构性缺失**（票价/无障碍为全库零表零列）。★ 换乘关系**已移出「结构缺失」档**（见第 4 条）。
2. **覆盖率必须双口径并列陈述，本报告采用 89.0%**：旧口径 105/2,750 = 3.8%（每线×邻接对）与 QA 口径 886/996 = 89.0%（物理有向邻接对）分子分母定义均不同；采用后者的理由是它与 `lookupHop` 的 L4 跨线共享取数语义一致。**同一陷阱在 `station_amap_map` 上重现**（主码归一 93.3% vs 原始码 59.0%）。
3. **「92% 样本 n≥30」是物理段级口径，行级只有 6.6%（1,590/24,161，中位 `samples=3`）**：车程数据「够用」靠的是跨行聚合，不是单行厚实——这直接决定了第 4 章算力与预计算量的估算基线。
4. **最薄弱两环 = 【跨主码换乘不建模】+ 无 ground truth**：澳门换乘以「同主码站群」为主流（86.1% 主码多线共用，站内跨度中位 33 m），`transfer_walks` 2 条是**设计收窄**而非缺口；真问题是本地 BFS 不建模跨主码换乘（量级**样本依赖**：独立复核 22.5% / 首轮 5.6%）+ 换乘段**已事实依赖高德**。无真值 ⇒ 一切「更准」主张只能靠代理指标（档 3 平均绝对偏差 0.58 分、双来源比值中位 0.989）。★ **漏线率 57%/41%/26.4% 是第三短板，根因是「候选数上限截断（cap）」（生产口径 59.6%）而非初稿所写的「K 太小」（21.3%）**。
5. **差异化落在数据层**：可解释的 `T_ours`、逐跳实测来源、澳门本地细节（穿梭巴士过滤 / 桥接站码 / 轻轨时刻表）是本项目真正的护城河；⇒ 第 4 章三层判定的预判方向：**时间计算与排序层无需再自建，几何层补不上，候选寻路层才是最有增量的那一层**。
