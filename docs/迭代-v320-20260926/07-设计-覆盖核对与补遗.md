## 2. 补遗 1 · P4 红钉 × 蓝点「起点 = 我的位置」组合形态（AC-76 细化）

> 背景：AC-76 要求「**起点为「我的位置」（未显式选择）**或显式选点，地图**必须**显示起点红钉」。
> 即：**当 origin = 我的位置时，红钉（z110）与蓝点（z128）会落在同一坐标** —— 03 §8 只给了单钉规格，未定义二者共存的叠放关系。本节补齐。

### 2.1 几何事实（现有实现量测）

| 元素 | 尺寸 / 锚点 | 相对坐标点 `P` 的竖向范围 |
|---|---|---|
| **红钉** `pin-origin.svg` | 20×26（`--destpin-w/h`）；`offset(-10,-26)` ⇒ **钉尖 = P** | `P.y − 26` … `P.y`（钉身向上） |
| 蓝点核心 `--you-dot-w` | 12px + 2.5px `--surface` 白描边（`anchor: center`） | `P.y − 8.5` … `P.y + 8.5` |
| 蓝点静态光圈 `--you-ring-0` | 4px（`box-shadow`，**不占布局**） | `P.y − 10` … `P.y + 10` |
| 蓝点 ping 扩散层 | 12px × `scale(2.2)` ≈ 26.4px（**动态**，`opacity ≤0.45`） | 峰值 `P.y − 13.2` … `P.y + 13.2` |

**结论（客观）**：两标记**竖向天然分离**——钉身占据 `P` 上方 26px，蓝点仅占 `P` 上下约 ±10px（ping 峰值 ±13.2px）。
⇒ 真正的重叠只有 **`P.y − 13.2` … `P.y`（约 13px）**，落在红钉的**钉尖→钉头下缘**区段；**钉头圆身（`P.y−20.1` … `P.y−8.3`）大体可见**。

### 2.2 组合形态规格（◆ 生效）

**定案：「钉立于点上」（pin stands on the dot）—— 蓝点 = 红钉的基座，不位移、不隐藏、不改色。**

```
        ╭───╮        ← 红钉钉头（≈ P.y−20 … P.y−8，完全可见）
        │ ● │           （钉头白点圆心 ≈ P.y−14.2）
         ╲ ╱
          ▽          ← 红钉钉尖 = 坐标点 P  ← 两者同心于此
        ╭───╮
        │ ● │        ← 蓝点核心（12px，圆心 = P；2.5px 白描边防混色）
        ╰───╯           ping 水波在 P 周围 ±13.2px 扩散（半透明）
```

| 决策项 | 规格 | 理由 |
|---|---|---|
| 是否隐藏红钉 | **不隐藏**（AC-76 硬要求） | 起点语义必须可见 |
| 是否移动蓝点 | **不移动**（圆心恒为真实坐标 P） | 定位真实性优先；挪到钉头 ≈ 偏 14px（zoom16 下 ≈ 15m）不可接受 |
| 层叠（谁在上） | **蓝点 z128 > 绿钉 z120 > 红钉 z110**（现状不变） | 「我在这里」永不被覆盖（定位优先） |
| 红钉是否抬高 z | **否**（保持 110） | 抬高会盖住蓝点 ⇒ 失去「我在哪」 |
| 红钉是否加脉动 | **否**（不加任何动画） | 避免与蓝点 ping 争注意力；脉动唯一顶点 = 「到站」 |
| 红钉/绿钉 是否随主题 | 否（固定色） | 钉画在地图，底图不随主题（03 §8.1） |

**可读性三重保障（缺一不可）**
1. 蓝点核心带 **2.5px `--surface` 白描边** ⇒ 压在红钉身上仍有清晰边界；
2. 红钉带 **2px 白外圈 + `drop-shadow(--destpin-shadow)`** ⇒ 从蓝点/底图"拔"出；
3. ping 峰值 `opacity ≤ 0.45` + 红钉白外圈 ⇒ 半透明水波扫过钉身不糊掉钉形。

### 2.3 分场景规则表（◆ 交前端/QA）

| 场景 | 红钉（起点） | 绿钉（终点） | 蓝点 | 说明 |
|---|---|---|---|---|
| **起点 = 我的位置**（未显式选点，AC-76 新增场景） | 显示 · z110 · 钉尖锚 P | 显示 · z120（终点在别处） | 显示 · z128 · 圆心 = P（钉的基座） | 「钉立于点上」；两标记竖向分离，钉头可见 |
| 起点 = 显式选点（远端） | 显示（在选点处） | 显示 | 显示（在真实位置） | 三标记通常互不重叠 |
| 终点 = 我的位置（罕见） | 显示 | 显示 · z120 · 圆心 = P | 显示 · z128 · 圆心 = P | 同构：蓝点压在**绿**钉脚（层叠不变） |
| 起点 = 终点 = 我的位置（退化） | 显示 · z110 | 显示 · z120（压住红钉） | 显示 · z128（最上） | 层叠 = 蓝 > 绿 > 红；红钉被压（可接受，起点=终点本身是退化行程） |
| **未获定位**（拒权/失败，AC-75） | 「我的位置」不可解析 ⇒ **无 origin ⇒ 不画红钉**（页面不空白、搜索照常） | 按已选点显示 | **不显示** | AC-75：蓝点不显示即可，其余功能不变 |
| 之后**获得定位**（用户开启权限） | origin=我的位置 ⇒ **红钉出现**（钉立于点上） | — | 出现 | 全程保活（03 §8.4） |

### 2.4 可选精修（advisory · 默认不做）

- 若真机观感「钉与点挤」，可给红钉在 **`origin === 我的位置`** 时施加 `opacity: .96` 或不加改动 —— **默认不加**（保持与显式选点完全一致，避免引入第二形态）。
- [否] **禁止**：为避重叠而给红钉加「向上偏移」的 CSS `transform`（会与 marker 的 `offset` 双重偏移 ⇒ 钉尖脱离坐标，03 §8.1 已记该坑）。

### 2.5 自检

- [ ] 起点选「我的位置」⇒ 红钉出现在蓝点正上方、钉尖与蓝点圆心重合；钉头圆身完整可见。
- [ ] 蓝点 ping 扩散扫过钉身时，钉形不糊、白点不与蓝点混淆（两者皆有白边/白点，需真机确认可辨）。
- [ ] 起点改显式选点 ⇒ 红钉移动到选点处，蓝点留在真实位置，无残留。
- [ ] 拒权 ⇒ 无红钉无蓝点，地图可用（AC-75）。

## 3. 补遗 2 · 导航模式「顶部组合」层叠全景（AC-82）

> 背景：AC-82「横幅显示中，左上/右上按钮与地图关键信息**必须不被遮挡**」。
> 03 §2.2 只给了 `top: calc(safe-top + 8px)` —— 本节省级核对发现 **tight case 会重叠面板头部**，给出修正公式与全景层叠表。

### 3.1 层叠上下文事实（先厘清，避免误判）

```
`.nav-shell--full .nav-map-wrap { position: fixed; …; z-index: 0 }`   ← z-index:0 ⇒ **形成层叠上下文**
⇒ 地图与其内全部 AMap marker（站点 90/95 · pin 110/120 · 蓝点 128 · 车辆 130）
   **被封在 z0 这一个单元内**，只彼此比较，**整体**参与根层叠。
```

⇒ 因此这些「上百的 z」**不会**压住 z24/z70/z90/z94 的页面浮层（这是 AC-13 层叠上下文教训的又一体现）。

### 3.2 层叠全景（导航模式 · riding · 自下而上）

| # | 层 | z-index | 定位 | 在导航态的内容 | 备注 |
|---|---|---|---|---|---|
| 0 | `.nav-map-wrap`（**含全部地图 marker**） | **0**（上下文） | fixed | 底图 + 站点(90/95) + 红钉(110) + 绿钉(120) + 蓝点(128) + 车辆(130) | 内部 z 只在单元内比较 |
| 1 | `.bottom-nav`（底导） | 30（既有） | fixed 底 | **riding 隐藏**（`body[data-nav="riding"]`） | AC-83/10 语境 |
| 2 | `.nav-brandbar`（品牌栏） | **20** | fixed 底 | 导航态右列隐藏（AC-84）⇒ 实际仅剩中列（换向+线路标签） | 底部，与顶部无关 |
| 3 | `.nav-locate-fab`（定位浮动） | **24** | fixed（`bottom` 公式） | 定位图标（唯一右侧控件，AC-85） | **上沿恒在面板顶边上方 12px** |
| 4 | `.route-sheet`（面板） | **70** | fixed，`translateY(--sheet-y-anim)` | 头部（左上双态 + 右上刷新）· 内容（推荐/详情）· 面板内 toast/瞬态（`--alarm-z 15`，在 pane 内） | 面板内层不影响外部 z |
| 5 | `.nav-card-overlay`（车卡/站卡浮层） | **90** | fixed 底 | 点站/车弹出的信息卡 | 底部锚定，与顶部横幅不冲突 |
| 6 | **`.nav-alarm--top`（下车横幅）** | **94** | fixed 顶 | soon / now（含 `navAlarmPulse 1.2s`） | **最上层**（安全级） |

**遮挡关系结论**：
- 横幅(94) 在**最上** ⇒ 永不被面板/车卡遮（AC-81）[通过]
- FAB(24) < 面板(70)：**同屏**时面板在其**下方**（FAB 在面板顶边上方 12px）⇒ 不遮挡 [通过]（AC-85）
- 车卡(90) < 横幅(94) 但**分居底/顶** ⇒ 互不遮挡 [通过]
- 地图 marker 被 `z0` 封住 ⇒ 只能在**无浮层覆盖的地图区**可见（这是既有设计，非本批回归）[通过]

### 3.3 [注意] 发现的 tight case：03 §2.2 的简单 `top` 会在带刘海机型 × full 档**贴到面板头部**

**量化**（横幅高 **定为精确 `H = 44px`**；面板 full 顶边 `T_full = clamp(max(safe-top + 44, 12vh), 96, 128)`）：

| 设备（safe-top） | 横幅底边（**朴素公式** `safe-top+8+H`） | `T_full` | 结果 |
|---|---|---|---|
| Android 无刘海（0） | 0+8+44 = **52** | `clamp(max(44,101),96,128)` = 101 | 无重叠 [通过] |
| Android 小刘海（24，844 高） | 24+8+44 = **76** | `max(68,101)`=101 | 无重叠 [通过] |
| iPhone 刘海（47，844 高） | 47+8+44 = **99** | `max(91,101)`=101 | 无重叠（余 2px）[注意] 临界 |
| **iPhone 灵动岛（59，844 高）** | 59+8+44 = **111** | `max(103,101)`=**103** | **重叠 8px** [否] |

重叠 8px 时：横幅会压住面板**抓手（grip）与顶部圆角**；且面板头部按钮的 `padding-top` 恰为 8px ⇒ 横幅底边**正好压在按钮命中区上沿**（矮屏/横屏更糟）⇒ **AC-82 存在失效风险**。

### 3.4 修正规格（◆ 生效，保证 AC-82 · 建议同步订正 03 §2.2）

**思路**：横幅的 `top` 取「理想位（安全区下 8px）」与「兜底位（不越过面板 full 顶边）」的**较小值**，再与安全区取**较大值**。**不做**「横幅出现时推面板」（会布局抖动，瞬态告警里最忌）。

```css
.nav-alarm--top {
  --topbanner-h: 44px;      /* ◆ 横幅**精确**高：padding 12×2 + 内容 20（图标 20 / 行高 1.2×13≈15.6）＝ 44 */
  --topbanner-gap: 8px;     /* 与安全区 / 与面板头部的呼吸 */
  position: fixed;
  left: var(--space-4);
  right: var(--space-4);
  min-height: var(--topbanner-h);          /* ◆ 让实际高度 == 预留高度（公式依赖它） */
  line-height: 1.2;                        /* ◆ 锁定行高 ⇒ 单行高度恰 44px（否则随默认 1.55 浮动） */
  /* ① 不侵入安全区；② 理想落位 = 安全区下 8px；③ 兜底 = 不越过面板 full 顶边（留 2px） */
  top: max(
    var(--safe-top),
    min(
      calc(var(--safe-top) + var(--topbanner-gap)),
      calc(var(--sheet-top-full) - var(--topbanner-h) - 2px)
    )
  );
  z-index: 94;
  pointer-events: none;
  animation: navAlarmInDown var(--dur-base) var(--ease-standard);
}
```

**安全证明（对全部机型严格成立，0 重叠）**：
```
令 H = 44px（由 min-height + line-height:1.2 锁定）。

① 当 min( ) 命中 ②/③ ⇒ 横幅底边 = top + H ≤ (T_full − H − 2) + H = T_full − 2   ⇒ 净空 ≥ 2px
② 当 max( ) 被 --safe-top 抬回（极端窄高比）⇒ 底边 = safeTop + H = safeTop + 44
   而 --sheet-top-full 的内层 max 保证 T_full ≥ safeTop + 44（clamp 的 96 / 128 边界只会把它抬高）
   ⇒ 底边 ≤ T_full                                                      ⇒ 0 重叠

面板**任意档位**顶边 T ≥ T_full（full 是最**上**档）  ⇒  横幅底边 ≤ T − 2 或 = T（零重叠）
面板头部按钮自 T + 8 起（.route-sheet__bar padding-top 8px） ⇒ 按钮上方净空 ≥ 8px  ⇒ AC-82 恒成立 [通过]
且 top ≥ safeTop ⇒ 永不侵入安全区（不压状态栏 / 灵动岛）[通过]
```

- **H 必须精确**：若未来横幅改为两行或多行（如新增副标题），**必须同步上调 `--topbanner-h` 与 `min-height`**，否则证明失效（禁止「内容撑高而变量不变」）。
- **窄屏/横屏**：极端情形下横幅会「顶贴安全区、底恰触面板顶」（净空 0），仍**不压按钮**（≥8px）。
- **不动画**：仅 `navAlarmInDown`（下滑 8px + 淡入 200ms）；`prefers-reduced-motion` 下只留淡入。
- **无布局位移**：横幅出/隐**不改变**面板与 FAB 的任何几何（`--sheet-top-*` 不改）。

## 4. 补遗 3 · 需求 6「0ms 瞬移 vs 150ms 过渡」真机判定标准（AC-78）

> AC-78 原文：「纵轴用户点**必须**瞬移（**≤150ms 过渡，真机二选一**）至该段两站正中间；且必须驻留…」
> 03 §4.3 已给两候选值（`--you-jump-dur` 默认 `0ms` / 建议 `150ms`）。本节给出**真机二选一的判定标准**，供 QA 现场裁定（本批留真机裁决，不预设）。

### 4.1 两候选

| 候选 | `--you-jump-dur` | 观感 | 依据 |
|---|---|---|---|
| **A · 瞬移** | `0ms`（无过渡） | 点「啪」地出现在中点 | 严格照用户原话「瞬移」（AC-78 首选） |
| **B · 微滑** | `150ms` + `--ease-standard` | 点「咻」地切到中点（快到近乎瞬时） | 项目动效收敛值；避免硬切 |

### 4.2 判定标准（QA 真机逐条走）

> 环境：Android 真机（第一验收环境）+ 一次完整乘车（至少含 2 次离站）。

| # | 观测 | 判 A（0ms）通过 | 判 B（150ms）通过 |
|---|---|---|---|
| J1 | 点从**站节点 → 中点**的切换 | 无「闪一下/跳帧感」；不误认为**到站**（不误触 1.2s 到站脉动的语义） | 过渡**可感知为位移**而非瞬变（能看出「点从节点滑到中点」） |
| J2 | 切换**期间**是否与站点节点重叠 | —（瞬时；除起止点外无中间帧） | **任一帧**均不与**两端节点圆**重叠（点始终在两站之间） |
| J3 | 与「停靠中」标签更新的**时序** | 点到位与标签更新**同帧**（无「先动后变」的错位） | 动效须在标签更新**之前**完成（不出现「点还在滑、文字已变」） |
| J4 | 到站（中点 → 节点） | 由 `is-at` 节点态接管（浮标卸载），无「滑入节点」 | 同左（本项两候选一致；若出现「滑入节点与节点圆叠压」= 不通过） |
| J5 | 反复离站/到站 ×N | 不产生视觉疲劳/「抽搐」感 | 不产生「迟滞/追不上」感 |
| J6 | `prefers-reduced-motion` | 必须 `0ms`（两候选在此均强制瞬移） | — |

### 4.3 裁定规则（推荐执行顺序）

1. 先按 **A（0ms）** 上线真机走 J1~J5；
2. 若 **J1 判 A 不通过**（用户明确感到「闪/像 bug」）⇒ 切 **B（150ms）**，复走 J1~J5；
3. 若 B 出现 **J2 失败**（过渡中出现与节点圆的重叠）或 **J3 失败**（文字先变）⇒ 回退 A，并把 **`--you-jump-dur` 降到 `90ms`（`--dur-instant`）** 作为第三候选再验；
4. **`prefers-reduced-motion` 恒为 `0ms`**（J6，两候选一致，不受裁定影响）。

**记录要求**：裁定结果（A / B / 90ms）+ 真机型号 + 观测证据（截图/录屏）写入本批真机复验清单；`--you-jump-dur` 的最终值由裁定决定（**Token 记为登记型新值，只增不改**）。

### 4.4 自检

- [ ] J1~J6 全部有观测记录（含真机型号）。
- [ ] 裁定后 `--you-jump-dur` 单一取值（不残留两套）。
- [ ] 中点驻留：点在中点**不随进度微动**（静帧对比相邻两秒无位移）。
- [ ] 点在中点与**两端节点**均不重叠（几何保证：`frac=0.5` 恒等距）。
