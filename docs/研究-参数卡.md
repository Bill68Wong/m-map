## 三、Phase 1 关键结论（谭溯源）

### ★★ 核心洞察：「自建」不是布尔问题，是**三层可分离能力**

```
① 几何/步行路由（Geo API 层）
   ← 唯一真正「缺基础数据」的一层
   ★ 最硬论据：高德短距步行失真 11.9 倍，而首末段典型正是 50~300m

② 候选寻路（算法层）
   ← 有成熟学术方案（RAPTOR）· 澳门 33km² ⇒ 算力完全够
   ★ 但卡在：本地枚举漏线率 41~57% + 无 ground truth

③ 时间计算与排序（数据层）
   ← ★★ 我们【早已自建】，且它才是产品差异化所在
```

### 外部调研结论

```
高德：
  · v5 transit/integrated · alternativeRoute 1-10（默认 5 · 实测上限 7）
  · 个人认证配额：基础 LBS 150,000/月 · 基础搜索 5,000/月 · QPS 3/s
  · ★ 超限静默返回无效结果（协议 3.7）⇒ 故障不可观测
  · 步行短距严重失真（实测）

谷歌：
  · 现行接口 = Routes API（computeRoutes / computeRouteMatrix），已取代 Directions / Distance Matrix
  · travelMode=TRANSIT · transit preferences（少步行/少换乘）· routingPreference=TRAFFIC_AWARE
  · Matrix 上限 625 元素
  · ★ 数据来源 = 各机构 GTFS + GTFS-Realtime（Google 只做校验与归一化，不改数据）
  · ★ 算法层细节【未查到】官方确认

学术：
  · RAPTOR（Delling/Pajor/Werneck, ALENEX 2012, 微软）—— round-based · 每轮每条线路最多扫一次 ·
    不依赖预处理 · 天然输出「到达时间 × 换乘次数」Pareto 集
  · McRAPTOR（多准则/票价分区）· rRAPTOR（时间范围批量）
  · CSA（最简 · 国家尺度毫秒级）
  · Transfer Patterns（查询微秒级但预计算数千 CPU 小时 · 舍弃最优性）
  · ★★ 我们本地「换乘≤2 有界 BFS」正是 RAPTOR 的退化雏形

澳门本地（Phase 1 新发现）：
  · DSCC 官方地理资讯应用程式库 https://mapapi.gis.gov.mo/
    （Token + 免费额度/付费计费单位）
    ★ 但条款：「未经书面许可严禁复制/改编/分发/向公众提供，不得商业用途」「只供参考，不具法律效力」
  · ★ 高德协议 14.1：「原则上仅面向中国大陆开发者及最终用户」
```
