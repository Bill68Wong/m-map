# 多人协作 · 开发与上线规矩

> 适用项目：**MUST登校 / M Map**（`github.com/Bill68Wong/musttoukou`）
> 目标：两个人（或更多人）**各用自己的电脑**，都能跑起来、都能改代码、都能碰数据库、都能上线，而**不互相破坏**。
> 如果你是新加入的队友，直接跳到 [§2 五步上手](#2-队友五步上手)。

---

## 1. 先认清现状：为什么需要「规矩」

项目只有**一套数据库**（云端 Supabase），而且**就是线上用户正在用的那一套**。

这件事决定了全部规矩的形状：

| 你可能以为 | 实际情况 |
|---|---|
| 我本地跑起来，改的是我自己的数据 | ❌ 你本地读写的**就是线上真实数据** |
| 我本地瞎试，最多把自己搞坏 | ❌ 你可能改到用户/队友正在看的数据 |
| 数据库出问题了，删掉重建就行 | ❌ 重建要重跑几十万条采集数据，**做不到** |
| 我改完直接推到 main 就好了 | ❌ main 被 ruleset 保护，**只能走 PR** |

好消息是：**代码冲突这件事已经被 GitHub 兜住了**（见 §5），真正需要靠自觉的是**数据**（见 §4）。

### 角色分工

| | 负责人（Owner） | 合作者（Collaborator） |
|---|---|---|
| GitHub 仓库 | 管理员 | Write 权限（可建分支、可提 PR、可合并） |
| 数据库账号 | `postgres` 超级账号 | `dev_partner` 受限账号 |
| 能改表结构 | ✅ | ❌（表读写全可以，改/删表、建库、提权都不行） |
| Vercel | 唯一管理员 | 不持有账号（预览部署由 PR 自动生成） |
| 高德 Key | 持有全部 3 个 Key | 共用同一套 Key |
| 发版（版本号 + tag） | 默认由负责人做 | 可以，但要先说一声（避免两人同时 bump） |

> `dev_partner` 这个账号是**故意做窄**的：34 张表逐张验证过，**读/增/改/删全部可用**，
> 但 `ALTER`（改表结构）、`DROP`（删表）、`TRUNCATE`（清表）、改表属主、建库、建角色**全部被拒**。
> 也就是说：**队友写业务数据完全够用，但无法一手把库搞崩。** 这是刻意的安全边界。

## 2. 队友五步上手

### 第 1 步 · 接受仓库邀请

负责人会先把你加为协作者。你会收到 GitHub 邮件/通知：

> 「Bill 邀请你协作 `Bill68Wong/musttoukou`」

点 **Accept invitation**（或在 `https://github.com/Bill68Wong/musttoukou/invitations` 接受）。

> ⚠️ 必须接受邀请、**不要 fork**。因为 fork 出来的仓库**拿不到 Vercel 预览部署**，
> 也拿不到规则校验，PR 会一直卡住。必须**直接在仓库里建分支**。

### 第 2 步 · 装环境 + clone

```bash
# 需要 Node.js 20 或以上（推荐 22 LTS）
node -v

git clone https://github.com/Bill68Wong/musttoukou.git
cd musttoukou
```

**第一件事：设置你自己的提交身份。** 用你自己 GitHub 账号的名字和邮箱：

```bash
git config user.name  "你的名字"
git config user.email "你的GitHub邮箱"
```

> ⚠️ 这一步不能省。提交身份如果是"随便编的邮箱"，平台可能判定提交来源不可信而**拒绝部署**。
> 建议用 GitHub 设置里给你的 **noreply 邮箱**（Settings → Emails → Keep my email addresses private 里那串 `xxxxx+名字@users.noreply.github.com`），最稳。

### 第 3 步 · 写 `.env`（关键一步）

```bash
cp .env.example .env
```

然后打开 `.env`，**只填"身份 B"那一段**（合作者用 `dev_partner` 连接串）：

```dotenv
DATABASE_URL=postgresql://dev_partner.项目代号:合作者密码@aws-0-....pooler.supabase.com:6543/postgres
```

这串东西**不要在群里要、不要让负责人贴截图**——见 §3 的传递方式。
`.env` 已经被 `.gitignore` 排除，**永远不会进仓库**，但你也**绝不能**把它发给别人或提交上去。

如果你还要调地图/路线相关功能，再补高德 Key（同样由负责人私下给）：

```dotenv
AMAP_KEY=...                # 服务端 Web 服务 Key（地址解析、POI、步行距离）
AMAP_JS_KEY=...             # 浏览器地图 Key（可以公开，但本地要能用需加到高德白名单）
AMAP_JS_SECURITY_CODE=...   # 地图安全密钥（只在本机服务端代理里用，不下发浏览器）
```

`ACCESS_PASSWORD` / `CRON_SECRET` **本地不用配**：开发模式（`NODE_ENV≠production`）会自动放行，
不需要口令、不会触发定时任务。

### 第 4 步 · 装依赖 + 起服务

```bash
npm ci        # 用 package-lock.json 精确安装（比 npm install 更可复现，建议固定用它）
npm run dev   # → http://localhost:3000
```

打开 `http://localhost:3000`，能看到地图页就通了。

### 第 5 步 · 自检（改代码前先确认基线是好的）

```bash
npx tsc --noEmit    # 类型检查，必须 0 错误
npm run lint        # 代码风格（当前：0 错误，另有 9 条历史遗留 warning 不影响通过）
npm run build       # 能构建成功
```

这三条**在你提交 PR 之前必须都是绿的**。不是"差不多就行"——见 §5。

> 只检查你自己改的文件会更快：`npx eslint <你改的文件路径>`。

| 凭据 | 谁需要 | 从哪来 | 怎么给 |
|---|---|---|---|
| 仓库协作权限 | 队友 | GitHub 邀请 | 平台邀请（自动） |

| `AMAP_JS_KEY` | 需要看地图的队友 | 负责人 | 私聊 |
| `AMAP_JS_SECURITY_CODE` | 同上 | 负责人 | 私聊 |
| `postgres` 超级连接串 | **只有负责人** | — | **不外发** |
| `ACCESS_PASSWORD`（网站口令） | 只是要用网站的人 | 负责人 | 私聊 |
| `CRON_SECRET` | 没人（Vercel 自动带上） | — | 不外发 |
| Vercel 账号 | 只有负责人 | — | — |
| GitHub token（看板工具用） | 需要发版留档的人 | 自己生成 | 自己保管 |

**传递三条铁律：**

1. 🚫 **绝不**走 git、绝不贴群聊、绝不发截图 —— 一律私聊/面对面/密码管理器分享。
2. 🚫 **绝不**写进任何 `.md` / 代码 / 注释 / 提交信息里（仓库是**公开**的）。
3. 🔁 **口令一旦换了，立刻通知所有队友**（换口令后必须在平台上重新部署才生效）。

> 如果负责人把口令以任何形式提交进了仓库，要**立刻**改口令并清理历史 —— 公开仓库的每一行都在全网缓存里。

## 4. 数据规矩（最容易出事的地方）

### 4.1 会动数据的命令，现在有「守卫」

所有会改数据的脚本都接上了一道**生产库守卫**。默认状态下，它们**不会真的执行**：

```bash
npm run db:seed                  # 🔒 被拦住：目标是非本地库 ⇒ 退出码 1，什么都不做
npm run db:seed -- --allow-prod  # 🔓 明确确认 ⇒ 才真正执行
npm run db:migrate-v2300         # 🔒 同样被拦
```

被拦时你会看到一段中文提示，写明「打到哪个库、用的哪个账号、为什么拦、要怎么做」。

只想看判定、不执行任何东西：

```bash
npx tsx scripts/db-guard.ts check                       # 按你的 .env 判定
npx tsx scripts/db-guard.ts check --url=postgresql://... # 判定指定连接串
```

**规则只有一条：目标是本地库（`localhost` / `127.0.0.1`）→ 直接放行；其它一律要 `--allow-prod`。**

它防的是**手滑**（把 migrate 敲成把生产库结构改了），不是防恶意 —— 所以你**绕过它很容易**（直接 `npx tsx db/xxx.ts`）。
团队约定：**一律走 `npm run` 脚本**。就是为了让"要不要动线上库"这件事，每次都过一遍脑子。

> 🚨 **一条最重要的实操建议**：跑任何会改数据的命令前，先说一句「我要跑 `db:xxx`」。
> 两个人同时改同一份数据，结果就是互相覆盖，而且**没有自动回滚**。

### 4.2 本地起服务也会写线上库（要注意！）

即使你只是在本地点点页面，本地服务也会往**共用的线上表**里写东西：

| 表 | 你会写什么 | 后果 |
|---|---|---|
| `search_quota_log` | 每一次高德搜索都记账 | **高德搜索配额 5,000 次/月，全队共用一份**。用完了高德会**静默返回空**（表现为「线路查不出来」，不报错） |
| `amap_rate_bucket` | 全局限速令牌桶（3 次/秒） | 高频请求会拖慢所有人的实时查询 |
| `transit_cache` / `dsat_call_logs` | 缓存与调用日志 | 影响不大，但会污染统计口径 |

**所以：**

- ✅ 调试时手点几次页面、看几条路线 —— 完全没问题。
- ❌ **不要**写循环脚本拼命刷 `/api/nav` 或首页搜索 —— 那是在烧全队共用的月配额。
- ❌ 不要用本地 dev 跑压测。要用高德做批量实验，**先跟负责人说**（要算配额）。

### 4.3 如果真需要动线上数据

按这个顺序：

1. **先说**：在群里/私聊说明你为什么要动、动哪张表、大概影响什么。
2. **先备份**：`npm run db:backup`（产物落 `backups/`，已被 gitignore，不进仓库）。
   > 注意：这个备份脚本目前是 PowerShell 写的（Windows）。macOS 队友请用 Supabase 控制台导出，或请负责人代跑。
3. **一次一个人**：同一时间只允许一个人在跑会改数据的脚本。
4. **带守卫显式放行**：`npm run db:xxx -- --allow-prod`。
5. **跑完回报**：说一声"跑完了，结果如何"，让别人知道现在可以动了。

### 4.4 队友动不了的东西（遇到就会报错，这是正常的）

改表结构（`ALTER TABLE`）、删表（`DROP`）、清表（`TRUNCATE`）、改表属主、建库、建角色 —— 全被拒。
`db/migrate-*.ts` 这类脚本基本都是改结构的，**队友跑不了**，需要负责人执行。
如果功能需要改表结构，**让负责人出脚本**，不要自己想办法绕。

## 5. 代码与发版规矩

### 5.1 分支命名

```bash
git checkout main && git pull          # 永远从最新 main 开分支
git checkout -b 你的名字-做的事          # 例：ann-favorites-fix / bill-collab-guard
```

**约定：分支名用「人名前缀 + 短横线」，不要用斜杠。**

> 原因：负责人这台机器的 git 工具链对带斜杠的分支名（`feat/xxx`）会出错，已踩过坑。
> 为了全队用同一套动作、避免"你推的我能拉我的推不了"，统一用短横线。
> 另外也不要起 `feat/` 这类没有信息的名字 —— 出问题时一眼看不出是谁的。

### 5.2 提 PR → 等检查 → 合并

```bash
git add -A && git status          # 提交前先看清楚改了哪些文件
git commit -m "做了什么（一句话）"
git push -u origin 你的名字-做的事
```

然后在 GitHub 上开 PR。**合并的前提是这两条都绿：**

| 门槛 | 说明 |
|---|---|
| 平台部署检查（Vercel） | PR 会自动部署一个预览环境，构建过了才算通过 |
| 讨论已解决 | 有 review 意见就回掉（规则是这么写的） |

规则里要求的批准数是 **0**，也就是说 —— **你可以自己合并自己的 PR**。
但「能自己合」不等于「随便合」，合并前请自查：

- [ ] `npx tsc --noEmit` = 0 错误
- [ ] `npm run lint` 通过（0 错误；9 条历史遗留 warning 允许存在，但**不要新增**）
- [ ] `npm run build` 成功
- [ ] **在浏览器里真的走了一遍你改的流程**（不是"接口返回 200"，是**真的点得通**）
- [ ] PR 描述写清了：改了什么、为什么改、怎么验证的（最好带截图）

> ⚠️ 本项目血泪教训：**类型检查 0 错 + 构建通过 + 接口 200，三重全过 ≠ 功能能用。**
> 一定要真的在浏览器里跑一遍用户流程。

**合并方式选 "Squash and merge"** —— main 保持线性，历史好读。

### 5.3 合并之后

合并进 main 后，平台会自动部署到线上，大约 1~2 分钟生效。

**「发版」是另一件事**（改版本号 → 打 tag → 归档）：默认由**负责人**统一做。
如果你也想发版，**先说一声**——两个人同时改版本号会打架。

- `patch` / `minor`（修 bug / 加功能）：可以直接发。
- `major`：先商量。**判据是"用户的使用习惯是否被改变"。**

另外：**功能 PR 里不要顺手改 `package.json` 的版本号**。版本号只在发版那一次动。

### 5.4 分支不要留垃圾

PR 合并后，那个分支就删掉（GitHub 上点 Delete branch）。长期挂着的旧分支会让后面的人误以为还有活。

## 6. 冲突与意外

### 我改了别人正在改的文件怎么办？

- **动手前先说**你在改哪一块（哪个页面、哪个功能）。两个人碰同一块，越早发现越省事。
- 冲突真的发生了：**不要**用强推（`git push --force`）去覆盖对方的提交。
  正确做法是本地把最新的 main 合进来解决冲突：

  ```bash
  git checkout main && git pull
  git checkout 你的分支
  git merge main          # 有冲突就手工解决，然后 commit
  ```

### 我改的东西把线上搞坏了

1. **别慌、别继续推。** 先说一声。
2. 最快的恢复方式：找到**上一个正常的提交**，在 GitHub 上新建一个 PR **把它改回来**（Revert 按钮或手工反向修改）。
3. **不要**直接强推 main —— 会被规则拒绝，且没有实际好处。
4. 数据库被改坏了：立刻找到 §4.3 第 2 步的备份文件，请**负责人**执行恢复（队友账号没有重建结构的权限）。

### 我跑 `npm run db:xxx` 报权限错误

大概率你跑的是「改表结构」的迁移脚本 —— 队友账号**本来就不允许**。见 §4.4，交给负责人。

## 7. 常见问题

**Q：为什么我本地必须连线上库？不能自己建一个本地库吗？**
A：技术上可以，但**不建议**。整个项目的价值在于"基于真实的采集数据算路线"，本地空库跑不起来任何有意义的功能。
（历史上确实有过本地库，2026-09-17 已停用并删除。）

**Q：我本地改了数据，会影响到线上用户吗？**
A：**会**。你连的就是线上库。这也是 §4 那些规矩存在的原因。

**Q：为什么我拿到 200 但页面还是不对？**
A：见 §5.2 那个血泪教训 —— 一定要在浏览器里真的走一遍。

**Q：预览部署没生成 / 显示被拦截怎么办？**
A：可能是提交身份或平台权限的问题。**先别反复重推**，把情况发给负责人。退路是明确的：
负责人本机复跑 `npm run build` 验证后合并，功能照样能上线。

**Q：我能改 `.env.example` 吗？**
A：可以，但里面**只能放占位符**，绝不能出现真值。这个文件是给全队看的。

**Q：我能改这份文档吗？**
A：当然。规矩是活的，发现不合理就提 PR 改。改之前先在群里说一声，避免两个人同时重写同一段。

## 8. 负责人侧：邀请与凭据交付清单

### 8.1 邀请队友（5 分钟）

1. 打开 <https://github.com/Bill68Wong/musttoukou/settings/access>
2. **Add people** → 输入对方的 GitHub 用户名或绑定邮箱
3. 角色选 **Write**（不要选 Admin —— Admin 能改仓库设置、能绕过分支保护）
4. 发送邀请，让对方去 `https://github.com/Bill68Wong/musttoukou/invitations` 接受

> 之后队友**直接在本仓库建分支**，PR 才会自动拿到预览部署与规则校验。（fork 不行。）

### 8.2 交付数据库凭据

1. Supabase 控制台 → **Settings → Database → Connection String** → 选 **Transaction Pooler**（端口 `6543`）
2. 把用户名从 `postgres.项目代号` 改成 `dev_partner.项目代号`，密码用合作者专用密码
3. 私聊把**整串**发给队友本人（一次性）
4. 提醒他：只填到 `.env`，别提交、别外发

### 8.3 交付高德 Key

1. 把 3 个 Key（`AMAP_KEY` / `AMAP_JS_KEY` / `AMAP_JS_SECURITY_CODE`）私聊给队友
2. 如果队友反映**本地地图不渲染**：
   去高德控制台 → 找到 JS API 的 Key → **域名白名单**里加上 `localhost`（或临时清空限制）
3. 记账提醒：高德搜索配额 **5,000 次/月，全队共用**，超限会**静默返回空**

### 8.4 一句话话术模板（可直接复制私聊）

```text
项目仓库：https://github.com/Bill68Wong/musttoukou
我已经把你加成协作者了，去这个链接接受一下邀请：
https://github.com/Bill68Wong/musttoukou/invitations

上手照着这份文档做，五步就能跑起来：

关键的三件事：
1) 别 fork，直接在仓库里建分支（fork 拿不到预览部署）
2) 数据库连接串我单独发你，只能写进本地的 .env，别提交别外发
   —— 本地连的就是线上生产库，所以改数据前一定先跟我说一声
3) 会改数据的脚本默认被拦住了，要加 --allow-prod，规则文档里都有

有卡住的地方随时问我，别自己猜。
```
