## 1. 需求 5 · /help 底导图标「怪怪的」——诊断 + 修复

### 1.1 根因（◆ 源码级已证，非猜测）

`BottomNav.tsx` 帮助 tab 用 `icon: "help-circle"` → `REGISTRY["help-circle"] = IconHelpCircle`。

`node_modules/@tabler/icons-react@3.47.0/dist/esm/icons/IconHelpCircle.mjs` 的路径：

```
M3 12a9 9 0 1 0 18 0a9 9 0 0 0 -18 0          ← 外圈
M12 16v.01                                      ← ◆ 问号的「圆点」= 长度 0.01 单位的线段
M12 13a2 2 0 0 0 .914 -3.782a1.98 1.98 0 0 0 -2.414 .483   ← 问号的钩
```

而项目 `src/components/ui/Icon.tsx` **固定**传入：

```
size={size} stroke={2} strokeLinecap="butt" strokeLinejoin="miter"
```

**`strokeLinecap="butt"` 对零长度线段不渲染任何像素** ⇒ **问号的圆点完全消失**，屏幕上只剩「一个圆圈 + 一段钩」⇒ 这就是用户看到的「怪怪的」。

> 同理：`IconInfoCircle` 的 `M12 9h.01`（i 的点）、`IconList` / `IconClipboardList` 的项目符号同样是零长度段 ⇒ 那些图标的「点/项目符号」也在丢。

### 1.2 全注册表审计（客观证据 · 可复现）

脚本 `.verify/audit-icon-dots.mjs`（扫描 `Icon.tsx` 注册表 46 项 → 逐 path 判定零长度段）：

```
结论：注册表共 46 项，缺陷 4 项
   · help-circle  (IconHelpCircle)      → v.01            （问号圆点 ×1）
   · info-circle  (IconInfoCircle)      → h.01            （i 的点 ×1）
   · records      (IconClipboardList)   → l.01 0 , l.01 0 （项目符号 ×2）
   · list         (IconList)            → l0 .01 ×3       （项目符号 ×3）
```

> 复现：`node .verify/audit-icon-dots.mjs`
> [注意] **判定边界**：仅**描边**图标受影响（`fill="none"` + `strokeLinecap:butt`）；`*Filled` 变体是**填充**路径，微小段属抗锯齿细节，不影响。

**真浏览器像素级复现（客观证据）** —— `.verify/verify-v330-icons.mjs`：渲染同几何图标，测「问号圆点」区域（viewBox (12,16)±2）的**墨迹像素数**：

| 渲染 | 点区墨迹 | 整图标墨迹 |
|---|---|---|
| `help-circle` · **butt**（现状） | **0 px** ← 点**完全不渲染** | 155 px |
| `help-circle` · round（修复后） | **4 px** ← 点出现 | 163 px |
| `book` · butt（方案 A） | 16 px（脊线，非点） | 156 px |

⇒ 客观证实「零长度段 + butt cap ⇒ 圆点消失」。复现：`node .verify/verify-v330-icons.mjs`（截图 `.verify/shots/icons330.png`）。

### 1.3 次因：选中态丢失「第二通道」

`TABS.help` 的 `icon` 与 `iconOn` **都是 `help-circle`**（其余两 tab 是 `home/homeFilled`、`bookmark/bookmarkFilled`）⇒ 帮助 tab 的选中态**少了「图标切实心」这条非颜色通道**（设计系统要求选中态 = 实心 + 加粗 + 青花蓝 三通道，见 `BottomNav.tsx` 头注）。

### 1.4 修复方案（三选一，**推荐 A**）

| 方案 | 做法 | 优点 | 代价 | 评价 |
|---|---|---|---|---|
| **A（推荐）** | `help` → **`book`**（`IconBook`）· `helpFilled` → **`bookFilled`**（`IconBookFilled`） | ① Tabler **同库 3.47.0**（不混库）；② **零长度段 = 0**（审计已验）；③ **原生 linear/filled 对** ⇒ 恢复三通道；④ 隐喻更贴切（/help = 使用指南 + 合规说明） | 图标隐喻改变（问号 → 手册） | 质量最高、零渲染风险 |
| **B（保留问号）** | registry 内以**同几何内联 SVG** 替换 `help-circle`：**仅圆点那条 path** 加 `stroke-linecap="round"`（SVG 逐 path 属性），其余 path 保持 butt/miter | 保持用户熟悉的问号；风格与其余 tab **完全一致** | 需手写内联 SVG（项目已有先例：`RouteSheet` 的 `PREF_OPTS` 同风格内联图标）；`helpFilled` 仍需手写（实心圆 + 挖空问号） | 忠实原貌、成本中等 |
| C（最小改动） | 调用处传 `strokeLinecap="round"`（`Icon.tsx` 的 `...rest` spread 在硬编码之后 ⇒ **可覆盖**） | 1 行改动、立刻可见圆点 | help 图标帽形与同栏其他图标**不一致**（其余仍 butt）；**仍无实心变体** | 应急可、非终态 |

**规格（按方案 A 生效）**

```tsx
// BottomNav.tsx
{ key: "help", href: "/help", label: "帮助",
  icon: "book",          // IconBook      （线性 · 无零长度段）
  iconOn: "bookFilled",  // IconBookFilled（实心 · 原生对）
  match: (p) => p.startsWith("/help") || p.startsWith("/about") }
```

```tsx
// Icon.tsx — REGISTRY 增补（“book” 之名与 fav 语义不冲突，且更中性）
book: IconBook,
bookFilled: IconBookFilled,
```

- 尺寸不变（14/20/24 三档；底导用 **24**）。
- 触摸目标不变（tab 半屏宽 × `min-height: 48px`）。
- 颜色不变（未选 `--muted` / 选中 `--accent`）；标签文本「帮助」不变。
- **无障碍**：`Icon` 已有 `focusable={false}` + `aria-hidden`（未给 aria-label 时）；tab 的可访问名来自 `.bottom-nav__label` 文本 ⇒ 无需补 aria。

### 1.5 附带建议（advisory · 同源缺陷）

`records`（公共交通路线 / 查看路线，**导航品牌栏与收藏菜单在用**）与 `info-circle`（到站横幅信息图标）同样丢点 ⇒ 观感上「图标缺了个点」。建议**同批顺手处理**（低风险）：

- `records` → 若其项目符号不可见不影响辨识，可**保留**（advisory）；若要修，改用 `list`…（同样有缺陷）→ 建议改用**无点**等价物或按方案 B 修那条 path；
- `info-circle` → 建议同方案 B 修（到站横幅是安全级元素，图标应完整）。
> 建议把 `.verify/audit-icon-dots.mjs` 纳入常规自检（与 `check-ui-copy` / `check-public-icons` 并列），防止后续新增图标再踩。

### 1.6 自检

- [ ] 帮助 tab：未选/选中**图标不同**（线性/实心），选中仍加粗 + 青蓝。
- [ ] 帮助图标**无「半截问号」感**（圆点/图形完整）。
- [ ] `node .verify/audit-icon-dots.mjs`：`help` 项 = OK。
- [ ] 三 tab 图标**同库同风格**（stroke 2 / 方头方角）。

## 2. 需求 2 + 7 · 多线标签一致性 & 轻轨方向 & 流程图结构

### 2.1 a) 导航顶部总览栏 = 与推荐界面同构（如 `25/26`）

**现状（缺口）**：`NavDetailBody.tsx:103` 用

```tsx
<RouteStack codes={card.rides.map((r) => r.route)} colors={colors} size="sm" />
```

—— `codes` 只给「主干线」，**丢掉了 `parallelRoutes`（并行可选线）** ⇒ 推荐卡上显示 `25/26`，点进导航却变成 `25`，两处不一致。

**规格（修）**：与 `RecommendCard.tsx:112/184` **逐字同构**：

```tsx
const routeSegments = card.rides.map((r) => ({ codes: [r.route, ...(r.parallelRoutes ?? [])] }));
<RouteStack segments={routeSegments} colors={colors} size="sm" />
```

| 维度 | 规格 |
|---|---|
| 形态 | **v0.19.1 组级裁剪**（`../迭代-v320-20260926/03-设计-规格与预览.md` §1.7，已用户确认） |
| 尺寸 | `size="sm"`（12px/700 · 斜切 6px · 缝 2px）—— 与推荐卡头部**同尺寸** |
| 段内并列 | 同段可选项 **并列**（斜切留白缝）—— 例 `25/26` 是一个**框内两块** |
| 段间换乘 | 箭头 `→` —— 例 `25 → 11` 是**两个框** |
| 上限 | 3 条/段，第 4 条起 `+N`（中性尾块） |

> **一句话**：总览栏与推荐卡头部**互为镜像**（同数据、同构件、同尺寸）⇒ 用户从列表进导航**看到同一个标签组**，不再「变形」。

### 2.2 b) 纵轴流程图车站旁 = **实际班车**标签

**口径（台账）**：「能赶 25 显示 25，能赶 26 显示 26」—— 即标签表示**你实际会坐上的那条线**，而非「方案计划的主干线」。

**数据依据**：`RecommendCard.altBuses: AltBusView[]`（含 `route` = 该后续班次所属线路码；同卡下主干线 + 各 `parallelRoutes` 的后续班次**合并下发**）+ 主干线本身。

**互斥规则（按优先级取唯一一条）**

| 情形 | 站条标签显示 | 说明 |
|---|---|---|
| 主干线**能赶上**（`stopsAway` 在阈值内 / `tier` 存在） | **主干线** `strip.route` | 与推荐卡主干一致 |
| 主干线赶不上，某并行线能赶上 | **那条并行线**（altBuses 中「最早可赶」者） | ← 本需求主场景 |
| 数据缺失 / 无法判定 | **回落** `strip.route`（主干线） | **不得**显示未经验证的线路 |
| 轻轨段 | 该方向**唯一**线路（轻轨无并行线） | 与方向文案同行 |

**位置与视觉**

```
┌ 纵轴流程图 · 上车站行 ────────────────────────────────┐
│  ●─ [26]  氹仔客運碼頭        ← 线路标签（实际可乘线）   │
│  │   下一站 · 停靠中 …（既有状态词不变）                │
└──────────────────────────────────────────────────────┘
```

- 载体 = `NavStrip` 第 `k === 0` 行（首站=上车站）的既有 `<RouteStack>`；**只换数据源，形态/尺寸不变**（v0.19.1 · `size="sm"`）。
- **不改**：`.navstrip__row` 四态（已过灰/下站蓝/下车绿/到站红）、节点、纵条、浮标（用户点）。
- **可选增强（advisory·默认不做）**：当「实际可乘线 ≠ 计划主干线」时，标签后加 `--text-2xs`/`--meta` 小字「（改乘）」—— 提高可解释性，但增加噪音；**请用户决定**。

> **交前端**：`SegmentStrip` 需携带「本段实际可乘线」（建议由服务端在 `altBuses` 已合并的基础上派生一个 `boardRoute?: string` 字段，前端优先取它、缺省回落 `strip.route`）——**字段命名/落点以架构师为准**。

### 2.4 d) 轻轨流程图末尾结构（步行 → 终点）+ 下车站点错误排查

**应有结构（规格 · 断言口径）**

```
… 下车 · {下车站号 站名}            ← 节点 role = "end"（下车站）
└─ 步行 N 分 → {目的地}             ← 末段必须是「步行 → 目的地」，且终点名 = 本次查询目的地
```

| 断言 | 规格 |
|---|---|
| A1 | 纵轴**最后一行**必须是**步行段 → 目的地**（不得以轻轨/巴士乘车段结尾） |
| A2 | 末段步行终点文案 **= 查询目的地名**（`walkIn.toLabel`） |
| A3 | 最后两个**节点**为 `下车站 → 目的地`；下车站必须 = **末段**（`rides[last]`）的 `alightLabel`，**不得**是换乘站 |
| A4 | 轻轨段：`下车站 = 该段 alightLabel`（站码映射）；方向 = 该段 `directionName` |

**下车站点错误出现在此 —— 排查清单（交架构师/QA）**

| # | 可疑点 | 判据 / 检查 |
|---|---|---|
| 1 | **取首段当末段**（历史坑，`RecommendCard` v2.4.1 修过；纵条是否同样修了？） | `NavStrip` 的 `alight = stops[stops.length - 1]` [通过] 已是末段；确认**下车站数据源**也是 `rides[last]` |
| 2 | 换乘段的下车站被当成终点 | 断言 A3：换乘路线的最后节点应是**末段**下车站 |
| 3 | 轻轨 `alight` 站码映射错（站名/站码对不上） | 对照 `lrt-transfer.ts` 的站码映射表；断言 A4 |
| 4 | `walkIn.toLabel` 未回填目的地（v2.4.1 修过一次） | 断言 A2：必须等于目的地名 |
| 5 | 站序方向反了（下行/上行站序取反） | 比对 `stops[]` 首站=上车站、末站=下车站；与方向文案一致 |

> 设计侧只给**结构断言**；根因定位交架构师（台账 Phase 1 清单 #5 已指派「设计师 + 架构师」）。
