# 巴士区间进度模型 · 调研报告与方案

> 调研：2026-09-27 · 数据：45 场 loc 采集（含当日下午用户新采 5 场 · 全部纳入）· **10.4 万个有效区间段 · 33 万个位置点**
> 目标：解决「巴士处于站间区间内时，剩余时间只能按整段估计」的不精确问题——**用经纬度判定「已行驶到哪里」**
> 配套实验档案：`data/tracking/analysis-20260927/progress/`（9 份报告）· 脚本 `.verify/_track-progress-*.mjs`（可复跑）

---

## 0. 摘要

**问题量化**（这就是现状的口径误差）：车在区间内、位置未知时，只能给「全区间」量级的估计——
**跨海段平均误差 2.11 分**（±2 分钟级），市区短段 0.93 分。

**解法与实测**（按场次时间切分的严格口径：28 场训练 → 13 场测试）：

| 模型 | 信息利用 | 全局误差 | 跨海段 | 市区短段 |
|---|---|---|---|---|
| A 无信息（现状哲学） | 只有「在区间内」 | 1.13 分 | **2.11 分** | 0.93 分 |
| B 时间减法 | + 已离开多久（u） | 0.51 分 | **0.28 分** | 0.52 分 |
| D 位置模型 | + 已走到哪（p，经纬度） | 0.49 分 | 0.45 分 | 0.46 分 |
| **E2 融合（0.5B+0.5D）** | u + p | **0.45 分** | 0.32 分 | **0.45 分** |

- **全局：1.13 → 0.45 分（改善 60%）**；**跨海段：2.11 → 0.28~0.32 分（改善 85%+）**
- 「越走越准」实测成立：误差随已走比例从 0.58 分收窄到 0.30 分
- 关键副产物：**「中途打开」场景（不知道车何时离站）只有位置模型可用**——跨海段仍能保持 0.44 分

**可行性结论：可做、已实证、数据管线全部现成**（shape、实时坐标、采集数据三项齐备）。

## 1. 现状为什么「只能按整段估计」

```
A 站等车，报站「还有 3 站」（车在 D-C 区间内或 C）
  · 车刚离开 D → 实际还要 ~4 分钟
  · 车马上到 C → 实际只要 ~1 分钟
现状只能给「D→A 整段区间」的估计（跨海段 ±2 分钟量级）——位置未知是误差核心
```

三个信息层级，等价于三种模型（上表 A/B/D）：
1. **A**：只知道「在区间内」→ 用区间中位时长（误差 = 整段分布宽度）
2. **B**：还知道「已离开多久」（观测到离站后计时）→ 中位 − 已用时
3. **D**：还知道「已走到哪」（本报告核心：经纬度→线路投影）→ 位置感知曲线

## 2. 数据与方法（全部已跑通）

### 2.1 坐标系标定（★ 关键前提，此前项目内标注为「未知」）

用「站坐标双源投影对比」定案：**高德数据 = GCJ-02，DSAT 经纬度 = WGS84，必须转换**——
转换后站线投影距离 198m vs 不转换 327m（13,690 个站×线组合对比），全面更贴线。

### 2.2 投影管线（`_track-progress-2-extract.mjs`）

```
loc 帧（15s，WGS84 经纬度）── wgs84ToGcj02 ──▶ 投影到 route_shapes 折线
                                               │（找最近线段 + 沿线累计里程）
报站帧（5s，挂载站/status）──▶ 识别「区间段」：离 X（1→0）→ 到 Y（status=1, idx+1）
                                               │
合并 ──▶ 每段：mX（离站位置里程）、mY（到站位置里程）、相对进度 p = (m−mX)/(mY−mX)
       每个位置点：(p, 剩余时间到「报站判定到达」)
```

- **投影质量**：多数段「车辆-几何投影中位距」**2-3 米**（路线高度重合）
- **数据规模**：45 场 → 128,414 段 → 质量过滤后 **104,295 段 / 33 万点**
- **过滤（质量门）**：排除「p 无变化/方向反了」段（18.8%，主要是采样点太少的短段）+ 物理速度门（>80km/h 的投影错位假段）
- **评估切分**：**按场次时间切分**（早 28 场训练 → 晚 13 场测试），严格模拟「用过去预测未来」

### 2.3 建模要素

- **md**：区间（route|from→to）的历史中位时长（复用现有 `segment_stats` 的数据体系）
- **h 曲线**：`剩余时间比例 = h(剩余路程比例)`——20 个桶 × 4 类段型的经验中位曲线（共 ~80 个系数）
  - 曲线形态揭示固有特性：**还剩最后 5% 路程时，仍平均剩 20-30% 时间**（进站减速 + 到站判定滞后平台）

## 3. 核心发现

### 3.1 四类段 × 四模型（测试集实测 · MADE·分）

| 段型 | 段数 | A | B | D | **E2 融合** |
|---|---|---|---|---|---|
| 市区短段（<1km） | 28,342 | 0.93 | 0.52 | 0.46 | **0.45** |
| 中距（1-2.5km） | 2,869 | 1.61 | 0.53 | 0.54 | **0.48** |
| **跨海快速段（≥2.5km 且 ≥25km/h）** | 884 | **2.11** | **0.28** | 0.45 | 0.32 |
| 市区长段（≥2.5km 且慢速） | 186 | 2.35 | **0.76** | 0.99 | 0.81 |

**解读**：
- 跨海段最优 = **时间减法（0.28 分）**——跨海段几乎不停靠、时间近似线性（单次运行时长高度稳定：25 路桥段 255-270 秒）；
- 市区段最优 = **融合/位置模型**——红灯随机性强，位置信息价值最大；
- **统一用 E2 融合即可覆盖所有场景**（跨海 0.32 vs 最优 0.28 只差 2.4 秒），无需按段型切换。

### 3.2 「越走越准」实测（融合模型误差随进度收窄）

| 已走比例 p | 0-0.05 | 0.3 | 0.5 | 0.7 | 0.9 | 0.95+ |
|---|---|---|---|---|---|---|
| MADE（分） | 0.58 | 0.46 | 0.41 | 0.38 | 0.41 | **0.30** |

### 3.3 红绿灯 / 静止专项（回答「等红灯怎么办」）

- 静止（位置不动 ≥12s）可被清晰识别；**60.5% 的段存在静止、约占总时长 26%**——公交约 1/4 时间在静止；
- 静止位置**双峰**：p 0-0.1（25%：出发后第一个路口）、p 0.9-1.0（17%：进站 + 到站判定滞后平台）；
- **反直觉发现：跨海段静止更多（90.8% 有、2.55 次/段）却预测最准**——关键不是「静止多少」而是「静止分布是否稳定」（跨海段把路口平均化，总时长高度稳定）；
- **策略：不需要单独建「红灯模型」**——h 曲线（实测分布）已自动吸收全部静止统计规律。

### 3.4 噪声鲁棒性（模拟线上环境）

| 方案 | 无噪声 | 加噪（u ±15s / p ±0.05） |
|---|---|---|
| B 时间减法 | 0.58 分 | 0.59 分 |
| D 位置模型 | 0.54 分 | 0.55 分 |

**两者都极抗噪**——线上的检测滞后、投影误差不会破坏模型（结论：可以部署）。

### 3.5 关键边界与限制（诚实标注）

| 项 | 状态 |
|---|---|
| **到站判定滞后** | 车停稳后报站 status 切换有 ~30-50s 平台——模型口径统一为「到系统宣布到达」（与线上逻辑自洽；也解释了 h 曲线尾端平台） |
| **螺旋坡（横琴口岸 T355/T560）** | 用户实测反馈 + 数据验证：口岸有螺旋匝道，2D 投影存在圈层混淆——实测中看到「p 卡顿 75 秒后突跳」「p 从 1.0 回退 0.3」、投影距 133m（正常 2-13m）。**受影响为局部子集**（601 个测试段中 p 回退率 1.5%），且**融合模型自动吸收**（该子集 E2=0.38 分 · 位置模型单独 0.63 · 时间减法 0.27）。解法见文献审查报告（连续性约束 + 段级信任度 + 低信任段自动降权） |
| 投影方向异常 | 个别线路（如 59 路）单 shape 往返线的方向消歧需处理（质量门已滤除 19% 可疑段；实施时需加「方向一致性校验」） |
| 短段采样稀疏 | 15s 采样下市区短段仅 1-3 个位置点（短段收益本来就小，可接受；如要更好可对特短段降级用时间减法） |
| shape 覆盖 | 111 条几何 / 93 线（对应 97 线计划——**差 4 条线待补 shape**，实施前核查） |
| h 曲线样本 | 跨海类测试段 884 个（持续采集会继续增厚；曲线存储为版本化常量，随采集重训） |

## 4. 模型设计（可实施方案）

### 4.1 公式

```
剩余到站时间 =
  E2 = 0.5 × D + 0.5 × B
  其中：
    D = md(route, from→to) × h[ type(route,from→to) ][ 1 − p ]     ← 位置感知
    B = max( md(route, from→to) − u, 0 )                            ← 时间减法（u = 已离开时长）
    p = (车辆沿线里程 − 起点站里程) / (终点站里程 − 起点站里程)        ← 经纬度投影
    type = 段型（短/中/跨海快/长慢）· h = 经验曲线（~80 系数）
```

### 4.2 场景化使用（覆盖所有线上情形）

| 场景 | 可用信息 | 用什么 | 跨海段误差 |
|---|---|---|---|
| 持续跟踪（APP 开着，从离站观测起） | u + p | **E2 融合** | **0.32 分** |
| **中途打开 / 手动刷新**（不知道何时离站） | 仅 p | **D 位置模型**（B 不可用） | **0.44 分** |
| 位置不可用（降级：投影失败/无坐标） | — | A（区间中位） | 2.11 分 |

### 4.3 运行时数据流（全部组件现成）

```
`/api/route-vehicles`（已有：12s 轮询，车辆坐标已转 GCJ）
  ├─▶ 投影模块（新）：坐标 → 线路 shape → 沿线里程 m → p
  ├─▶ md（已有体系：segment_stats）
  └─▶ h 曲线（新：版本化常量 ~80 系数）
      └─▶ 「本区间剩余分钟」
           + 后续区间逐跳求和（量化方案 P0 体系）
           = 导航中「还有 N 站 · 约 X 分钟」
```

### 4.4 改动清单（估算）

| 组件 | 内容 | 备注 |
|---|---|---|
| 数据准备（脚本/一次性） | ① 站点里程表（对每条线每方向把站投影到 shape → `route_station_mileage`）② h 曲线重训脚本 ③ shape 差 4 条线补齐 | 离线，可复跑 |
| 服务端 | 投影模块（纯函数）+ `route-vehicles`（或新端点）输出 `progress/remainMin` | 每请求毫秒级 |
| 客户端 | 导航「N 站」小字消费 `remainMin`（与量化方案 P1 同槽位、直接升级） | 小改 |
| 验证 | 影子模式（先算不显示→对比）→ 真机 | 沿用现有探针体系 |

## 5. 与既有方案的关系

- 本模型 = **量化方案（P1）的精度升级模块**：「还有 X 分钟」从「逐跳静态求和」升级为「本区间位置感知 + 后续静态求和」；
- 建议排期：**量化方案 P0/P1（先落地基础版）→ 本模块（P2，把「本区间」部分升级）**；
- 依赖不变（shape/segment_stats 均已就绪），无破坏性改动。
