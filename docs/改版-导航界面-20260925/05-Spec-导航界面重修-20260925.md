## 1. 产品定义

- **一句话**：把「路线详情界面」升级为**乘车导航界面**——用户看手机就知道"我到哪了、还有几站下车、要不要换条线"。
- **目标用户**：作者本人（澳科大通勤 + 全澳出行），单人主力使用。
- **核心问题**：v2.13 详情页是"静态文字 + 车辆位置代理"，用户「上车后无感、不知道该看什么」；本次以「用户位置双通道 + 站条仪表盘 + 可切换方案」重构。

## 2. 本次范围（锁定）

## 4. 技术架构（锁定）

### 4.1 双通道
- **车辆通道（权威）**：12s 轮询 `/api/route-vehicles`；驱动进度（`progressOf`）/已驶过切割（`cutAt`）/下车提醒（soon/now）/候选车。**GPS 绝不参与站序进度**。
- **GPS 通道（新增 `userFix`）**：`navigator.geolocation.watchPosition`（WGS84 → `wgs84ToGcj02` → 投影/距离）；节流 **候车 15s / 乘车 30s**（仅前台）；驱动地图蓝点、走向车站距离、上车判定 R2、提醒佐证。
- 坐标铁律：GPS 结果必须转 GCJ-02；`AMap.Geolocation convert:true` 已是 GCJ-02 不得再转；两入口不得混用。

### 4.2 七阶段行为（引用 04 §3.1，开发即按此表）
①走向车站（GPS）→ ②站台等车（车辆+GPS 辅）→ ③车来了（车辆）→ ④上车判定（全自动，§4.3）→ ⑤乘车中（车辆权威）→ ⑥临近下车（车辆+GPS 佐证）→ ⑦下车后（GPS）。

### 4.3 全自动上车判定（用户拍板；安全网为必做项）
- **切换**：R1（车辆停靠/刚离上车站）**或** R2（GPS 45s 窗口：投影 ≤80m ＋ 沿线位移 ≥150m ＋ 速度 8–80km/h）命中 → **自动切换**到「乘车中」并锁定车牌（不弹确认条）。
- **轻轨段（2026-09-25 修订）**：无逐车数据 ⇒ **R2 单独命中即自动切换**（收紧档：投影 ≤60m、速度 ≥12km/h、采样 ≥3；`plate=null`、`progressSource='gps'`）；站序由 `lib/nav/lrt-progress.ts` 投影推进（保守规则：单帧最多 1 站／连续 2 帧一致／hysteresis）；信号差**冻结不跳**；「手动模式」「估算」字样禁用。详见 `07 §8`。
- **安全网（必须实现，参数由 Phase 2 架构师定稿）**：
  1. 判据保守（宁可晚判、不误判）；
  2. **异常检测 → 纠错入口**：检出「疑似未上车/提前下车」时不静默——展示轻提示与「我没上车 / 不是这辆 / 我已下车」一键纠正；
  3. **可回退**：纠正后回到上一阶段，不丢方案；
  4. 手动通道保留（「我已上车/我已下车」始终可用）。
- 切换时给出**轻量反馈**（如瞬态提示"已开始跟踪 51 路"，不打断操作）。

### 4.4 保留 / 重写边界（引用 02 §B）
- **保留**：`app/api/**`、`lib/**`（track/route-overview/detail-fold/coord/nav-service）、数据 hook 逻辑、UI 原子件。
- **重写（视图层）**：`RouteDetailBody`（→ 导航界面主体）、`StationStrip`、`StationReachFold`、`RecommendCard`、面板视觉、`NavMap` 取景段；重写顺势拆分超 300 行文件（`NavMap` 1228 / `NavShell` 536）。
- 工程约束：client 禁 import 含 `pg` 的 server 模块；色值一律 Token；单文件 ≤300 行。

## 5. API / 数据变更（锁定）

- **0 个新端点**（middleware 白名单无需新增）。
- 字段级变更 2 处：
  1. `GET /api/station/eta` 响应**新增 `serverNowMs`**（设备时钟对时；老客户端无感降级 offset=0）；
  2. `POST /api/nav/switch-plans` 响应**新增可选 `plans[].siblings?: RecommendCard[]`**（每父线路 top-3 走法〔直达+换乘混排，按 `totalMin` 升序〕；纯新增、向后兼容；前端消费 `siblings ?? [card]` 退化）。
- 其余接口契约不变（`/api/route-vehicles`、`/api/nav/detail-body`）。

## 9. 验收标准（AC · EARS · QA 依据）

| 编号 | 领域 | 标准（摘要） |
|---|---|---|
| AC-01 | 导航入口 | When 点「开始导航」，同屏替换为导航界面（无跳转/无叠层）；退出回原界面且不丢方案 |
| AC-02 | 导航信息 | 导航中持续显示：当前站/区间、下一站、下车站、剩余站数、预计到达、其他线路入口 |
| AC-03 | 车辆通道 | 12s 轮询；进度正确推进；丢信号**冻结**（不跳站）；连续 3 次丢信号给出提示 |
| AC-04 | GPS 通道 | 授权后按 15s/30s 节流取位；蓝点随之更新；拒权/失败→不画蓝点、其余功能不受影响 |
| AC-05 | 上车判定 | 全自动切换（R1/R2；**范围含巴士＋轻轨，轻轨仅 R2 收紧档**）；安全网（保守判据＋纠错入口＋可回退）；「不是这辆」可用 |
| AC-06 | 纵条位置 | 「您在这里」随进度推进（锚点＝停靠站后 / 已过站后）；纵条不断线；**轻轨段同样生效** |
| AC-07 | 站条四态 | 已过灰 / 当前·下一站蓝加粗 / **下车站副主题绿** / 到站红脉动；**不依赖颜色单一维度**（字重/图标并存） |
| AC-08 | 地图双标记 | 车辆图标＝车、蓝点＝人；上车前两者分离可见 |
| AC-09 | 已驶过段 | 灰实线随进度推进；换乘逐段独立；冻结时不更新 |
| AC-10 | 非乘车区间 | 灰虚线（dashed）；乘车段仍彩色实线 |
| AC-11 | 下车提醒 | 下一站＝下车站→横幅（**警告色系**；**站名〔编号+站名〕用副主题绿**）＋震动（可用时；**禁声音**）；到站二次提醒；iOS 无震动如实降级 |
| AC-12 | 提醒佐证 | GPS 距下车站 <500m 仅提升置信，**不单独触发** |
| AC-13 | 其他线路 | 站台＝第一程上车站；**结构＝线路为父、方案为子**：父＝线路标签一行，子＝该线路的直达/换乘方案（标签串/总用时/快慢差/「切换路线」按钮）缩进其下；**每父最多 3 个走法（top-3）** |
| AC-14 | 切换路线 | 关旧弹窗→同屏替换→新方案「等车」态；起终点自动带入（按钮文案「切换路线」） |
| AC-15 | 排序 | **有方案线路组置顶**（组内子方案按 `totalMin` **升序**〔快→慢〕；组间按组内最快 `totalMin`）；**无方案线路**数字-字母序一行一条；加载失败软降级 |
| AC-16 | 全屏化 | 导航中隐藏底导、面板收敛、「我已下车/刷新」吸底（安全区适配） |
| AC-17 | 取景 | 四场景按可见区；拖动中地图不动；落定后仅遮挡时微调 |
| AC-18 | 轻轨读秒 | `serverNowMs` 对时后偏差 ≤±1s；归零自动翻下一班；收班预告次日首班 |
| AC-19 | 轻轨段 | **全自动 `progressSource='gps'`**：投影推进（防跳站）＋到站提醒；信号差冻结不跳；无「手动/估算」字样 |
| AC-20 | altBuses | 有数据即渲染；无数据不显示空壳；`npm run test:altbuses` 回归过 |
| AC-21 | 文案 | 14 项清单落实；禁用词（几何缺失/冻结/在途车辆/不掺/「手动模式」「估算」等）0 命中 |
| AC-22 | 视觉走查 | 390×844 无横滚/无安全区遮挡/无 CLS；**单行完整显示（无折行、无省略号截断）**；零 emoji 图标/零紫粉/零硬编码色 |
| AC-23 | 来源标注 | 两态：「依据车辆位置」（有车牌）/「实时定位」（GPS 驱动：巴士 R2 单独＋轻轨段）；「手动」仅作纠正入口不作模式 |
| AC-24 | 数据新鲜 | 涉及实时数据的区块可判断新鲜度（"上次更新：N 秒前"类中性标注，不出现技术词） |

## 10. 边界与约束

- 主视口 390×844；iOS/Android 安全区避让；`env(safe-area-inset-bottom)` 吸底条。
- 锁屏/后台：定位与提醒暂停——**如实告知**，前台做强（横幅＋站条＋地图三处同步）。
- 地图失败/缺 Key 不阻塞导航信息（沿用铁律）。
- 可访问性：四态区分不依赖颜色单一维度；`prefers-reduced-motion` 全关（已有）；横幅 `role="alert"`（已有）。
- 性能：新增 GPS 通道后首屏与轮询开销不得劣化现有 E2E 指标；动效只动 transform/opacity/color。
