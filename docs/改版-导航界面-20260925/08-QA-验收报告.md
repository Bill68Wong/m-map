### 13.2 疑点判读

**#2 「手动兜底点击后未进 riding」—— 判为真缺陷（体验回归，P1），已确定性复现。**

- **判读**：**非**「探针点击未生效」，而是 `useRideTracking.board()` 在**本段无在途车**时**静默中止**（保持 `boarding`、不换态）；且失败提示**根本没有渲染**。
- **确定性复现**（`.verify/probe-v2141-boardnote.mjs`：stub `/api/route-vehicles` → `{vehicles:[]}`）：
  - 点「手动标记上车」后 `data-nav-phase` **仍 = `boarding`**；状态行原样「等待上车 · C653 金峰南岸/金譽峰 · 正在检测车辆」；
  - 全 DOM 失败提示文案命中 = **`[]`（空）** ⇒ **静默无反馈**（点按后界面无任何变化）。
- **代码级根因（v2.13 → v2.14 回归）**：
  - `board()`：`if (!ranked.length) { setNote(NOTE_NO_VEHICLES_BOARD); return; }`（不换态）；`fetch` 抛错 → `setNote("车辆数据获取失败…")`（同样不换态）；`legs[legIndex]` 未就绪 → `return`（亦无提示）。
  - **v2.13** `RouteDetailBody` 渲染 `track.note`（`{track.note && <p className="nav-track__note">{track.note}</p>}`，boarding 与 riding 均渲染，见 `21dfe19:RouteDetailBody.tsx:151/179`）。
  - **v2.14** `NavDetailBody` **未渲染** `track.note`（仅 `frozen={… phase==='riding' && !!track.note}` 供 NavStrip 的「· 位置停在上一站」标签，`NavDetailBody.tsx:228`）⇒ **所有 boarding 提示**（`NOTE_NO_VEHICLES` / `NOTE_NO_VEHICLES_BOARD` / 请求失败）**全部不可见**；`.nav-track__note` CSS（`globals.css:5888`）成**死样式**。
- **影响面**：① 点「手动标记上车」在无车时**无反应**；② 候车时本段无在途车**无提示**；③ 手动兜底锁到「不在本段」的车后**无进度、也无解释**（`NOTE_NO_PROGRESS` 同未渲染）。
- **建议修**（一行级）：在 `NavDetailBody` 的 boarding / riding 分支渲染 `track.note`（恢复 v2.13 的 `.nav-track__note`），或改用现有 `.nav-note-neutral` 中性样式。

**#3 「其余线路」= 0 —— 判为数据合理态（非渲染缺失）；探针断言已条件化。**

- 证据：「其余线路」= `otherRoutes` 去掉「已有方案的首程线路」后的余项 ⇒ **当该站台所有线路都有可切换方案时合法为 0**。
  - 复跑（關閘）：「本站台其他线路 · **15 条**」→ 父组 11 / 「其余线路」 **5**（有非方案线路时正常显示）。
  - lead 那次（父组 8 / 其余线路 0）：该时刻所有线路均已归入有方案组 ⇒ 0 为**合法数据态**。
- 处理：探针已把「其余线路」断言改为**条件式**（存在则记行数；为 0 判「数据合理态」不判失败），并整体以 `planGroupN>0` **守卫**「有方案组」的结构/排序/切换断言 ⇒ **无方案 OD 不再误报**。
