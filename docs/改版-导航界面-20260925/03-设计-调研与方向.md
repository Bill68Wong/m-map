## 0. 一页速览（TL;DR）

| 项 | 结论 |
|---|---|
| **定位** | 本轮不是「重新设计一个 App」，而是**在 v2.13 已实装的导航追踪之上，把信息层级、状态色彩、排版节奏、动效克制做精**。 |
| **最大结构性判断** | 公交导航的**主信息面是「站条」，不是地图**——主流 App（Citymapper / Transit / Apple Maps / 高德）皆然（§1.3 结论 1）。本项目 v2.13 已把站条做成主面，方向正确；本轮是**把站条做成"仪表盘"级清晰**。 |
| **四态色彩** | 已过＝绿（用户口径，**降饱和退后**）／当前·下一站＝青花蓝（**加粗**）／下车站＝赭黄橙／到站＝砖红脉动。见 §3.2(a)。 |
| **冲突预警** | 折叠区「更快＝绿」与站条「已过＝绿」可能**同屏出现两处绿**，触碰品牌硬规则「每屏 ≤1 处绿」→ 需用户拍板（§5 问题 3）。 |
| **动效** | 现状有 **3 处 `infinite` 脉动**（到站横幅／站条「您」点／地图「您」标记）＝视觉噪音 → 建议收敛为 **2 处、统一节奏**（§3.3）。 |
| **文案** | 抽查出 **9 处**用户可见工程黑话（「几何缺失」「冻结」「在途车辆」「N 个可换乘」等）→ 逐条给改法（§4.2）。`不掺高德方案` 类已在 v2.13 清除（全库 0 命中）。 |
| **P0 自检** | 用户可见 JSX **零 emoji**（扫描命中项全部在代码注释内，非功能图标）· 零紫粉渐变 · 零硬编码色（新建议 Token 全部 `var()`/`color-mix` 派生）。 |

### 1.2 逐家拆解（只取与"导航进行中界面"相关的部分）

#### ① Google Maps 公交逐步导航
- **交互骨架**：输入目的地 → 选公交 → 「开始」→ 出现**自身所在位置**、发车时间、预计抵达；**临近下车站推送通知（含锁屏）**。〔Engadget 2017-12-15；iThome 2017〕
- **路线色语义＝二值**：**蓝＝当前选中路线**（navigating 时主动、vivid，刻意与路网/交通色拉开）／**灰（或浅蓝）＝备选、未选中路线**；交通拥堵色（橙/红/深红）**叠在蓝线之上、不替换蓝**；虚线＝指引不确定（步道/停车场/数据不足）。〔GeekChamp；ItechGuides 2026〕
- **"已驶过 vs 未驶过"**：公开资料**只确证"当前路线/备选"二值语义**，未见对"行驶过段是否置灰"的权威说明 → 记为**待验证**（不作为设计依据）。真正承担"我到哪了"的是**导航卡片 + 蓝色定位点 + 相机跟随**。
- **新版视觉方向（支撑「清爽」）**：减少视觉杂乱、把 route-critical 细节**靠近体验中心**；重做调色板以区分自然带/商业区/水域/主路，避免用户反复缩放；transit 模式下让站名/换乘点/方案选项**在小屏上更易比较**。〔positioniseverything「Google Maps' new Live look」〕

#### ② Citymapper（GO / 实时导航）
- **分段（legs）呈现**：把行程切成清晰的 legs，逐段指引；突出「该从车厢头/中/尾上车」与「哪个出口出站」——**细节到物理动作**。〔Pratt IxD 2026-02；ustransitpath 2026〕
- **导航中的持续反馈**：倒计时、实时到达时间、**站数计数**、明确的 **"Get off now"** 提示；反馈**不过载**、在恰当时机出现，降低记忆负担。〔Pratt IxD 2026-02〕
- **配色**：继承实体交通图线色（如伦敦地铁）降低认知负荷；**高对比调色板 + 粗体图标**，保证强光与颠簸车厢中可读；2023 改版引入 **Adaptive Contrast**（按环境光自动调明度）。〔Grokipedia「Citymapper」；PrismAPKs〕
- **可迁移点**：**"站数是主刻度"**（用户看的是"还有几站"，不是"还有几公里"）。

#### ③ Transit（GO 模式）—— 文案分层范式
- **分级提醒文案**（原文）：`Go in … minutes`（该出发了）→ `Hurry up!`（要赶不上）→ `5…4…3…2.. more stops`（逐站递减）→ `Your stop is next!`（下一站是目的地）→ `This is your stop!`（到站）。〔help.transitapp.com《How to use GO》〕
- **GO 后台运行 + 语音通知**：可听音乐/打盹不漏站；到站自动结束。〔同上；SixColors 2026-02〕
- **站列表在 6.0 版"更大更粗"**，等待时长大字块化——**导航态的可读性优先于信息密度**。〔SixColors 2026-02〕
- **Live Activity / Dynamic Island / 锁屏 widget** 一眼看全程进度；**只在需要动作时唤醒**（"Leave now" / "Get off in 2 stops"），批次通知而非连续轰炸。〔help.transitapp.com〕
- **无障碍**：GO 提供逐步音频指令，视障用户尤其受益；整体**趋近 WCAG 2.2 AAA**。〔resources.transitapp.com〕

#### ④ Apple Maps（实时公交）
- **实时公交标识**：发车信息旁 **绿/红 Wi-Fi 状图标**＝实时数据 + 准点/晚点；点站看全部班次与发车频次。〔LetemSvetemApplem 2025-04〕
- **分层法**（WWDC2016）：主特色 = ① 美观的公交地图（**淡化道路等驾驶元素，突出公交线路、主要终点站与换乘站**）② 每站出发时刻表 ③ 点到点指引 + 导航体验 ④ 实时建议/改路。〔Apple Developer WWDC2016 §241〕
- **到站提醒多通道**：站内通知 + **Dynamic Island** + 震动（含地铁内）。〔LetemSvetemApplem 2025-04〕
- **进站后**给"从哪个出口出"，服务"到站之后"的那一段。〔Yahoo Finance；Cult of Mac〕

#### ⑤ 高德地图（公交导航 / 换乘提醒）
- **三阶段提醒**：**上车提醒**（距上车站 50m 提示乘车信息）→ **乘车中提醒**（屏显途经站名 + 实时位置 + 距目的几站）→ **到站提醒**（距下车站 1 站且 <500m 时提示，并告知下一步骤）。〔IT168 2013-04-27〕
- **到站三重提示**：震动 + 铃声 + 桌面通知；**前台震动 1 次、后台持续震动 1 分钟**直至用户确认。〔IT168 2013；鉅亨網〕
- **实时公交页**：蓝小箭头既示方向、又示"我相对车的位置"；车图标随车实时移动；文案形如「还有 14 分钟，6 站 4 公里到咱们站」——**同时给时间与站数两种刻度**。〔今日头条教程〕
- **公交闹钟**：到站前 5 分钟或固定时刻强提醒浮窗。〔mizhijia 教程〕

### 1.3 对标结论（本设计采纳的 6 条）

1. **纵条＝主信息面，地图＝背景舞台。** Citymapper 用"站数计数"、Transit 用逐站递减、Apple/高德用"途经站名 + 实时位置"，四家一致：**用户 90% 时间看站列，不看地图**。→ 本项目 v2.13「导航中强制展开站条」方向正确，本轮把站条当"仪表盘"来精修（§3.2a/b）。
2. **状态文案必须"分级递进"，不能是一句静态统计。** Transit 的 `5→1 more stops → Your stop is next → This is your stop` 是公认范式。→ 本项目现状只有一句「已过 3/5 站」（`RouteDetailBody.tsx:181-184`），缺"下一站就是下车站"的语气跃升（§3.2a 文案表）。
3. **地图路线色主流是"选中/备选"二值（蓝/灰），交通色叠不替换。** 把"已驶过"染成**强色**（本项目＝品牌绿）是**差异化选择**，可行，但**必须守住唯一性**：绿只能表达"正向进度"，不得与线路数据色、警告色混淆，且每屏绿只此一处（§3.2c；冲突见 §5 问题 3）。
4. **到站提醒是"多通道"，且需要视觉兜底。** 主流皆"横幅/通知 + 震动/语音"。本项目 iOS 浏览器**无震动**（`useRideTracking.ts:147-153` 已如实降级）→ **视觉通道必须补强**：横幅 + 站条下车站高亮 + 地图「您」标记，三处同步提示（§3.2a/d）。
5. **"克制"是四家共识，直接支撑用户"清爽"诉求。** Google 新版"减少杂乱、关键信息靠近视线中心"；Apple"淡化驾驶元素、突出线路与换乘"。→ 导航中应**收敛同屏色彩与动效数量**，而非增加装饰（§3.3）。
6. **可读性/无障碍是硬指标。** Citymapper 高对比 + 自适应对比；Transit 趋近 WCAG 2.2 AAA + 语音。→ 本项目须保证：正文对比 ≥4.5:1、存在 `prefers-reduced-motion` 兜底（**现状已做**，`globals.css:6058-6064`）、提醒横幅有 `role="alert"`（**现状已做**，`RouteDetailBody.tsx:117`）。

## 3. 导航界面设计方向

### 3.1 信息架构（区块 + 层级 + 五态）

**区块（导航进行中）**

```
┌─ 地图层（背景舞台，fixed 铺满，不被挤压）────────────────────┐
│  底图 · 线路灰底/乘车彩段 · 站点 marker · 车辆 marker(z130)   │
│  「您」marker(z140) · 已驶过绿覆层(z74)                       │
└──────────────────────────────────────────────────────────────┘
┌─ 下车提醒横幅（跨 soon/now；z 高于面板内容）──────────────────┐  ← 视觉焦点 ①
├─ 导航操作条（吸底 · 主按钮随态切换）───────────────────────────┤  ← 视觉焦点 ②
├─ 进度纵条（主信息面 · 「您在这里」骑在纵条上）──────────────────┤  ← 视觉焦点 ③
├─ 其他线路折叠区（可切换方案置顶 + 其余线路）────────────────────┤
└─ 数据出处 ────────────────────────────────────────────────────┘
```

**视觉重量排序**（1＝最抢眼）：
1. **下车提醒横幅**（`--warn-soft`/`--danger-soft` 底 + `role="alert"`）——唯一允许持续脉动
2. **站条三焦点**：下一站 / 下车站 / 「您在这里」
3. **操作条主按钮**（`btn--primary` 青花蓝）
4. 车牌 · 已过站数 · note
5. 其他线路折叠区
6. 数据出处（`--meta`）

**五态（把现有 4 个 phase 与 alarm 组合成用户可感知的 5 个界面态）**

| 界面态 | phase | alarm | 站条表现 | 操作条主按钮 | 地图表现 |
|---|---|---|---|---|---|
| **等车** | `boarding` | — | 静（未开始追踪）；上车站高亮 | 「我已上车」 | 车辆 marker 全显；无绿覆层 |
| **已上车 / 乘车中** | `riding` | `none` | 已过＝绿（退后）／下一站＝蓝加粗／「您在这里」随车 | 「我已下车」（＋「刷新」） | 「您」marker + 绿覆层随车推进 |
| **临近下车** | `riding` | `soon` | 下车站＝橙 **并升级为"下一站"语气** | 「我已下车」 | 绿覆层逼近下车站 |
| **已到站** | `riding` | `now` | 下车站＝砖红 + 脉动 | 「我已下车」 | 绿覆层抵达下车站 |
| **已到达** | `done` | — | 全部已过（绿）；无「您」 | 「结束导航」 | 绿覆层全程；「您」移至终点 |

**另设「手动 / 降级模式」**（轻轨段或几何缺失，`useRideTracking.ts:191-193, 301-307`）：站条**不显示**「您在这里」与四态，仅保留上/下车静态标注；操作条给出**诚实说明文案**（改法见 §4.2 #1/#2）。

**建议（体验）**：导航进行中**隐藏底部主导航**（`.bottom-nav`）并把详情面板收敛到 **peek 档**（`--sheet-top-peek`），让地图在导航中占比最大——对齐"地图即舞台"。（是否采纳见 §5 问题 4。）

### 3.2 关键设计决策

#### (a) 纵条四态：色彩 + 文字规范（站牌语言下）

**色彩分配原则**：回到品牌硬规则「一个焦点一个品牌色；面积(蓝) ≥ 面积(绿)；绿每屏 ≤1 处」。导航态若"绿 + 蓝 + 橙 + 红"四色齐发，会从"克制"滑向"圣诞树"。归并方案：

| 态 | 色 Token | 圆点 | 文字 | 字重 | 备注 |
|---|---|---|---|---|---|
| **已过 passed** | ~~`--brand-green` 降饱和~~ → **灰（`--track-passed` = `--meta`）**〔2026-09-25 拍板修订〕 | ~~不变色~~ → **圆点填充灰**、无描边 | `--track-passed`（灰） | `400`（**不加粗**） | 〔修订〕用户拍板**已过＝灰**，绿色从站条退场；灰 + 不加粗 = "退后一步"。详见 `06-设计-详细设计.md` §0 / §1.1 |
| **当前停靠 at** | `--accent` | 蓝点 + `--accent-soft` 环 | `--accent` | `600` | |
| **下一站 next** | `--accent` | 空心 + 蓝描边 | `--accent` | `600` | |
| **下车站 alight（未到）** | `--warn`（赭黄橙） | 橙描边 | `--warn` | `600` | 与蓝/绿异色相，明示"提醒级别" |
| **到站 now** | `--danger`（砖红） | 实心橙→红 | `--danger` | `700` | 唯一允许脉动 |

**文字规范（站牌语言 · 只说"用户此刻要做什么/理解什么"）**

| 态 | 站条文字 | 中文化（口语 · 无黑话） |
|---|---|---|
| 已过 | 站名（弱化） | 站名 |
| 当前停靠 | 站名 + `停靠中` | `M220 祐漢街市 · 停靠中` |
| 下一站 | `下一站` 前缀 | `下一站 M220 祐漢街市` |
| 下车站（未到） | `下车` 后缀 | `M218 水坑尾 · 下车` |
| **下一站＝下车站**（soon） | **语气跃升**（对齐 Transit 范式） | `下一站就是下车站：M218 水坑尾 · 准备下车` |
| 到站（now） | 到站 | `到站了：M218 水坑尾 · 请下车` |

> **对齐结论 2**：现状操作条文案 `已过 3/5 站 · 下一站 X`（`RouteDetailBody.tsx:181-184`）应补一个**"还有几站到下车"**的递进刻度（Transit / 高德的"站数刻度"），例如：`距下车站还有 3 站 · 下一站 X`。

#### (b) 「您在这里」如何插入纵条（修正现状两处问题）

**修正 1（锚点语义）**：锚点规则改为
```
atIdx !== null  → 挂在 atIdx 之后（车正停靠该站）
否则 passedIdx ≥ 0 → 挂在 passedIdx 之后（行驶中，最后一个完全驶过的站）
否则（一站未过且行驶中）→ 挂在「上车站」之前（车尚未到上车站）
```
〔对应 `StationStrip.tsx:71-72` 的 `youAnchor` 需按此改写〕

**修正 2（不打断纵条）**：「您在这里」**不再是横条行**，而是**"骑"在纵条上的一个节点**：
- 纵条在该处**不中断**（节点以 `z-index` 压在纵条上）；
- 视觉 ＝ **实心蓝点 `--track-you-dot-w`(12px)**（比站点圆点 9px 大一档，形成"您＞站"的尺度关系）＋ 右侧一条 `--accent-soft` 底、`--radius-chip` 圆角的小标签「您在这里」（`--text-2xs`，`--accent` 字）；
- 与地图「您」marker **同色同义**（都是 `--accent`）→ 站条与地图形成"同一焦点同一色"的正向呼应，不新增第四个颜色。
- **冻结（丢信号）时**：保留最后位置，标签文字改为 `--muted`＋`位置停在上一站`，并**停止脉动**（诚实，符合"对不上就冻结不跳"铁律）。

#### (c) 已驶过路段绿色覆层视觉规范

> **〔2026-09-25 拍板修订〕** 本节"绿色覆层"口径**已作废**：地图「已驶过路段」改为**灰实线**（`--map-line-passed`），「非乘车区间」改为**灰虚线**（首次引入虚线）。以下"色 = `--brand-green`"等绿系表述仅作历史留档；**最终以 `06-设计-详细设计.md` §2.8 为准**。

| 项 | 现状 | 本轮结论 |
|---|---|---|
| 色 | `--brand-green`（读 Token） | **保持**（用户口径；深色跟随 `#6dd58c`）。**不改地图线参数**（架构师域） |
| 粗细 | `strokeWeight 6` | **保持 6**（与灰底/乘车彩段同宽 → 上/下车站处无粗细台阶，对齐 `11-设计` §5.1 的 6/6 口径） |

### 3.4 建议新增 Design Token（**只增不改** · 向后兼容）

> 原则：**不修改任何既有 Token 的值**（`--brand-green`/`--accent` 等一律不动），只新增 `--track-*` 命名空间；新 Token 全部由 `var()` / `color-mix()` 派生 ⇒ 换主题色零改动、满足"禁止硬编码颜色"。

```css
:root {
  /* ── 导航追踪专用（2026-09-25 · 导航界面升级；只增不改）── */
  /* 四态（全部派生自既有 Token） */
  --track-passed: var(--meta);                        /* 已过站文字：灰〔2026-09-25 拍板修订；原为"绿降饱和"已作废〕 */
  --track-passed-opacity: 0.72;                       /* 已过站文字不透明度（不加粗，避免抢焦点） */
  --track-current: var(--accent);                     /* 当前停靠 / 下一站 = 青花蓝 */
  --track-alight: var(--warn);                        /* 下车站（未到）= 赭黄 */
  --track-alight-now: var(--danger);                  /* 到站 = 砖红 */

  /* 「您在这里」（站条 + 地图同色同义） */
  --track-you: var(--accent);
  --track-you-soft: var(--accent-soft);
  --track-you-dot-w: 12px;                            /* 比站点圆点(9px)大一档：您＞站 */
  --track-you-glow: color-mix(in srgb, var(--accent) 45%, transparent); /* 替代现硬编码 rgba(27,77,143,.35) */

  /* 几何（登记既有值，供组件统一引用） */
  --track-rail-w: 3px;                                /* 纵条宽（现 .rc-strip__rail 用 3px） */
  --track-dot-w: 9px;                                 /* 站点圆点（现用 9px） */
  --track-line-w: 6px;                                /* 地图线宽（灰底/彩段/绿覆层统一 6） */
  --track-passed-opacity-line: 0.88;                  /* 绿覆层透明度（现 0.95 → 建议 0.88） */

  /* 动效（唯一脉动节奏） */
  --track-pulse-dur: 1.6s;
}

/* 深色：仅补派生项（其余 derive 自既有深色 Token） */
@media (prefers-color-scheme: dark) {
  :root {
    --track-passed: var(--meta);                      /* 深色下 = 深色 --meta（#A9ADB8）〔拍板修订〕 */
  }
}
```

> **Token 层级归属**：`--track-current/--track-alight/--track-alight-now` 为 **B-slot**（既有 Token 的语义别名）；`--track-passed`、`--track-you-glow`、`--track-line-w`、`--track-pulse-dur` 等为 **C-extension**（导航专属）。**不改任何 A1**。

### 3.5 深色模式

现有深色变量齐备（`globals.css:234-297`）：`--accent:#a8c7fa`（浅蓝）、`--brand-green:#6dd58c`（浅绿）、`--warn:#f3c27a`、`--danger:#ffb4ab`。

**风险点（须处理）**：深色下「下一站蓝 `#a8c7fa`」与「已过绿 `#6dd58c`」**都是高明度浅色**，色相区分度下降，"下一站"与"已过"在暗底上可能难分。

**建议**：
1. `--track-passed` 深色派生到更暗（`color-mix(--brand-green 55%, --meta)` ⇒ 明显退后）；
2. 「下一站」在深色下**加大字重或加左侧 `--accent` 竖标**（形态区分，不靠颜色）；
3. 「您」标记深色下加 `--track-you-glow` 光晕，保证在暗底图上可见；
4. 所有新组件**不裸奔**（每个 `--track-*` 在深色块有值）。

## 4. 文案去 AI 化（设计视角）

### 4.1 审查标准（用户可见文案）

**该出现**
- 用户**此刻要做的动作**：`我已上车` / `我已下车` / `切过去`
- 用户**此刻要理解的现实**：`下一站 M220 祐漢街市` / `距下车站还有 3 站` / `这辆车暂时收不到信号`
- **数据口径与出处**：`数据来源：澳门交通事务局（DSAT）`
- **诚实的不确定**：`估算` / `不含通关` / `位置停在上一站`

**不该出现**（出现即改，AI 味 / 工程黑话）

| 类别 | 禁用词 | 原因 |
|---|---|---|
| 工程术语 | 几何缺失 / 降级 / 接口 / 缓存 / 轮询 / 投影 / 冻结 / 在途车辆 / 兜底 / 契约 / 钩子 / 落定 / 参数 / 算法 / 模型 | 用户不关心实现；**本该写在代码注释** |
| 自我辩解 / 元叙述 | 不掺高德方案 / 本地推算 / 本系统 / 该模块 | 把内部口径说给用户听 |
| 空洞填充 | Welcome to / 开始你的旅程 / 智能推荐 / 一站式 | 无信息量 |
| 伪精确 | 99.9% 可靠 / 基于 XX 算法 | 编造指标 |
| 量词/称呼错误 | `N 个可换乘`（应为"条"） | 中文语感 |

**替代表法**：一律「**口语 + 具体动作**」，并把技术概念翻译成**用户能观察到的现象**（"丢信号"→"暂时收不到这辆车的信号"；"几何缺失"→"这段看不到实时进度"）。

## 5. 待确认问题（给用户 · 选择题口径）

> 按用户偏好，一律「选择题 + 通俗解释 + 代价」。

> **〔2026-09-25 用户已拍板 · 本节问题全部闭环〕**
>
> | 问题 | 用户决定 | 落点 |
> |---|---|---|
> | 1 已过站要不要绿 | **已过＝灰**（非 A/B/C 任一项：改为灰） | `06` §0/§1.1 |
> | 2 「您在这里」形态 | **骑线节点**（采纳 A） | `06` §2.2 |
> | 3 折叠区绿与站条绿冲突 | **折叠区「更快」保留绿**；站条已过改灰 ⇒ 冲突自然消解 | `06` §0/§2.3 |
> | 4 导航全屏化 | **采纳**（隐藏底部主导航、面板收敛） | `06` §2.1 |
> | 5 操作条吸底 | **采纳**（含安全区适配） | `06` §2.1 |
>
> 另：用户拍板**上车判定＝全自动**（放弃确认条）→ 轻反馈 + 纠错入口；**车/人双标记**；**轻轨 L1 GPS 弱提示**。详见 `06-设计-详细设计.md`。

**问题 1 · 「已过站」到底要不要绿？**
- **A（推荐）**：文字淡绿（降饱和 + 不加粗 + 7 成不透明）——既满足"已过站变绿"的直觉，又"退后一步"，不与"下一站蓝"抢注意力。
- **B**：文字用灰色（`--muted`）——最克制，但与你上一轮的口径（"纵轴上已过站文字同步变色为绿"）不符。
- **C**：文字饱和绿 + 加粗——最醒目，但导航中会出现"绿蓝橙红"四色齐发，观感偏吵。
- 代价：A 需要新增一个派生色（`--track-passed`）；B 改动最小但需你改口径。

**问题 2 · 「您在这里」用什么形态？**
- **A（推荐）**：**骑在纵条上的一个节点**（纵条不断开）＋右侧小标签「您在这里」——保持"一条线到底"，与地图「您」标记同色。
- **B**：保持现状（横条行插入，纵条被切断）——改动为零，但视觉有断裂感。
- 代价：A 需改 `StationStrip.tsx` 的渲染结构（Phase 3 工作量中等）。

**问题 3 · 折叠区「更快＝绿」与站条「已过＝绿」同屏冲突怎么办？**
- **A（推荐）**：折叠区「更快」**不再用绿**，改为「↑ 快 6 分」的**箭头 + 深灰字**（`--fg`）——绿只保留给"已驶过进度"一处。
- **B**：站条「已过」改灰（见问题 1-B），把绿让给折叠区"更快"。
- **C**：两者都用绿，接受同屏两处绿。
- 代价：A 需改 `globals.css:6036-6038`；这是本项目**品牌硬规则**（每屏 ≤1 处绿）的直接取舍，建议 A。

**问题 4 · 导航进行中要不要"全屏化"？**
- **A（推荐）**：导航中隐藏底部主导航、面板收敛到 peek 档——地图占比最大，最像"在导航"。
- **B**：保持现状（面板 half 档、底导可见）——改动最小。
- 代价：A 需处理"如何退出导航/回首页"的出口（可用操作条的"结束导航"承担）。

**问题 5 · 导航操作条要不要吸底？**
- **A（推荐）**：乘车中把「我已下车 / 刷新」做成**吸底操作条**（不随内容滚动）——随时可手动兜底。
- **B**：保持现状（卡内块，需滚动）——改动最小，但乘车中想兜底要先滚回顶部。
- 代价：A 需新增一个吸底容器与安全区处理（`env(safe-area-inset-bottom)`）。
