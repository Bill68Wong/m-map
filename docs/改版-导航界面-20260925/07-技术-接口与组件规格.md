## 1. 全自动上车判定规格

### 1.1 R1（车辆侧）精确化

复用 `src/lib/nav/track.ts:105-124` `rankBoardingVehicles` 的**打分分组判据**，但**只用前两组（分档 0/1），不用距离项（分档 2+）**：

- 分档 0（`track.ts:112`）：`mainOf(v.atStation?.code) === boardMain` —— 车辆**正停靠本上车站**。
- 分档 1（`track.ts:113`）：`mainOf(v.interval?.from?.code) === boardMain` —— 车辆**刚离开本上车站**。

**R1 判定**（在候选车辆集合 `status ∈ {moving, stopping, terminal}` 上，同 `track.ts:122` 过滤）：

| 档 | 条件 | 语义 | 强度 |
|---|---|---|---|
| **R1-strong** | 存在 `interval.from.main === boardMain` 的车 | 车刚从你的站开走（你很可能上了它） | 强 |
| **R1-weak** | 仅存在 `atStation.main === boardMain && status === 'stopping'` 的车 | 车正停在你站（你可能正在上车） | 弱 |
| 不一致 | 两者都存在且车牌不同 | 数据歧义 | 不触发（见下） |

**多车歧义处理**：若 R1-strong 命中多辆不同车牌 → 取 `rankBoardingVehicles` 排序第 1（`track.ts:121-123` 已按此排序）**且**该车牌必须能在本帧车辆列表中找到；若仍无法唯一 → **不触发 R1**（宁可晚判）。

### 1.2 R2（GPS 侧）最终阈值

在 `leg.colored`（`useRouteOverview` 提供的乘车段 GCJ-02 折线）上做 `nearestOnPath`（`src/lib/nav/route-overview.ts:103`）。

**窗口**：最近 **45s** 内的 GPS 采样点（`userFix` 序列，见 §2）。
**参数（最终值）**：

| 参数 | 值 | 理由 |
|---|---|---|
| 投影容差（沿线距离） | **≤ 80m** | 严于 `CUT_TOLERANCE_M=250`（`track.ts:137`）；上车判定要保守；80m ≈ 澳门一个街口 ~ 站台宽度量级 |
| 沿线位移（窗口内最早→最新投影点累计距离） | **≥ 150m** | 排除原地抖动；约 1~2 个站距（`DECIMATE_STEP_M=15` 之上一个量级） |
| 平均速度 | **8–80 km/h** | 排除步行（<8 ≈ 2.2 m/s）与异常高值；澳门无 >80 限速 |
| 最少采样数 | **≥ 2**（有 R1 佐证时）／**≥ 3**（R2 单独判定时） | 单点不可信；单独判定需更多证据 |
| 独立可信度 | 投影 **≤ 60m** 且速度 **≥ 12 km/h**（仅当 R2 单独触发时收紧） | 无车辆佐证时，收紧以防"沿街步行/骑行"误判 |

### 1.3 自动切换时机

- **触发**：`R1-strong` **或**（`R1-weak` 且 `R2`）**或** `R2`（按 §1.2 收紧口径）。全局门控：`phase === 'boarding' && active`（**巴士与轻轨均适用**，见 §8 修订 R1）。
  - ⚠️ **巴士段**：R1 优先；**R2 单独命中 → 进入「GPS 驱动进度」模式**（无车牌锁定，进度由 GPS 投影推进）。原「无车牌 → 手动进度」定义**作废**。
  - ⚠️ **轻轨段**（无逐车数据）：**仅 R2 可用**，R2 命中即自动切换为「GPS 驱动进度」模式（见 §8）。
  - ⚠️ 几何缺失（`leg.colored.length < 2` 或 `leg.degraded`）⇒ 无投影基准 ⇒ **R2 与轻轨推进均不可用**；巴士段退化为 **R1-only**；轻轨段**不自动**（保持站台态，用户可手动进入）。
- **判定节点**：车辆帧到位（12s）或 GPS 帧到位（节流 15s）**即判定**；命中即切，不跨帧等待（R2 已要求多采样）。
- **防抖 / 冷却**：
  - **冷却 20s**：任何状态切换（自动或手动）后 20s 内自动检测器不再触发（防抖 + 防死循环）。
  - **单次会话单次自动触发**：同一 `leg` 内自动切换只触发一次；用户手动纠正后进入冷却，冷却结束后**允许再次自动**（但需满足判据）。
- **锁车牌 / 进度来源**：
  - R1 或（R1-weak 且 R2）触发 → 写入 `plate`，进度来源 = **车辆**（`progressOf`，`track.ts:65-98`）。
  - **R2 单独触发**（巴士 / 轻轨）→ `plate = null`，进度来源 = **GPS 驱动**（投影推进，见 §8；巴士段同口径）——**不再称"手动进度"**，UI 标注「实时定位」。

### 1.4 切换轻反馈

- **触发点**：仅自动切换成功那一刻（`phase` 由 `boarding` → `riding` 且 reason=auto）。
- **形态**：瞬态提示条（非模态，`role="status"`），文案「**已开始跟踪 51 路 · 车牌 XX**」（车牌缺失时省略车牌）；**2.5s 自动消失**；`prefers-reduced-motion` 下用淡入淡出（无位移）。
- 不阻塞操作、不打断滚动、不改变档位。

### 1.5 安全网（必做 · 参数定稿）

**异常检出（组合拳，需同时满足，避免单点误报）：**

| 编号 | 名称 | 条件（全部满足，连续 2 次判定，间隔 ≥ 45s） |
|---|---|---|
| A1 | 疑似**未上车** | ① `phase==='riding'` 且当前 `leg` 为**自动切换**进入（非手动）；② 近 60s GPS 平均速度 < 2 km/h（静止）；③ 最新 GPS 到 `leg.colored` 投影距离 > 250m（离线）；④ 自切换到此刻，锁定车辆 `progressOf` 已推进 ≥ 1 站 |
| A2 | 疑似**提前下车** | ① `phase==='riding'`；② 近 45s GPS 静止（< 3 km/h）；③ 投影距离 > 250m；④ 车辆已推进 ≥ 1 站 |
| A3 | 疑似**坐错车**（低优先，可后置） | 锁定车牌 `P` 的 `interval` 不含本 `leg` 的任一站主码，或 GPS 沿线投影沿**反方向**单调移动 ≥ 150m |

> A1/A2 差别：A1 用于"刚自动切换就发现人没动"，A2 用于"坐一段后下车了"。二者共用同一纠错入口。
> ⚠️ **GPS 驱动进度**（R2 单独触发 / 轻轨段）无车辆用于佐证 ⇒ A1/A2 的第 ④ 条改为「**GPS 自身投影里程停止增长且持续离线**（连续 2 帧，间隔 ≥ 45s）」；其余条件（静止、离线 > 250m）不变。轻轨段"已推进"以投影里程增长判定，不以站点主码判定。

**纠错入口（检出即显示，不静默）：**
- 轻提示条（`role="status"`）：「**看起来您还没上车？**」（A1）／「**看起来您已下车了？**」（A2）。
- 三个一键纠正（按检测类型给）：
  - 「**我没上车**」（A1）→ 回退到 `boarding`。
  - 「**我已下车**」（A2）→ 走 `alight` 流程（`useRideTracking.ts:348-366`）。
  - 「**不是这辆**」→ 换车牌（复用 `onRepick`，`useRideTracking.ts:340-346`）；无候选 → 回退 `boarding`。
- 提示条 **12s 无操作自动收起**（不自动改状态）。

**回退规则：**
- 回退＝改 `phase` 并清理该帧进度（`prog/traveled` 置空），**保留** `card`/`legIndex`/方案（不丢方案，Spec §4.3）。
- 回退后**进入 20s 冷却**（同 §1.3），不再立即自动重判。
- 手动通道始终可用：「我已上车 / 我已下车 / 换一辆」不因自动逻辑失效（`useRideTracking.ts:380-396` 既有操作保留）。

**误判最坏情况分析（一次误判的影响面与恢复路径）：**
- **影响范围**（人在步行被误判为乘车）：① 站条四态/「您在这里」显示为车的进度（错）；② 下车提醒可能提前触发（错）；③ 地图"已驶过"灰实线画出（错）；④ 自动切换轻反馈误报一次。
- **不影响的**：路线规划、卡片数据、收藏、`routes`/`stations` 等**无任何 DB 写入**；`ride` 是纯内存视图态，`card`/`active` 变化即复位（`useRideTracking.ts:116-144`）。
- **恢复路径**：① 安全网 A1 在约 60–90s 内检出 → 提示 → 一键「我没上车」回 `boarding`；② 用户随时可手动「我已下车」；③ 关闭详情/切卡自动复位。
- **兜底**：若安全网误报（人确在车上但被提示）→ 只需忽略提示（12s 自动收起），**不产生副作用**（不自动改状态）。

## 2. `userFix` 通道规格

### 2.1 类型定义

```ts
/** 用户实时定位（GCJ-02；已由 wgs84ToGcj02 转换） */
export interface UserFix {
  lng: number;      // GCJ-02 经度
  lat: number;      // GCJ-02 纬度
  accuracy: number; // 水平精度（米），来自 GeolocationPosition.coords.accuracy
  ts: number;       // 采样时刻（设备时钟 ms）
}
```

> `accuracy` 用于：投影可信度加权（accuracy 越大越不采信）、地图精度圈（可选，MVP 可只存不画）。
> 坐标来源：`navigator.geolocation.watchPosition` 返回 **WGS84** → 必须 `wgs84ToGcj02`（`src/lib/amap/coord.ts:66-77`，client-safe 纯函数）。**禁止**与 `AMap.Geolocation`（已是 GCJ-02）混用（`amap-loader.ts:16-17` 铁律）。

### 2.2 实现选择（取舍与推荐）

| 方案 | 取舍 | 结论 |
|---|---|---|
| A：并入 `useRideTracking` | 单处状态、判定直接读；但 `useRideTracking.ts` 已 403 行，加入后超 300 行限制，且 GPS 生命周期（候车/走向车站）与 ride 生命周期不一致 | 不推荐 |
| **B：独立 hook `useUserFix`** | 关注点分离、文件不膨胀、可单测；GPS 在 `off/boarding/riding` 全阶段可复用（「走向车站」也需）；NavShell 持有并向下传 | **推荐** |

**推荐 B 的接口：**
```ts
export interface UseUserFixResult {
  fix: UserFix | null;
  /** 定位不可用（拒权/超时/失败）——供降级链读取 */
  denied: boolean;
  /** 在用户手势内调用，申请权限并开始订阅 */
  start: () => void;
  stop: () => void;
}
export function useUserFix(opts: {
  enabled: boolean;                    // 是否处于需要 GPS 的态（导航态）
  intervalMs: number;                  // 节流：候车 15000 / 乘车 30000
}): UseUserFixResult;
```
`useRideTracking` 通过 `opts.userFix` 接收（只读，不自己订阅）。

### 2.3 节流实现要点

- 底层 `navigator.geolocation.watchPosition(success, error, { enableHighAccuracy: true, timeout: 10000, maximumAge: 5000 })`。
- **节流**：`lastAcceptRef` 记录上次采纳时刻；回调到达时若 `ts - lastAccept < intervalMs` 则**丢弃**（并更新一个 `pendingRef` 保留最新一帧）；到达阈值时采纳 `pendingRef`。⇒ 保证尾帧不丢、又不高频 setState。
- **interval 通过 ref 读取**（`intervalRef.current`），由调用方按 `phase` 更新 ⇒ **不重订阅** watchPosition（重订阅会丢监听、触发二次权限）。
- 采样间隔参考：iOS Safari `watchPosition` 回调本就近 10s（`04` §一/§二来源），节流主要是"下限"保护，不放大频率。

### 2.4 生命周期

- **权限申请时机＝用户手势**：「开始导航」按钮 onClick 内调用 `start()`（首次 `watchPosition` 即触发权限弹窗）。若用户在 `off` 阶段就需要 GPS（"走向车站"），由点击定位/开始导航触发，**不得在 `onload` 自动调用**（Chrome/Safari 要求手势，`04` §一来源）。
- **页面隐藏**：`visibilitychange` → `hidden` 时 `clearWatch`（省电；iOS 后台本就会暂停）；`visible` 时重新 `watchPosition` 并重置节流计时（对齐 `useRideTracking.ts:176-183` 的 Wake Lock 重申请模式）。
- **卸载**：`clearWatch` 兜底。
- **与降级链联动**（Spec AC-23，**已按修订 R1 更新**）：`fix === null || denied` ⇒ ① 地图不画蓝点（UserDotLayer 仅 `fix` 非空时渲染）；② **巴士段**自动判定退化为 **R1-only**；③ **轻轨段**无 R1 ⇒ **不自动**（保持站台态，用户可手动进入）；④ "走向车站"距离不显示，退回文字指引；⑤ **车辆通道的进度/提醒不受影响**。
  - **来源标注（更新）**：常态仅两种——「**依据车辆位置**」（有车牌）／「**实时定位**」（GPS 驱动：巴士 R2 单独 + 轻轨段）；「手动模式」**不再作为模式出现在界面**，手动仅保留为用户主动纠正入口（§8.4）。

## 3. API 字段变更规格（`serverNowMs` · `switch-plans.siblings`）

### 3.1 服务端字段

`src/app/api/station/eta/route.ts` 响应体外层**新增字段**（纯新增，老客户端无感）：

```ts
interface StationEtaResponse {
  code: string;
  fetchedAt: string;
  serverNowMs: number;   // ★ 新增：本次响应生成时的服务端 Date.now()
  items: StationEtaItem[];
}
```
- 取值：`nowMs`（函数内已存在，`eta/route.ts:305`）；在组装 `data` 处（`eta/route.ts:376`）加 `serverNowMs: nowMs`。
- 缓存分支（`eta/route.ts:313-316`，仅巴士）：命中缓存时 `serverNowMs` 用的是**缓存写入时刻** ⇒ 会偏旧。**处理**：缓存分支返回时用**当前** `Date.now()` 覆盖 `serverNowMs`（`{ ...cached.data, serverNowMs: nowMs }`）。轻轨本就不走缓存（`eta/route.ts:310,377-378`），无此问题。

### 3.2 客户端对时算法

- **offset 计算**：每次 `/api/station/eta` fetch 成功：
  `offsetMs = j.serverNowMs - Date.now()`（设备时钟相对服务端的偏移；正=设备慢）。
- **更新时机**：每次成功响应重算（MVP 取最新值，不做平滑；若抖动明显可改为指数平滑 `offset = 0.7*offset + 0.3*new`，列为可选）。
- **倒计时公式**：`leftSec = Math.floor((depMs - (Date.now() + offsetMs)) / 1000)`。
- **降级**：响应无 `serverNowMs`（老版/异常）⇒ `offsetMs = 0`（＝v2.13 现行为）。

### 3.3 `StationCard` 倒计时改造点

| 改造 | 现状 | 改法 | 依据 |
|---|---|---|---|
| 倒计时取值 | `Math.max(0, (it.depMs - nowMs)/1000)`（`StationCard.tsx:103`） | 改为 `depMs - (Date.now() + offsetMs)` | §3.2 |
| 到点重拉阈值 | `nowMs - it.depMs > 2000`（`StationCard.tsx:188`） | 改为 `Date.now() + offsetMs >= it.depMs`（归零即拉） | 消除"过期仍显示即将开出" |
| 重拉期文案 | 保持「即将开出」（`StationCard.tsx:104,107`） | 重拉进行中显示「**正在获取下一班…**」（`reloadBusy` 态） | §C 缺口 2（`02`） |
| 护栏 | `4000ms`（`StationCard.tsx:191`） | 降为 **1500ms**（轻轨站服务端不缓存，可承受） | `02` §C.3 |
| 计时器条件 | `needSec`（`StationCard.tsx:163-170`） | 保持；offset 变化不重启秒表 | 减少抖动 |
| 静默重拉 | 已实现（`StationCard.tsx:196-224`） | 保持（不闪加载态） | — |

> 秒表依赖：`nowMs` state 每 1s 更新（`StationCard.tsx:168`）；`offsetMs` 存 `useRef`，**不**参与秒表依赖（避免每秒重置）。

### 3.4 `/api/nav/switch-plans` 新增 `siblings`（折叠区「一父多子」）

> 用户 2026-09-25 14:29 明确示例为「**一父多子**」（A 线方案 + A→Xx 线方案同挂 A 线父下）⇒ 采用**最小扩展方案**（纯新增字段、向后兼容）。

**端点内变更**（`src/app/api/nav/switch-plans/route.ts:254-284`）：
- `bestCard: Map<string, RecommendCard>` → `bestCards: Map<string, RecommendCard[]>`：每组（＝首程线路）保留 **top-K** 方案，**K = 3**（模块常量 `SIBLING_TOP_K`，便于调整；≤ 现建模上限 `PER_GROUP_MAX=6`，`switch-plans/route.ts:58`）。
- 组内**排序**：按 `totalMin` **升序**（**直达与换乘混排**，不再按"直达优先"分组）。
- 组内**去重**：去重键 = `chainRoutes.join(">") + "@" + alightMain`；同键保留 `totalMin` 最小者；与主卡同键的兄弟剔除。

**响应变更**（`SwitchPlanItem`，`switch-plans/route.ts:63-84`）：
```ts
interface SwitchPlanItem {
  route: string;              // 首程线路（父）
  chainRoutes: string[];
  totalMin: number;
  deltaMin: number;
  card: RecommendCard;        // ★ 组内最优（top-1）——语义不变（向后兼容）
  siblings?: RecommendCard[]; // ★ 新增可选：组内其余方案（top-2 ~ top-3），totalMin 升序，≤ K-1 条
  boardMain: string;
  alightMain: string | null;
  alightLabel: string | null;
}
```

- **仍无新端点**（middleware 白名单无需新增，Spec §5 的"0 个新端点"不变）；本字段与 §3.1 的 `serverNowMs` 并列为本版**两处字段级变更**。

5. 轻轨站距实测值（用于校准 `lrt-progress` 的 `H` 与可信门，见 §8.7）。

## 8. 修订 R1：轻轨段全自动（GPS 推算推进）

> 背景：用户 2026-09-25 看过设计稿后要求「**轻轨也要全自动**」，并去除「手动 / 冗余提示 / 估算」类表述。
> **本节替代原 AC-19（L1 稳妥版）**，并修订 §1.3 / §1.5 / §2.4 / §4.2 相关条目；核心原则＝**轻轨无逐车数据，改用「GPS 推算推进」**。

### 8.1 数据基础（均已有 · 零新端点 · 零 detail-body 改动）

| 需要 | 来源 | 证据 |
|---|---|---|
| 轻轨线路 polyline（GCJ-02） | `route_shapes` 含 LRT 3 线 → `useRouteOverview` → `leg.colored` | `useRouteOverview.ts:117`（`buildColoredLegs`） |
| 轻轨站坐标索引（GCJ-02） | `GET /api/stations?include=lrt&v=2`（**NavMap 已在用**） | `NavMap.tsx:906,920`、坐标语义 `NavMap.tsx:122`；LRT 站存在 `stations` 表（`anchor.ts:98`） |
| 本段站序（主码） | `strips[legIndex].stops[].code`（LRT 段同样产出） | `strips.ts:36-48` |

> 结论：**复用上述两源即可**；无需新增接口，也无需改 `/api/nav/detail-body`（不触碰 Spec §5 的"字段级变更仅 serverNowMs"约束）。

### 8.2 自动进入乘车态

- 轻轨段（`leg.kind === 'lrt'`）：**仅 R2** 可用（无车辆 → 无 R1）。
- R2 命中 → 自动切 `boarding → riding`，`plate = null`，`progressSource = 'gps'`。
- R2 在轻轨段采用 §1.2 的「**R2 单独**」收紧档：投影 **≤60m**、速度 **≥12 km/h**、采样 **≥3**。
- 轻反馈：「**已开始跟踪行程（氹仔线）**」类文案（不含车牌）。

### 8.3 站序推进（保守规则）

**预计算（进入 riding 时算一次）：**
1. 对本段每个 stop，用 `nearestOnPath`（`route-overview.ts:103`）投影到 `leg.colored` → 用 `cumDistM`（`route-overview.ts:96`）得该站沿线里程；
2. 单调化（强制递增；乱序/投影离站过远的站**剔除**，不参与推进）；
3. 得站点里程阶梯 `ladder[i]`。

**每帧判定（保守，防跳站）：**

| 规则 | 定义 | 目的 |
|---|---|---|
| 可信门 | 离线距离 `dist_off ≤ 120m` **且** 精度 `accuracy ≤ 100m` | 弱信号不推进 |
| 已过站 | `passedIdx = max{ i : d_now > ladder[i] + H }` | 越过站点里程 + 迟滞才判"已过" |
| 下一站 / 区间 | `nextIdx = passedIdx + 1`；区间 = `[passedIdx, nextIdx]` | 与巴士同构 |
| **单帧最多推进 1 站** | `passedIdx = min(passedIdx_prev + 1, computed)` | 防跳站 |
| **连续确认** | 推进需连续 **2 帧** computed 一致才采纳 | 防单帧毛刺 |
| **Hysteresis** | `H = max(60m, accuracy, 0.25 × 相邻站距)`；回退需 `d_now < ladder[i] − H` | 防边界抖动 |
| 速度合理性 | `\|Δd_now\| / Δt ∈ [8, 80] km/h`（异常大丢帧；异常小不推进） | 排除投影跳变/静止漂移 |
| 地下/弱信号 | 连续 2 帧不满足"可信门" → **冻结**（沿用总线策略，§8.5） | 不跳不猜 |

- 输出与巴士**同构**：`TrackProgress { kind:'at'|'between', passedIdx, atIdx, nextIdx }`（`track.ts:42-56`）→ 直接喂 `StationStrip` 四态与「您在这里」锚点（`StationStrip.tsx:62-72`）。
- **定位精度 vs 站距适配**：澳门轻轨站距约 0.5–1 km（**待实测核准**），GPS 开阔精度 10–30m ⇒ 足以区分相邻站；`accuracy > 100m` 时不推进，`H` 随 `accuracy` 放大，避免抖动跳站。

### 8.4 到站提醒（轻轨）

- `nextIdx === alightIdx` → `alarm='soon'`（横幅）；`d_now ≥ ladder[alightIdx] − 80m` → `alarm='now'`。
- 形态：横幅 + `navigator.vibrate`（**禁声音**，沿用户口径 `useRideTracking.ts:146-153`）；iOS 无震动 → 仅横幅。
- 级别跃升只触发一次（沿用 `useRideTracking.ts:270-273` 节奏）。

### 8.5 信号差 / 地下段降级

- **冻结不跳**：连续 2 帧不满足"可信门" → 保留最后进度、停止推进（沿用巴士「对不上就冻结」铁律）。
- **中性文案（禁「手动模式」「估算」）**：「**这一小段定位信号弱 · 位置停在上一站，恢复后自动跟上**」。
- 恢复：可信门重新满足 → 续推（**不重置**进度）。

### 8.6 来源标注矩阵（更新 · 替代原三态）

| 场景 | 进度来源 | 界面标注（中性） |
|---|---|---|
| 巴士段 · 有车牌（R1 / 混合） | 车辆 | 「依据车辆位置」 |
| 巴士段 · R2 单独（无车牌） | GPS 驱动 | 「实时定位」 |
| **轻轨段（R2 自动）** | GPS 驱动 | 「实时定位」 |
| 用户主动纠正后 | 保留原来源 | 不新增模式 |

> 「手动模式」**不作为独立模式出现**；用户纠正入口（「我没上车 / 我已下车 / 不是这辆」）常驻操作条（§1.5）。

### 8.7 风险与边界（如实记录 · 给开发与 QA）

1. **地下 / 半地下 / 车站内**：GPS 失效 → 冻结（该区间无进度）。澳门轻轨多为高架，但**具体失效路段需实测**（待验证）；预计单程可能出现 1~2 次短冻（数秒~数十秒）。
2. **阈值敏感**：过松跳站、过严不推进 ⇒ 三个常量须可在实施期微调：`LRT_TOL_M=120`、`LRT_H_MIN_M=60`、`LRT_ACC_MAX_M=100`。
3. **站坐标质量**：轻轨站坐标逐站漂移（禁常数偏移，MEMORY 铁律）⇒ 用 `stations` 表**实测坐标**投影；某站投影离线 > 站位半径 → 该站从 `ladder` 剔除（不参与推进）。
4. **换乘**：轻轨段→巴士段，`legIndex` 变化，来源由 GPS 驱动自动切回车辆。
5. **验收**：E2E 增加轻轨 OD（如石排湾线 SPW→UH），断言站条四态 + 「实时定位」标注 + **全库零命中「手动模式 / 估算」**。
