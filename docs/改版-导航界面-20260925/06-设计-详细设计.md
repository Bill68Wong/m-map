### 1.3 状态机映射（与实装对齐）

```
off ──「开始导航」──▶ boarding ──〔自动检测上车〕──▶ riding ──〔自动/手动 下车〕──▶
   （等车·车人分离）  （自动锁定车辆+12s 轮询）      ├─ 还有下一程 ⇒ 回 boarding（车人再次分离）
                                                    └─ 最后一程 ⇒ done（车人分离）
纠错入口（任意 riding 态常驻）：我没上车（回 boarding）· 不是这辆（换车）· 我已下车（推进）
```

- **自动检测上车**：系统判定后 → 进入 `riding` → 触发**瞬态反馈** + 常驻**纠错入口**；用户无需点击。
- 保持既有铁律：**对不上就冻结**（丢信号/站序对不上 ⇒ 冻结上次进度 + 提示，绝不乱跳）。

## 2. 逐组件设计说明

### 2.1 导航操作条（`.nav-track` → 吸底 `.nav-actions`）

**结构（吸底条，`position: sticky/absolute; bottom:0`）**

```
┌─────────────────────────────────────────────────┐
│ 状态行   ● 乘车中 · AA-77-59        下一站 M9 …   │  ← --text-xs / --muted，右侧对齐补充信息
│ [ 我已下车 ]   [不是这辆]                    [刷新] │  ← 主按钮 flex:1 / 文字按钮 / 图标按钮
└─────────────────────────────────────────────────┘
  背景 --surface · 上边发丝线 --frame-w --border · 底 padding = max(10px, env(safe-area-inset-bottom))
```

**各态内容**

| 界面态 | 状态行（左） | 状态行（右补充） | 主按钮 | 次按钮 | 图标按钮 |
|---|---|---|---|---|---|
| 等车 | `● 等待上车 · M1 關閘總站` | `正在检测车辆` | （无主按钮，改为提示文字） | `手动标记上车`（**弱样式常显**）· `结束导航`（弱样式） | — |
| 乘车中 | `● 乘车中 · AA-77-59` | `下一站 M9 黑沙環馬路` | `我已下车` | `不是这辆` | `刷新` |
| 临近下车 | `● 乘车中 · AA-77-59` | `即将到达 M250 澳科大` | `我已下车` | `还没到` | `刷新` |
| 已到站 | `● 已到站 · M250 澳科大` | — | `已下车` | `还没到` | — |
| 已到达 | `● 已到达目的地` | — | `结束导航` | — | — |
| 轻轨段 | `● 乘车中 · 轻轨 石排灣線` | `下一站 石排灣` | `我已下车` | — | `刷新`（图标） |

**状态行第三槽：进度来源与新鲜度（AC-23 / AC-24）**

状态行左侧 `●` 之后追加一枚**中性来源标签**（`--text-2xs`、`--meta`、无术语），并在右侧补充位给出**更新新鲜度**：

| 来源（`data-source`） | 标签文案 | 何时出现 |
|---|---|---|
| GPS 实时 | **实时定位** | 有有效 `userFix`（蓝点在动） |
| 车辆位置 | **依据车辆位置** | 无 GPS/拒权，但有车辆通道（乘车中常见） |
| 手动 | **手动** | GPS 与车辆双失（降级链，AC-23）。**轻轨段不再计入**（已改全自动，来源＝实时定位） |

- 新鲜度（AC-24）：状态行右侧在无更紧急信息时显示 `上次更新：12 秒前`（`--text-2xs` `--meta`，tabular-nums）；有"下一站"等信息时，新鲜度降级为**更小更淡**或收进 note，避免与"下一站"抢位。**不出现"轮询/缓存/接口"等技术词**。
- 视觉纪律：来源标签与新鲜度均为 `--meta` 低重量文本，**不占用主按钮/次按钮位**（决策点仍 ≤4 项）。

**设计要点**
1. **吸底**：不随 sheet 内容滚动 ⇒ 乘车中随时可手动兜底（解决 03 §2.3 #7）。
2. **全屏化**：导航进行中 `body[data-nav="riding"]` 下隐藏 `.bottom-nav`；面板收敛至 **peek 档**（`--sheet-top-peek`）或 full（由用户拖动），地图占比最大化。退出导航的出口 = 操作条的 `结束导航`。
3. **安全区**：底部 `padding-bottom: max(10px, env(safe-area-inset-bottom))`（吸底条贴底，必须吃安全区）。
4. **层级**：`z-index` 高于 sheet 内容、低于提醒横幅？——两者不同区（横幅在 sheet 顶部、操作条在底部），无冲突；toast `z` 高于操作条（见 2.6）。
5. **色彩纪律**：主按钮用 `--accent`（蓝的岗位）；状态行的 `●` 指示点用 `--accent`；纠错按钮为**文字按钮**（低视觉重量，不争主 CTA）。

### 2.2 进度纵条（`.rc-strip` · 导航态）

**结构（骑线节点模型）**

```
        ●  M1 關閘總站  上车          ← 端节点（灰=已过）
        │
        ●  M5 看台街                  ← 中间站（灰）
        │
       (o) 您在这里                    ← 「您在这里」骑线节点（蓝点 + ring，纵条不断开）
        │
        ●  [下一站] M9 黑沙環馬路        ← 蓝加粗 + 徽记
        │
        ●  M220 祐漢街市
        │
        ●  M240 東北大馬路
        │
        ●  M250 澳科大  下车            ← 端节点（品牌绿=下车站）
        ↑ 左侧纵条：已过段=灰实线，未过段=线路数据色
```

**关键决策**
1. **「您在这里」是"骑线节点"，不是横条行**（修正 03 §2.3 #2）：纵条在该处**不中断**（节点的圆点以 `z-index` 压在纵条上）；视觉 = `12px` 蓝点（比站点 9px 大一档）+ `--track-you-ring` 光环 + 右侧 `--text-2xs` 蓝色小标签「您在这里」。
2. **锚点语义修正**（修正 03 §2.3 #1）：
   ```
   atIdx !== null  → 挂在 atIdx 之后（车正停靠该站）
   否则 passedIdx ≥ 0 → 挂在 passedIdx 之后（行驶中，最后一个完全驶过的站）
   否则（一站未过且行驶中）→ 挂在「上车站」之前（车尚未到上车站）
   ```
3. **纵条分段着色**（与地图一一对应）：已过段 = `--map-line-passed`（灰实线）／未过段 = 线路数据色。实现建议：每个站点行自带一段纵条（`top:0;bottom:0`，首行 `top:16px`、末行 `bottom:16px`），按该行状态着色 ⇒ 天然对齐、无绝对高度换算。
4. **导航中强制展开**（沿用现状）：无收起键；静态详情保留折叠键（`≥44px`）。
5. **逐站刻度**：导航态下每站右侧给出**到该站的分**（`--text-xs` `--meta`，tabular-nums）；顶部行给「距下车站还有 N 站」（对齐 Transit 站数刻度）。
6. **冻结态**：丢信号时「您在这里」保留最后位置，标签转 `--muted` + 「位置停在上一站」，**停止脉动**。
7. **排版密度**（导航态"可读优先"）：站名 `--text-md`(15px)、副行 `--text-xs`(13px)、行距 `padding: 6px 0`（端点 10px）——比静态详情略松，对齐 Transit 6.0"站列表更大更粗"。

```
│  [MT4]   还有 6 站 · 约 11 分                               │
│  [56]    暂无班次信息                                       │
└─────────────────────────────────────────────────────────────┘
```

**设计要点**
1. **父子结构（核心修订）**：**线路为父、方案为子**——父行 = **线路标签单独一行**（`--surface-2` 微底，`--text-sm`/600）；子行 = 该父线路的**可切换方案**，以**左侧树形连线**（`::before` 竖线 ＋ `::after` 肘线，`--border-2`）缩进挂在父下。**不再有"方案独立行"**。
2. **子排序**：同一父内子行按**总用时快 → 慢**（更慢的往下排）；一个父整体走完再进下一个父。
3. **子行内容**：线路标签串（直达＝单标签／换乘＝`色→色`，整体不可折断）· 总用时 · 快慢差 · 右侧「切换路线」按钮。
4. **父排序**：**有方案的线路整体置顶**（组间按该线路"最快方案用时"升序）；**无方案的线路**在分隔线下方按**数字-字母序**一行一条（父行保留实时报站"还有 N 站"）。
5. **分组呈现**：`可切换路线`（顶部小标签）＋ `其余线路`（**带顶部分隔线**的小标签）——目标：一眼看懂"上面这组有方案可切换、下面是其余线路"。**不加**"含 N 个走法"类计数（清爽优先；子行已自明）。
6. **两层视觉**：父子组 = **卡片级**（`--surface` 底 + `--frame-w` 描边 + `--radius-card`，父行 `--surface-2` 微底）；其余线路 = **列表级**（无底、仅发丝线）。
7. **快慢徽记**：`↑ 快 N 分`（`--brand-green`）/ `↓ 慢 N 分`（`--warn`）/ 平（`--muted`）。绿现服务两处（折叠区「更快」＋ 站条下车站名），用户已接受，但仍保持克制（两者不并置于同一焦点）。
8. **「切换路线」**：蓝框 outline 主操作 + `chevron right`(14px) 暗示"离开当前视图"。
9. **量词修正**：见 §4（原「N 个可换乘」量词错误）。

### 2.4 提醒横幅（`.nav-track__alarm` → 吸底条上方 / sheet 顶部）

| 级别 | 触发 | 底/字 | 文案 | 动效 | 无障碍 |
|---|---|---|---|---|---|
| `soon` | 下一站 = 下车站 | **`--warn-soft` / `--warn`（警告色系）** | `下一站就是下车站：` ＋ `{下车站}`（`--brand-green`）＋ ` · 准备下车` | 无脉动（克制） | `role="alert"` + **震动** |
| `now` | 已到下车站 | `--danger-soft` / `--danger` | `到站了：` ＋ `{下车站}`（`--brand-green`）＋ ` · 请下车` | `1.2s` 脉动（唯一） | `role="alert"` + 震动 |

- **〔2026-09-25 二轮修订〕横幅恢复警告色系，绿只标记"下车站名"**：用户反馈"绿色不像警告色、没有提醒感，只要下车站名绿就行"。故 —— 横幅底/字回到 `--warn-soft`/`--warn`（soon）与 `--danger-soft`/`--danger`（now）；**仅"下车站名（编号+站名）"用 `--brand-green`** 作目标标记。
- **分级理由**：`soon` = 赭黄（还有一站，提醒但不惊慌）→ `now` = 砖红 + 脉动（必须立即动作）。两级形成清晰的**紧迫度阶梯**，比单色更符合"提醒感"。
- **绿聚焦原则（配套）**：站条下车站 = **站名文本绿**；**圆点回归线路色（中性）**、**徽记回归蓝（中性）**——绿不再分散到圆点/徽记。地图下车站 pin 仍为 `--warn`（与横幅同族，强化"下车站"识别）。

- **到站（now）为何不跟着改绿（裁决理由）**：到站是全流程**唯一"必须立即动作"**的时刻，保留 `--danger` 砖红 ＋ 脉动作**唯一的"警报顶点"**；此态下站条其余节点已全部是"已过（灰）"，同屏仍只有一个强调色（红），不破坏克制。**分工：绿＝"这是你的站"（靠颜色识别）、红＝"现在"（靠动效紧迫）。** 若日后用户希望更柔和，可平移为 `--brand-green-deep` ＋ 加强脉动（一行 Token 改动）。
- **提醒方式硬约束：横幅 + 震动；禁止声音**（不播放任何音频/提示音）。

- **位置**：sheet 顶部（详情头之上）——现状即如此，可保持；若采纳全屏化，横幅亦可浮在操作条上方。**结论：保留在 sheet 内容顶部**（避免与吸底操作条争底部空间）。
- **视觉兜底（关键）**：iOS 浏览器无震动 ⇒ 视觉通道必须**三处同步**：① 横幅 ② 站条下车站高亮（绿/红）③ 地图蓝点停在终点。**不依赖单一通道**。
- **内距修正**：`padding: 10px 12px` → `padding: var(--space-3)`(12px)，回到 4px 网格。
- `prefers-reduced-motion` 下脉动关闭（现状已做）。

### 2.5 蓝点（人）与车辆标记（车）——双标记

**视觉对照（必须明确区分）**

| 标记 | 形状 | 色 | 边 | 附加 |
|---|---|---|---|---|
| **车辆（车）** | 30×30 圆角方块（`--radius-btn`）+ 巴士图形 | **线路数据色**（`routes.color`） | `2px` `--surface` 白边 | 车牌标签（白底/`--fg-2` 字/1px `--border`） |
| **蓝点（人）** | Ø12 圆 | `--track-you`（青花蓝） | `2.5px` `--surface` 白边 + `--track-you-ring` 光环 | 可选小标签「您」（蓝底白字，`--text-2xs`） |
| **起点（上车站）** | Ø14 实心圆 | `--brand-green` | `2.5px` 白边 | — |
| **终点（下车站）** | 16×16 水滴（rotate 45°） | `--warn` | `2.5px` 白边 | — |

> **〔2026-09-25 裁决 · 车辆图标〕** 实现层**保留既有 `VehicleMarker` 组件**（运营商涂装 + 5 状态，**不改动**——少动已验证件）；本文件的"线路数据色圆角方块 + 巴士图形"与 `nav-preview.html` 中的车辆图标**仅为预览示意**，不代表实现样式。

**三阶段行为**

| 阶段 | 车标记 | 人标记（蓝点） | 观感处理 |
|---|---|---|---|
| **上车前** | 显示（在途车，可多辆） | 显示在用户 GPS 位（上车站附近） | 车与人**分离**；蓝点带「您」标签；车牌标签归车辆 |
| **上车后（重合）** | 显示（锁定车） | **隐藏独立蓝点**，改为车辆图标**外圈 `--track-you-ring` 蓝环** | 避免"车上叠一个蓝点"的双层杂乱；车辆车牌标签改为 `您 · AA-77-59`（`--accent` 字/边）表达"我在这辆车上" |
| **下车后** | 显示（若仍有在途车） | 恢复独立蓝点（用户 GPS 位） | 车人**再次分离** |

**重合判定（以"上车态"驱动，而非原始距离——避免车在 80m 外驶来就被误判重合）**

```
phase === riding && plate 已锁定   ⇒ 重合：隐藏独立蓝点，车辆图标加 --track-you-ring
phase === boarding / done / 无锁定 ⇒ 分离：显示独立蓝点（用户 GPS 实位）
```
- 与 Spec §4.3 对齐：**上车判定**由 R1（车辆停靠/刚离上车站）**或** R2（GPS 45s 窗口：投影 ≤80m + 沿线位移 ≥150m + 速度 8–80km/h）触发；触发后即进入 `riding` ⇒ 视觉随即重合。
- `--track-merge-dist`（**80m**，对齐 Spec §4.3 的 R2 投影容差）仅作**兜底判据/边界保护**（如 riding 但蓝点偏离车辆 >80m 时提示"疑似已下车"，交纠错入口）；**不作为主判据**。**〔2026-09-25 裁决〕重合判定参数以 `07-技术-接口与组件规格.md` 为准**；本文件与 `design-tokens.nav.json` 中的 80m 为该规格的视觉侧对齐值。
- 实现归属：蓝点图层 = `UserDotLayer`（Spec §7）；车辆 = 既有车辆 marker（zIndex 130）；蓝点 zIndex 140。
- 更新节奏：GPS 通道节流 候车 15s / 乘车 30s（Spec §4.1）⇒ 蓝点移动为"跳变 + 500ms 位移动画"，不做丝滑插值（避免误导精度）。

**重合时的观感细节**
- 蓝环用 `box-shadow: 0 0 0 3px --track-you-ring`（不改变图标尺寸 ⇒ 不引起 marker 跳动）；
- 车牌标签**不新增**第二个标签，而是**替换**为「您 · 车牌」（避免标签堆叠）；
- `prefers-reduced-motion` 下运行动效关闭（蓝环为静态）。

### 2.6 自动上车反馈与纠错入口（新交互）

**背景**：用户拍板"上车判定全自动，放弃确认条"。⇒ 系统**不弹确认框**，而是「**静默切换 + 轻反馈 + 常驻纠错**」。

**① 瞬态轻反馈（toast）**

```
┌────────────────────────────────────────────────┐
│ (locate)  已开始跟踪 51 路 · AA-77-59   [不是这辆] [x] │
└────────────────────────────────────────────────┘
```
- **形态**：单行条（左图标 + 文案 + 内联纠错 + 关闭），`--surface` 底 + `--frame-w` `--border-strong` 蓝框 + `--radius-card`；`z` 高于吸底操作条、低于提醒横幅层级（不打断）。
- **位置**：浮在吸底操作条**上方** 16px 处（不遮挡操作条，也不遮地图主体）。
- **生命周期**：进入 200ms（`translateY(8px) + opacity`）→ 停留 `--toast-dur`(3s) → 退出 200ms；可点 `x` 提前关闭；**不设遮罩、不阻断任何操作**。
- **文案**：`已开始跟踪 51 路 · AA-77-59`（"跟踪"为本项目既有用词，用户已接受；含线路 + 车牌＝具体）。
- **无障碍**：`role="status"`（礼貌播报，非 `alert`，避免打断）；关闭键 `aria-label`。

**② 常驻纠错入口（`纠正`）**

| 入口 | 位置 | 形态 | 语义 |
|---|---|---|---|
| `不是这辆` | toast 内 + 吸底操作条状态行右侧 | 文字按钮（`--accent`） | 自动锁定错了车 → 换一辆（回到候选车选择） |
| `我没上车` | 吸底操作条（等车/乘车中） | 文字按钮 | 系统误判已上车 → 回到等车态 |
| `我已下车` | 吸底操作条 | **主按钮**（`--accent` 实底） | 主动结束本程（推进/到达） |
| `还没到` | 临近下车/已到站时 | 文字按钮 | 误报"到了" → 修正回乘车中 |

- **视觉层级**：**主按钮只有 1 个**（`我已下车`）；纠错一律为**文字按钮**（低重量，`--accent` 文字、无框），避免多个按钮争焦点（对齐"决策点 ≤4 项"：`我已下车` + `不是这辆` + `刷新` = 3 项）。
- **位置理由**：纠错入口必须**常驻可达**（不能只在 toast 的 3s 内），故放在吸底操作条状态行右侧——用户随时能找到，且不占用主按钮位。

**③ 安全网（Spec §4.3 · AC-05 必做项，视觉侧承担）**

| 安全网项 | 视觉呈现 |
|---|---|
| 判据保守（宁可晚判、不误判） | 等车态**不显示**任何"已上车"暗示；自动切换**只发生一次**（切换后 toast 出现，不重复弹） |
| 异常检测 → 纠错入口 | 检出「疑似未上车 / 提前下车」时，**不静默**：状态行右侧显示中性提示（`疑似还没上车` / `疑似已下车`，`--text-2xs` `--meta`）+ 对应纠错按钮**高亮**（`--accent` 文字加粗） |
| 可回退 | 点纠错后回到上一阶段：`我没上车` → 回等车；`不是这辆` → 回候选车；`已下车` → 推进/到达。**方案不丢**（同屏，不重新规划） |
| 手动通道保留 | **〔2026-09-25 裁决〕常显但次要**：等车态操作区恒有一个**弱样式可点入口**「手动标记上车」（`--muted` 文字、无框、`--text-sm`，不抢主视觉）；自动切换成功后随等车态一并消失。理由：Spec §4.3「手动通道始终可用」是防呆底线——全自动一旦不灵，用户必须能找到手动入口；弱化样式已足够克制。 |

- **实现归属**：导航界面主体 = `NavDetailBody`（Spec §7 重写 `RouteDetailBody`）；toast 与纠错入口随 `NavDetailBody` 渲染。

### 2.7 轻轨段（全自动 · 与巴士一致）

> **2026-09-25 修订（重要）**：本段原为「GPS 弱提示 + 估算样式 + 手动兜底」。用户评审后**删除全部「估算 / 手动」字样**，改为**全自动**（GPS 推算推进；精确规格由架构师同期产出）。轻轨体验与巴士**完全一致**。

**体验规格（与巴士同一套）**
- **站条四态 + 「您在这里」**：已过＝灰（＋对勾）／当前·下一站＝青花蓝加粗＋徽记／下车站＝品牌绿／到站＝砖红脉动；「您在这里」为**骑线节点**（纵条不断开，见 §2.2）。
- **下车提醒**：与巴士同一套——下一站＝下车站时 **横幅 + 震动**（**不出声**），到站二次提醒（§2.4）。
- **来源标注**：`实时定位`（GPS 推算推进）；**不出现「估算 / 手动」**。
- **操作条**：与巴士一致——主按钮 `我已下车` ＋ 图标按钮 `刷新`。

**信号弱 / 地下段 —— 「冻结不跳」中性形态**

```
 ● 暂时收不到信号 · 位置停在上一站
```

- **中性样式**：`--muted` 文字 + 一枚 `--meta` 小圆点；**无警告色、无虚线框、无「估算」字样**（与旧版 `.estim` 明确区分，类名 `.note-neutral`）。
- **语义**：**保留最后一次可信进度**（横幅与站条都不回退、不乱跳），恢复后自动续上；诚实但不说技术词。
- **保留**：地图「您」蓝点（用户 GPS 实位）与站点标记照常；**不设**任何"手动模式"入口（全站唯一的兜底通道＝§2.6 的纠错入口）。

### 2.8 地图线规范（灰体系）

| 层 | 形态 | 色 | 线宽 | z | 说明 |
|---|---|---|---|---|---|
| 非乘车区间 | **虚线**（dash `2 14`，cap round ⇒ 圆点线） | `--map-line-dim`（浅灰） | 6 | 68 | 全仓首次引入虚线 |
| 乘车未驶段 | 实线 | 线路数据色（`routes.color`） | 6 | 72 | — |
| **已驶过路段** | **实线** | `--map-line-passed`（灰，比 dim 深一档） | 6 | 74 | 替代原绿覆层；压在最上 |
| 站点 | 圆点 | 线路数据色描边 | — | 90/95 | 不变 |
| 车辆 / 蓝点 | marker | 见 §2.5 | — | 130 / 140 | — |

- **区分依据**：已驶过（灰实线）与非乘车（灰虚线）**靠线型区分**（实 vs 虚）+ 明度（深灰 vs 浅灰）双重区分 ⇒ 同色系不混淆。
- **端点**：`lineCap/lineJoin: round`（沿用，不改地图引擎参数）；已驶过实线末端点 = 车辆坐标，由蓝环/车辆 marker 盖住线头。
- **不画"断头线"**：某段无 shapes ⇒ 不画线（沿用现状）。

2. **绿的唯一性**：深色下 `--brand-green #6DD58C` 是**高饱和亮绿**，若站条已过也用绿会非常抢眼 —— 已过改灰后此问题消失；折叠区「更快」绿为唯一，仍是"每屏 ≤1 处绿"。

## 4.5 排版策略（全稿约束：单行不折行 · 禁截断）

> **2026-09-25 用户要求**：同一条信息**不得折行**、**不得用省略号截断**（禁 `text-overflow: ellipsis`）。对可能超长的信息，用**排版调整**保证单行完整——而不是截断。

### 4.5.1 硬规则

| # | 规则 | 反例（禁） | 正解 |
|---|---|---|---|
| 1 | 同一条信息（站名 / 线路标签串 / 按钮文案 / 数值+单位）**不折行** | 站名折成两行 | `white-space: nowrap`，靠版式让位 |
| 2 | **禁省略号截断** | `…` / `ellipsis` | 用**字号档位 / 容器弹性 / 间距重分配 / 次要信息让位** |
| 3 | 允许**行级换行**（如方案行整体重排到第二行） | — | 但**单个信息单元**必须完整（标签串作为不可折断的整体） |

### 4.5.2 四类易超长信息与对策

| 信息 | 最长示例 | 对策 |
|---|---|---|
| **站名** | `離島醫療綜合體`（7 字）、`澳門科技大學（B/C 座）`（含括号+拉丁字符） | 站条 `.slbl` 设 `nowrap`；该行**让位次要信息**（去掉右侧"跳数/约 N 分"），字号保持 `--text-md` |
| **方案行线路标签串** | `[25] → [3] → [51]`（3 段换乘） | 标签串整体 `nowrap`（不可折断）；收紧 chip 内距（`0 6px`）、`.rstack/ .main` 间距（`gap:6px`）、按钮内距（`6px 9px`）后仍单行；极端再长时允许**行级换行**（按钮落到第二行右对齐） |
| **按钮文案** | `切换路线`（4 字 + 图标） | 按钮 `nowrap`；`padding` 紧凑；不与长信息同挤一行 |
| **操作条状态行** | `● 乘车中 · 轻轨 石排灣線` + 来源标签 + 右侧 `下一站 石排灣` | 状态行 `nowrap`；右侧信息可**让位**（紧急信息优先）——与 §2.1「新鲜度让位」同一策略 |
