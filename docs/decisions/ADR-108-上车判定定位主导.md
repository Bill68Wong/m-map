# ADR-108：上车判定改为「定位主导」，车辆降级为佐证

## Status

Accepted（2026-10-29，用户裁决「定位主导，车辆仅辅助；车辆不得单独触发」）

## Background

v2.14 引入全自动上车（`src/lib/nav/boarding-detect.ts`），设计意图是"宁可晚判、不误判"，
文档也这么写。但实现上车辆通道（R1）成了**独立触发器**，且优先级最高：

`boarding-detect.ts:226-230`

```ts
// 巴士：R1 优先
const r1 = r1Of(input.vehicles, input.boardMain, input.boardPos);
if (r1.kind === "strong") {
  return { hit: true, plate: r1.plate, source: "vehicle", reason: "r1", streak: prevStreak + 1 };
}
```

这一句**在几何可用性判定之前返回**（`geomOk` 在 `:208` 算好，到 `:231` 才用来挡退化），
即 GPS 通道完全不参与。而 R1 strong 的判据是「任何一辆车的 `interval.from` == 本上车站」
（`:83-85`），对应 DSAT 的 `status=0`「已离开挂载站、正驶向下一站」
（`api/route-vehicles/route.ts:221-226`）—— 这是一个**持续 40~180 秒的时间窗**，不是瞬间。

再叠加两处：

- `tryAuto` 对 R1 免除多帧确认：`useRideTracking.ts:530`
  `if (res.reason === "r1" || res.streak >= R2_STREAK)` —— R2 需连续 2 帧，R1 一帧即切；
- 冷却基准在「开始导航」时被清零：`useRideTracking.ts:729`（`lastSwitchTsRef.current = 0`），
  于是 `nowMs - lastSwitchTs` 恒 > `SWITCH_COOLDOWN_MS(20s)`（`boarding-detect.ts:206`），
  冷却对首次判定完全不生效；每换一腿又重置一次（`:852-853`）。

用户体验因此是：「点开始导航 → 12 秒内只要该方向有车刚离开我的上车站，就被判成已上车」，
即"第一辆车到站（刚走）就被判上车"，无论我人在不在站台。

## Decision

**巴士段不再接受"车辆单独触发"。** 定位（R2）是唯一主判据，车辆只用于**降低门槛**。

判定模型（`autoBoardOf` 巴士分支重写）：

- 硬门：几何可用（`colored.length ≥ 2 && !degraded`）+ 有 ≥3 帧可信 GPS（`accuracy ≤ 150m`）
  + 冷却已过 + 本腿未自动触发过。**几何缺失时巴士也不再自动判**（比现状更严）。
- 定位三项：投影在容差内（`tol = max(80, accuracy×1.5)`）、沿线位移 ≥ `max(60m, 5.5km/h×dt)`、
  平均速度 ∈ `[5.5, 80] km/h`。
- 车辆佐证（只降门槛）：存在车 `interval.from == 上车站`（刚离站）或车停靠/挂靠上车站 ⇒
  位移门 ×0.6、所需帧数 3 → 2；否则 ×1.0、3 帧。
- `AutoBoardResult` 增加 `need: number`；调用方统一 `if (res.hit && res.streak >= res.need)`，
  **删除** `res.reason === "r1"` 这个特权分支。

配套（对应 AC-25a）：

- 新增纯函数 `detectPausedOf(fixes, nowMs)`：无帧 / 60s 无新帧 / 连续 2 帧 `accuracy > 150m` ⇒ paused；
- `paused` 时：明示「定位不可用 · 自动上车判断已暂停，到站后请手动点「我已上车」」，
  保留手动入口，且**不得**把"未判定"渲染成"正在检测"。现状反例：
  `NavTrackBar.tsx:110` 硬编码 `right = "正在检测车辆"`。
- 新增观测钩子 `.nav-actions[data-board-detect] = on | paused` 与
  `.nav-actions[data-board-source] = gps | gps+vehicle | manual`（**不得出现纯 `vehicle`**）。

## Consequences

正面：

- 消除"人在家里被判上车"这一类误判，且误判来源（车辆时间窗 40~180s）从机制上被切断。
- 判定逻辑全部收敛到纯函数，可用 `scripts/test-boarding-detect.ts` 对拍（防"沉默逻辑错误"）。
- 误导性文案（"正在检测车辆"）与误导性状态（未判定 ⟶ 正在判定）一并修正。

负面（均已承接）：

- **漏判率上升**：隧道、室内、GPS 拒权、手机休眠时无法判定。承接方式 = 三件套
  （明示 + 手动入口 + 可断言钩子），而不是放宽阈值。
- 「自动上车」不再是**必然**路径。任何写成"系统必须自动进入 riding"的验收句都必须加前提
  （"定位可用且用户随车移动"），否则 e2e 必然红 —— e2e 需注入 `context.setGeolocation`。
- 候车阶段仍需 12s 轮询车辆 + 1.5~3s GPS 帧，判定频率比"一帧即切"更高，但每次都是纯计算，
  不增加外部调用。
