# ADR-104：收藏模型 v3（组合 + 地点两实体；方案层退役）

## Status

Accepted（2026-09-26 深夜 · team-lead 确认模型方向；Q5 裁定「地点来源 = 高德 POI 与我们的站点**两者都支持**」）

## Context

- 需求（台账 §二）：收藏 = **「组合（起点→终点）」+「地点（单点）」** 两类；系统**预置路线全删**；「保存具体方案 / 站链编辑 / 流程图编辑 / 步行覆盖」整体退役；分组「组合在上 / 地点在下」；点组合 = 首页式实时规划。
- 现状 v2：`localStorage["must.favorites.v2"]`（`FavoritesFileV2{schemaVersion:2, seedVersion?, combos:Combo[]}`）。
  - `Combo` = OD + `chain?` + `walk?` + `tiers?` + `plans: ComboPlan[]`（**两级**：组合 → 方案）。
  - 预设：`presets.ts`（`SEED_VERSION=2`，生成 **10 组合**）+ `route-presets.ts`（**31 条预置路线**）；`applySeed` 幂等补种。
  - v1 键 `must.favorites.v1`（`PlaceFavorite|PlanFavorite`）保留、按需 `migrateV1`。
- 约束（红线）：预设删除**必先备份**；收藏老数据**不丢**（迁移兼容）。

## Decision

1. **模型 v3（键 `must.favorites.v3`）**：
   - `ComboV3 { id, type:'combo', name, from, to, createdAt, updatedAt, pinned?, lastUsedAt? }`（**无** chain/walk/tiers/plans）；
   - `PlaceV3 { id, type:'place', endpoint:FavoriteEndpoint, name?, createdAt, updatedAt, pinned?, lastUsedAt? }`；
   - `FavoritesFileV3 { schemaVersion:3, updatedAt, migratedFrom?:'v2', combos, places }`。
2. **退役**：`ComboPlan` 类型与 `plans` 字段、`PlanFavorite/PlanSnapshot/planFingerprint`（收藏层用途）、组件 `RouteFlow/RouteFlowEditor` 与 `ComboPlans` 的方案子列表、`ComboEditor` 的方案编辑、`presets.ts` 补种逻辑 + `route-presets.ts`（31 条）。
3. **迁移（备份双层 → 删预设）**：
   - ① **导出 JSON**（下载 `must-favorites-backup-<时间戳>.json`，含 v2 全文；若 v1 存在一并导出）；
   - ② 写**本地隐藏备份键** `must.favorites.v2.backup`（= v2 全文 + 时间戳，不参与 UI 读取）；
   - ③ `migrateV2ToV3`：`combos` 丢 `plans` 保留 OD；`places` 由单点来源构建；**`isDefault` 组合与 31 条预置全部删除**；`seedVersion` 机制下线（不再自动补种）；
   - ④ 读优先 `v3`；缺 v3 且有 v2 → 迁移；**v2 / v1 键不删**。
4. **回滚**：删 `v3` 键即可回读 v2（原 v2 键 + 备份键俱在）。
5. **复用首页导航态**：点组合 → 以 `from/to` 发起首页式规划（复用 `NavShell` stage 机 + `useRecommend`，方案进导航弹窗）；点地点 → 首页式选点（`to=地点`，`from=我的位置`）。收藏入口（搜索结果确认后「收藏地点」）；按钮文案「收藏组合」（起终点页 + 推荐弹窗顶部），**导航弹窗不设收藏**。
   - **Q5 裁定**：地点来源**两者都支持**——高德 POI 与我们的站点均可就地收藏；`PlaceV3.endpoint` 存 `kind/code/poiId`（与 `FavoriteEndpoint` 同构）。

## Considered Options

1. **保留两级（组合+方案）仅隐藏 UI**：与台账「方案层整体退役」冲突，且保留 `planId/fingerprint` 回放复杂度。
2. **原地改 v2 结构并就地删预设**：风险高（老数据不可逆）；违背「先备份」红线。
3. **新键 v3 + 迁移 + 备份双层（采纳）**：兼容最好、可回滚、满足数据安全红线。

## Consequences

- 正面：模型简化（两实体）、界面收敛、回放稳定（不再依赖跨请求不稳定的 `planId`）；数据安全（导出 + 隐藏键 + 旧键不删）。
- 负面：需一次性迁移与多处组件下线；`Combo` 字段（chain/walk/tiers）删除后，任何仍引用它们的代码必须同步清理（编译期可查）。
- 风险控制：迁移为纯客户端 `localStorage` 操作、单测覆盖（丢 plans / 删预设 / v1→v3）；备份键存在性纳入回归。
- 验证：迁移后组合保留、方案层消失、预设删除、导出 JSON 与备份键存在；点组合进首页式规划可用。
