# ADR-106：拆除访问口令门与开发者模式，改为「全站公开 + 写接口分级防护」

## Status

Accepted（2026-10-29，用户裁决）

## Background

M Map（澳搭車）自 v1.1.10 起采用 **fail-closed 口令门**（`src/middleware.ts`）：只有显式登记在
`PUBLIC_PAGES` / `PUBLIC_PREFIXES` / `PUBLIC_FILES` 的路径公开，其余一律要求 `ACCESS_PASSWORD`
对应的 `mx_auth` cookie。当时的产品口径是「网站是做给别人用的，当然要公开」+「开发者模式只有我能开」，
因此把「推荐/详情/合规」设为公开、「记录/统计/自由记站/计时」设为受保护。

到了 v3.6.0，这两条前提都变了：

1. 产品定位从「学校通勤工具」转为「全澳导航 PWA」，口令门与"给公众用"直接冲突；
2. 开发者模式的实际 UI 早已消失（`DevModeToggle` 自 v3.2 起不在任何页面渲染，
   `CardDevActions` 亦不再渲染，注释见 `HomeClient.tsx:12`、`RecommendClient.tsx:15`、
   `CardDetailClient.tsx:341-342`），口令门事实上只在保护「采集类四页」。

但**拆门不是删一个 if**。核查全部 21 个 `route.ts` 后确认：**只有 `/api/cron/rebuild` 自带
Bearer 鉴权**（`api/cron/rebuild/route.ts:59-67`），其余 20 个接口**完全依赖 middleware 顺带保护**。
其中 `POST /api/dsat/grab`（`api/dsat/grab/route.ts:44`）会解析 DSAT 响应并写 `segment_samples`
等采样表，且会触发外部 DSAT 请求 —— 拆门当天就是「任何人 POST 一个空 JSON 即可污染唯一数据资产
并放大 DSAT 调用」。这已经越过程序缺陷，命中项目风控红线（铁律 19 / 36）。

## Decision

拆除口令门。`middleware.ts` 只保留**路径重定向**与**分级防护表**，不再读取 `ACCESS_PASSWORD`。

1. **页面**
   - `/routes`：**整目录删除**（`git rm -r src/app/routes`），访问自然 404，不保留 308；
   - 采集类四页 `/timer` `/records` `/stats` `/free` 及 `/finish`：**全部下线**，308 → `/`；
   - 其余页面（`/` `/card` `/commute` `/favorites` `/help` `/recommend` `/line/[code]`）全公开。
2. **接口按四类处置**（不允许存在"仅靠中间件顺带保护"的接口）
   - **A1 采集/运维**：`POST /api/dsat/grab` → Bearer `GRAB_TOKEN`（照 `cron/rebuild` 写法），
     未通过返回 `401 {"error":"unauthorized"}`；**保留既有 `RISK.timerGrab.enabled`
     风控开关作为第二道闸**（`api/dsat/grab/route.ts:46`），两道闸互不替代。
   - **A2/A3 退役写与单条读**：`/api/timer/*` + `/api/free/*`（17 个路由）→ `410 {"error":"gone"}`，
     **由 middleware 的 `GONE_PREFIXES` 统一实施**，17 个 handler 零改动。
     单条读必须一起关：`timer_sessions.id` 为 `SERIAL`，公开后可顺序枚举 = 真实出行记录泄露。
   - **A4 已有公开写**：`/api/fav-routes` 保持公开（收藏页是产品功能），加三道护栏：
     同源校验（跨站/缺 Origin ⇒ 403）、body ≤ 16KB、`fav` 令牌桶。
     **不硬造认证** —— 无账号体系时造出来的"认证"只是装饰。
   - **B 只读**：全公开，但 `/api/station/eta`、`/api/dsat/eta` 走新增 `dsat` 令牌桶
     （复用 `amap_rate_bucket` 表加行，**无 DDL**），否则拆门等于把 DSAT 配额送给第三方。
3. **错误体**：所有 4xx/5xx 的 `error` 只允许固定枚举
   （`unauthorized` / `gone` / `forbidden` / `rate_limited` / `bad_request` / `upstream_error`），
   禁止回显 `err.message`、SQL、环境变量名。现状 `api/nav/route.ts:136` 的 `msg.slice(0, 500)` 一并收紧。
4. **白名单机制保留为"可恢复的设计记录"**：`PUBLIC_*` 常量删除，但 `middleware.ts` 头部保留
   一段注释块记录 v3.5.5 的 fail-closed 设计与"恢复上锁的 3 步"，本 ADR 作为其正式出处。

## Consequences

正面：

- 全站对公众可用，与产品定位一致；不再存在"忘登记白名单 ⇒ 生产 401"这一类事故
  （`middleware.ts:50-56` 记录该项目已踩过 3 次）。
- 拆门同时补齐了 20 个接口的鉴权/限流缺口，其中 `dsat/grab` 是修掉了一个真实可利用的写库洞。
- 净减约 700 行代码，删除 8 个文件 + 1 个 CSS 块，无新增依赖、无 DB 迁移。

负面（均已承接）：

- **隐私面扩张**：`/records` `/stats` `/free` `/timer` 曾被口令门保护，现在整页下线（不只是接口）。
  代价是这些历史功能对用户不可达。
- `ACCESS_PASSWORD` 仍留在 Vercel 环境变量中。本 ADR 明确**代码层不再读取**，
  避免"改完代码但线上仍锁站"的运维耦合；建议清理，但不是必须。
- `/api/fav-routes` 仍公开可写，残余后果是「任何人可塞垃圾收藏行」。影响面限于数据质量，
  不涉隐私与库结构；已作为已知风险入 PM 文档 R1。
- 门禁脚本必须重写：`.verify/_check-middleware-public.ts` 从「断言受保护页被拦」改为
  「断言全公开 + 308 + 410 + 401 + 403 + 无内部信息」；`.verify/e2e-devmode.mjs` 整脚本删除。
