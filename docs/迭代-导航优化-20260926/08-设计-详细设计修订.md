### 2.1 头部：去灰框 + 总用时/线路标签同行（`NavDetailBody.tsx`）

**现状根因（复核保留）**：`globals.css` 中**没有 `.rc-detail__head` 规则**（全仓仅 JSX 一处引用），头部只吃到 `.card` ⇒ `display:block` / `padding:0` / `1px solid` / `radius 10px` ⇒ 文字顶边框 = 用户所见「灰框紧紧框住」；且非 flex ⇒ `margin-left:auto` 失效，到达时刻与线路标签被挤到第二行。

```css
/* ① JSX：<div class="card rc-detail__head"> → <div class="rc-dhead">（去掉 .card） */
/* ② CSS（globals.css 新增） */
.rc-dhead{
  display:flex; align-items:flex-start; gap:var(--space-3);
  flex-wrap:wrap;
  padding-bottom:var(--space-3);
  border-bottom:1px solid var(--border);       /* 唯一分隔：下划线，不是四方框 */
}
.rc-dhead__l{display:flex;flex-direction:column;gap:2px;min-width:0}
.rc-dhead__total{display:flex;align-items:baseline;gap:2px}
.rc-dhead__total .rc-total{font-size:30px;font-weight:700;line-height:1;letter-spacing:-.02em;
  font-variant-numeric:tabular-nums;color:var(--fg)}
.rc-dhead__total .rc-total__unit{font-size:14px;color:var(--muted);font-weight:500}
.rc-dhead__arrive{font-size:var(--text-xs);color:var(--muted);white-space:nowrap}
.rc-dhead__arrive b{color:var(--fg);font-weight:var(--fw-emphasize);font-variant-numeric:tabular-nums}
/* 右上：线路标签总览（与总用时同一行） */
.rc-dhead__r{
  margin-left:auto;                            /* 必须处于 flex 容器内才生效 ← 本次修复关键 */
  display:flex; align-items:center; gap:var(--space-2);
  flex-wrap:wrap; justify-content:flex-end;
  max-width:56%;                              /* 防多段换乘标签把左列挤窄 */
}
```

|---|---|
| 一行两栏 | `.rc-dhead__l` 与 `.rc-dhead__r` 的 `getBoundingClientRect().top` 差值 ≤ 2px |

| 三程换乘 | `A/B → C/D → E` 时右列换行但**不挤压**左列（`max-width:56%` 兜底） |

`{degraded && <span className="nav-degraded nav-degraded--inline t-label">估算</span>}` ⇒ **整行删除**（`globals.css:2430-2438` 的 `.nav-degraded` 若他处仍用则保留规则，仅删该分支）。

### 2.3 下车横幅：单行式 + 浮层化（`AlightBanner.tsx`）

**定稿文案（用户已拍板）**

| 态 | 文案 | 视觉 | 实测宽度 |
|---|---|---|---|
| `soon` | `准备下车 · {站号} {站名}` → 例：`准备下车 · T345 氹仔客運碼頭` | `--warn-soft` 底 / `--warn` 字 / 600；站名 `--track-alight` / 700 | ≈180px（容器可用 ≈300px）→ **不溢出** |

**三条硬规则**
1. **站号 + 站名原样保留**（含繁体、含 `T345` 前缀），不做任何截断/缩写；
2. **删除** `AlightBanner.tsx` 中的 `<span className="nav-alarm__hint">横幅 + 震动</span>`（开发期说明，不得出现在用户界面）；`.nav-alarm__hint` 样式规则一并删除；

**浮层化（Spec §7「横幅浮层化」）**

/* 现状：横幅在 .route-sheet__scroll 滚动流内 ⇒ 被滚走 + 出现/消失推挤内容（布局抖动） */
/* 定稿：挂到面板内容层，绝对定位于内容顶部，不参与滚动 */

**现状问题**：只显示 `换乘步行 N 分（atLabel）`，**等车被隐藏** ⇒ 换乘方案在列表里看起来总比直达快（用户需求 7 的观感根因）。

|---|---|

| 数据来源徽标 | 命中 `route_frequency.headwayAt` → `按班距估`；轻轨命中 `lrt_timetables` → `按时刻表`；**均未命中** → 不显示数字，改 `等车时长待确认`（明确降级，**不得拍脑袋设默认值**，见 AC-61） |

### 2.5 吸底操作条防跑位（`RouteSheet.tsx` 等 —— 定稿方案②）

**现状实测（复核保留）**：拖动 `full↔half↔peek`，松手后 `.nav-actions` 的 y 采样 `170 → 321 → 591 → 642`（约 300ms 横跨 472px，中途盖住正文）；`full→peek` 时先冲到 `1202`（越出视口 844）再回弹。

**根因**：面板位移走 `transform`（合成层、不动布局）；操作条用的是 `bottom`（**布局属性**）+ `transition` 补偿 ⇒ 两者永远不在同一时基。

**定稿实现（方案②：换挂载点）**

```css
/* 现状：.nav-actions { position:sticky; bottom:calc(var(--sheet-y-layout)); transition:bottom … } */
/* 定稿：把操作条移出 .route-sheet__scroll，挂到 .route-sheet 根，与面板同 transform 上下文 */
.route-sheet{ position:absolute; /* 既有 */ }
.route-sheet__actions-slot{
  position:absolute; left:0; right:0; bottom:0; z-index:20;
  background:var(--surface);
  border-top:var(--frame-w) solid var(--border);
  padding:10px var(--space-4) max(10px, env(safe-area-inset-bottom));
  display:flex; flex-direction:column; gap:var(--space-2);
}
/* 滚动容器为操作条让位（既有 padding-bottom:96px 同义，改为变量化） */
.route-sheet__scroll{ padding-bottom:calc(96px + env(safe-area-inset-bottom)); }
/* 渲染期去掉过渡补偿（不需要了） */
.nav-actions{ position:static; bottom:auto; transition:none; margin-top:auto;
  padding:0; background:transparent; border-top:0; }
```

**实现要点**
1. `NavTrackBar` 的 DOM **结构不变**（`.nav-actions` 及内部 `staterow / btnrow / note` 类名全保留 ⇒ QA 断言不受影响），只改**挂载位置**：从 `.route-sheet__scroll` 内移到 `.route-sheet` 根下的 `.route-sheet__actions-slot`；
2. 面板 `full / half / peek` 三档下操作条都跟随面板移动（同一 `transform`），**物理上不可能跑位**；
3. `peek` 档时若操作条仍在视口外，属预期（面板 80% 收起）—— QA 断言以「相对面板上缘的距离」为准，而非绝对 y；
4. `prefers-reduced-motion` 下无额外处理（无过渡即无问题）。

**AC-58 视觉验收（数值口径，可直接写入 QA 用例）**

| 断言 | 判据 |
|---|---|
| 拖动中跟随 | `full↔half↔peek` 各往返 3 次；采样 `navActions.y − sheet.y` 的变化幅度 ≤ **2px** |

### 4.1 偏好模型 UI（定稿 · 详见 `04-pref-model-v2.html`）

| 项 | 规格 |
|---|---|

**排序规则（已锁定）**

| 档 | 第一键 | tie-break | 参数 |
|---|---|---|---|
| 综合（默认） | `cost` 升序 | ① 换乘次数 ↑ ② 步行量 ↑ ③ 来源（高德优先）④ `planId` | `cost = totalMin + α×换乘次数 + (β−1)×步行分钟 + 紧接换乘风险项`；**α = 10 分/次**、**β = 1.8**、**安全余量 3 分钟** |
| 少换乘 | `transferCount` 升序 | `cost` ↑ → 步行量 ↑ → 来源 → `planId` | 换乘次数为硬第一键 |
| 少步行 | `walkMin` 升序 | `cost` ↑ → 换乘次数 ↑ → 来源 → `planId` | 步行 = 上车前 + 换乘 + 下车后总和 |

**三条口径铁律**
1. **α / β 不进 `totalMin`**：卡面时间与明细一致，排序用广义成本（避免「显示 22 分却排在 24 分之后」的解释困境）；
2. 三档**都不得出现不可行方案**（赶不上换乘 ⇒ 先顺延/剔除，AC-61）；
3. 偏好**只作用于推荐/导航排序**；`switch-plans` 组内**保持 `totalMin`**（保契约）；参数落在 `score.ts` 常量，前端只读。

**徽标语义（只 3 种，不新增颜色）**

| 徽标 | 触发 | 视觉 |
|---|---|---|
| `推荐` | 当前档下 `cost` 最小者 | `--accent-soft` / `--accent` |
| `更快` | 列表中 `totalMin` 最小者（且非「推荐」） | `--brand-green-soft` / `--brand-green`（全屏唯一绿） |
| `含等车 N 分` | 方案含换乘时**始终**披露 | `--warn-soft` / `--warn` |

### 4.2 换乘等待（需求 ⑦）与偏好（⑧）的联动

- 换乘等待来自 `route_frequency.headwayAt`（**偏保守取值**，具体分位由 Phase 2 架构师标定，须可对账）；轻轨用 `lrt_timetables`；**缺失时明确降级标注**，禁止常量默认值（AC-61 断言 `BUS_HEADWAY_FALLBACK_SEC/2` 直用为 0 处）。
- 等待时长**计入 `totalMin`**（因此换乘方案不再凭空更快）；`α`（换乘不便）只在排序中用。
- 设计表现见 §2.4（换乘行）与 `04-pref-model-v2.html`（卡片明细 + `含等车 N 分` 徽标）。

### 4.3 自动判定（需求 ⑨）的设计约束

| 场景 | 设计约束 |
|---|---|
| 自动上车成功 | **瞬态反馈（≤2.5s toast）+ 常驻纠错入口**（`不是这辆`）；反馈非模态、不遮挡地图 |
| 自动上车失败/低置信 | `等待上车` 态保留 `手动标记上车`（弱样式按钮）+ 原因说明（既有文案）；**不弹模态** |
| 自动下车成功 | `我已下车` 主按钮降级为**纠错**语义（自动完成时无需用户点），但按钮**必须常驻**（防误判）；**新增 `撤销` 出口**（Spec §7 `onUndoAlight`），撤销入口须在 44×44 触摸区内 |
| 通用铁律 | 任何自动判定都必须有 ≤1 个纠错出口，且出口 ≥44×44px；判定状态必须**可见**（不许静默） |
| 全屏化 | `body[data-nav="riding"]` 隐藏底导（既有）；但**必须**保留「正在导航」的持续指示（品牌栏线路标签 + 呼吸蓝点）⇒ 否则用户会以为导航已结束 |

### 4.4 底图自带站点（需求 ⑩）的验收视觉项

| 项 | 判据 |
|---|---|
| 底图不得出现高德公交站标/站名 | 随机 3 个缩放级别截图；地图上站点标注总数 = **我们图层的 marker 数**（无双层、无多出来的底图站名） |
| 实现路径 | 仅走 `mapStyle`（自定义样式 ID），`setFeatures` 属幻觉接口**禁用**（Spec §11） |
| 环境要求 | `AMAP_MAP_STYLE_ID` 须与 jsKey **同账号**；未配置 ⇒ 视为**验收不通过**（会出现双层站点）；配置失败 ⇒ 回退默认样式（降级安全，但同样判不通过） |
