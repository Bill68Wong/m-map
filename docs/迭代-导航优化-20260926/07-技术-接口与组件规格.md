## 2. 组件级实施规格

### a. 取景让位锁（需求 ①；AC-25~28 / AC-58 / AC-59）

#### a.1 状态机

```
        ┌──────────────── 用户点「重新居中」/点定位键 / 双击地图 ────────────────┐
        ▼                                                                      │
   follow ──dragstart──▶ free ──dragstart/手势 zoomstart──▶ free（保持）────────┘
     │                    │
     └──地图首次就绪──────┘（初始 follow）
```
- **事件**：
  - `map.on('dragstart', onUserGesture)` → `free`（拖动恒为用户行为）；
  - `map.on('zoomstart', onUserGesture)` → 仅当 `!programmaticRef.current` 时 → `free`；
  - `map.on('dblclick', restore)` → 恢复 `follow` + 重放当前取景（辅助入口）。
- **程序化调用打标分离**（关键）：所有程序化相机调用一律经封装函数
  ```ts
  const programmaticRef = useRef(false);
  const applyCamera = useCallback((fn: () => void) => {
    programmaticRef.current = true;
    try { fn(); } finally { window.setTimeout(() => { programmaticRef.current = false; }, 350); }
  }, []);
  ```
  `setZoomAndCenter` / `panBy` / `setBounds` 全部包在 `applyCamera` 内 ⇒ `zoomstart` 中判 `programmaticRef.current` 即可区分「手势缩放」与「程序缩放」。

#### a.2 状态存放 + 钩子写入点

```ts
const [followState, setFollowState] = useState<'follow' | 'free'>('follow');
const followRef = useRef(followState);
followRef.current = followState;
useEffect(() => { canvasRef.current?.parentElement // .nav-map 根
  .setAttribute('data-map-follow', followState); }, [followState]);
```
> 根元素加 ref（`rootRef`）以写钩子；`data-map-follow='follow'` 时**隐藏**恢复按钮。

#### a.3 取景 effect 守卫（AC-59 核心）

`NavMap.tsx` 现取景 effect L563-673。改造：
1. **依赖收敛**：`[view, dest, origin, phase]` → **仅 `[view.tick, phase]`**（`dest`/`origin` 改从 `destRef`/`originRef` 读，ref 在渲染期同步赋值，参照既有 `viewRef` L256-257）；
2. **让位守卫**：在 L565 守卫之后加一行：
   ```ts
   if (followRef.current === 'free') return;   // ★ 让位锁：free 态跳过一切自动取景
   ```
3. **数据刷新禁调**（AC-59）：`setZoomAndCenter` / `setBounds` / `panBy` 的调用点**收敛到唯一入口** `applyView(cmd)`（从现 effect body 抽出），该函数**只被两处调用**：① 取景 effect（`view.tick` 变化）；② 恢复按钮/双击 `restore()`。**严禁**在任何数据 effect（`overview` 绘制 L1020-1048、站点图层 L721-879、车辆、`dest`/`origin` 标记 effect L485-554）中调用。

#### a.4 恢复入口（挂点 + 类名 + 样式钩子）

- 挂点：`NavMap` 内浮层（`.nav-map` 内、VehicleLayer 之后的 DOM，避免被地图 canvas 覆盖）：
  ```tsx
  {followState === 'free' && (
    <button type="button" className="nav-map__recenter" data-recenter="on"
      onClick={restore} aria-label="回到路线">回到路线</button>
  )}
  ```
- 样式钩子：`.nav-map__recenter`；定位建议 `.nav-map` 右下（`position:absolute; right:12px; bottom:calc(96px + safe-area)`；`pointer-events:auto`；z-index 高于地图容器、低于面板与卡浮层）。
- `restore()`：`setFollowState('follow')` + `applyView(lastCmdRef.current ?? view)`。
- **与 locateTick / 显式意图的交互**：
  - `locateTick`（点定位键）→ 视为**显式意图**：先 `setFollowState('follow')`，再 `runLocate({ focus: true })`；
  - `runLocate` 的 `applyLocateView`（L267-298）现有「有 view 意图则不抢镜头」守卫（L282）→ 加 `focus` 参数：`focus===true` 时**跳过该守卫**（强制居中）；
  - `frame()`（打开面板/切 pane/换 OD/切舞台，NavShell L200-216）→ 亦视为显式意图：调用方 `frame()` 前**不**强制改 follow（保持 free 的语义是「用户此后不再被打断」）；但**首次进入 detail 的取景**（follow 初值）正常生效。
  - ⚠️ 决策（锁定）：**`free` 态下 `frame()` 指令一律被 a.3 守卫跳过**；用户要恢复取景须点恢复按钮/定位/双击。这满足 AC-27「只手动回中」。

#### a.5 边界

- 卸载/重建地图（`jsKey` 变，L444-461）→ `followState` 复位 `'follow'`；`programmaticRef` 复位。
- 无 `map` 时所有事件不注册（沿用 `phase==='ready'` 守卫）。
- `prefers-reduced-motion` 不影响本机（无动画）。

### c. 蓝点投影链（需求 ⑤；用户拍板 = 手机 GPS）

#### c.1 数据结构

#### c.2 投影算法（视觉层跟 GPS）

```ts
const YOU_SNAP_MAX_M = 60;                 // Token --you-snap-max
// riding && userFix && leg.colored.length>=2 && !leg.degraded：
const proj = nearestOnPath(leg.colored, fix);      // 最近顶点（track.ts cutAt 同源）
if (proj.distM <= YOU_SNAP_MAX_M) {
  const p = leg.colored[proj.idx];
  youDot = { lng: p[0], lat: p[1], src: 'gps', frozen: false, ts: fix.ts };
} else {
  youDot = lastGoodDot ? { ...lastGoodDot, frozen: true } : null;   // 投影失败 ⇒ 冻结不跳
}
// 非 riding（boarding/off/done）：youDot = null（NavShell 回落到 userFixR.fix 原始 GPS）
```
- **吸附失败 → 冻结上次好点**（`lastGoodDotRef`），**绝不跳到别处**（铁律：对不上就冻结）。
- ⚠️ **`nearestOnPath` 只取最近顶点**（无线段插值，`route-overview.ts` L127-139）→ 蓝点会「逐顶点跳」。**平滑**：marker 位置加 CSS/AMap 过渡（设计 §4.1「marker 位置过渡 1000ms linear」），或后续升级为「线段投影」；本批次以过渡抹平，**不新增几何插值**（控范围）。

### d. NavStrip 插值用户点（需求 ⑤；AC-43/44）

#### d.1 数据结构（`StripNav` 扩展）

```ts
export interface StripNav {
  passedIdx: number; nextIdx: number | null; atIdx: number | null;
  alarm: 'none' | 'soon' | 'now';
  youAt: { afterIdx: number; frac: number } | null;   // ★ 新增
}
```

#### d.2 `frac` 两分支（纯函数，放 `track.ts`）

```ts
// 车辆源：区间估算 —— 用车辆坐标投影到 leg.colored 得里程，落在 [ladder[passedIdx], ladder[passedIdx+1]] 内插值
// GPS 源 ：lrt-progress 已算 distNow（沿线里程 L131）⇒ 与 ladder 插值即得 frac
export function fracBetween(cum: number[], i0: number, i1: number, dNow: number): number {
  if (i0 < 0 || i1 <= i0) return 0;
  const a = cum[i0], b = cum[i1];
  if (!(b > a)) return 0;
  return Math.max(0, Math.min(1, (dNow - a) / (b - a)));
}
```
- **停靠中**（`atIdx !== null`）：`youAt = { afterIdx: atIdx, frac: 0 }`（点落在节点上）。
- **行驶中**：`afterIdx = passedIdx`，`frac = fracBetween(...)`（GPS 用 `distNow`；车辆用车辆投影里程）。
- `do nothing` 情形：`passedIdx < 0 且 atIdx===null`（尚未到上车站）→ `youAt = { afterIdx: -1, frac: 0 }`（点在上车站之前，同上轮 `youAnchor=-1` 语义）。

#### d.3 渲染（NavStrip.tsx）

- **删除** L110-119 `youNode` 与 L124/126/147/162 的 `youAnchor` 插入。
- **停靠中**：复用既有 `.navstrip__row.is-at .navstrip__dot` → 由 CSS 变为用户点（设计 §4.2d）；**无额外 DOM**。
- **行驶中**：在 `afterIdx` 对应行内插入绝对定位浮标：
  ```tsx

    <span className="navstrip__youmark" style={{ ["--you-frac" as string]: String(nav.youAt.frac) }} />
  )}
  ```
  插在 `row(afterIdx)` 与 `row(afterIdx+1)` 之间（DOM 顺序）；`.navstrip` 需 `position: relative`。
- **类名冻结**：四态 `is-passed/is-at/is-next/is-alight/is-alight-now` + `navstrip__badge/check/sub` **必须保留**（E2E AC-07 依赖）；新增类名仅 `.navstrip__youmark`。

#### d.4 边界

- `youAt.frac` 越界 → 已在纯函数 clamp。
- 短段（`i1===i0+1` 但两站重合）→ `b<=a` ⇒ frac=0（点贴站）。
- 冻结（丢信号）→ `frozen` 时**保留** youAt 不更新（视觉点不跳）。

### f. `alight-detect.ts`（需求 ⑨；AC-55）

#### f.1 新文件（client-safe 纯函数）

```ts
// src/lib/nav/alight-detect.ts
export const ALIGHT_CONFIRM = 2;          // 连续命中帧数
export const ALIGHT_GPS_OVER_M = 30;      // GPS 越过下车站 ≥30m 视为已下车
export const ALIGHT_HOLD_MS = 0;          // 预留（当前不要求时间保持）

export interface AlightInput {
  source: 'vehicle' | 'gps';
  lastIdx: number;                        // 本段下车站下标 = stopMains.length - 1
  atIdx: number | null;                   // 车辆源：当前停靠站下标
  passedIdx: number;                      // 已驶过
  dNow: number | null;                    // GPS 源：沿线里程（米）
  dAlight: number | null;                 // GPS 源：下车站沿线里程（ladder[lastIdx]）
  loop: boolean;                          // 环线 ⇒ 恒不判（首尾同站）
  frozen: boolean;                        // 冻结/丢信号 ⇒ 不判
  streak: number;                         // 调用方维护的连续命中帧数
}
export type AlightReason = 'at_alight' | 'passed_alight' | 'none' | 'loop' | 'frozen' | 'unsat';
export interface AlightResult { hit: boolean; streak: number; reason: AlightReason; }

export function autoAlightOf(input: AlightInput): AlightResult {
  if (input.loop) return { hit: false, streak: 0, reason: 'loop' };          // 环线排除
  if (input.frozen) return { hit: false, streak: 0, reason: 'frozen' };      // 冻结不判
  if (input.lastIdx < 1) return { hit: false, streak: 0, reason: 'unsat' };
  let inst = false;
  if (input.source === 'vehicle') {
    inst = input.atIdx === input.lastIdx;                                    // 停靠在下车站
  } else {
    inst = input.dNow != null && input.dAlight != null && input.dNow >= input.dAlight + ALIGHT_GPS_OVER_M;
  }
  const streak = inst ? input.streak + 1 : 0;
  if (streak >= ALIGHT_CONFIRM) return { hit: true, streak, reason: input.source === 'vehicle' ? 'at_alight' : 'passed_alight' };
  return { hit: false, streak, reason: inst ? (input.source === 'vehicle' ? 'at_alight' : 'passed_alight') : 'none' };
}
```
