三、回退时**必须顺手修掉**的 v2.4.0 两处自身缺陷

缺陷 1 · sm 并列仍是斜切（回退时**别把 4 条 sm 规则整份抄回来**）

v2.4.0 的 CSS 里同时存在 两套 sm 规则，且它们与新的并列规则**特异性相同（均 0,3,0）**、靠**文件顺序**决胜负： .route-stack--sm .route-stack__seg:first-child { clip-path: polygon(...6px...) } 写在 3058 段之前… 实测结果是 —— sm 并列块的 clip-path 仍然生效（上表：polygon(0 0, 100% 0, calc(100% - 6px) 100%, 0 100%)）， 即 sm 档下「每块圆角」被打回直角斜切，与 sm 单码的 6px 圆角不一致。
⇒ 正确处理：回 v2.4.0 时，那 4 条 .route-stack--sm 规则里只保留尺寸类属性（padding / font-size）， 删掉其中所有 clip-path 声明。这样才顺带真修掉长期挂着的 size="sm" 失效（D5）， 而不是把一个「sm 直角斜切」的新 bug 一起带进来。

缺陷 2 · +N 白字白底不可见

v2.4.0 的 .route-stack__more { color:#fff } 没有描边（同提交给 __slash 加了描边却漏了它）， 而多码组底是 transparent ⇒ 白卡上 +N 看不见。 ⇒ 保留当前 --muted（=「v2.4.0 + 2 处修正」）。
这两个缺陷的存在，恰好解释了为什么 v2.4.1 的作者会在注释里写「回归『斜切 + 等宽空隙』形态」—— 他当时看到的现象（圆角不一致 / 白字看不见）确实存在，但**归因归错了**：真因是「内侧圆角 + 白斜杠缺描边」的实现细节， 不是「圆角 + 白斜杠」这个形态本身。形态该回 v2.4.0，两个细节 bug 顺手修掉。

四、容器规则的「净效果」写法（回答前端的工程质疑）

v2.4.0 的 .route-stack 确实声明了两次（① inline-flex / align-items:stretch / border-radius:6px / overflow:hidden / flex-shrink:0 / max-width:100%； ② flex-wrap:wrap / row-gap:4px / overflow:visible）。按净效果写一条是正确做法，验收不会按字面比对，请按下面这条写即可： 
.route-stack {
  display: inline-flex;
  align-items: center;          /* ② 覆盖 ① 的 stretch；v2.4.0 实测布局为居中 */
  flex-wrap: wrap;
  row-gap: 4px;
  flex-shrink: 0;
  max-width: 100%;
  overflow: visible;            /* ② 生效；① 的 overflow:hidden 与 border-radius:6px 均被弃用 */
  /* border-radius 交给「块本体 / 组容器」承担 —— 容器不再裁剪 ⇒ 多段换行不会被切边 */
}
我给出的验收口径（V1–V9）针对的是 块与组的计算值（.route-stack__seg / .route-stack__group / .route-stack__slash）， 不比对容器字面声明，所以「写一条」与「抄两段」都能通过 —— 放心按净效果写。
