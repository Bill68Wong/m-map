用户拍板：三档快捷切换（综合 / 少换乘 / 少步行），默认「综合」；不做偏好设置页、不做自动学习（Spec §3）。 三档与谷歌地图 Route options 的 Best route / Fewest transfers / Least walking 一一对应（PM `06-产品-补充调研` 一手证据）。 模型为广义成本 cost 升序；α / β 是内部排序效用，不并入展示的 totalMin（显示口径与排序口径分离，避免「显示对不上明细」）。

UI 放置原则 · 位置：只在推荐列表顶部（.rc-list 之上），不散落到详情/收藏/其它页面； · 形态：一枚 segmented 控件（40px 高以内），不引入设置页； · 记忆：选择写入本地偏好（同一用户下次直达上次选择），默认 = 推荐； · 决策点计数：3 个（≤4 上限），符合工作记忆约束。

参数与排序规则（已锁定 · Spec AC-52~54 / AC-62）

档位第一排序键并列（tie-break）参数 / 口径
综合（默认）
谷歌 Best route		 cost 升序 ① 换乘次数 ↑　② 步行量 ↑　③ 来源（高德优先）　④ planId cost = totalMin + α × 换乘次数 + (β − 1) × 步行分钟 + 紧接换乘风险项
α = 10 分/次（纯换乘不便，不含已计的等待/步行）
β = 1.8 ⇒ 步行额外项 = 0.8 × 步行分钟（OTP walk.reluctance = 2.0 折中）
风险项：仅当换乘余量 slack < 安全余量 3 分钟 时施加（轻微）；slack < 0 ⇒ 判不可用、顺延下一班
全部为可调命名常量（代码内可审计、可复算）
少换乘
谷歌 Fewest transfers		 transferCount 升序 cost 升序 → 步行量 ↑ → 来源 → planId 换乘次数为硬第一键；同次数内退化为综合模型
少步行
谷歌 Least walking		 walkMin 升序 cost 升序 → 换乘次数 ↑ → 来源 → planId 步行 = 上车前步行 + 换乘步行 + 下车后步行总和
① α / β 不进 totalMin：卡面显示的时间与实际明细一致，排序按效用成本 —— 避免「显示 22 分却排在 24 分后面」的解释困境；
② 三档都不得出现「不可行方案」（赶不上换乘的班次必须先剔除，见 §4.7 / AC-61）；
③ 偏好只作用于推荐 / 导航排序；switch-plans 组内保持 totalMin（保契约，Spec §5）；
④ 参数落在 src/lib/recommend/score.ts 常量，前端只读；档位只影响排序，不改变展示字段；
⑤ 观测钩子：data-pref（当前档）、data-transfer-feasible（换乘可行性）。
