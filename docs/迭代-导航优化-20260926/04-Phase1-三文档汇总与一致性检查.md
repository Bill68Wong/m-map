## 三、一致性检查（9 项）

1. ✅ **蓝点数据源**：用户拍板"手机 GPS"（覆盖架构师"跟车为主"建议）⇒ Phase 2 以 GPS 投影为主线；视觉层（蓝点/灰线）跟 GPS，逻辑层（站条/提醒）保持既有权威链防跳
2. ✅ **偏好默认档**：用户拍板"默认综合"（修正架构师"默认 fastest"建议）——`score.ts` 默认 = balanced
3. ✅ **换乘"赶不上"口径**：总监裁决 = **顺延到能赶上的下一班 + 计入等待**（用户原话"匹配的下一班车需要能赶上"+"总时长要包括换乘时的等车"；仅完全无法顺延/收班时降级剔除）
4. ⏳ **α（换乘罚分）量级**：PM 8~12 vs 架构师 3 vs 设计师 8 ⇒ 待用户拍板（T1）+ Phase 2 实测标定
5. ✅ **站点过滤**：三方一致（`lineStops` 白名单 / 不渲染 / 导航态 = 方案全线路并集）
6. ✅ **窗格跑位**：架构师（横幅/toast 浮层化 + 固定锚点）与设计师（操作条移出滚动容器挂面板根、同 transform 上下文）兼容互补 ⇒ Phase 2 定稿
7. ✅ **顶部灰框**：设计师锁定根因（**CSS 回归**：`.rc-detail__head` 无规则，只吃 `.card`）⇒ 修复 + 新布局（总用时左 / 标签右）
8. ✅ **高德样式**：用户已创建 ⇒ 仅需配 Vercel env + 上线验证（公交站点隐藏、道路/POI 保留、我方图层正常）
9. ⚠ **超范围项**：设计师 Q1「首页是否也过滤站点」——**本轮不做**（用户需求限定"路线查看/导航模式"；范围锁定原则），如后续需要再单开
