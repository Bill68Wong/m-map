## B · 标点规格（终点钉 / 起点钉 / 用户蓝点）

### B.1 终点钉 → 「logo 上那种绿色」

**核查结果**：`public/brand/mark.svg` 的终点钉填充 = `var(--brand-pin, #0b6e4f)`，Token 定义在 `globals.css:6560-6581`：

| Token | 亮色值 | 深色值（`prefers-color-scheme: dark`） |
|---|---|---|
| `--brand-pin`（终点钉） | **`#0B6E4F`**（澳门绿） | `#6dd58c` |
| `--brand-route`（M 路线） | `#1B4D8F`（青花蓝） | `#a8c7fa` |

即用户说的「logo 上那种绿色」= **`#0B6E4F`**（与 `--brand-green` 同值）。
**现状**：地图终点钉是 `public/pin-destination.svg`，钉身 `fill="var(--danger,#b4342a)"` ⇒ 实际呈 **砖红 `#B4342A`**。

**修正规格**

| 项 | 规格 |
|---|---|
| 目标色 | **`#0B6E4F`**（澳门绿 / 品牌终点钉绿） |
| 实现方式 | 改 `public/pin-destination.svg` 钉身 `fill` 的**兜底值**为 `#0b6e4f`（写成 `fill="var(--pin-dest, #0b6e4f)"`） |
| 注意： 技术要点 | 该 SVG 通过 **CSS `background: url("/pin-destination.svg")`** 引入（`globals.css:2131-2136`）⇒ **页面 CSS 变量不穿透外部 SVG 文档**，`var()` 永远取兜底值。所以**必须改 SVG 文件内的兜底值**，改页面 Token 无效 |
| 是否随主题 | **不随主题**（固定 `#0B6E4F`）。理由：钉画在**地图**上，而底图不随站点主题切换（`mapStyle` 固定浅色）；若跟 `--brand-pin` 走，深色下会变 `#6dd58c`，在浅色底图上对比度仅 **1.53:1**（几乎看不见） |
| 保留 | 白色外圈描边（把钉从底图"拔"出来）+ 钉头白点；`--destpin-w/-h/-shadow` 几何 Token 不动 |
| 对比度 | `#0B6E4F` on 底图 `#E9ECE8` = **5.25:1**（优于现砖红 5.09:1） |

### B.2 起点钉 → 新增红色地图钉

| 项 | 规格 |
|---|---|
| 目标色 | **`#B4342A`**（项目砖红）——**正是现终点钉在用的那个红**（`--danger` 亮色值），因此换到起点钉上属「零新增色」，且与「红=起点/离开」直觉一致 |

### B.3 用户蓝点 → 「谷歌地图那样的呼吸闪烁」

**设计判断**：现在的实现是 `navYouPulse 1.6s` 动 **`box-shadow`**（`globals.css:6427-6438` / 6456-6465），存在两个问题：
① 动 `box-shadow` 会触发**重绘**（非合成层），移动端地图上跟随 GPS 时掉帧；
② 周期 1.6s 与「到站砖红脉动」**同频** ⇒ 全屏会「一起闪」，削弱「到站」作为唯一警报顶点的地位。

**规格：双层结构 + 独立 ping 层**

```
        ╭───────────────╮   ← ③ ping 层（扩散光圈，动态：scale 0.6 → 2.2 + opacity 0.45 → 0）
        │   ╭───────╮   │   ← ② 白描边（2.5px --surface；把核心点从底图"拔"出来）
        │   │  ●    │   │   ← ① 核心点（静态：12px --track-you，实心）
        │   ╰───────╯   │
        ╰───────────────╯
```

| 参数 | 值 | 说明 |
|---|---|---|
| 核心点 | `12px` / `var(--track-you)` / `border: 2.5px solid var(--surface)` | **静态**（不参与动画）—— 保证任何时刻都能看清「我在哪」 |
| 静态光圈 | `0 0 0 4px var(--track-you-ring)`（= `--you-ring-0`） | 精度/存在感；不参与动画 |
| ping 层 | `12px` 同尺寸层，`background: var(--track-you)`，`opacity: 0` 起 | 单独一层，与核心点同圆心 |
| ping 动画 | `transform: scale(0.6) → scale(2.2)`，`opacity: 0.45 → 0` | **只用 transform + opacity**（合成层，零重绘） |
| 周期 | **2.4s**，`infinite`，`ease-out` | **刻意与「到站脉动 1.2s」拉开**（1.2 × 2 = 2.4）⇒ 两者不会共振成「整屏闪」。同时比 1.6s 更从容，「一看就是活的」但不焦躁 |
| 扩散半径 | 视觉直径 `12 × 2.2 ≈ 26px`（≈ 光圈 7px） | 不遮挡站点/车辆（车辆 z130 > 蓝点 z128，本就不被压） |
| 衰减曲线 | `opacity` 线性衰减（0.45 → 0）＋ `scale` `ease-out`（先快后慢） | 观感接近 Google Maps 的「水波」而非「心跳」 |
| 相位 | 单层即可（不做双层错相） | 错相会显「两个圈」，反而不像定位点 |
| 减动效 | `prefers-reduced-motion: reduce` ⇒ `ping { display: none }`，仅留静态核心点 + 4px 光圈 | 已具备减动效分支，替换即可 |

```css
/* 结构（UserDotLayer.buildContent） */
.user-dot            /* 相对定位容器 16×16 */
.user-dot__core      /* 核心点（静态） */
.user-dot__ring      /* 静态 4px 光圈（用 box-shadow，不动画） */
.user-dot__ping      /* 新增：扩散层（动态 scale + opacity） */

.user-dot{position:relative;width:16px;height:16px}
.user-dot__core,.user-dot__ring,.user-dot__ping{
  position:absolute;inset:0;margin:auto;width:var(--you-dot-w,12px);height:var(--you-dot-w,12px);
  border-radius:var(--radius-full);
}
.user-dot__core{background:var(--track-you);border:2.5px solid var(--surface);z-index:2}
.user-dot__ring{box-shadow:0 0 0 var(--you-ring-0,4px) var(--track-you-ring);z-index:1}
.user-dot__ping{
  background:var(--track-you);opacity:0;z-index:0;
  animation:navYouPing 2.4s cubic-bezier(0, 0, 0.2, 1) infinite;
}
@keyframes navYouPing{
  0%   {transform:scale(0.6);opacity:.45}
  70%  {opacity:.06}
  100% {transform:scale(2.2);opacity:0}
}
@media (prefers-reduced-motion:reduce){ .user-dot__ping{display:none} }
```

**同时删除**：`.user-dot__core` 上的 `animation: navYouPulse 1.6s`（改由 ping 层承担呼吸），并清理 `navYouPulse` keyframes 在蓝点处的引用（**注意**：`navYouPulse` 可能仍被 `.nav.alarm`/站条引用，仅在蓝点处移除）。
**验收**：`riding` 与 `boarding` 两态下蓝点均存在并呼吸；`prefers-reduced-motion` 下无动画；位置随 GPS/投影单调推进（AC-60）。

### C.2 开屏两处白不是同一种白

**定位结果（两处白的来源）**

| 位置 | 值 | 来源 |
|---|---|---|
| 「M 旁边的白」= 图标底板 | **`#FFFFFF`** | `public/icon.svg` 第 1 个 `<rect fill="#ffffff">`（以及由它导出的 PNG） |
| 「底下 M Map 后面的大背景白」= 开屏/PWA 底色 | **`#F2F4F0`** | `public/manifest.webmanifest` → `"background_color": "#F2F4F0"`；同值也用于 `theme_color`（`layout.tsx` viewport）与站点 `--bg`（`globals.css`） |

**差异量化**：`#FFFFFF` 相对亮度 1.000 vs `#F2F4F0` ≈ 0.885 ⇒ 后者明显偏灰 ⇒ 与用户「**后者稍暗**」的观察**完全一致**。

**统一方案（二选一，建议 A）**

| 方案 | 做法 | 改动面 | 代价 | 评价 |
|---|---|---|---|---|
| **A（推荐）** | 把**图标底板**由 `#FFFFFF` 改为 **`#F2F4F0`** | **只改图标**（1 组文件重出 PNG） | 图标在白系统面上呈「米白」，与产品「站牌纸色」调性一致 | 通过 开屏 → 首屏（`body` 背景 = `#F2F4F0`）**零跳变**；`background_color` / `theme_color` / `--bg` 三处已有值不动 |
| B | 把 `manifest.background_color`、`theme_color`、`--bg` 全改 `#FFFFFF` | 3 处代码 + 全站底色变纯白 | 与既有品牌纸色体系冲突；开屏→首屏仍有实现风险 | 否 不推荐 |

> **推荐 A**：语义上「开屏底色 = 站点底色 = 图标底板」全部收敛到 **`#F2F4F0`**（单一真源），且只动 1 处。

### C.3 深色主题 M 右侧绿钉「做浅了」

**核查结果**

| Token | 亮色 | 深色 |
|---|---|---|
| `--brand-pin`（M 右侧终点钉） | `#0B6E4F` | **`#6DD58C`** |
| `--brand-route`（M 路线） | `#1B4D8F` | `#A8C7FA` |

**当时换色的理由（需向用户说明）**：**对比度**。`#0B6E4F` 画在深色底 `#111318` 上只有 **2.97:1**（低于 3:1，小图形会「糊」）；换成 `#6DD58C` 后为 **10.22:1**。这是标准的「深色底提亮品牌色」做法（同 `--brand-route` 也是这个逻辑）。

**三档选项（待用户选）**

| 选项 | 值 | 深色底对比度 | 说明 |
|---|---|---|---|
| ① 严格照用户原话（= 亮色同值） | `#0B6E4F` | **2.97:1** | 与亮色完全一致，但深色下**偏暗、辨识度不足** |
| **② 折中（推荐）** | **`#2E9E6E`** | **5.51:1** | 比 `#6DD58C` 明显**更深、更接近亮色的重量感**；同时满足可辨识 |
| ③ 保持现状 | `#6DD58C` | 10.22:1 | 最亮、最清晰，但被用户判为「做浅了」 |

**另需注意（不要让图标跟着变）**：**青花蓝底 app 图标**里的钉绿固定为 `#6DD58C`（`apple-touch-icon-180.svg` / `icon-*.svg` 蓝底版）。因为 `#0B6E4F` 画在 `#1B4D8F` 蓝底上只有 **1.34:1**（等同不可见）⇒ **图标文件不建议改成深绿**；若用户坚持「两处都要同样的绿」，需连带把图标底从青花蓝改成白/浅底，链路变长 —— 请总监转用户确认。

| 落点 | 建议值 |
|---|---|
| 站点内品牌标志（页眉 `BrandMark`） | 按用户选择（建议 ②`#2E9E6E`）→ 改 `globals.css:6577` 的 `--brand-pin`（深色段） |
| 青花蓝底 app 图标 | **保持 `#6DD58C`**（否则不可见）——需向用户说明 |
| `public/brand/mark-dark.svg` / `lockup-dark.svg` | 同步改兜底值（`--brand-pin-on-dark`） |

## D · 站点显示比例尺阈值建议

### D.1 现状与语义

| 常量 | 值 | 位置 | 语义 |
|---|---|---|---|
| `STATION_MIN_ZOOM` | **14** | `NavMap.tsx:65` | **普通模式**：`zoom < 14` ⇒ 不显示任何站点 |
| `STATION_MIN_ZOOM_ROUTE` | **12** | `NavMap.tsx:73` | **路线查看 / 导航模式**：`zoom < 12` ⇒ 不显示 |

**历史沿革（源码注释原文）**
- 2026-09-22：`16 → 15`（用户反馈「要放得很大站点才显示出来」）
- 2026-09-23：`15 → **14**`（用户拍板「打开定位后的默认视野就要能看到站点」；实测定位完成后视野 ≈ **14.47**，故取 14 时定位完成即显示）
- 路线模式取 12：因为 `setBounds` 把视野缩到「装下整条线」后，跨全澳长线（如 26 号）实测落到 **zoom ≈ 12~13**，若用 15 则站点图层整体不显示（本线高亮等于白做）

### D.2 密度依据（用 Phase 1 量化资料）

| 场景 | 站点 marker 数 | 说明 |
|---|---|---|
| 全澳站点总量 | **470+**（源码注释） | 「全澳总览（zoom ≈ 12.4）不显示，避免整屏 470+ 站点糊在街区细节上」 |
| 首页默认视野（阈值 14 生效） | **192** | Phase 1 只读实拍实测（`stationAll = 192`）⇒ 用户看到的就是这 192 个点 |
| 路线查看「51」（阈值 12 生效） | **425**（本线 19 + 非本线 406） | Phase 1 实测；**本批次需求 ② 已改「非本线不渲染」⇒ 生效点位数将降到 19** |
| 定位完成后视野 | **≈ 14.47** | 2026-09-23 实测；阈值 14 ⇒ **一打开就满屏**（与用户「太密集」一致） |

### D.3 建议值

| 模式 | 现值 | **建议值** | 理由 |
|---|---|---|---|
| **普通模式** | 14 | **15** | 定位完成后视野 14.47 **< 15** ⇒ 打开时**不显示**站点，用户「稍微再放大一点」才出现（正好是用户本次诉求）；同时全澳总览（12.4）与街区级采样都更干净。等价于回到 2026-09-22 的值 |
| **路线查看 / 导航** | 12 | **保持 12** | 不可提高：长线 `setBounds` 后落在 **12.x**，若提到 13 则 `12.3 < 13` ⇒ **整层站点不显示**（功能失效，正是 2026-09-22 记录过的坑）。且本批次「非本线不渲染」后，路线模式最多只剩十几~二十几个点，**不会密集**，无需提阈值 |
| 备选微调 | — | 15 若仍偏密 ⇒ **15.5**（zoom 支持小数） | 上限不建议 ≥16（2026-09-22 曾用 16，用户反馈「要放得很大才显示」） |

**必须让用户知道的取舍**：把普通模式提到 15，**推翻了 2026-09-23「打开定位后的默认视野就要能看到站点」的旧拍板** —— 两者不可兼得（定位后视野 14.47：14 看得见但密，15 干净但要推一下）。**建议按本次反馈取 15**，并请总监在真机上让用户二选一确认。

**验收**：真机上「打开定位 → 不显示站点 → 轻微放大一档 → 本站附近站点出现」；路线查看/导航下本线站点始终可见。
