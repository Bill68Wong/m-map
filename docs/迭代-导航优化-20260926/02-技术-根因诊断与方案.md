### 0.2 与「总监摸底发现」的差异（重要修正）

总监给的三条嫌疑中，两条**方向正确但触发点需修正**：

- **「比例尺归位」**：总监归因于 `ov.box` 新引用。复核后确认存在，但**真正高频的触发点是 `NavShell.tsx` L313-314 的 `dest`/`origin` 行内对象字面量**——它使 `NavMap` 取景 effect（L563-673，依赖 `[view, dest, origin, phase]`）**每次 NavShell 重渲染都重跑**；而 riding 期间 `useRideTracking` 的 12s 轮询 + `useUserFix` 的 GPS 帧**持续**触发 NavShell 重渲染 ⇒ 这才是「后台自动刷新导致比例尺归位」的直接链路。`ov.box` 是次要触发点（仅 detail 数据真正重载时）。
- **「用户标记 3 个」**：核实为 3 个 ref，但**同一时刻可见的最多是 2 个**——GPS 起点场景下 `origin` prop = `from` = `null` ⇒ `originpin` 不渲染，实际可见 = `mepin`（静态蓝圆）+ `user-dot`（呼吸的「您」），与用户描述「蓝色圆 + 呼吸的您」完全吻合。

## 1. 需求 1 · 弹窗抖动 + 比例尺归位

### 1.1 现状核实（行号证据）

**A. 取景 effect 逐次重跑（主因）**

`src/components/nav/NavShell.tsx` L313-314（NavMap 传参）：
```tsx
dest={to ? { lng: to.lng, lat: to.lat, label: to.label } : null}   // ← 行内新对象，每次渲染新引用
origin={from ? { lng: from.lng, lat: from.lat, label: from.label } : null}
```

`src/components/nav/NavMap.tsx` L563-673（视口取景 effect）：
- 依赖数组 L673：`[view, dest, origin, phase]` —— **`dest`/`origin` 每渲染必变** ⇒ effect 每次重跑；
- 守卫 L565：`if (!map || phase !== "ready" || !view || view.mode === "none") return;` —— detail 态 `view.mode === "fit-box"`，**不 return**；
- `fit-box` 分支 L645-672：`map.setZoomAndCenter(z, [centerLng, centerLat], true)`（L664）+ `map.panBy(0, size.height/2 - slotTop/2)`（L666）—— **无条件重设缩放与中心，无「是否已应用」幂等守卫**。

**触发频率（riding 期间的重渲染源）**：
- `src/components/nav/useRideTracking.ts` L401-406：`phase==='riding' && plate` ⇒ `setInterval(fetchFrame(plate), 12_000)`；`fetchFrame` 内 `setLastUpdateTs`/`setProg`/`setTraveled`（L291/L312/L317）⇒ 每 12s 触发 NavShell 重渲染；
- `src/components/nav/useUserFix.ts` L65-96：`watchPosition` 每 15s（boarding）/30s（riding）采纳一帧 ⇒ `setFix`（L85）⇒ NavShell 重渲染；
- 二者叠加 ⇒ 导航期间 **每 12~30s 必有一次「地图被重设缩放/中心」**。

**完整链路（比例尺归位）**：
```
useRideTracking 12s 轮询 / useUserFix GPS 帧
  → NavShell state 变化 → NavShell 重渲染
  → 新建 dest/origin 对象字面量（NavShell L313-314）
  → NavMap 取景 effect 依赖变化 → effect 重跑（NavMap L563-673）
  → view.mode==='fit-box' → setZoomAndCenter(自算z) + panBy（L664/L666）
  → 用户手放大后的 zoom 被覆盖为「装下整段」的 zoom  ⇒ 比例尺归位
```

**B. 面板档位落定重取景（次因，抖动）**

`NavShell.tsx` L267-270：
```tsx
function onDetent(d: Detent) {
  setSnap(d);
  reframeOnSettle(topsPx[...]);   // → useNavFrame.reframeOnSettle
}
```
`useNavFrame.ts` L59-68：当新槽比上次更靠下（面板更高、更遮挡）⇒ `frame({...last, slotTopPx})` ⇒ 再次 `setZoomAndCenter`+`panBy`。打开/上拉弹窗时地图「跳一下」。

**C. `ov.box` 新引用（第三因，仅 detail 数据重载时）**

`useRouteOverview.ts` L120：`setBox(unionBox(paths, extra))` 每次 effect 执行都产出**新对象**；`NavShell.tsx` L200-216 取景 effect 依赖 `ov.box` ⇒ 重下发 `frame({mode:'fit-box'})`。

**D. 拖动本身已命令式（v2.15 已修）**

`useSnapSheet` + `RouteSheet.tsx` L102（`sheetRef` 命令式写 `--sheet-y-anim`）⇒ 拖动手势本身零 React 更新；**「操作弹窗时仍抖」来自 A/B 两条（重渲染触发的重取景）。**

### 1.2 方案

**S1（治本，P0）· 稳定化取景触发**
1. `NavShell` 用 `useMemo` 包 `dest`/`origin` 对象：依赖 `to?.lng/to?.lat/to?.label`、`from?.lng/...`；
2. `NavMap` 取景 effect 依赖收敛为 `[view.tick, phase]`（`dest`/`origin` 改从 `viewRef` 之外的 ref 读取，或保持 props 但**只依赖 `view.tick`**）——`tick` 只在**显式 `frame()`** 时自增（`useNavFrame.ts` L53-57），故重渲染不再触发取景；
3. `useRouteOverview` 的 `box` 改为**值比较后再 set**（`boxKey = minLng|minLat|maxLng|maxLat`，相同则复用旧引用），或直接在 NavShell 侧用 `useMemo` 由 `ov.legs` 重算并冻结。

**S2（新增能力，P0）· 「用户手动让位」锁（明确落地）**

> 目标：用户手动拖动/缩放地图后，系统**不再自动取景**（比例尺/中心都不动），直到用户显式恢复。

- **监听什么**：`NavMap` 内对 `map.on('dragstart')` 与由手势驱动的 `zoomstart` 打标为「用户手动」；**程序化 `setZoomAndCenter`/`panBy` 不触发 `dragstart`**，天然区分（如需更稳，可用 `AMap` 的 `map.on('movestart')` + 一个 `programmaticRef` 在程序调用前后置位）。
- **状态放哪**：`NavMap` 内 `userYieldRef = useRef(false)`（不参与 React 渲染，避免额外重渲染）；配合一个 `data-map-yield="on|off"` 观测钩子（沿用现有 `data-*` 钩子风格，供 E2E 读取）。
- **取景 effect 如何检查**：在 effect 开头（L565 之后）加：`if (userYieldRef.current && cmd.mode !== 'restore') return;`。即**被让位后，所有自动取景指令一律跳过**。
- **恢复交互**：地图右下（或品牌栏）出现「回到路线」小按钮（`pointer-events: auto`，z-index 高于地图）→ 点击 `userYieldRef.current = false` + 下发一次 `frame({mode:'fit-box'/...})`（沿用上层 `useNavFrame.frame`）+ 写 `data-map-yield="off"`。
  - 或用户双击地图恢复（`map.on('dblclick')`）——**建议两者都留**，按钮为主、双击为辅。
- **谁触发让位**：仅 `dragstart`/手势缩放；`locateTick`（点定位按钮）属**显式意图**，应**重置让位**（用户点了定位 = 想看我的位置）。

**S3（减小跳变）**：`reframeOnSettle` 的阈值放大（`useNavFrame.ts` L64 现为 `slotTopPx <= last.slotTopPx + 4`）或取消「变高即重取景」，改为**只在首次进入 detail 取景一次**，面板档位变化不再重取景（让位锁的自然延伸）。

### 1.3 影响面 / 回归风险

- 直接影响：`NavShell.tsx`、`NavMap.tsx`、`useNavFrame.ts`、`useRouteOverview.ts`。
- 断言影响：`e2e-v214.mjs` 未直接断言 zoom 稳定性；**建议新增 AC**：拖动/缩放后等待 ≥15s（跨过一轮 12s 轮询）断言 `data-nav-zoom` 不变。
- 风险：取景 effect 依赖收敛时，若 `dest/origin` 由 ref 读会「读到上一个值」——需保证 `view.tick` 变化时 ref 已更新（同帧赋值即可，参照 `viewRef` 现有用法 NavMap L256-257）。

## 2. 需求 2 · 路线查看 / 导航模式隐藏非本线站点

### 2.1 现状核实

`NavMap.tsx` L742-815（站点图层 `render()`）：

  ```ts
  const inRoute = routeStopsRef.current.size > 0;

  const routeCls = !inRoute ? "" : isOnRoute ? " nav-map__station--onroute" : " nav-map__station--dim";
  ```

### 2.2 方案

**S1 · 新增「本线站点白名单」prop**
- `NavMapProps` 增 `lineStops?: Set<string> | null`（主码集合）。渲染时（L760 循环内）：

- 覆盖两种模式：路线查看（`rv.picked` → 既有 `routeStopsRef` 逻辑保留，等价白名单）与导航 detail（新 prop）。建议**统一**为 `lineStops`：路线查看模式把 `j.stops` 写进 `lineStopsRef`，detail 模式由 NavShell 计算后传入。

**S2 · 白名单来源（无需额外请求）**

**S3 · 渲染改动点**
- `NavMap.tsx` L742-815：循环内加白名单跳过；`data-station-count` 钩子（L813）自动反映过滤后数量；
- 移除/保留 `--dim` 类：建议**保留 CSS 但不再使用**（避免误伤），或按需求彻底删除 `--dim` 用法（设计确认）。

### 2.3 影响面 / 回归风险

- `e2e-v214.mjs` 未断言站点数量/类名 ⇒ 低风险；但 `data-station-count` 语义变化（过滤后更小），若有其他断言依赖需复核（当前未见）。

### 8.2 方案

**S1 · 抽出统一评分函数**
```ts
// src/lib/recommend/score.ts（新）
export interface Prefs { mode: 'fastest'|'balanced'|'fewer_transfers'|'less_walk'; wTransfer: number; wWalk: number; }
export const DEFAULT_PREFS: Prefs = { mode:'balanced', wTransfer: 3 /*分/次*/, wWalk: 0.08 /*分/百米?*/ };
export function scoreOf(card: RecommendCard, p: Prefs): number {
  const transfers = card.transfers.length;
  const walkMin = (card.walkOut.minutes||0) + (card.walkIn.minutes||0)
                + card.transfers.reduce((a,t)=>a+t.minutes,0);
  const w = p.mode==='fastest' ? {t:0,w:0}
          : p.mode==='fewer_transfers' ? {t:p.wTransfer*2,w:0}
          : p.mode==='less_walk' ? {t:0,w:p.wWalk*2}
          : {t:p.wTransfer,w:p.wWalk};
  return card.totalMin + w.t*transfers + w.w*walkMin;
}
```

## 9. 需求 9 · 上车灵敏度 + 全自动下车

### 9.1 现状判据参数表（逐参数，行号）

`src/lib/nav/boarding-detect.ts`：

| 参数 | 值 | 行号 | 含义 |
|------|----|------|------|
| `R2_WINDOW_MS` | 45 000 | L32 | GPS 采样窗口 |
| `R2_TOL_M` | 80 | L33 | 投影容差（米） |
| `R2_LRT_TOL_M` | 60 | L34 | 轻轨收紧档 |
| `R2_DISPLACE_M` | 150 | L35 | 沿线位移（米） |
| `R2_SPEED_MIN_KMH` | 8 | L36 | 平均速度下限 |
| `R2_SPEED_MAX_KMH` | 80 | L37 | 上限 |
| `R2_LRT_SPEED_MIN_KMH` | 12 | L38 | 轻轨速度下限 |
| `R2_MIN_SAMPLES_WITH_R1` | 2 | L39 | 有 R1 佐证所需样本 |
| `R2_MIN_SAMPLES_ALONE` | 3 | L40 | 单独判定所需样本 |
| `SWITCH_COOLDOWN_MS` | 20 000 | L43 | 状态切换冷却 |
| `ANOMALY_CONFIRM` | 2 | L46 | 安全网确认次数 |
| `ANOMALY_MIN_GAP_MS` | 45 000 | L46 | 安全网最小间隔 |

判据：R1（`r1Of` L62-93）= 车 stop/刚离上车站；R2（`r2Of` L113-140）= 窗口内每帧投影 ≤ tol + 沿线位移 ≥ 150m + 速度 ∈ [8,80] + 样本 ≥ 3。

### 9.2 瓶颈分析（数据侧 / 判定窗口 / GPS 精度）

1. **boarding 期间无 12s 轮询（最主要）**：`useRideTracking.ts` L385-392 —— 「候车态」只在 `[phase, active, legIndex]` 变化时拉**一帧** `fetchFrame(null)` 并 `tryAuto()`；**没有 `setInterval`**（L401-406 的 12s 轮询条件是 `phase==='riding'`）⇒ R1 只有单帧数据，若该帧不满足「刚离站」，**在用户手动「刷新」前不会再评估** ⇒ 体感「不灵敏」。
2. **R2 判据自相矛盾**：`window=45s` + `displace=150m` + `speedMin=8km/h` ⇒ 8km/h = 2.22m/s，45s 最多 100m < 150m ⇒ **R2 单独判定实际要求 ≥12km/h 持续整窗**（100m→150m 需 67.5s > 窗口）。澳巴在市区含停站均速常低于此 ⇒ 频繁漏判。
3. **GPS 15s 节流 × 45s 窗口 = 仅 ~3 样本**（`useUserFix` L83-87，`intervalMs` boarding=15s）：`minSamples=3` 是临界值，丢一帧即不足。
4. **tol 不随精度自适应**：城市峡谷 / 高架下 `accuracy` 常 >50m，固定 `tol=80m` 易被外层 `if (projs.some(p => p.distM > tol)) return false;`（L129）一票否决。
5. **自动下车缺失**：`alight()`（useRideTracking L585-611）只由手动按钮调用（`NavTrackBar` L168「我已下车」）+ 安全网 A2（`anomalyOf` L247-248，仅提示不自动）。

### 9.3 改进设计

**A. 上车灵敏度**
- **A1（P0）**：boarding 态加 **12s 轮询** `fetchFrame(null)`（复用 `POLL_MS`），使 R1 持续评估；
- **A2**：R2 阈值改为**与采样间隔/精度自适应**：
  - `tol = max(R2_TOL_M, accuracy * 1.5)`；
  - `displace` 按窗口内实际 `dt` 缩放（`displaceEff = max(60m, speedMin/3.6 * dtSec)`）；
  - `speedMin` 降到 ~5~6 km/h（巴士低速蠕行/红灯排队也应可判）；
- **A3**：引入**多帧确认**（学 `lrt-progress.ts` 的哲学：单帧最多推进，连续 2 帧一致才采纳）——R2 命中需**连续 2 帧**成立（用一个 `r2StreakRef`），避免单帧噪声误判；与 `SWITCH_COOLDOWN_MS`（20s）配合防抖；
- **A4**：保留「宁可晚判不误判」铁律 + 常驻「我没上车/不是这辆」纠错入口（已有，`NavTrackBar` L154-158/L177-184）。

**B. 全自动下车**
- 新增 `src/lib/nav/alight-detect.ts`（纯函数，client-safe）：
  ```
  autoAlightOf({ progressSource, prog, colored, latestFix, nowMs, arrivalHeldMs }):
    · 车辆源：prog.atIdx === lastIdx 连续 2 帧（或用 prog.passedIdx >= lastIdx-1 且区间终点=下车站）
    · GPS 源：投影沿线里程 >= ladder[lastIdx] （越过下车站）且保持 ≥ N 秒
    · 冻结/对不上 ⇒ 不判（沿用铁律）
  ```
- 落点：`useRideTracking` 增 effect（`[prog, phase]`）→ 命中 ⇒ 自动 `alight()` + 展示「已到站，导航结束（撤销）」提示（`alight` 内部已 `buzz`+推进下一程/done，L600-610）；
- **撤销**：新增 `onUndoAlight`（回到 riding、恢复 `legIndex`）——需状态快照；
- **降级**：信号丢失/几何缺失 ⇒ 不自动（仅横幅提醒，现状保留）；
- **可选开关**：`AUTO_ALIGHT_ENABLED`（默认 true，回退=手动）。

### 9.4 影响面 / 回归风险

- `e2e-v214.mjs` AC-05（全自动切换 R1/R2，L296）：改动**提高**命中率 ⇒ 正向；AC-06「您在这里」已因需求 5 变更（见 §5.3）。
- 「riding 出口」E2E 未强断言（L508 注明「真机项」）⇒ 自动下车不影响现有断言。
- 风险：自动下车**误判**（提前到站）——用多帧确认 + 撤销兜底；`atIdx===lastIdx` 在**环线**（首尾同站）可能提前命中 ⇒ 需排除环线（`route-overview.isLoop` 已有）。
