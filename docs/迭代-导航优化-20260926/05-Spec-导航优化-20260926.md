## 1. 产品定义

- **一句话描述**：M Map（澳搭車）导航体验优化批——修复 10 项导航体验缺陷，对齐「谷歌地图式」的稳定、清晰、诚实体验。
- **目标用户**：作者本人（唯一主力用户；个人非商业项目）。
- **核心问题**：导航期地图被系统刷新夺回视野（比例尺归位/抖动）；站点杂乱；用户点混乱（双标记 + 乘车中不跟随）；车辆图标不更新且点击中断导航；换乘方案系统性偏乐观；无偏好模型；上下车判定不完备；底图自带站点重叠。

## 4. 技术架构（锁定）

- **栈**：Next.js 15 App Router + TS + Supabase + 高德 JS API（不变）。
- **本批次新增模块**：
  - `src/lib/nav/alight-detect.ts`（新）——全自动下车判据纯函数（多帧确认 + 环线排除）
  - `src/lib/recommend/score.ts`（新）——偏好评分 `Prefs` / `scoreOf` / 默认档
  - `src/lib/nav/lrt-progress.ts`（改）——导出段内位置比 `frac`
  - 其余为既有文件内改造（清单见 §7）。
- **关键机制裁定（总监，已综合三方一致性检查）**：
  1. **取景状态机**：`follow | free` 两态；用户手势（dragstart/手势缩放）→ `free` 且**后续一切自动取景指令跳过**；恢复=「回到当前位置」按钮（主）+ 双击地图（辅）+ 点定位键（=显式意图，恢复并取景）。
  2. **蓝点数据链（用户拍板=手机 GPS）**：视觉层（蓝点位置 + 灰色已驶过线）跟 **GPS 投影**（`nearestOnPath` 吸附，最大 60m；投影失败→冻结不跳）；逻辑层（站条进度/下车提醒）**保持既有权威链**（车辆或 GPS 多帧确认推进），两者数据源独立、语义各自正确。riding 时**蓝点不再隐藏**（修正 `NavShell` L329-331）。
  3. **换乘等待（用户拍板=偏保守+数据驱动）**：废除常量 `BUS_HEADWAY_FALLBACK_SEC/2`；改按"到达换乘站的时刻"查 `route_frequency`（`headwayAt`）取班距，**偏保守侧取值**（具体分位由 Phase 2 标定，须可对账）；轻轨用 `lrt_timetables`（已有）；**数据缺失时明确降级标注**（不得拍脑袋设默认值）。赶不上 ⇒ **顺延到能赶上的下一班并计入等待**（仅末班场景剔除/降级）。
  4. **偏好模型（用户拍板=三档+默认综合；参数按高德/谷歌调研）**：`cost = totalMin + α·换乘次数 + (β−1)·步行分钟 + 紧接换乘风险项`，**cost 升序**；三档=综合（默认）/少换乘/少步行（**与谷歌 Route options「Best route / Fewest transfers / Least walking」一一对应**，`06-产品-补充调研` 一手证据）；**参数定稿（依据 06 调研）：α=10 分/次、β=1.8、换乘安全余量 3 分钟**（均为可调常量，落地后按真机体感微调）；**α/β 为内部排序效用，不并入展示的 totalMin**（显示时间与排序口径分离，避免"显示对不上明细"）；偏好只作用于**推荐/导航排序**，`switch-plans` 组内保持 `totalMin`（保契约）；少换乘/少步行的并列键=cost 升序。
  5. **标签形态（用户指示=既有 v2.4.1）**：单码=圆角矩形（`--radius-chip`）/ 同段并列=**斜切+等宽空白斜间隙**（缝露背景色）/ 段间=箭头 `→`；统一动作=**修正偏离者**（`.nav-linechip` 999px 胶囊等）**+ 清理死 CSS/重复规则**（旧 `.route-stack` 段 L785-857 等）；**不引入新形态**。
