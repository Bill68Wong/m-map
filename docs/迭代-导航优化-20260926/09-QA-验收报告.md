### 13.2 复验中发现的环境/基础设施问题（非本批回归 · 不阻断）

**现象**：页面出现 3~4 条 `Uncaught SyntaxError: Unexpected token ':'`（Playwright `pageerror`）。

**根因定位**（`.verify/qa-v310-errprobe.mjs` + curl）：
- 报错源为 **AMap JS SDK 的 JSONP 回调脚本**经安全代理 `/_AMapService/*`（`route.ts` `maxDuration=15`、`TIMEOUT_MS=8s`）返回：
  `curl` 该端点 **4/4** 得 `{"status":"0","info":"proxy error: The operation was aborted due to timeout"}`。
- 代理超时后返回 **JSON 错误体**，而 SDK 以 `<script>`（JSONP `callback=jsonp_*`）方式加载 ⇒ `{...}` 被当块语句解析 ⇒ `Unexpected token ':'`。
- 涉及端点：`v3/log/init`（SDK 遥测）、`v3/config/district`、`v3/assistant/coordinate/convert`（GPS→AMap 转换）。

**归属与影响**：
- 代理路由 `src/app/api/amap-service/[...path]/route.ts` **不在本批 diff**（`git diff --name-only` 0 命中），亦为上游 `restapi.amap.com` 从 Vercel `sin1` 当前**不可达/超时**所致 ⇒ **环境/基础设施问题，非本批代码回归**。
- **不影响本批功能**：底图瓦片（`jsapi-data*.amap.com`）与地图交互正常（geom/reverify 探针在报错存在下仍完整跑通：free 态、恢复按钮四态、站点过滤、H3 契约均通过）。
- 但会使「全局 `pageerror=0`」理想口径**间歇性不达标**（早先批次探针与主 e2e 均曾观测到 `pageerror=0`，说明为**上游时段性**）。

**建议（另行处理，非本批阻断）**：给 `api/amap-service` 增加 `callback` 感知——JSONP 请求失败时返回 `callback && callback({status:'0',...})`（脚本安全），或提高超时/重试，避免 SDK 内部调用把错误 JSON 当脚本解析。

**本轮裁决建议：放行。** 两项 P1 均已关闭；peek 已修；sheet-closed 为非缺陷；唯一异常（AMap 代理超时）属上游/基础设施，且未影响本批功能。
