## 1. 高德 JS API 2.0 图层能力调研（用户第 1 条）

### 1.1 现状对照（读码取证）

`src/` 全量检索后确认：

- `new AMap.Map(canvasRef.current, {...})`（`NavMap.tsx:347`）**未传 `layers`** ⇒ 按官方约定「未指定则默认添加一个标准图层」⇒ **当前就是默认标准图层**。
- 无 `setFeatures` / `setMapStyle` / `showLabel` / 任何 `TileLayer` 子类调用 ⇒ 无卫星、无路网、**无实时路况**、无楼块。
- 站点/定位/目的地/线路全部是 **`AMap.Marker` / `AMap.Polyline`**（覆盖物），与「底图图层」是两回事。
- 结论：用户问的「现在是不是高德公共交通图层」——**否**；看到的公交站图标来自**底图矢量的 POI（`point`）要素**，不是我们的站点图层、也不是「公交图层」。

### 1.2 官方图层能力清单（官方文档，最后更新 2024-10-25）

| 能力 | 类 / 参数 | 当前 | 备注 |
|------|-----------|------|------|
| 默认标准图层 | 隐式 / `AMap.createDefaultLayer({zooms,visible,opacity,zIndex})` | **在用** | `layers` 缺省即它 |
| 卫星 | `AMap.TileLayer.Satellite` | 未用 | 与 RoadNet 常组合 |
| 路网 | `AMap.TileLayer.RoadNet` | 未用 | 纯路网覆盖 |
| 实时交通（路况） | `AMap.TileLayer.Traffic({autoRefresh, interval=180})` | 未用 | 拥堵色带 |
| 楼块 | `AMap.Buildings` | 未用 | 有效级别 `[17,20]`；需 `showBuildingBlock:false` 且 3D 视图 |
| 室内 | `showIndoorMap` / `AMap.IndoorMap` | 未用 | zoom>17 自动 |
| **底图元素开关** | `features: ['bg','point','road','building']` / `map.setFeatures([...])` / `getFeatures()` | 未用 | `point` = POI 点（含公交站/地铁站） |
| 底图文字标注 | `showLabel:false` | 未用 | 会一并隐藏街道名，**不建议** |
| 样式主题 | `mapStyle: 'amap://styles/<name\|id>'` / `setMapStyle()` | 未用 | 官方模板 normal/dark/fresh… |

### 1.3 「底图公交站点 POI 何时出现、能否关」结论

- **何时出现**：公交/地铁站点属底图 `point` 要素，**随矢量瓦片分级出现**（一般到较大 zoom 才绘出点标；官方未公开精确阈值，随城市数据与样式而定）。它们**不受我们 `STATION_MIN_ZOOM=14` 站点阈值控制**（那是我们自己的 marker 层）。
- **能否关**：
  1. 粗暴：`map.setFeatures(['bg','road','building'])` —— 去 `point` 即隐藏**所有** POI 点（含公交站，也含餐饮/商场）。
  2. 精细：仅隐藏公交站需在**高德自定义地图平台**配置 `mapStyle`（关闭「公交站点」图层），MVP 不必。
  3. 折中：`showLabel:false` 只关文字、不关图标 —— 会丢街道名，**不采用**。
- **用户第 1 条答案**：「想用默认图层」⇒ **现状已满足**，无需改动。若要「地图更干净只留我们的站」，唯一干净做法是 `features` 去 `point`（有连带副作用，需产品拍板）。**本轮建议不动**，仅把 `features` 开关记为可选 Backlog（放 `/help` 显示设置或不做），避免无谓回归。

## 2. 可变高度 Bottom Sheet 技术方案

### 2.1 架构决策：单一宿主 + 内容切换（推荐）

**推荐**：新建一个 **`RouteSheet` 宿主**（可拖拽、双停靠点），内部在 **两个内容 pane** 间切换：
- `pane='list'` → 推荐列表（复用 `RecommendCards` + 现有空态）；
- `pane='detail'` → 详情（复用 `RouteDetailBody`）。

**不推荐**：把现有 `RouteResultSheet`(z-70) 与 `RouteDetailSheet`(z-80) 两个独立全屏弹窗各给一个高度后叠加 —— 会出现「推荐层 88% 顶边 12% 露在详情层 50% 顶边之上」的**怪异层叠**（PM §2.2 已点明），且手势归属冲突。

**收益**：① 高度联动是一条 `transform`，最平滑；② 列表 pane **常驻不卸载** ⇒ 保滚动位置、秒回；③ 消除双层高度打架。

> 兼容既有复用：`RouteDetailSheet`（**收藏页 `ComboPlans` 在用**，无地图上下文）保留，但其内部的「取数 + 渲染 `RouteDetailBody`」抽成 `RouteDetailPane`，与宿主详情 pane **共用同一份数据路径**，防两处漂移。

### 2.2 停靠点（snap points）与几何

| 档位 | 顶边位置 | 用途 |
|------|----------|------|
| **full（88%）** | `top = clamp(max(var(--safe-top) + 44px, 12vh), 96px, 128px)` | 推荐默认；详情上拖态。**顶部留一条地图带**（≈96–128px） |
| **half（50%）** | `top = 50vh` | 详情默认；上半屏地图显示**路线总览** |
| peek（20%） | `top = 80vh` | **已拍板采用**（用户新增）：收起浏览地图的休息态；三档中最低档，**从此档继续下拉 = 关闭** |

- 面板结构（**只动画 `transform`，不动画 `top`/`height`** —— 动画 `top` 每帧触发布局/重绘，低端机掉帧，违背「丝滑」）。**位移量拆两个变量**：`--sheet-y-anim` 拖动中每帧更新、**只喂 `transform`**；`--sheet-y-layout` **仅档位落定时更新一次**、喂滚动容器 `padding-bottom`（避免每帧重排，与「只动画 transform」目标一致）：
  ```css
  .route-sheet { position: fixed; top: 0; left: 0; right: 0; height: 100dvh;
                 transform: translateY(var(--sheet-y-anim));   /* full: ~101–128px；half: 50dvh；peek: 80dvh */
                 transition: transform 260ms cubic-bezier(0.32, 0.72, 0, 1);
                 will-change: transform; }
  .route-sheet[data-dragging="on"] { transition: none; }
  /* ⚠️ padding 加在**滚动容器**（面板内容区），不是文档 body —— body 不是滚动容器，加了无效 */
  .route-sheet__body { overflow: auto; -webkit-overflow-scrolling: touch;
                       padding-bottom: calc(env(safe-area-inset-bottom) + var(--sheet-y-layout)); }
  ```
- ⚠️ 面板是全高元素**下移** `--sheet-y`，**滚动容器必须补 `padding-bottom: var(--sheet-y-layout)`**，否则列表底部会被推出视口不可达（真机验证：档位落定后**列表底项可滚到底且可见**）。`--sheet-y-layout` 只在档位落定（过渡结束）时同步一次，**拖动中不动**（拖动中更新会每帧重排，反噬手感）。
- ⚠️ **面板打开期间隐藏地图搜索框**（`.nav-searchbar` 200ms 淡出）：搜索框底边 = `safe-top + 12 + 52 = safe-top + 64px`，比 full 档顶边下界 `safe-top + 44` 低 20px ⇒ **会裁掉搜索框 10–20px**（iPhone 实测）；且搜索框通栏会遮掉「露出的地图带」。改目的地走「返回 → 半屏面板」。
- 顶部**抓手下握条**（36×4 胶囊，纯 CSS），命中区 ≥44×24（WCAG）。
- ⚠️ **面板（含 peek）会盖住底部导航**（单实例单向 `transform` 的必然结果；`.bottom-nav` z30 < 面板 z70）：当前口径 = 允许（与现有一致）。若产品要求 peek 时保留底导，需给 peek 单独让出 `var(--tabbar-h)` —— **标为可选，待产品定**。
- `border-top-left/right-radius: var(--radius-sheet)`；`box-shadow: var(--shadow-sheet)`；`padding-bottom: env(safe-area-inset-bottom)`。

### 2.3 跟手拖拽 + 吸附（复用既有已验证模式）

**直接复用 `StepSheet.tsx` 的成熟实现**（`src/components/nav/StepSheet.tsx:108-216` + `globals.css:3299-3323`），抽成 hook `src/components/nav/useSnapSheet.ts`：

- 起拖：仅**抓手下握条 + 头部区**（`e.clientY - rect.top <= HANDLE_H`）触发，避免抢列表/输入框事件；
- **跟手用 `transform: translateY(calc(var(--sheet-y-anim) + <拖动增量>))`**（GPU 合成，`will-change: transform`），`data-dragging="on"` 时 `transition: none`（面板结构见 §2.2）；
- `touch-action: none`（面板本体）/ `pan-y + overscroll-behavior: contain`（内容区），**拖动中不重排布局**；
- 越界 **rubber-band**（`RUBBER=1/3`）；
- 松手 **位移 + 速度双判定**吸附（阈值与三档链路见 §2.3.1）；过渡 `260ms cubic-bezier(0.32,0.72,0,1)`，`prefers-reduced-motion` 下 `transition:none`；
- **嵌套滚动协调**：内容区 `scrollTop > 0` 时不接管拖拽（先滚列表、滚到顶才拖面板）；
- 键盘：见 §2.3.1。

### 2.3.1 三档吸附 / 关闭链路（阈值通用）

档位数组（**非等距**）：`DETENTS = [full, 50vh, 80vh]`（面板顶边 `y`，向下 = 收起）：`full ≈101–128px` ＜ `half = 50dvh` ＜ `peek = 80dvh` ＜（虚拟）`closed`。
状态属性：`data-sheet-state="recommend|detail"` + `data-detent="full|half|peek"`（两态共用同一档位集）；关闭后 `--sheet-y-anim` 复位 `100dvh`。

**吸附（drop，三档同一算法）**：把「结束位置 + 速度投影」落点取**最近可用档**；判定 = `|Δy| > 0.28 × 相邻档距` 或 `|v| > 0.5px/ms`（同向 fling）⇒ 切到该方向相邻档，否则回弹当前档；**flick 允许跨两档跳档**（如 full ↓ 直落 peek）。
- ⚠️ **阈值必须逐对、且按运行时 px 计算，不能用固定 px**：`阈值Px = 0.28 × (相邻档位实际 px 间距)`；`gapPx` 由当前屏高把 `[fullPx, 50vh, 80vh]` 换算后取相邻差。参考（≈1000px 屏）full↔half ≈ 38vh→106px、half↔peek ≈ 30vh→84px；**390×844 真机**则 ≈90px / 71px —— 故实现里只存 **vh 比例**、运行时算 px。
**越界阻尼**：`peek` 继续下拉 / `full` 继续上拉 → rubber-band 1/3，松手回弹。
**上滑**：逐档展开 `peek→half→full`；`full` 到顶 rubber-band。

**关闭（contextual，按 pane 与当前档区分）**：
- **只在最低档 `peek`** 才允许「继续下拉关闭」：`Δy > 96px` 或 `v > 0.5px/ms` 向下 ⇒ 触发关闭。`full`/`half` 下拉只**逐档下移**，不直接关闭（防误触）。
- 关闭动作按 pane：
  - `pane='list'` → **关闭面板**（回半屏可出发态；无 OD 则回全屏地图）；
  - `pane='detail'` → **回推荐列表**（`pane='list'`, `snap='full'`，符合「详情可关闭 → 回推荐」）。
- **X 按钮**：list = 关闭面板；detail = 回推荐列表。**返回箭头**（detail）：回推荐列表（与 X 等价）。
- **键盘**：`Esc` = 当前 pane 的关闭动作（detail→list；list→关闭）；`↑/↓` 在档间切换。

**peek 的最小内容区由 pane 承担**：host 把当前档位下发给 pane；`snap==='peek'` 时 pane 渲染**紧凑摘要**（独立子组件 `.sheet-peek-summary`，随档位 200ms opacity 显隐；**只读**，点击整区回该 pane 的默认档，**不放滚动列表**）：
- `RouteResultPane`（list）：OD + 「N 条路线」一行；
- `RouteDetailPane`（detail）：OD + 线路标签（`RouteStack`）+ 「X 分到达」一行；
- peek 态**收起头部动作键**（刷新/收藏），仅留抓手 + 摘要 + 关闭途径（抓手下拉 / 返回）。

### 2.4 与地图协同（取景）

- 地图容器 `.nav-map--full` 保持 **fixed 全屏**（`NavMap.tsx` 不动容器）；面板为覆盖层。
- 定义**可视槽高** `slotH = window.innerHeight - sheetTopPx`。**档位落定后**（非拖动中）才取景，避免抖动（PM §2.2）。
- 取景复用 `NavMap` 已有**全自算**逻辑（`NavMap.tsx:577-624` 的 `fit-two`：中点 + 反推 zoom + `setZoomAndCenter(..., immediately=true)` + `panBy` 上移）。
  - `slotH` 随当前档取（= 面板顶边以上区域）：`full → ≈12vh`、`half → 50vh`、`peek → 80vh`；**档位落定后**才重取景。
  - `pane='list'`：把 OD 两点适配进当前 `slotH` 槽；
  - `pane='detail'`：把**路线总览外包框**（所有彩段 + 起终点）适配进当前 `slotH` 槽；
  - 上移到目标槽中心：`panBy(0, window.innerHeight/2 - slotH/2)`（正 dy 把内容上移，与既有 `fit-two` 同号）。
- ⚠️ **禁止用 `setBounds`/`setFitView` 取景** —— 本项目已实测：在 `setLimitBounds(澳门)` 场景下会被撑到珠海斗门（`NavMap.tsx:580-593` 三次踩坑记录）。一律走自算。**设计稿若写「`setBounds` 下边距 = 当前面板高 + 24」，实现一律改读为「自算 `fit-box` 到顶部槽（`slotTopPx` = 当前档顶边）」**，二者视觉等价但后者可控。
- 取景参数经 `NavMap` 的 `view` prop 下发：**扩展** `view` 为
  ```ts
  view?: {
    mode: "none" | "dest-center-top" | "fit-two" | "fit-box";
    tick: number;
    /** fit-box：待装下的经纬度外包框 + 可视槽底边像素（面板顶边） */
    box?: { minLng:number; minLat:number; maxLng:number; maxLat:number };
    slotTopPx?: number;
  } | null;
  ```
  `fit-two` 分支可复用同一次自算（把 `origin/dest` 当作 box）。

### 2.5 状态机（NavShell 持有）

```
closed（全屏地图）
   │ 点搜索框
   ▼
full（SearchSheet）
   │ 选中地点
   ▼
half（RoutePanel，可出发）
   │ 点「出发」
   ▼
sheet{ open, pane:'list', snap:'full' }          // 推荐默认 full(88%)
   │ 点卡片（pane→detail + 88%→50% 平滑降）
   ▼
sheet{ open, pane:'detail', snap:'half' }         // 详情默认 half(50%)：上半屏路线总览
   │
   ├─ 上拖 ────────────► snap:'full'    // 顶部只留一条地图带
   ├─ 下拖 ────────────► snap:'peek'    // 20%：收起浏览地图（紧凑摘要）
   └─ 下拖越阈 / X / 返回 ► sheet{ pane:'list', snap:'full' }   // 回推荐（原位、保滚动）
                                    │ 再由 peek 下拖越阈 / X
                                    ▼
                              half（回可出发态；无 OD 则 closed）
```

- 档位集合：`full(88%) / half(50%) / peek(20%)`；吸附与关闭链路见 §2.3.1。
- 用 `pane` 切换时**列表 pane 不卸载**（`hidden`/`display` 切换，保 `scrollTop`）。
- **点卡片当帧**：先切 pane + 启动 88→50 动画 + 骨架；`POST /api/nav/detail-body` 并行拉取（PM §2.3「动画永不被网络阻塞」）。
- **peek 最小内容区由 pane 承担**（见 §2.3.1）：list 显「N 条路线」、detail 显线路标签 + 到达时刻。
- **非模态**：不加 scrim；露出的地图带**可拖、可点车/站**（PM §1.2 iOS/Google 惯例）。点地图空白**不关闭**面板。

### 2.6 层级（z-index）与「卡片浮在面板之上」

## 3. 路线总览渲染方案

### 3.1 数据来源（两条腿，均可缓存）

1. **乘车段几何 + 站坐标**：扩展 **`POST /api/nav/detail-body`** 返回体，新增
   ```ts
   legs: {
     route: string; kind: "bus"|"lrt"; color: string|null;
     board:  { code: string; lng: number; lat: number };   // GCJ-02
     alight: { code: string; lng: number; lat: number };   // GCJ-02
   }[]
   ```
   - 服务端在 `detail-body/route.ts` 内**一次批量查询**涉及站码的坐标（`stations` 表 WGS84 → `wgs84ToGcj02()`，出口 GCJ-02），**绝不放进循环**（防 N+1）；颜色查 `routes.color`。
   - 与 `card.rides` **一一对应**（同序），供前端切割。
2. **线路走向**：`GET /api/route-shapes?code=`（已存在，`force-cache`；`polyline` 为 **GCJ-02**，直接喂地图）。每条 distinct route 并行拉一次。
3. **在途车辆**：`GET /api/route-vehicles?code=&dir=`（已存在，`no-store`）。`dir` 由所选 shape 的 `dsat_dir` 决定；**每条乘车段并行拉**。

> 坐标系：`route_shapes.polyline`（高德 GCJ-02）与 `/api/stations`（DSAT WGS84→GCJ-02）**同为 GCJ-02**，可叠加；但**来源不同**，切割用「最近顶点 + 容差」而非精确相等（见风险 R4）。

### 3.2 切割算法（新增纯函数 `src/lib/nav/route-overview.ts`，client-safe、无 pg、可单测）

```
parsePolyline(s: string): [number,number][]          // "lng,lat;..." → 点列
cumDistM(pts): number[]                               // 等距近似：dLat*111320, dLng*111320*cos(lat)
nearestOnPath(pts, p): { idx, distM }                 // 最近顶点（小范围，欧氏近似足够）
isLoop(pts): boolean                                  // distM(pts[0], pts[last]) <= 25m
chooseShape(shapes, board, alight): Shape             // 依据见下
cutColored(pts, iBoard, iAlight, loop): [number,number][] | null
```

**选方向 `chooseShape`**：对每个 `shape`（`dsat_dir` 0/1）分别求 `board`/`alight` 最近点距离 `dBoard`/`dAlight`；剔除任一 `> TOL(≈80m)` 的 shape；在合法 shape 中取 `dBoard+dAlight` 最小者；若仍并列，取「沿路径 board 在 alight 之前（正向）」者。

**切分 `cutColored`**：
- 非环线：`pts.slice(iBoard, iAlight+1)`；若 `iBoard > iAlight` ⇒ 视为方向不符（返回 `null` → 走降级）。
- **环线（`isLoop` 或 `startStop===endStop`）**：若 `iAlight >= iBoard` 取 `slice(iBoard, iAlight+1)`；若 `iAlight < iBoard` ⇒ **环绕**：`pts.slice(iBoard).concat(pts.slice(0, iAlight+1))`。
- **起终点同站（board≈alight）**：整线着色（PM 边界 #4「环线不画区间外灰色」）。

**降级**：`shapes` 缺失 / 两方向都超容差 / 切割失败 ⇒ **只画该段整线着色 + 起终点标记，不画灰段**，并 `console.warn`（不阻塞）。

### 3.3 图层与线型（Token 化，禁硬编码）

| 层 | 内容 | 颜色来源 | 线宽 | zIndex |
|----|------|----------|------|--------|

> `AMap.Polyline.strokeColor` 由画布绘制、**拿不到 CSS 变量** ⇒ 运行时 `getComputedStyle` 读 `--border-2`（读不到则用 `--muted`，再不行跳过灰段），与 `NavMap.tsx:92-99` 的 `maskFill()` 同一做法。

## 4. 车辆图标原生化方案（「粘地」修复）

### 4.1 根因（读码取证）

现有实现（`NavMap.tsx:977-1047`）：以 `lngLatToContainer` 把车辆投影成**屏幕像素**，`viewchange/zoomchange/move/zoom` 触发 **rAF 节流**，再 **`setVehiclePts(...)` → React setState** 重渲染 `VehicleMarker`。

- 拖拽时地图画布由 AMap 自身渲染循环重绘；我们的图标要**等 React commit 后**才更新 ⇒ **至少落后一帧**，且每帧触发一次 React 协调（reconciliation），合成层与地图不同步 ⇒ 视觉「飘/滞后」。
- **反证**：站点层/定位/目的地同为 `AMap.Marker`（`NavMap.tsx:740`）用的是**原生字符串 `content`**，从不「飘」；只有车辆这一处走 React 覆盖层 ⇒ **问题定位在"覆盖层 + setState"，而非数据**。

### 4.2 推荐：原生 `AMap.Marker` + `content` 传 DOM 元素（每簇一个 React root）

**方案**：把每个车辆簇渲染进一个 DOM 容器，作为 `AMap.Marker.content` 交给高德；位置由**地图引擎驱动**（与地图变换同循环），拖拽期**零 JS、零 React 更新**。

```ts
// 伪代码（新增 src/components/nav/VehicleLayer.tsx，挂在 NavMap 内）
const live = new Map<string, { marker: any; root: Root }>();
function upsert(clusters: VehicleCluster[]) {
  for (const c of clusters) {
    let rec = live.get(c.key);
    if (!rec) {
      const el = document.createElement("div");
      const root = createRoot(el);                 // react-dom/client（React 19）
      const marker = new AMap.Marker({
        position: [c.items[0].lng, c.items[0].lat],
        content: el,                               // ★ DOM 元素
        anchor: "center",                          // 44px 命中区居中
        zIndex: 130,                               // ★ > dest pin 120 > station 95，否则车被 pin 压住
        bubble: true,
      });
      marker.on("click", () => onVehicleClickRef.current?.(c.items[0], c.items.length));
      map.add(marker);
      rec = { marker, root };
      live.set(c.key, rec);
    }
    rec.marker.setPosition([c.items[0].lng, c.items[0].lat]);
    rec.root.render(<VehicleMarker items={c.items} x={0} y={0} onClick={...} />);
  }
  // 清理消失的簇：map.remove(marker) + root.unmount() + live.delete(key)
}
```

- **合并（28px）**：不再每帧重算。改为在 **数据刷新时** + **`moveend`/`zoomend`（节流 120ms）** 时用 `lngLatToContainer` 重算一次簇，然后 diff 增删。**拖拽进行中不重算**（图标只随地图平移，不弹跳）——这与 Google Maps 标号「平移后再收拢」的手感一致，且消除拖拽期全部 JS。
- **样式零改动**：`VehicleMarker.tsx` 的 SVG/`data-state`/`--vbus-livery` 全部保留（`x/y` 传 0，由 marker 定位）。`.vbus-wrap` 里 **`position:absolute` / `left:0` / `top:0` / `transform: translate(-50%,-50%)` 四行删除**（居中改由 marker `anchor:'center'` 负责，避免双重偏移）；`.vbus` 32×32 与 44×44 命中盒（`place-items:center`）**保留**（anchor 居中 44 盒，32 svg 自动居中，视觉与现状一致）。
- ⚠️ **z-index 回归**：车辆原为 `.nav-vehicle-layer`（DOM 覆盖层 z15，天然压在站点/pin 之上）；改原生 marker 后进入高德覆盖物命名空间，若不给高值会被 station(90/95)、pin(110/120) 压住 ⇒ 车 marker **`zIndex:130`**（> pin 120）务必落码（见 §3.3）。

**迁移路径**：① 先按 feature flag 落地 `VehicleLayer`（原生）与旧覆盖层并存；② 真机对比拖拽手感（低端安卓 + iOS Safari）；③ 稳定后删除旧覆盖层与 `vehiclePts` state。

### 4.3 备选方案（评估结论：不推荐）

| 方案 | 评价 |
|------|------|
| **B. 覆盖层 + 全事件同步 + 去 setState**（保留 React 覆盖层，改为在 `dragging/mapmove` 里**直接写 DOM `transform`**，不进 React） | 保住现有合并/组件逻辑，比现状好；但仍是「地图渲染后再手动补位」，低端机仍可能落后一帧。**仅作 Plan B**。 |
| **C. `AMap.MarkerCluster` 插件** | 官方插件按**网格/zoom**聚合，视觉是聚合气泡，**不符合**「保持现有车辆样式 + 28px 屏距 + 数量角标」的口径。**不采用**。 |

### 4.4 风险

- `createRoot` 与 `root.unmount()` **必须成对**（否则内存泄漏）；用 `Map<key,{marker,root}>` 严格配对，组件卸载时遍历清理。
- React 19 允许多 root；但**容器 DOM 由高德持有**，`root.render` 前后不得让高德重建容器。
- 原生 marker 依赖「自定义 `content` 走 DOM 渲染」这一行为（官方支持 `content: String|HTMLElement`）。**实施第一步先做 10 辆小样验证**：确认 DOM content 在 2.0 下确实为 DOM 节点、click 正常、拖拽不飘。若该行为在某些版本退化，回落方案 B。
- click 命中：`anchor:'center'` + 44px 命中盒；`bubble:true` 允许冒泡到地图。
- `raiseOnDrag` 默认行为会把拖拽中的 marker 置顶 —— 对车辆可接受（可选 `raiseOnDrag:false` 保持稳定层级）。

| R9 | 兼容 | 原生 marker DOM content 行为跨版本 | 先 10 辆小样验证；回落覆盖层 Plan B |
| R10 | 手感 | 拖面板时取景抖动 | **落定后**才 `fit-box`；拖动中不触地图取景（PM §2.2） |
| R11 | 手感 | 列表滚动 vs 面板拖拽冲突 | 内容区 `scrollTop>0` 不接管拖拽 + `touch-action: pan-y` |
| R12 | 兼容 | iOS 安全区 / 灵动岛压地图带 | full 顶边 `max(safe-top+44, 12vh)` clamp [96,128]；底部 `safe-bottom` padding |
| R13 | 兼容 | `prefers-reduced-motion` | 面板/车标过渡在该媒体查询下 `transition:none` |
| R14 | 性能 | 弱网动画被阻塞 | 面板当帧先动 + 骨架；detail-body 并行（PM §2.3） |
| R15 | 回归 | 删页后旧链接 401 | middleware 前置重定向（§5.5）；`/api/nav` 前缀保留 |
| R16 | 合规 | 硬编码颜色 / emoji | 颜色走 Token / `routes.color`；图标走 `@tabler/icons-react` + `VehicleMarker` SVG |
| R17 | 性能 | 多段换乘并行请求过多 | 各段 `route-shapes`/`route-vehicles` **并行** `Promise.all`；`route-shapes` 用 `force-cache` |

## 8. 端到端验证步骤（收尾即验收）

**构建/静态门（必须全绿）**
1. `npm run lint`（ESLint 9）—— 无 error、无新增 warning。
2. `npx tsc --noEmit`（`tsconfig.tsbuildinfo`）—— 类型通过。
3. `npm run build` —— 构建通过（**防幻觉 import / 静默缺失**）。

**核心成功流（真机 390×844 优先）**
4. 首页定位成功 → 选目的地 → 半屏「出发」→ 推荐面板在 **88%（顶边 96–128px）** 出现且顶部地图带**未被状态栏遮挡**；此时**拖动顶部地图带能平移地图**（非模态）。
5. 点任一张卡 → 面板**平滑降到 50%**（无网络等待阻塞，先骨架）；**上半屏出现路线总览**：乘车段彩色（主题色）、其余灰、起/终点标记；**换乘路线每段独立着色**。
6. `26 号线`（单向循环）作为任一乘车段 → 检查切割**不出现首尾连错**、环线不误画长灰段。
7. 详情半屏上拖越阈 → 吸附 **88%**，顶部仍留地图带；下拉越阈 / 点返回箭头 → **回推荐列表且列表滚动位置不变**。
8. 点面板 X / 推荐下拉越阈 → 回半屏可出发态。

**关键错误/边界流**
9. 地图 Key 缺失/加载失败 → 弹窗与列表**完全可用**（沿用「地图失败不阻塞」）。
10. `detail-body` 500 → 详情显示「详情加载失败（路线不受影响）+ 重试」，**总览与地图照常**。
11. 该方向无在途车 → 地图**不显示车图标**，文案区分「未发车 / 已收班」。
12. 旧直链 `/nav?fromLng=…&toLng=…` 与 `/nav/detail?…&plan=…` → 308 到 `/?<query>`，首页**预填 OD 进半屏**（未登录也生效）。

**性能观测**
13. 车辆拖拽：DevTools Performance 录制拖地图 3s —— 拖拽期主线程**无 React commit**（原生 marker 方案）；帧率稳定。
14. 面板拖拽：`transform` 合成层，无 layout thrash；落定后才出现一次取景。

**回归观测钩子**：既有 `data-nav-zoom` / `data-nav-z` / `data-station-count` / `data-limit-bounds` / `data-map-mask` 保持不变。**新增（契约锁定，Spec §10；取值以 Spec 为准）**：`data-sheet-state=recommend|detail`、`data-detent=peek|half|full`、`data-phase=loading|ready|empty|failed`、`data-live=on|none|ended`、`data-map=ok|failed`、`data-overview-legs=<number>`（详情已绘制乘车彩段数）。辅助钩子 `data-sheet=open`（面板开合，驱动搜索框淡出）与 `data-sheet-state` **是两个不同属性**，勿合并。
备注：面板态命名为 `data-sheet-state`，与 `VehicleMarker` 的 `data-state`（车辆状态 moving/stopping/…）**区分开**，QA 断言不再撞名。
