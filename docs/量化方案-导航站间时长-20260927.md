# 量化方案 · 站间时长与导航「N 站 = X 分钟」精度提升

> 制定：2026-09-27 · 依据：9 项离线实验（162k 样本 · 47 轮采集 · 时间切分验证）· 配套实验档案见 `data/tracking/analysis-20260927/quant/`
> 状态：**已定稿 · 已存档**（2026-09-27 用户决定：**暂缓实施——先补采盲区数据、之后再动工**）· 目标：把「还有 N 站 = 还有 X 分钟」从「能用」做到「可信」
> 动工前置：优先补采盲区（§6.5）：**周五 17-19 时**（最高）> **周末 14-19 时** > 07 时 > 13-14 时

## 0. 摘要：三个问题的直接回答

| 问题 | 结论（数据支撑） |
|---|---|
| **① 用什么统计量？** | **中位数（p50）够用、不加列**——trim10 仅再省 <0.5pp，收益主来自分层（详见 §2 实验 6 双版本验证）；异常靠「护栏 + n≥5 细层门槛」双保险 |
| **① 异常数据怎么处理？** | 保留现护栏（命中 0.24%，防偶发大错）；**细层设 n≥5 门槛，小样本键不允许进入细层**（回退粗层，宁缺毋滥）；截尾均值为 v2 备选 |
| **② 按什么分？** | **数据驱动时段划分**（不预设 7-10/17-20，推导见 §6）：**`am 7-9`（工作日/周末两池）· `day 9-16` · `pm 16-20` · `night 20-7`**。关键修正：**16 时已慢（1.14）应从「日间」挪入晚高峰；19 时已回落；18 时才是真峰（1.21）**；**周末晨间不慢反快（−21%）必须与工作日分池**；「星期」维度除晨间外无增益（**周一可并入工作日池**，实测比值 0.96-1.00）；**逐小时不可行**（命中 2.2%） |
| **③ 导航中怎么更准？** | ① 静态层用新口径（时段+门槛）——**链上 A/B 实测改善 ~24%**（剩余 3 跳 MADE 1.095→0.835；p50/trim10 双版本同效）；② 导航中**新增「还有约 X 分钟」显示**（现状只有站数没有分钟），随车过站重算；③ **不做「动态修正」**——两项独立实验证明实时修正（本车实测/他车代理）**无收益甚至有害** |

## 1. 现状盘点（代码链路）

### 1.1 现有实现（已核验）

| 环节 | 位置 | 现状 |
|---|---|---|
| 车距用户站 N 站 | `src/lib/dsat/eta.ts` | DSAT 挂载站 + status 判定；含环线/总站特殊规则；顺带返回逐跳站对 `hops` |
| 「N 站 → X 分钟」 | `src/lib/recommend/live.ts#toBusArrival` | 逐跳 `lookupHop` 求和；`lo = sum`（已离站减第一跳）、`hi = sum × 1.25` |
| 逐跳时长查询 | `src/lib/recommend/segment-lookup.ts#lookupHop` | 回退链：**L1 本线+星期** → L2 本线全周 → L3 本线全周(all) → L4 跨线站对 → L5 本线单跳均值 → L6 全局；**门槛 n≥1；取值 p50 优先** |
| 数据表 | `segment_stats` | 分层键 = `route|from|to|weekday|bucket|kind` + 兜底行（`weekday=-1`）；**bucket 分层行已存在但查询侧没用** |
| 导航中显示 | `NavDetailBody.tsx` L166 | **只有「距下车站还有 N 站」——没有剩余分钟** |

### 1.2 实测发现的四个问题

1. **分层没用对**：数据层已按「星期 × 时段」存了行，查询只用了「星期」——而实验证明「时段」才是有效维度（星期链 MADE 0.595 vs 时段链 0.515）。
2. **门槛太松**：`n≥1` 就用——单条样本的噪声直接进预测。实验：n<3 的键 MADE 0.866 vs n≥10 的 0.475。
3. **系统性高估**：现状链（p50 + 星期）对「剩余跳之和」**平均多报 +0.4 分（4 跳时）**——用户看到的 X 平均比实际多 20 多秒。
4. **导航中无分钟**：「还有 X 分钟」只存在于等车/推荐场景；上车后用户只能自己数站。

| **7b** | **时段划分方案对比**（11 个候选 × 时间切分） | 最优 = **C1H**：`7-9 / 9-16 / 16-20 / 20-7` + **早高峰桶按工作日/周末拆两池**——总 MADE **0.512**（现状划分 0.518 · 不分时段 0.528）、**细层内 MADE 0.484**（现状 0.502）；全时段日型拆池反而更差（0.527-0.530，样本切碎）；六桶/五桶均不如四桶微调（命中率跌） |

## 3. 方案设计

### 3.1 统计层（离线聚合改造）

**改动点：`src/lib/rebuild/segment-stats.ts`（聚合 push + 时段函数）**

1. **时段定义升级为数据驱动版（C1H，推导见 §6）**——新增共享函数 `bucketOfRoute(weekday, hour)` → **五值**：
   `am_work`（工作日 07-09）· `am_weekend`（周末 07-09）· `day`（09-16）· `pm`（16-20）· `night`（20-07）
   - 数据层按它生成聚合行：`route|from|to|-1|bucket|kind` + 兜底 `-1|all|kind`、`-1|all|all`——**不再生成旧 `wd|bucket` 行**（重建全量替换；新表 ≈ 2-3 万行，比现 4.1 万更少）。
   - ⚠️ **同步点**：`segment_samples` 的 samples 路径**不再信任存储的 time_bucket**，rebuild 从 `observed_at` 就地重算（一行改动）；`import-segment-samples.ts` 写入同步升级新桶（保持字段语义一致）。
2. **取值统计量**：`avg` 之外补 **`p50`** 与 **trim10 需新列**——
   - 现表已有 `avg_minutes` 与 `p50_minutes` 两列。trim10 需要**新列**或「用 p50 近似」。
   - 简化路径（推荐 v1）：**直接用现有 p50 列**——实验显示 trim10 vs p50 差异仅 ~1 秒/跳，**不值得加列**；trim10 列为 v2 备选。
   - ✅ v1 决策：**统计量保持 p50（不加列）**——A/B 双版本验证：新口径用 p50 改善 −23.1~−24.6%、用 trim10 −23.7~−25.1%（差 <0.5pp）→ **收益主来自分层+门槛**；trim10 记入 backlog。

**改动点：`src/lib/rebuild/segment-samples.ts`（护栏）**

3. 护栏参数保持（`mult=3 / floor=2min / n≥5`，命中 0.24%）——不变。

### 3.2 查询层（`lookupHop` 回退链重构）

**改动点：`src/lib/recommend/segment-lookup.ts`**

**新回退链**（按实验②⑦的排序；门槛只施于「细层」；bucket = `am_work|am_weekend|day|pm|night` 按当前时刻与星期取）：

```
L1 本线 + 当前时段（-1|bucket|stop）     n≥5  ← 新
L2 本线 + 全周（-1|all|stop）            n≥1  ← 原 L2
L3 本线 + 全周（-1|all|all）             n≥1  ← 原 L3
L4 跨线站对 + 当前时段（任一线路行）      n≥5  ← 新
L5 跨线站对（-1|all|all 任一线路）        n≥1  ← 原 L4
L6 本线单跳均值 × 1
L7 全局单跳均值 × 1
```

- 签名调整：`todayWeekday: number` → 改传 `nowMs`（内部用共享 `bucketOfRoute` 算 星期+时段——调用方少改、口径唯一）。**调用方清单**：`card.ts`、`live.ts`、`model.ts`、`recompute.ts`、`strips.ts`、`nav-service.ts`（eval 全文 grep 复核）。
- ⚠️ **兼容设计**：兜底行（`-1|all|*`）在两种版本中都存在 → **数据侧或查询侧单独先上线都安全**（找不到细层时自动回退全周，最坏精度降级、不会崩）。回滚 = 还原代码 + 重算（或回部署旧版）。
- ⚠️ **环线/eval 断言**：改后必须复跑既有测试（`test:altbuses` 14 / `test:siblings` 17 / e2e-v330 探针）+ 新增单测：「时段行优先」「n<5 回退」「周末晨间走 am_weekend」三条断言。

### 3.3 导航中「还有 X 分钟」（新功能）

**改动点：`src/components/nav/NavDetailBody.tsx`（显示）+ 依赖既有 `strips` 数据（求和）**

1. 「距下车站还有 N 站」**下方加小字「约 X 分钟」（用户口径 · 两行布局）**：
   ```
   [距离] 距下车站还有 3 站 · 下一站 氹仔客運碼頭
          约 5 分钟
   ```
   - `X = Σ strips[legIdx].stops[nextIdx .. alight-1].minToNext`（从下一站到下车点的逐跳值之和——**strips 里逐跳值已是服务端 lookupHop 产物，3.2 改造后自动升级到新口径**）。
   - N=1 时小字「即将到站」；X 下限 1 分（防「还有 0 分钟」）。
2. **帧间平滑（递减器）**：两次车辆轮询（12s）之间，X 按真实时间流逝本地递减；新帧到达重算并校准。
   - 冻结（丢信号）时：**数字停住 + 「信号恢复后自动跟上」**（沿用现有冻结哲学，绝不乱跳）。
   - ⚠️ 递减器只递减到「距上次重算的剩余量」为止，防止长时间无帧时显示 0 分却未到。
3. **验收**：`data-nav-*` 观测钩子扩一个剩余分钟字段；E2E 断言「导航中显示分钟且单调不增（冻结除外）」。

### 3.4 放弃项（有数据论证，明确不做）

| 放弃 | 依据 |
|---|---|
| 本车动态修正（K 系数） | 实验④：MADE 全线更差/持平（噪声>信号；K 集中在 [0.76,1.25]） |
| 他车路况代理 | 实验⑤：他车近邻预测 0.545 > 静态池 0.518（无预测力） |
| 逐小时分层 | 实验②：命中率 2.2%（168 格样本密度不足） |
| 星期×时段 28 格 | 实验②：命中 29%、总 MADE 反而差于 4 桶 |
| 导航中显示「X~Y 区间」 | 多跳时区间宽（k=5 时 ± 数分钟），移动场景噪音源；**单值 + 「约」**即可 |

### 3.5 等车场景区间重标定（P2，可选）

- 现状 `[sum, 1.25sum]` 单侧区间实测覆盖率 **24%**——严重低估。可选口径（择一）：
  - a) 改为双侧 `[0.75c, 1.25c]`（覆盖率 61.8%，宽 1.05 分/跳）
  - b) 目标 80%：`[0.6c, 1.4c]`（宽 1.68 分/跳）——**推荐**（多跳时覆盖率自然升到 ~81-96%）
- 涉及 UI（卡片「约 X~Y 分」）与 `live.ts` 的 `loSec/hiSec` 计算——独立小改，低风险。

## 6. 时段划分的推导过程（专题 · 回答「7-10/17-20 是否想当然」）

> 方法：**不预设边界**——「同一站对键内的**小时级中位比值**」（每个键自己与自己比，自动控制站对构成差异；跨键取中位）。
> 全部数字来自实验⑦a/⑦b/⑦c（脚本 `.verify/_track-quant-7a|7b|7c-*.mjs`，可复跑）。

### 6.1 小时级慢化曲线（全真形态）

| 小时 | 慢化比（>1 慢） | 说明 |
|---|---|---|
| 08 | **1.154** | 早高峰峰值 |
| 09 | 1.030 | 快速回落 |
| 10-12 | 1.00 | 平峰（基准）|
| 13-15 | 1.06→1.08 | 采集盲区×午间微峰 |
| 16 | **1.143** | **已入慢区（现划分却归「日间」）** |
| 17 | 1.143 | 持续慢 |
| 18 | **1.207** | **全天真峰** |
| 19 | 1.059 | 回落中（现划分仍归「晚高峰」）|
| 20 | 0.987 | 已恢复 |
| 21-23 | 0.937→0.800 | 夜间持续走低 |

**结论**：真实的「早高峰」≈ 8 时前后 1 小时；真实的「晚高峰」≈ **16:00-19:00 区间**（16 时开始、18 时峰值、19 时回落）——**均与 7-10 / 17-20 的理想化窗口有 1-2 小时的错配**。

### 6.2 候选划分对比（实验⑦b · 时间切分）

| 候选 | 总 MADE | 细层命中 | 细层内 MADE | 判读 |
|---|---|---|---|---|
| C0 现状（7-10\|10-17\|17-20\|20-7） | 0.518 | 92.0% | 0.502 | 基准 |
| **C1 四桶微调（7-9\|9-16\|16-20\|20-7）** | **0.512** | 92.3% | 0.486 | 边界修正有效 |
| C2 五桶（+19-21 eve） | 0.514 | 91.1% | 0.490 | eve 拆分无净收益 |
| C3 六桶（+午间 noon） | 0.516 | 82.8% | 0.489 | 样本切碎、命中跌 |
| C1W 全时段×日型双池 | 0.527 | 85.9% | 0.503 | **反而更差**（样本切碎）|
| **C1H C1 + 早高峰桶分工作日/周末** | **0.512** | 91.4% | **0.484** | **★ 采纳**（细层内最优，晨间物理正确）|

### 6.3 日间合并核验（实验⑦c）

| 对比 | 结果 | 结论 |
|---|---|---|
| 周一 vs 周二~四 | 08 时 0.96 · 09 时 1.00 · 21 时 0.97 | **可合并为「工作日池」**——没有证据支持周一分池 |
| 周末 vs 工作日 | 08 时 **0.79**（快 21%）· 09 时 0.94 · 12-13 时 +4~6% · 其余 ≈1 | 差异集中在**晨间** → 仅早高峰桶分池 |
| 周五 vs 周一~四 | 15/16 时 +8~9% · 20-22 时 +3~20% | 存在但样本少（17-19 盲区）→ **待补采复核**，暂不单列 |

### 6.4 最终时段方案

```
am_work    工作日（周一~五）07:00-09:00   ← 分池理由：工作日晨峰 1.15 vs 周末 0.92
am_weekend 周末（周六日）  07:00-09:00
day        09:00-16:00（含午间微峰，暂不细分）
pm         16:00-20:00（16 时从旧「日间」挪入——最大单点修正）

```

**与「现状四桶」差异摘要**：① 晚高峰边界 17-20 → **16-20**（16 时实测已慢 1.14）；② 早高峰 7-10 → **7-9 且分工作日/周末**（9 时已回落 + 周末晨间快）；③ 20 时归夜间（实测已恢复 0.99）。
