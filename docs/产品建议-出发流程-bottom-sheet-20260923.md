# 产品建议 · 「出发」流程 Bottom Sheet 交互（M Map / MUST登校）

> 角色：产品经理 许清楚　｜　日期：2026-09-23　｜　范围：首页「出发」→ 推荐弹窗 → 详情弹窗（路线总览）
> 输入：用户 7 条原话（与本文件相关的 4 条）+ 已澄清口径（路线总览：乘车区间彩色 / 区间外灰色；巴士图标保持现状；收藏页不加地图）
> 定位：本文件为**产品建议**，供架构师 / 设计师落地。不做技术选型，不下代码结论。

---

## 0. 一句话结论

把「推荐」「详情」两层做成**同一个可拖拽 bottom sheet 的多个停靠点**（不是两个独立全屏弹窗），用**三档吸附（20% / 50% / 88%）**表达；推荐默认落 **88%（基本全屏，顶部留一点点地图）**，点卡片降到 **50%（上半屏地图露出路线总览）**，再上拖回 **88%**。动画优先于网络——面板先动起来，数据后填。

## 1. 调研发现

### 1.1 Google Maps 的 bottom sheet（用户明确说「学习谷歌地图」）

**三停靠点比例**（业界已知的 Google Maps 风格参数，`FlexibleSheetSize`）：

| 档位 | 屏幕占比 | 说明 |
|------|----------|------|
| 收起态 Peek（slightlyExpanded） | **≈0.18（18%）** | 底部一小条摘要 |
| 半屏 Half（intermediatelyExpanded） | **0.5（50%）** | 快速详情 |
| 全屏 Full（fullyExpanded） | **0.9（90%）** | 综合信息，**顶部仍留一条地图**（"leaving a sliver of the map visible at the top"） |

> 对照参考：Material `FlexibleSheetSize` **默认**是 1.0 / 0.5 / 0.25；但要做「Google Maps 感觉」，社区共识是调成 **0.9 / 0.5 / 0.18**。即"基本全屏但不是真全屏，顶部固定留一点点地图"。

**2024–2025 改版要点（与本需求高度一致，可直接对照）**：
- 菜单**不再铺满整屏**，**顶部永远露出一块地图**；菜单「看起来是浮在地图之上」，而不是一个独立页面。
- 面板顶部有一条**明显的拖拽条（grabber handle）**提示可下拉收起；另有 **X 按钮**可彻底关闭。
- 公交的**出行方式切换**（驾车/公交/步行…）在收起/半屏时放在**屏幕底部**，只有**全屏时**才移到顶部。
- 上滑展开**不再拉伸到整条屏幕高度**，所以**能持续看到大部分路线**。

**吸附与关闭手势**：
- 松手后**吸附到最近的停靠点**，不是停在手指松开的位置；吸附判定**同时看位移与速度（fling velocity）**——轻甩即切档。
- 关闭=从**最低档继续下拉**越阈值即关闭；行业内常见自定义阈值为 **下拉位移 > 120px**（叠加速度判定），iOS 系统 sheet 则是「越过档位间距一半或带速度」。
- **嵌套滚动协调**：全屏态内部列表可滚；列表**滚到顶再继续下拉**才拖动整个面板（避免"想滚列表结果把面板关了"）。

**内容随档位切换**：Google Maps 收起态=地点名，半屏=照片/评分，全屏=评论/详情。且用 `targetValue`（**用户一拖就切内容**，不等动画结束）→ 「丝滑」的关键来源之一。

**过渡方式**：点列表项 → 详情是**同一个 sheet 的内容切换 + 视口变化**，**不是**叠加一个全新页面；地图同时 `fitBounds` 到该路线。

### 1.2 iOS / Material 规范补充（用来定"权威边界"）

- **iOS detent**：`medium ≈ 50%`、`large ≈ 全高`；Apple Maps 就是 medium ↔ large 两档。`largestUndimmedDetentIdentifier` 控制"到哪一档才加遮罩"——地图类应用在 **medium 不加遮罩**，背景地图**可继续操作**。
- **Material**：`标准 bottom sheet`（非模态）与**主区域地图共存**、默认 elevation 8dp；而 `模态 bottom sheet` 初始高度**上限为屏高 50%**（本场景应走**非模态**，不加 scrim）。
- 术语统一：本文件「停靠点 / 档位」= detent = snap point。

### 1.3 高德 / 百度「公交路线详情」对比

| 维度 | 高德地图 | 百度地图 |
|------|----------|----------|
| 线路详情结构 | 顶部：线路名 + 运营方向（起点→终点）+ **换向**按钮；全程距离、票价；**站点以时间轴（路线图）排列**，首站标「始」、末站标「终」 | 换乘提示、预计到达、总站数、步行距离、票价 |
| 实时公交 | 地图上显示该线路**所有在线运营车辆**的移动图标，每辆标注**距最近站点的站数与预计分钟**；支持**关注线路**、**多线路对比** | 有实时公交，但「实时地图」页呈现**略逊**，且**无法拖曳地图**查附近站点（差评暴露的短板） |
| 地图与详情分割 | 详情为底部抽屉；地图在上方持续可用；另有「公交图层」可**直接在图上显示站点** | 分割类似，但列表/地图联动较弱 |

**结论**：高德的强项 = **"整条线上全部车辆 + 每车到站预测 + 关注/收藏"**；百度的短板 = **地图与列表联动弱、实时页不可拖拽**。我们的方向（全线车辆 + 地图可交互）**与高德强项一致、需避开百度式短板**。

### 1.4 实时公交位置 · 行业惯例（Citymapper / Moovit / 高德）

- **Moovit Live Location（2022 上线）**：车辆以**图标沿地图实时移动**；同屏显示三件事——① 到站倒计时（绿色）、② **数据最后更新时间**（"上次收到车辆信号"）、③ 该线路的**服务提醒**。可从「行程 / 线路详情 / 站点详情」任一处一键进入。
- **Citymapper / Transit**：实时到站 + 分步导航 + 下车提醒；强调**可信度提示**（数据新鲜度）。
- **高德**：全线车辆图标 + 每车到站分钟数 + 关注线路。

**共性惯例（我们应遵守）**：
1. **显示整条线上的全部在途车辆**（不是只显示最近一辆）——与用户「整条线上全部实时巴士图标」口径一致。
2. **车辆图标随刷新移动**，并**给出数据新鲜度**（多久前收到信号）——用户已强调低延迟，**"数据多新"必须可见**（否则低延迟无从判断）。
3. **到站倒计时**放在最显眼处。
4. 车辆/线路视觉分层：**乘车区间**与**非乘车区间**要能一眼区分（用户已拍板：区间彩色 / 区间外灰色）。

## 2. 产品建议

### 2.1 三停靠点比例（**拍板建议**，含安全区）

采用**单一 bottom sheet + 三档吸附**。比例按**屏高百分比**定义，并对**顶部安全区**做下限保护：

| 档位 | 建议占比 | 典型设备高度（px） | 用途 |
|------|----------|--------------------|------|
| **收起 Peek** | **20%** | 852→≈170 / 667→≈133 | 「收起浏览地图」休息态（可选档） |
| **半屏 Half** | **50%** | 852→426 / 667→334 | **详情默认**：上半屏地图 = 路线总览 |
| **全屏 Full** | **88%** | 852→≈750 / 667→≈587 | **推荐默认**；详情上拖态。顶部留 **≈12%（96–128px）地图** |

**"顶部留一点点地图"的精确口径（关键）**：
- 全屏态面板顶边位置 = `max(顶部安全区 + 44px, 12vh)`，clamp 到 **[96px, 128px]**。
  - iPhone 14 Pro（852 高，安全区≈59）：留 ≈103px（12%）→ 顶边落在灵动岛之下，**不压状态栏**。
  - 直屏 Android（800 高，状态栏≈24–28）：留 ≈96px（12%）。
  - iPhone SE（667，安全区≈20）：留 ≈96px（14.4%）。
- 即：**"一点点地图"≈ 一个状态栏 + 一条 44px 的可读地图带**，既满足"基本全屏"，又保证地图条落在**安全区内、不被刘海/灵动岛遮挡**。
- **半屏 50%** 时，上半屏地图**必须容纳整条路线总览**（见 2.4 的取景 padding）。

> **MVP 取舍**：MVP 最小实现 **{50%, 88%} 两档**即可满足用户 4 条原话；**20% 收起档建议保留设计位**（符合 Google Maps 手感），但可放 Backlog。
> **安全区**：底部半屏/全屏面板需 `padding-bottom: env(safe-area-inset-bottom)`，避免内容被 Home 指示条压住；顶边避让 `env(safe-area-inset-top)`。列表滚动区不要被底部指示条遮挡。

### 2.2 交互细节建议

**手势与吸附（直接回应"丝滑流畅低延迟"）**
- 拖动直接用 `transform: translateY()`（GPU 合成、`will-change: transform`），**不重排布局**；跟手用 `pointermove`（`touch-action: none` 防止页面滚动干扰）。
- 松手吸附 = **位移 + 速度**双判定：
  - 位移越过"当前档→相邻档"间距的 **50%**，或 **速度 > ≈0.5 px/ms** 同向 → 吸附相邻档；
  - 否则回弹当前档。
- **越界阻尼**：到最高/最低档继续拖时给 1/3 阻尼（rubber-band），松手回弹。
- 过渡动画 **≈240–300ms**，缓动 `cubic-bezier(0.32, 0.72, 0, 1)`（iOS 手感）；**拖动中不播动画，仅松手后播放**。
- 内容切档：用户**一拖就切**（用拖动方向/目标档预测，而非等动画结束）→ 这是"丝滑"的隐形关键。
- **拖拽中不要触发地图重绘/重新取景**；地图 `fitBounds` 在档位**落定后**再做，避免抖动。

**关闭 / 返回方式**
- **顶部抓手下握条**（居中，宽 ≈36–40px、高 4px，胶囊形，SVG）——提示可拖。
- **返回箭头图标**（左上角）在详情层：点击 = **关闭详情、回到推荐列表**。
- **关闭（X）图标**：彻底退出该层（推荐层 X → 回全屏地图）。
- **下拉手势**：详情从 50% 继续下拉越阈值 → 关详情回推荐；推荐从最低档下拉 → 关推荐回地图。
- **返回详情后必须原位原样**：推荐列表**保持挂载不卸载**（保留滚动位置），详情层关闭即显形 → "秒回列表"（现有 `RouteResultSheet` 常驻挂载思路正确，沿用）。
- **非模态**：半屏/全屏时**不加 scrim**，地图在露出的部分（尤其半屏上半屏）**可拖、可点车、可点站**；点击地图空白**不**关闭面板（避免误触），关闭只走抓手下拉 / 返回 / X。
- 焦点管理：面板打开时焦点入面板；`Esc` 关闭（桌面 PWA 可达性）；抓手下握条、返回/X 均可键盘达。

**过渡方式（点卡片 → 详情）**——**推荐：同一 sheet 内容切换 + 高度联动**（最像 Google Maps、手势最连续）
- 点卡片瞬间：面板从 **88% 平滑降到 50%**，**同时**地图从"露一条"扩到"上半屏"并 `fitBounds` 到该路线总览 → 视觉上"面板让位、地图露出路线"。
- 内容从"推荐列表"**淡帧切换**为"详情"（短交叉淡入，避免生硬跳变）。
- 实现上推荐列表**保留在内存**（不卸载），返回时秒恢复。
- **备选（真叠层）**：详情作为独立层盖在推荐层之上（现有 `RouteDetailSheet` z-80 即此模式）。缺点：两层各有高度、手势归属易冲突、"缩到半屏"会出现列表在详情上方露出的怪异层叠 → **不建议**用于本场景，除非架构师证明同层方案成本更高。

### 2.3 加载策略（预加载）

**目标：面板动画永不被网络阻塞。**

- **点击即开面板**：点卡片的**当帧**就让面板开始从 88%→50% 的动画 + 显示**骨架**；`POST /api/nav/detail-body`（站条/实时报站）**并行后台请求**，到达后填充。**绝不等接口返回才开面板**。
- **路线总览画线**所需数据（各段线路、乘车区间上/下车站）**推荐卡里已有** → 地图可**立即**画"区间彩色 + 区间外灰色"，**无需等 detail-body**。这是"点开就有路线"的关键。
- **预取建议（MVP 最小集）**：
  1. **首张卡预取**：推荐列表渲染完成后，后台预取**第一张卡**的 detail-body（用户最常点）。
  2. **可见性预取（进阶/Backlog）**：某卡进入视口且用户滚动出现短暂停顿（≈150–200ms）时，低优先级预取该卡。
  3. **实时车辆预热**：进入详情前 300–500ms（或卡片即将打开时）触发一次车辆拉取，复用现有 `useRouteVehicles`（10s 冷却口径不变）。
- **缓存与失效**：沿用现有"同 query 只拉一次、关闭再开秒显上次结果"；仅换目的地 / 刷新 / 车辆 10s 冷却到期才重拉。
- **降级优先**：detail-body 失败 → 详情显示"详情加载失败（路线本身不受影响）+ 重试"，**地图与总览照常**（沿用现有降级铁律）。

### 2.4 换乘路线（1~2 次换乘）的「路线总览」显示

**色彩与线型（用户口径：乘车区间彩色 / 区间外灰色）**
- **乘车段**：用该段线路**主题色**，线宽最粗最亮（建议 5–6px）；相邻乘车段**不同色**，若恰为同色，在换乘节点加**分隔环**避免连成一条。
- **区间外**：同一条线路上"未乘坐"的其余部分画**灰色细线**（建议 2–3px、低饱和灰），**视觉权重最低**，不要与乘车段抢夺注意力。
- **步行段**（点到站、换乘步行、末段步行）：**虚线**（区别于实线乘车），配步行时长/距离小标签。
- **图层顺序**：区外灰线在最底 → 步行虚线上 → 乘车彩线在最上（保证彩线不被压住）。

**节点标记（文字描述，统一 SVG 图标库，**不用 emoji**）**
- **起点标记**：圆点 + 「起」字内嵌（或实心圆点 + 出发箭头图标）。
- **终点标记**：图钉/旗标图标 + 「终」（或「終」）。
- **换乘节点**：在两段交接处放大为**双色环**（内环=上段色、外环=下段色）+ 换乘图标；点击节点可放大该换乘点。
- **上/下车站**：在乘车段首尾用小圆点标注（可显示站名气泡）。

**取景（最容易做错的一点）**
- 打开详情时 `fitBounds` **要装下整条推荐路线（所有段 + 起终点）**，**不是**单条线路。
- **必须给底部面板留 padding**：把取景的"可视区域"当作**上半屏**，即 `fitBounds` 时向下补偿约 **50% 屏高**的 padding，使路线主体落在**不会被面板盖住的上半屏**。否则路线会被面板遮住一半（这是百度式联动的典型槽点）。

**多段信息层级（列表侧）**
- 详情列表按"步行 → 乘车（N 站）→ 换乘步行 → 乘车（M 站）→ 步行"顺序，每段一个卡块：**线路色标签 + 上下车站 + 站数 + 该段实时状态**。
- 学生卡点出门 → **最关键的"下一班/到站倒计时"置顶且大号**。

### 2.5 与已澄清口径的关系

| 已澄清口径 | 本建议 | 是否冲突 |
|------------|--------|----------|
| 路线总览：乘车区间彩色 / 区间外灰色 | 2.4 完全遵守，并补充线宽/图层/换乘节点建议 | 无 |
| 巴士图标保持现有样式（运营商涂装色 + 5 状态） | 沿用 `VehicleMarker`（澳巴橙 / 新福利蓝 + moving/stopping/terminal/lost/unknown），**不改样式** | 无 |
| 收藏页不加地图 | 本建议**不涉及**收藏页 | 无 |
| 「详情缩成下半屏」「详情上拖到基本全屏」「关闭详情回推荐」 | 2.1/2.2 落为 50%↔88% 两档 + 返回 | 无 |

**建议复核项**：20% 收起档（用户未提，但符合 Google Maps 手感）→ 标为**可选/Backlog**，请用户拍板是否要。

## 3. 边界情况清单

| # | 场景 | 期望表现 |
|---|------|----------|
| 1 | **无实时车**（该方向当前无在途车辆） | 地图**不显示**车图标；面板显著位置显示"暂无在途车辆"并给**下一班发车时间**；区分"未发车"与"信号缺失"两种文案 |
| 2 | **已收班** | 不显示实时车；显示首末班时间 + "今日已收班"；给次日首班参考；不误导为"暂无车" |
| 3 | **单段 vs 换乘** | 单段 = 一条彩线 + 起终两点；换乘 = 多段多色 + 换乘节点；detail-body 需能处理 **0 / 1 / 2 次换乘** |
| 4 | **环线 / 起终点同站** | `fitBounds` 不能退化为一个点；环线**不画"区间外灰色"**（全线即乘车区间）；保留换向 |
| 5 | **超长跨全澳线路**（如 26 号） | `fitBounds` 后 zoom 很小 → 车辆图标密集重叠，**必须聚类**（沿用 `VehicleMarker` 屏距合并 + 数量角标） |
| 6 | **多车重叠 / 单车站点** | 聚类 + `9+` 角标；单车正常显示 |
| 7 | **地图加载失败 / 缺 Key** | 面板与详情**完全不受影响**（沿用"地图失败不阻塞"铁律）；顶部地图区显示占位 + 重试 |
| 8 | **详情接口失败** | 显示"详情加载失败（路线不受影响）+ 重试"；总览与地图照常 |
| 9 | **定位失败** | 起点回落"我的位置"缺失 → 沿用现有提示，可手动选出发点 |
| 10 | **网络慢 / 弱网** | 面板动画先行 + 骨架；不阻塞；车辆新鲜度可见 |
| 11 | **拖拽中数据刷新** | 拖拽期间**暂停**地图重绘/取景，落定后统一刷新，避免抖动 |
| 12 | **列表滚到顶再下拉** | 先滚内容，滚到顶才拖面板（嵌套滚动协调），避免误关 |
| 13 | **面板打开时点地图上的车** | 车信息卡（`VehicleCard`）z 序需明确 —— 建议**高于面板**，关闭车卡回面板；请架构师锁定层级 |
| 14 | **低端设备** | 限制车辆刷新频率（10s 冷却）；避免拖拽时重算 `fitBounds`；聚类降密度 |
| 15 | **横屏 / 大屏** | 横屏地图放宽；面板可退化为侧栏或限宽居中（Backlog） |
| 16 | **`Esc` / 键盘** | 桌面 PWA 可 `Esc` 关层；焦点陷阱；抓手下握条可键盘操作 |
| 17 | **空推荐（too_close / no_live / no_candidate）** | 沿用现有空态文案（不写空洞占位），不进入详情 |

## 4. 验收要点（Given/When/Then 摘要）

- Given 首页已选起终点，When 点「出发」，Then 推荐面板在 **≈88% 高度**出现，**顶部保留 96–128px 地图条**，且地图条**不被状态栏/灵动岛遮挡**。
- Given 推荐面板展开，When 点任一张推荐卡，Then 面板**平滑降到 ≈50%**，**上半屏地图显示该路线总览**（乘车段彩色 / 区间外灰色 / 起终点标记 / 换乘节点 / 全线在途车辆图标），且**面板动画不被接口阻塞**。
- Given 详情在半屏，When 向上拖并松手越阈，Then 吸附到 **≈88%**，顶部仍留一点点地图。
- Given 详情在任一档，When 下拉越阈 / 点返回箭头，Then **关闭详情、回到推荐列表（原位、保滚动位置）**。
- Given 面板在半屏，When 拖动地图 / 点地图上的车或站，Then **地图可正常交互**（非模态、无 scrim）。
- Given 列表在半屏且内部可滚，When 在列表上向下拖，Then **先滚列表，滚到顶才拖面板**。
- Given 该方向无在途车辆，Then 不显示车图标并给出"暂无在途车辆 + 下一班时间"或"已收班"文案。

## 5. 合规与调性（P0 绝对规则 · 自检）

- **禁止 emoji 作功能图标**：抓手下握条、返回箭头、关闭(X)、起点/终点/换乘节点、刷新、定位等**一律用统一 SVG 图标库**（具体由架构师按项目选型锁定，本文件不预设库名）；车辆图标沿用现有自绘 SVG。
- **禁止紫色→粉色渐变**：色彩沿用现有主题 Token（线路色为数据注入，不硬编码渐变）。
- **禁止 AI 模板味文案**：面板文案使用真实业务语言（如"暂无在途车辆"「已收班」「步行约 N 分钟」），不出现 "Welcome" / "Lorem ipsum" 类占位。
